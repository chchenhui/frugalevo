<DESCRIPTION>
The current implementation uses a fixed process-noise Q = 0.05*q_scale²*I. This forces a single rigidity/flexibility tradeoff across the entire signal: too rigid in volatile regions (lag, missed genuine dynamics) and too flexible in quiet regions (noise-induced wobble, false reversals — slope_changes 65.8, false_reversals 44.4). The first prior program showed that volatility-scheduling Q (rigid where quiet, flexible where volatile) directly targets these two metrics while preserving responsiveness. This edit computes a per-sample q_arr scaled by normalized local volatility and uses q_arr[i] inside the Kalman predict step, keeping everything else (RTS smoother, multi-scale SG, confidence-gated trend lead) byte-identical so the score delta isolates the Q-scheduling effect. Costs O(n) extra and no latency.
