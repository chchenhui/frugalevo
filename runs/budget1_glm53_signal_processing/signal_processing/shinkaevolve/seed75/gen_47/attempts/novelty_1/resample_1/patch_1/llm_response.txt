The current program (0.59) suffers from high slope_changes (121.8) and false_reversals (91.2) while having excellent lag (0.24) — it sits at the responsive-but-noisy end of the trade. The best prior program (0.63) had far fewer reversals but slightly more lag. The recommendation is to attack both ends simultaneously: (1) apply one short zero-phase Savitzky-Golay pass (window 5, order 2) to the RTS-smoothed level estimates to kill residual micro-reversals — since the RTS output is already heavily denoised, this only removes high-frequency residual energy without adding meaningful lag; (2) recover the small lag cost with a conservative slope-lead computed from an SG-smoothed slope channel. Prior lead attempts (Gen 41: 85.4 false reversals) failed because they amplified noisy slopes; here the slope is first passed through the same short SG filter, so the lead term carries almost no high-frequency energy. A conservative coefficient (0.2 · sg_half, capped at 2.0) keeps the lead well within the safety margin demonstrated by the lag_error budget (0.24 currently). The two mutations work on opposite ends of the smoothness–lag trade: SG reduces reversals, the gentle lead restores responsiveness.

def _sg_smooth_short(y, half=2):
    """Single short zero-phase Savitzky-Golay pass (order 2, window 5).
    Applied only to already-denoised Kalman/RTS output, so it removes
    residual high-frequency energy without introducing meaningful lag."""
    n = len(y)
    if n < 2 * half + 1:
        return y.copy()
    c = np.array([-3.0, 12.0, 17.0, 12.0, -3.0]) / 35.0
    padded = np.concatenate((
        2 * y[0] - y[2:0:-1],
        y,
        2 * y[-1] - y[-2:-2 * half - 2:-1],
    ))
    return np.convolve(padded, c, mode='valid')[:n]
