<DESCRIPTION>
The Kalman filter's lag error (0.26) and slope changes (82.20) can be improved by adding lead compensation using the *RTS-smoothed* Kalman slope state rather than a raw gradient. The smoother already produces a denoised slope estimate (`smoothed[:, 1]`) as part of the state vector — using it is essentially free. Applying a short 5-tap moving average to this slope channel removes any residual high-frequency energy before lead compensation, so a moderately aggressive lead (0.3 × effective lag) reduces lag error without re-injecting noise or causing spurious reversals. Additionally, tightening the reversal-gate thresholds slightly (sig 1.5→1.8, innovation significance 1.0→1.2) reduces false reversals (currently 60.40) by demanding more statistical evidence before boosting process noise, at minimal cost to genuine turning-point responsiveness since the gate only *increases* agility when triggered.</DESCRIPTION>

    estimates = smoothed[:, 0]

    # Denoised slope channel: RTS-smoothed slope state, then a short
    # moving average to strip residual high-frequency energy before it
    # is used for lead compensation (raw np.gradient would re-inject noise).
    slope_raw = smoothed[:, 1]
    ks = 5
    kernel = np.ones(ks) / ks
    slope_pad = np.concatenate((np.full(ks - 1, slope_raw[0]), slope_raw))
    slope_sm = np.convolve(slope_pad, kernel, mode='valid')

    # Lead compensation with the denoised slope cancels most of the
    # group delay of the smoothing without raising slope-change count.
    lead = 0.3 * (window_size - 1)
    estimates = estimates + lead * slope_sm

    # Match sliding-window output contract exactly:
    # output length = n - window_size + 1, end-aligned (smoothest region,
    # full forward+backward evidence -> minimal noise at equal responsiveness)
    output_length = n - window_size + 1
    y = estimates[n - output_length:]
    return y
