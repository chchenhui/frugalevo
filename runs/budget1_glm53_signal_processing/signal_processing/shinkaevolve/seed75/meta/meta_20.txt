# Optimization Insights from Program Evaluations

## Successful Algorithmic Patterns
- **The current best program (Gen 7, "stronger_smoother_with_trend_compensation", 0.64) remains the confirmed winner.** Its architecture — adaptive constant-velocity Kalman (MAD-based noise, 3-sigma innovation gating with R×9 inflation) → two zero-phase Savitzky-Golay passes with reflection padding → conservative slope-based lead compensation (0.25×sg_half) → end-aligned trim to `len(x) − W + 1` — is the only design in this round that combined all four elements correctly.
- **Causal Kalman + backward RTS smoother is a viable rival architecture.** Gens 15 (0.62), 19 (0.63), and 16 (0.56) all passed with correlation 0.92–0.97, noise reduction up to 0.83, and efficiency 1.00 — but all plateaued at smoothness ≤0.20 with 58–66 false reversals and slope changes 66–82. The RTS designs deliver *better noise reduction* (0.83 vs 0.67) than the best program but worse smoothness.
- **Reversal gates that boost process noise actively hurt smoothness.** Every correct RTS variant (Gens 15, 16, 19, 20) carried a trend-reversal gate, and every one showed the same pathology: high correlation + high false reversals (58–116) + smoothness 0.12–0.20. Gen 19's localized SG hysteresis pass (only smoothing weak-gradient sign-flip neighborhoods) was the best mitigation (58.4 false reversals) but still insufficient.
- **Accuracy/speed are saturated; smoothness is the score frontier.** Correct programs all hit correlation ≥0.92 and efficiency 1.00 (0.03–0.05s). The gap between 0.56–0.63 and the best 0.64 is entirely in smoothness (0.12–0.20 vs 0.27) and false-reversal counts.

## Ineffective Approaches
- **Contract failures remain the dominant cause of 0.00 scores.** Gen 9 never implemented `process_signal` despite sensible internal logic; Gen 18 (0.00) failed on edge cases/alignment in its two-stage adaptive Kalman+SG pipeline despite an architecture similar to the best program. Gens 13 (0.00) and 14 (0.00) also died on runtime/alignment bugs — fragile multi-stage pipelines without simple-input validation are fatal.
- **Non-causal filtering designs that violate real-time constraints fail.** Gen 10's forward-backward Kalman with geometric-mean blending (0.00) explicitly broke the real-time/online constraint, and geometric-mean fusion of squared estimates was numerically unstable near zero. Gen 12's RTS smoother (0.00) reused the final P instead of per-step posteriors — covariance bookkeeping bugs invalidate the entire output.
- **Note the RTS inconsistency:** Gen 10 was flagged as failing *because* the backward pass is non-causal, yet Gens 15/16/19/19's RTS backward passes scored 0.55–0.63. The evaluators evidently accept RTS smoothers in practice — the Gen 10 failure was more likely fusion numerics and misalignment than the backward pass per se. - **Trend-reversal gates + limited selective smoothing don't suppress micro-oscillations.** Gen 20 (0.55) applied SG only to weak-gradient sign-flip regions and got 115.8 false reversals and 149.4 slope changes — the most selective smoothing was the least effective. Gen 16's slope lead + SG polish (0.56, 66.4 false reversals) shows that lead compensation reintroduces ripple.
- **Complexity without verified correctness.** Gens 13 (constant-acceleration + RTS + median trend + blending) and 14 (triple SG + majority-vote slope + trend-lock with double padding) illustrate that stacked unvalidated stages compound fragility rather than improve quality.

## Implementation Insights
- **The best program's specific winning details:** `Q = 0.05·(median|diff(x)|)²` for the constant-velocity model; per-step measurement noise from a 3-tap moving average of |diff|; R×9 inflation when |innov| > 3√S; SG kernels via `pinv(AᵀA)Aᵀ` row 0; reflection padding `2·sig[0] − sig[1:half+1][::-1]`; conservative lead `0.25·sg_half·0.5·slope`. Each element is simple, vectorized, and edge-safe (`if m < 2*half+1: return sig.copy()`), which is why it passes while heavier pipelines crash.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

# Recommendations for Future Program Mutations

1. **Replace the forward-only Kalman with a causal Kalman + per-step-posterior RTS smoother, then feed its output into the existing double SG stage.** RTS is the optimal linear smoother for the constant-velocity model and demonstrated superior denoising (0.83 vs 0.67) in Gens 15/19 while holding correlation 0.92–0.97. Critically, store both `s[i]` and `P[i]` per step in the forward loop (Gen 12's fatal bug was reusing the final P) and run the standard backward recursion `s_smooth[i] = s[i] + (P[i]FᵀP_pred[i+1]⁻¹)(s_smooth[i+1] − F s[i])` through that sequence, keeping the end-aligned trim `smoothed[-output_length:]` and the `if m < 2*half+1: return sig.copy()` guards untouched.

2. **Add a third zero-phase SG pass (h3 = max(2, sg_half // 3), quadratic kernel) or widen the second pass from `sg_half // 2` to `(2 * sg_half) // 3` to directly attack the bottleneck metrics: smoothness (0.27) and false reversals (37.4).** The 0.59→0.64 jump came precisely from adding the second pass, and the false-reversal count tracks smoothness inversely (37.4→0.27, 58→0.20, 116→0.12), confirming they measure the same phenomenon. Use unconditional full-signal smoothing — evidence shows selective/gated smoothing consistently underperforms (Gen 20's region-restricted SG produced 115.8 false reversals vs Gen 7's 37.4 with full passes).

3. **Raise the trend-compensation lead from 0.25×sg_half toward 0.4×, but compute the slope from a denoised source instead of raw `np.gradient(smoothed)`.** The raw gradient re-injects high-frequency energy that undoes the double smoothing (Gen 16's slope-lead + SG polish showed lead compensation reintroducing ripple at 66.4 false reversals). Instead, store the Kalman slope state `s[1]` per step during the forward loop and use it (or apply one short SG pass to the gradient) before multiplying by `lead = 0.4 * sg_half` — this should improve lag_error (0.35) and false reversals simultaneously without sacrificing the 0.96 correlation.

4. **Make the SG half-window locally adaptive using the `local_std` array already computed in Stage 1, avoiding any new state or noise estimation.** Segment the signal into ~32-sample blocks, classify into 2–3 noise terciles, and assign per-block half-windows (e.g., `sg_half // 2`, `sg_half`, `3*sg_half // 2` by volatility), blending 2–3 samples across block boundaries to avoid seams.
