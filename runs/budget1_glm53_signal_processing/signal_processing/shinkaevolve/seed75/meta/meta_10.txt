# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

# Optimization Insights from Program Evaluations

## Successful Algorithmic Patterns
- **Kalman + zero-phase Savitzky-Golay pipeline is the dominant winner pattern.** The current best program (Gen 7, "stronger_smoother_with_trend_compensation", score 0.64) uses a constant-velocity Kalman with locally-adapted measurement noise (median abs-diff scale), 3-sigma innovation gating, *two* zero-phase S-G passes with reflected padding, and mild slope-based trend compensation. This is a direct evolution of Gen 3's single-pass version (0.59) — adding the second smoothing pass, stronger adaptive noise, and trend compensation cut slope changes from 107→54.8 and false reversals from 83→37.4 while *raising* correlation (0.95→0.96).
- **Zero-phase (non-causal) smoothing on the full signal is what fixes smoothness without adding lag.** Causal Kalman-only variants (Gen 1: 0.51, Gen 5: 0.52, Gen 11: 0.51) all had smoothness ≤0.08 and 175–324 slope changes; the S-G-based two-stage designs achieved smoothness 0.16–0.27 with slope changes 54–107.
- **Reflective edge padding + trimming to `len(x) − W + 1` aligned to the END of the signal** is the API contract that passes validation. Both top-scoring programs (Gen 3, Gen 7) use this exact convention.
- **Trend/lag compensation via slope extrapolation** (0.25×half-window lead in Gen 7) trades minimal noise reduction for much better responsiveness (0.74) at low lag cost.

## Ineffective Approaches
- **Backward "smoothing" passes that re-initialize state from raw noisy samples fail completely.** Gen 8 (score 0.00) reset the backward pass from raw samples, injecting noise instead of smoothing, and 100% of tests failed. A true RTS smoother must run backward through the forward covariance sequence.
- **Output alignment/length contract violations are fatal.** Gen 2 (zero-lag double-EMA, 0.00), Gen 6 (RTS-style light smoothing, 0.00), and Gen 8 (0.00) all failed on API/alignment issues (window alignment, initialization, `len(x) < window_size` handling) despite reasonable algorithms — algorithmic sophistication cannot compensate for contract mismatch.
- **Runtime bugs in polynomial/edge-padding stages kill otherwise sound designs.** Gen 4 (score 0.00, "kalman_trend_guard_filter") crashed on every test (short-signal edge padding, degenerate lstsq, dead `if False else` code). Gen 6 and Gen 8 also carried dead/redundant code (`if False else`, recomputation), correlated with total failures.
- **Aggressive adaptive process-noise boosting alone trades smoothness away with little gain.** Gen 1's reversal-gated process-noise boost (0.51) and Gen 5's innovation-triggered gain boost (0.52) produced 253–324 slope changes and smoothness 0.06 — responsiveness without an explicit smoothing stage plateaus near 0.51.

## Implementation Insights
- The current best program's key implementation details: (1) `Q = 0.05 · median(|diff(x)|)²`-scaled process noise; (2) per-step measurement noise from a 3-tap moving average of |diff|; (3) outlier gating that multiplies R by 9 when |innov| > 3√S; (4) **two** S-G passes (half-window W/2 cubic + smaller second pass) — the second pass is what drove the 0.59→0.64 improvement over Gen 3.
- S-G coefficients computed via `pinv(AᵀA)·Aᵀ` row 0 give a zero-phase kernel; reflection padding (`2·sig[0] − sig[1:half+1][::-1]`) handles edges without boundary artifacts.
- Vectorized cumsum box filter (Gen 0's `adaptive_filter`) delivers efficiency 1.00 at 0.01–0.03s across all programs — runtime is never the bottleneck; all filter stages should stay O(n) or convolve-based.
- Keep the baseline `adaptive_filter` and wrapper functions (`process_signal`, `run_signal_processing`) intact — every program that modified the output convention rather than just the evolve-block filter internals failed validation.

## Performance Analysis
- **Score trajectory by architecture:** simple/weighted MA (0.50) → causal Kalman variants (0.51–0.52) → Kalman + single S-G pass (0.59) → Kalman + double S-G pass + trend compensation (0.64, current best). Each stage added ~0.05; the biggest remaining gap is smoothness (0.27) vs. its other metrics.
- **Smoothness vs. responsiveness tradeoff is the active frontier:** the best program has correlation 0.96, noise reduction 0.67, lag 0.35, but smoothness only 0.27 with 54.8 slope changes and 37.4 false reversals — the feedback explicitly notes raising SG smoothing strength or the trend-compensation lead would cut false reversals further at ~0.74 responsiveness.
- **Failed programs cluster at exactly 0.00 with sentinel metrics** (slope_changes=100, false_reversals=50, lag/avg_error=1.0), distinguishing hard crashes/contract failures from tuning problems — 4 of 10 evaluated programs (Gens 2, 4, 6, 8) died this way, all with output-length/alignment or runtime-shape bugs.
- **Noise reduction correlates strongly with the smoothing stage count:** no S-G (0.33–0.53), one S-G pass (0.69), two passes (0.67 but with better smoothness/reversal metrics), confirming the two-stage smoothing pipeline is the right composite-score lever.

# Recommendations for Future Program Mutations

1. **Add a third zero-phase S-G pass (or widen the second pass) to directly attack the weakest metric, smoothness (0.27).** The 0.59→0.64 jump came precisely from adding the second S-G pass, and noise reduction correlates strongly with smoothing-stage count, so extend Stage 2 with a third pass using `h3 = max(2, sg_half // 3)` with a quadratic kernel, or raise `h2` from `sg_half // 2` to `(2 * sg_half) // 3`. Keep the `pinv(AᵀA)·Aᵀ` row-0 zero-phase construction and reflection padding exactly as-is, and re-measure `lag_error` to confirm it stays near 0.35.

2. **Raise the trend-compensation lead from 0.25×half-window toward 0.4–0.5×, but compute the slope from a denoised estimate instead of raw `np.gradient(smoothed)`.** The evaluation feedback explicitly states a stronger lead would cut false reversals while holding ~0.74 responsiveness; the current risk is that the raw gradient re-injects high-frequency energy that undoes the double smoothing. Use the Kalman slope state `s[1]` (already computed per-step — store it during the forward loop) or apply one short box/SG pass to the gradient before multiplying by `lead = 0.4 * sg_half`, which should improve lag_error (0.35) and false_reversals (37.4) simultaneously.

3. **Implement a true Rauch-Tung-Striebel backward smoother over the stored forward pass, feeding its output into the existing double-S-G stage.** Gen 8 scored 0.00 not because RTS is wrong but because its backward pass re-initialized state from raw noisy samples; the correct version stores per-step filtered states `s[i]` and covariances `P[i]` during the forward loop and runs the standard RTS recursion backward through that covariance sequence. This is the optimal linear smoother for the constant-velocity model, so it should reduce noise at equal responsiveness — and rigorously retain the end-aligned trim `smoothed[-output_length:]` with the fallback path, since all four 0.00-score programs died from output-length/alignment bugs, not algorithmic ones.

4. **Add a reversal-suppression hysteresis as a final light stage targeting false_reversals (37.4) and slope_changes (54.8).** After Stage 2, compute `g = np.gradient(smoothed)` and flag short segments where `sign(g)` flips within a few samples while `|g| < k * median(|g|)` (k ≈ 0.5) — these are residual micro-oscillations the S-G passes didn't kill. Apply one extra short zero-phase S-G pass (half-window ≈ 3–5) restricted to flagged neighborhoods so the well-performing correlation (0.96) and trend structure are untouched elsewhere.

5. **Make the S-G half-window locally adaptive using the `local_std` array already computed in Stage 1.** Segment the signal into blocks (~32 samples), classify each block into 2–3 noise terciles, and select the half-window per block (e.g., `sg_half // 2`, `sg_half`, `3 * sg_half // 2` by volatility), blending a few samples across block boundaries to avoid seams. Wide windows in noisy regions buy smoothness exactly where slope changes and false reversals originate, while narrow windows in quiet regions preserve the 0.74 responsiveness — attacking the tradeoff the feedback names as the active frontier. Keep all stages convolve-based and O(n) so efficiency_score stays 1.00.
