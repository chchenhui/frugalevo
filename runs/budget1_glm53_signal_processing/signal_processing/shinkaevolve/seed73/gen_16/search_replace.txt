<DESCRIPTION>
The current pipeline's final stage re-weights already-smoothed data with a Python loop, adding both compute cost and residual group delay (the exponential weights emphasize the window start-relative position, shifting the effective evaluation point backward and inflating lag_error to 0.41). This edit (1) replaces the per-sample loop with a single `np.convolve` using a precomputed weight vector (identical math, O(n) instead of O(n·W) Python overhead), and (2) spends the recovered efficiency on a light inter-window slope-consistency pass: we estimate noise σ robustly via MAD of the input's first differences, and wherever consecutive filtered values differ by less than 0.5σ — i.e., the difference is statistically indistinguishable from noise and cannot represent a genuine trend change — we snap the sample toward a 5-tap running median blend. This directly attacks slope_changes (41.2) and false_reversals (36.6) without touching genuine dynamics, since real trend changes exceed the noise floor. The smoothing kernel is also rebalanced toward the window's later samples to shave a bit of phase lag, improving responsiveness_score and correlation.

    # --- Inter-window slope-consistency pass ---
    # Robust noise sigma from MAD of first differences (diff var = 2 * noise var).
    d = np.diff(x_smooth)
    mad = np.median(np.abs(d - np.median(d))) / 0.6745
    sigma = max(mad / np.sqrt(2.0), 1e-12)

    if len(y) >= 5:
        # 5-tap running median of the filtered output
        pad = np.pad(y, 2, mode="edge")
        med = np.array([
            np.median(pad[i:i + 5]) for i in range(len(y))
        ])

        # (< 0.5 * sigma) toward the running median. Genuine trend changes
        # exceed this threshold and are left untouched, preserving dynamics.
