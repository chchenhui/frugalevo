# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Add Huber-style iterative reweighting between the Kalman and SG stages to attack the champion's two weakest metrics (noise_reduction 0.34, lag 0.41).** Run `savgol_filter` once on `x_kalman`, compute residuals, estimate robust σ via `MAD(residuals)/0.6745`, winsorize residuals to ±2.5σ, and re-run SG on the adjusted signal for 2 vectorized iterations. Gen 13's robust quadratic achieved noise_reduction 0.59 with correlation 0.93, so robust reweighting is the highest-leverage gap in an otherwise-saturated pipeline.

2. **Cap the NIS-driven Q multiplier: replace `q_scale = q_base * (1.0 + 10.0*min(nis,50)/10.0)` (up to 51×) with `q_base * min(1.0 + nis/10.0, 4.0)` and raise `q_base` from 0.01 to 0.02.** The uncapped multiplier can inject noise into the velocity state upstream of the SG window, partially defeating the 39-tap smoothing (a likely cause of the 30.2 remaining slope changes). The capped variant is the exact mechanism that made Gens 14/30 reliable at 0.53–0.54 responsiveness backbones.

3. **Apply a second 5-tap, 0.5σ median snap to `x_smooth` *before* the exponential recency convolution.** Removing noise-sized steps prior to window averaging compounds the smoothing effect (smoothness 0.40 is the score-driving metric), and efficiency headroom is ample (0.03s, efficiency 1.00). This stays entirely in the level-domain, noise-scaled mechanism that decisively beat all slope-gating designs — do not add any slope machinery.

4. **Make the snap threshold locally adaptive instead of the single global MAD-of-diffs σ**: compute rolling robust σ over ±25-sample blocks of `x_smooth` diffs via `np.lib.stride_tricks.sliding_window_view` (fully vectorized), then use 0.5×(local σ) per sample. Keep any changes vectorized via `np.convolve` "valid" mode to preserve the 1.00 efficiency score.
