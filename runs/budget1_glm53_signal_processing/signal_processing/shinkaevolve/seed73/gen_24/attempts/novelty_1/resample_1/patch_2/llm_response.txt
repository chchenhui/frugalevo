<DESCRIPTION>
The current NIS-driven process-noise scaling can inflate Q up to ~51× q_base (1.0 + 10.0 * 50/10 = 51), which leaks measurement noise directly into the velocity (slope) state — the likely cause of the 41 spurious slope changes and the elevated false-reversal count (36.4). Since false reversals are the metric that almost perfectly predicts rank (all programs under 60 reversals score ≥ 0.57), taming this over-aggressive adaptation is the highest-leverage change. I cap the multiplier at 4× while raising q_base from 0.01 to 0.02 so that genuine turns are still tracked quickly, but noise-driven overshoots in the velocity estimate are suppressed. This should reduce slope changes and false reversals with only a minor, acceptable increase in lag error.
</DESCRIPTION>
