widen_only_adaptive_r

<DESCRIPTION>
The current adaptive R blend (0.5·R0 + 0.5·ewma_var) slightly hurt noise_reduction (0.59 vs 0.63) and correlation (0.92 vs 0.93) versus the static-R Gen 20 baseline, because when the EWMA variance dips below R0 (clean segments where innovations are small largely because the prediction is good), R tightens, the gain rises, and more measurement noise leaks into the estimate — the exact opposite of what we want in quiet regions. The theoretically sound use of innovation-based adaptive R in a smoother context is *widen-only*: let R increase during genuine noise bursts (large squared innovations ⇒ wider R ⇒ smaller Kalman gain ⇒ more smoothing) but never fall below the robust static MAD estimate R0, which already represents the best global noise floor. I implement this as Rk = max(R0, 0.7·R0 + 0.3·ewma_var) in the forward pass, keeping the state update purely x_est = xp + K·innov (no signal-shaping terms, per the Gen 2 lesson). The second (refinement) pass reuses the same Rseq[k] so it stays consistent. This should recover the noise reduction of the static-R version while retaining burst robustness, improving smoothness and slope-change/false-reversal metrics with no extra pipeline stage and negligible cost.
</DESCRIPTION>
