# Analysis of Program Evaluation Results

## Successful Algorithmic Patterns

- **True RTS (Rauch-Tung-Striebel) backward smoothing on a constant-velocity Kalman filter is now the best-scoring architecture (0.67, Gen 21 kalman_rts_smoother_variant)** — surpassing the prior best (forward-backward velocity-weighted fusion, 0.64 Gen 20 / 0.55 Gen 5). It achieves correlation 0.95, noise reduction 0.65, efficiency 1.00, and the fewest slope changes (36.0) and false reversals (26.6) of any correct program, with lag error 0.32.
- **Forward-backward Kalman fusion remains the strongest family**: Gen 20 (akf_bidirectional_smoother, 0.64, correlation 0.96, noise reduction 0.78) and Gen 13 (rts_smoother_zero_phase, 0.53) confirm that dual-pass zero-phase designs consistently dominate single-pass (Gen 10 savgol at 0.58 with lag 0.28 is competitive only via zero-phase SG).
- **Robust MAD-based noise estimation for R (MAD of first differences / (0.6745·√2)) paired with acceleration-derived adaptive Q** in the best program gives data-driven tuning without hand-set constants, and the quadrature noise-subtraction trick (`mad2² − noise_d2²` with a `0.05·σ_r` floor and `0.6·σ_r` cap) prevents Q from over-trusting noise.
- **Routing both "basic" and "enhanced" modes through the same best filter** (as in the current best program) is safe and simplifies the interface contract.

## Ineffective Approaches

- **Missing `process_signal` entry points cause total failure regardless of algorithm quality**: Gen 2 (adaptive_kalman_wavelet_hybrid, 0.0) and Gen 16 (kalman_trend_adaptive_filter, 0.0) both left the tested harness function undefined/NameError — sophisticated cores never executed. This is a recurring, fatal interface error.
- **Hidden systematic biases in the filtering math poison output even when wired correctly**: Gen 2's additive trend-lean term (`trend_sign·σ̂·0.05`) and blended wavelet correction would have injected offsets harming RMSE/correlation; deliberate signal-shaping terms are risky.
- **Stair-step/deadband level-correction reconstruction degrades smoothness**: Gen 22 (fused_velocity_deadband, 0.51) saw its deadband rebuild-from-previous-level produce 107 slope changes and 83 false reversals (smoothness 0.16, noise reduction only 0.24). Gen 15's held-velocity level correction similarly contributed to failure (0.0).
- **Over-trusting noisy dynamics via adaptive process noise limits smoothness**: the best program's own feedback notes the adaptive Q still over-trusts noisy dynamics (smoothness 0.36, lag 0.32); Gen 13 (261.8 slope changes, smoothness 0.07) shows aggressive smoothing parameters tracking noise too closely from the other direction.

## Implementation Insights

- **The best program's structural keys**: (1) full forward pass storing `xp/xf/Pp/Pf`, then true RTS recursion `xs[k] = xf[k] + G(xs[k+1] − xp[k+1])` with `G = Pf[k]FᵀPp[k+1]⁻¹`; (2) covariance symmetrization `P = 0.5(P+Pᵀ)` for numerical stability; (3) slicing `xs[window_size−1:, 0]` with an explicit length assertion (`n − window_size + 1`) — the output-length contract is enforced, not assumed.
- **Correct output-length contract remains the make-or-break detail**: Gen 12 (hybrid_hysteresis_trend_filter) failed entirely (0.00, "All test signals failed") with lag_error 1.00 and zero correlation — likely a shape/alignment mismatch despite a sophisticated pipeline; Gen 15's truncation slicing also broke validation. All correct programs (Gens 10, 13, 14, 20, 21, 22) emit exactly `n − window_size + 1`.
- **Slope-reversal suppression needs more than a single-neighbor average**: Gen 10 (savgol_zerophase, 0.58) used slope_hysteresis averaging only one neighbor, leaving 127 false reversals and smoothness 0.10. Persistence-based gates (3-step commitment in Gen 12, deadbands in Gen 22) either failed validation or introduced artifacts — the best program achieves the lowest reversal counts (26.6) with *no explicit reversal stage*, purely via RTS minimum-variance smoothing.
- **Efficiency is saturated**: every correct program scores 1.00 at 0.03s, but Gen 15's pure-Python per-step matrix Kalman was flagged as slow — the best program avoids this cost via small fixed 2×2 operations and vectorized noise estimation.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

# Actionable Recommendations for Future Program Mutations

1. **Refine the acceleration-noise floor/cap calibration to better separate true dynamics from measurement noise.** The best program's feedback notes that adaptive Q still over-trusts noisy dynamics, and its smoothness (0.36) remains the weakest major metric. Try a grid of floor values (0.02, 0.05, 0.10)·σ_r and caps (0.4, 0.6, 0.8)·σ_r while keeping the quadrature subtraction `mad2² − noise_d2²` fixed — a slightly larger floor or tighter cap would shrink Q, trading a small amount of the lag (0.32) for fewer slope changes (currently 36) and false reversals (26.6). This is a two-constant tuning mutation that leaves the validated RTS structure, slicing contract, and interface untouched.

2. **Make Q locally adaptive instead of globally constant: estimate acceleration variance in overlapping segments and interpolate a per-step Q[k].** The current implementation computes one global `qa`, which forces a single smoothness/responsiveness trade-off across the whole signal. Compute `mad2` over sliding blocks (e.g., blocks of length ≈ window_size with 50% overlap), linearly interpolate σ_acc(k) between block centers, then build Q[k] = σ_acc(k)²·[[0.25, 0.5], [0.5, 1.0]] in the forward pass (using Q[k] at each prediction step; the RTS backward pass uses the same stored `Pp` and needs no change). This targets avg_error (0.35) on the multi-frequency test signal, where the high-frequency 5 Hz component needs larger Q than the slow trend segments.

3. **Add a bidirectional (zero-phase) post-smoother with moderate strength on the RTS output, applied before slicing.** Gen 20 showed bidirectional Kalman fusion achieves lag 0.28 with correlation 0.96, suggesting the lag budget has headroom. Run a forward-then-reversed one-pole smoother (α ≈ 0.5–0.65) or a short Savitzky-Golay (window ≈ window_size//4, odd, order 2) over the full `xs[:, 0]` sequence, then apply the existing slice `xs[window_size−1:]`.
