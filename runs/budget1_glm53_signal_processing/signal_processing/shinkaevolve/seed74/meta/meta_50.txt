# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **The two-pass Kalman + true RTS refinement with 4×-reduced Q remains the winning skeleton**: the current best (Gen 47 `rts_velocity_clamp_fusion`, 0.72, and Gen 51 `kalman_rts_velocity_clamp_v2`, 0.72) both use forward constant-velocity Kalman → true RTS backward pass → second forward+RTS pass at Q/4 (Gen 51 extends to Q/1, Q/4, Q/8 three-pass blend), fused with velocity-aware displacement clamping. Metrics: correlation 0.89, noise_reduction 0.55, smoothness 0.50, lag 0.34, false_reversals 14.2, efficiency 1.00 at 0.05–0.07s.
- **The current best program's code confirms the plateau architecture**: full forward pass storing `xp/xf/Pp/Pf`, exact RTS recursion with `G = Pf[k]FᵀPp[k+1]⁻¹` + pinv fallback, MAD-of-first-differences for R, quadrature-subtracted acceleration variance for Q (floor 0.05σ_r, cap 0.6σ_r), covariance symmetrization, and a final bidirectional one-pole damper with alpha 0.55–0.95 via tanh on residual-noise ratio.
- **Adaptive-Q extensions deliver the best tracking metrics but not the best composite**: Gen 43/Gens 52 `localq_rts_pipeline_filter` (0.60) hit correlation 0.96 and noise_reduction 0.73–0.74, but smoothness collapsed to 0.17–0.18 with 68–71 false reversals — high responsiveness achieved at the cost of the smoothness/reversal metrics that dominate the composite.
- **The whole 0.68–0.72 cluster is one family**: Gen 44 (RTS cascade with widen-only R, 0.68), Gen 48 (`local_block_mad_q`, 0.71), Gen 47/51 (velocity-clamp fusion, 0.72) — all correctly-wired zero-phase Kalman/RTS + damper variants.

## Ineffective Approaches

- **Interface wiring failures remain the only source of zeros**: Gen 28 (`adaptive_hybrid_kalman_zla_filter`, 0.0) called an undefined `process_signal` instead of its `filter` method, referenced `self._p_prev_01` before initialization, and returned a dict rather than an array. Gen 36 (`adaptive_bidirectional_damper_rts`, 0.0) likewise called undefined `process_signal` and never invoked `filter_signal`. Gen 49 (0.0) crashed on harness edge-case signals (likely `n < window_size` ValueError). Three of nine programs were killed by integration, not algorithms.
- **Too-weak final polish lets residual jitter through**: Gen 43/52's short Savitzky-Golay polish (window ≈ window/2) failed to smooth residual Kalman noise — 68–96 slope changes vs the best program's 20.4. Feedback is consistent: the polish stage must be stronger/longer or replaced by more smoothing inside the RTS stage.
- **Over-conservative correlation guards (≥0.97) and high alpha floors (0.40–0.55) block smoothing**: Gen 44's damper backed off too aggressively (smoothness 0.41, 23 false reversals); Gen 45 (`sgolay_multiscale_adaptive`, 0.65) accepted smoothing stages too rarely, yielding noise_reduction 0.36 and 20.8 false reversals.
- **Stacking extra adaptive machinery on the damper doesn't beat doing more work in the RTS stage**: Gen 45's three cascaded SG passes with trend-guided clamping scored 0.65, well below the 0.72 simple two-pass RTS core.

## Implementation Insights

- **The best program (Gen 47/51 code shown) keeps all entry points (`adaptive_filter`, `enhanced_filter_with_trend_preservation`, `process_signal`) routed through one core `kalman_rts_filter`**, with the explicit output contract `y = y[window_size-1:]`, `len(y) = n − window_size + 1` — this exact pattern is what Gens 28/36/49 lacked and died on. Note Gen 49's identical architecture scored 0.0 purely from fragile edge-case handling; the current best guards `n < window_size` and `n == 1` gracefully.
- **Velocity-aware displacement clamping guarded by correlation retry/fallback is validated as the top scorer's differentiator** (Gen 47/51, 0.72) — combining Gen 37's dynamics-blend refinement with Gen 41's clamp, exactly as the previous insights predicted.
- **Robust statistics are universal across all top scorers**: MAD-of-first-differences R, block/local MAD second-difference Q with noise-floor subtraction (Gen 48's block-MAD adaptive Q, 0.71), EWMA widen-only R (Gen 44). These add robustness without runtime cost (0.05–0.07s, efficiency 1.00 everywhere).
- **Iterated refinement passes are cheap and safe**: Gen 51's three Q-reduced passes (Q/1, Q/4, Q/8) blended via dynamics-aware weights matched Gen 47's 0.72 with identical metrics — no gain from the third pass, but no penalty either, indicating saturation of the refinement lever.

## Performance Analysis

- **Score ceiling unchanged at 0.72**: the correctly-wired RTS family spans 0.60–0.72 with the same accuracy/efficiency saturation (correlation 0.89–0.96, efficiency 1.00). The gap between Gen 47/51 (0.72, smoothness 0.50, 14.2 reversals) and Gen 43/52 (0.60, smoothness 0.17, ~70 reversals) confirms smoothness/false-reversals are the dominant composite levers, not correlation.
- **Responsiveness vs smoothness trade quantified**: Gen 43/52 achieved lag_error 0.27–0.28 and correlation 0.96 (best in family) but lost ~0.12 combined score to jitter; the best program accepted lag 0.34 for 4–5× fewer false reversals. Future gains likely require preserving adaptive-Q tracking while adding a stronger zero-phase ripple suppression stage.
- **Noise reduction is decoupled from score**: Gen 44 (nr 0.61, score 0.68) vs Gen 47 (nr 0.55, score 0.72) — the composite rewards the balanced profile; chasing nr at the expense of reversals is counterproductive.
- **Zeros are entirely preventable**: 3 of 9 programs (33%) failed on NameError/crash/interface issues while their underlying algorithms were reasonable (Gen 36's RTS + damper was "never wired in"). Contract compliance — single funnel entry, array return, graceful short-input handling — is worth more than any single algorithmic tweak.

# Actionable Recommendations for Future Program Mutations

1. **Add velocity-aware displacement clamping between the second RTS pass and the bilateral damper.** After computing `y = xs[:, 0]` from the Q/4 refinement pass, clamp per-step displacement in a forward sweep plus a mirrored backward sweep (zero-phase): limit |y[k]−y[k−1]| ≤ 2·|velocity estimate at k| + 0.5·σ_r, where the velocity estimate comes from the second pass's `xs[:, 1]` state. Guard with a correlation retry (if corr(clamped, unclamped) < 0.97, double the slack to 1.0·σ_r and re-apply); the current best already stores velocity states, so this costs nothing structurally and directly targets smoothness (0.50) and false reversals (14.2), the dominant composite levers per the score-ceiling analysis.

2. **Replace the final bilateral one-pole damper with a fixed-λ Whittaker–Henderson polish (second-order difference penalty).** Use λ = clip(25·(r_std/σ_r)², 1, 200) from the existing residual MAD, solved with a banded (bandwidth-5) O(n) Cholesky solver to preserve the 0.05s runtime. The evidence shows Gen 40's Whittaker hit 0.71 with only the curvature-relaxed λ leaking noise — a *constant* λ keeps the penalty uniform, and the second-order penalty's flatter passband should cut residual ripple (slope changes 20.4 → fewer) without the lag a stronger one-pole adds. Apply it to the full-length signal and slice last to protect the `len(y) = n − window_size + 1` contract (Gen 23's zero came from a length-changing post-smoother).

3. **Make Q locally adaptive via block-MAD second differences computed from the first-pass smoothed output, interpolated per-sample.** Compute σ_acc in overlapping blocks of length ≈ window_size (50% overlap) using y1's second differences (y1 is already denoised, so its d2 reflects genuine dynamics like the 5 Hz component a global Q under-serves), subtract the (σ_r/√w)·√6 noise floor per block, floor at 0.05σ_r, cap at ~1.5σ_r, and linearly interpolate to Q[k] used at each prediction step — the second pass uses 0.25·Q[k]. This fuses Gen 48's validated block-MAD Q (0.71) with the two-pass core to attack lag_error (0.34) and avg_error (0.39) by granting busy segments larger process noise while smoothing slow segments harder — but keep the strong final polish so the Gen 43/52 jitter collapse (smoothness 0.17, ~70 reversals) is not repeated.

4. **Reorder the pipeline: run the moderate-alpha bilateral damper between the two RTS passes instead of last.** Place a one-pole pass at alpha ≈ 0.65 after the first RTS output, then let the Q/4 refinement pass finish the signal — RTS's minimum-variance smoothing re-sharpens corners the damper rounds while the ripple it removed stays gone. Keep R = σ_r² and all noise statistics unchanged, and monitor lag_error; if it exceeds 0.40, back the inter-pass alpha toward 0.75 or add a light alpha=0.9 final bilateral only when the post-pass-2 residual MAD exceeds 0.3·σ_r. This exploits the consistent finding that smoothing inside the RTS stage beats damper-stage heuristics (Gens 42/45 damper stacking capped at 0.65–0.68).

5. **Harden the interface and edge-case envelope before any algorithmic change — copy the current best's contract verbatim into every mutation.** Three of nine prior programs scored 0.0 from integration failures (undefined `process_signal`, dict returns, `n < window_size` crashes), which outweighs any algorithmic gain. Concretely: route `adaptive_filter`, `enhanced_filter_with_trend_preservation`, and `process_signal` through one core function that returns a 1-D float array sliced as `y[window_size-1:]` with a final length assertion, guard `n < window_size` by returning a graceful fallback (e.g., the input clipped to length max(1, n − window_size + 1)) rather than raising, and handle n == 1 and NaN/inf inputs explicitly. Test with n = 1, 2, window_size−1, and window_size before submission.
