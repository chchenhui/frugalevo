<DESCRIPTION>
The metrics show the main weakness is smoothness: slope_changes (307) and false_reversals (245.4) are very high, while lag/accuracy are already good. The current causal Kalman filter is noisy because the adaptive measurement noise (r = r_base + 0.5*innov²) makes the filter over-trust large innovations (which are often noise spikes), producing spurious directional reversals. Two targeted fixes:

1. Soften the adaptive R using a smoothed innovation estimate (EMA of squared innovations) instead of the instantaneous innovation — this prevents single noise outliers from collapsing the measurement noise and yanking the state, which directly reduces slope changes and false reversals without adding lag.

2. Add a forward-backward (Rauch-Tung-Striebel style two-pass) smoothing pass over the Kalman estimates. Since this is offline sliding-window processing (we already return a windowed output), running the same constant-velocity filter backwards and averaging with the forward pass makes the filter effectively zero-phase, eliminating the phase delay of the causal filter while suppressing high-frequency jitter — this improves smoothness AND reduces lag error simultaneously, without hurting tracking accuracy since both passes use the same dynamics model.

These changes attack the weakest metrics (smoothness_score 0.06, slope_changes, false_reversals) while preserving the strong ones (correlation 0.93, avg_error 0.23).
