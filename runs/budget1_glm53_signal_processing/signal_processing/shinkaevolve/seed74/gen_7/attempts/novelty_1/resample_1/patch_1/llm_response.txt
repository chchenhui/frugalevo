<DESCRIPTION>
The metrics show the current filter tracks well (correlation 0.92, lag 0.36) but suffers from many slope changes (231) and false reversals (183), giving a very low smoothness score (0.08). The bottleneck is spurious high-frequency ripple in the endpoint estimates, not lag. Adding more linear smoothing would increase lag error, so instead I add a nonlinear "reversal suppression" post-pass: small sign changes in the output's first difference that are within the estimated noise floor are damped (partially reverted toward the previous trend), while large, genuine reversals (magnitude well above noise) are passed through untouched. This directly targets slope-change minimization and the false-reversal penalty with almost zero additional lag, since only sub-noise-scale reversals are attenuated. The noise floor is estimated robustly via MAD of the first differences already computed, so the method adapts to the signal's noise level without parameters tied to a specific test signal.</DESCRIPTION>

    # Reversal suppression: small sign flips in the first difference that
    # are within the estimated noise floor are spurious ripple; damp them
    # toward the previous trend. Large reversals (genuine dynamics) pass
    # through untouched, so lag error stays minimal.
    if output_length > 2 and r_std > 0:
        # Noise floor for a single step difference
        thresh = 2.0 * r_std
        damping = 0.3  # retain 30% of a sub-noise reversal
        prev_d = y[1] - y[0]
        for i in range(2, output_length):
            d = y[i] - y[i - 1]
            if prev_d * d < 0:  # sign flip (reversal candidate)
                if abs(d) < thresh:
                    # Spurious, noise-driven reversal: keep mostly the
                    # prior trend direction, only partially apply the flip.
                    y[i] = y[i - 1] + (1.0 - damping) * prev_d * 0.0 + damping * d
                # else: genuine reversal, leave unchanged

    return y
