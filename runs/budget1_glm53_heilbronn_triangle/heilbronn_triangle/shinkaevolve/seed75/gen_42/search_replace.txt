<DESCRIPTION>
The current local search only perturbs the 3 points of the single worst triplet, which easily cycles: many near-degenerate triples compete, and the search oscillates between them without structural escape. Two targeted improvements:

1. **k-worst point set**: instead of only the worst triplet's points, gather the union of points appearing in the k=5 smallest-area triples. This spreads the gradient/mutation signal across all binding constraints (as recommended), avoiding the dilution and cycling of a single binding constraint.

2. **Longer budget with more candidates**: the run finishes in 5.3s while the prior 20s run also scored only 0.71 — the incremental area updates make each step cheap, so we can afford more restarts, more candidates (K=48), and a full polish phase. Raising the budget to 17s trades a small eval_time cost for a much better chance to find the high-area boundary configurations known for n=11 (best arrangements place most points on the boundary).

Both changes are consistent with the existing incremental machinery (`best_of_k_move` already supports any point index).
