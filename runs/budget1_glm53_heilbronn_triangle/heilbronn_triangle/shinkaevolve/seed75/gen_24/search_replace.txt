<DESCRIPTION>
Two changes: (1) The current `_optimize` gradient uses a Python loop over all 165 triples inside every SLSQP jacobian call, which caused the huge 3.23s eval time while yielding only 0.03 score (and the polish phase was dropped, explaining the collapse from 0.46). Replace the loop with a fully vectorized `np.add.at` scatter-add gradient — mathematically identical but orders of magnitude faster, freeing time budget. (2) Re-introduce the batched worst-triplet guided random polish (the component that produced the 0.46 result in only 0.39s), applied after projecting the SLSQP solution into the triangle. The polish moves points belonging to the currently-worst triplets, evaluates a whole batch of candidate moves at once via vectorized min-area computation, and includes occasional global teleport escapes. This combination of fast SLSQP refinement plus guided stochastic polish is the best-performing architecture among the prior programs.

        yhi = SQRT3 * x if x <= 0.5 else SQRT3 * (1.0 - x)

        return 0.5 * np.abs(cross).min(axis=1) / TRI_AREA
