# Optimization Insights: Heilbronn Triangle Problem (n=11)

## Successful Algorithmic Patterns
- **Random-restart discrete local search with worst-triplet perturbation remains the winning pattern.** The current best program (Gen 12, score 0.77, min_area 0.03, 7.06s) uses 25 restarts, best-of-32 Gaussian moves on the worst triplet's points, shrinking step size (×0.6), and barycentric projection — matching the previous best's core design. A nearly identical variant (Gen 19, "batched_kworst_perturbation") scored 0.55 with a much faster 0.29s runtime by perturbing the 6 worst triples in batch, showing the pattern is robust to parameterization.
- **Uniform random barycentric initialization (sqrt-transform) is essential.** All successful programs (Gen 12, Gen 19) start from non-degenerate random interior points; every structured/lattice seed produced zero-area collinear triplets and scored 0.00.
- **Deterministic seeding (fixed RNG seed 12345) with vectorized C(11,3)=165 triple evaluation** keeps runs reproducible and fast (7.06s for 25 restarts), and targeted perturbation of only the offending triplet is cheap per-iteration.
- **Increasing restart count from 12 to 25 kept the best program at the 0.77/0.03 plateau** — consistent with the observed min_area ceiling of 0.03 across all evaluated programs.

## Ineffective Approaches
- **Softmin/soft-relaxation with gradient-based optimizers underperforms discrete search.** Gen 17's softmin-SLSQP + polish scored only 0.22 (min_area 0.01, 0.35s); Gen 14's softmax/Powell multi-start crashed outright (broadcasting bug: `rng.normal(size=(n,3))` added to a flattened 33-vector). Smooth relaxations consistently land in near-degenerate basins or fail entirely.
- **Lattice/symmetric fallback paths guarantee zero scores.** Gen 11 (0.00), Gen 16 (0.00), and Gen 15 (0.00) all had their primary search crash silently into a fallback: Gen 15's fallback even contained an infeasible point (0.25, 5h/6) outside the triangle. Gen 9's seed loop wrote 14 points into an 11-slot array, crashing before any except path could help.
- **Near-instant eval time (~0.01s) is a perfect diagnostic for total failure.** Gen 11, Gen 13, and Gen 16 all scored 0.00 with 0.01s runtimes — the main optimizer never executed and the fallback returned degenerate (collinear) configurations.
- **Sophisticated frameworks with broken scoring/feasibility pipelines waste their design.** Gen 13's barycentric annealing with directed moves and Gen 11's three-phase hill-climb with restarts were structurally sound but reported min_area 0.00 — robustness/validation failures completely negate the algorithmic quality.

## Implementation Insights
- **The best program's per-iteration economy is the key to its lead**: `_min_area` gathers all 165 triples at once via `points[triples]` vectorized cross products and returns the argmin index, enabling targeted perturbation of only the 3 offending points — no softmin approximation, no gradient machinery.
- **Barycentric projection (clip weights to [0,1], renormalize, recombine with vertices) is the proven feasibility repair** — used without issue by Gen 12 (0.77) and Gen 19 (0.55); never triggers exceptions, unlike hardcoded lattice clipping paths.
- **Silently-swallowed exceptions are the dominant failure mode across generations** (Gen 11, 13, 15, 16, 9). Programs that fail visibly (validation errors from array-shape bugs like Gen 14's missing `.ravel()` or Gen 9's out-of-bounds seeding) at least produce diagnosable feedback; the worst cases are broad try/except blocks that return zero-scoring fallbacks. Validating that any returned configuration has strictly positive min area would eliminate this class.
- **Batched worst-triple evaluation (Gen 19's k-worst, 6 triples at a time) achieves 24× speedup** (0.29s vs 7.06s) at some score cost (0.55 vs 0.77), suggesting per-restart throughput can be substantially improved without abandoning the discrete search paradigm.

## Performance Analysis
- **Score distribution is starkly bimodal**: 0.00–0.31 for crash/fallback/degenerate cases (Gens 9, 11, 13, 14, 15, 16, 20) vs. 0.55–0.77 for working discrete local searches (Gens 12, 19). The best program (Gen 12, 0.77) exceeds the nearest working alternative (Gen 19, 0.55) by 40%.
- **min_area_normalized 0.03 remains the observed ceiling** across all 10 evaluated programs, including the previous best. Neither more restarts (12→25), more polish phases (Gen 20's 1500-iteration perpendicular-escape polish, 0.31), nor hybrid SLSQP+hill-climb (Gen 17, 0.22) broke past it — indicating pure worst-triplet local search saturates near 0.03 and further gains require structurally different global search.
- **Eval time inversely signals failure**: all 0.01s runs scored 0.00 (fallback path), while the top scorer needed 7.06s. Gen 19's 0.29s at 0.55 shows the runtime/score tradeoff is tunable via batch size.
- **Every crash was an implementation bug, not an algorithmic limit**: array-shape mismatches (Gen 9, Gen 14), infeasible fallback points (Gen 15), and unhandled exceptions falling into degenerate lattices (Gen 11, 16). Fixing these would likely promote several 0.00 programs into the 0.2–0.6 band, but none showed evidence of surpassing the 0.03 min_area plateau.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

# Recommendations for Future Mutations

1. **Add directed (gradient-informed) perturbation moves to the worst-triplet loop.** Instead of only isotropic Gaussian moves, compute the direction perpendicular to the line through the other two points of the worst triplet and move the perturbed point along that direction (scaled by the current step), which provably increases that triplet's area. This replaces wasted random attempts — the analytic direction comes free from the same vectorized cross-product machinery already in `_min_area`, and acceptance is still gated on global min-area improvement, so it can't hurt feasibility.

2. **Hybridize with Gen 19's batched k-worst perturbation to raise per-restart throughput.** Port Gen 19's 6-worst-triplets-at-once batching as a fast inner loop (cheap exploration at 0.29s-class speed), then switch to the current best's single-worst fine-grained loop with shrinking steps only when the batched phase stalls. This directly combines the two proven working programs (0.77 and 0.55) and could afford 2–5× more restarts within the same ~7s budget.

3. **Add a post-restart crossover/merge polish phase.** After all 12 restarts, take the top 2–3 configurations, build merged candidates (e.g., random subset of ~5 points from one config and 6 from another, projected via `_project`), and run the existing shrinking-perturbation loop on each. This exploits the restart count increase evidence (12→25 restarts stayed at 0.77) which suggests independent restarts saturate — combining complementary sub-arrangements is the lowest-risk structurally-new move.

4. **Add global point-relocation moves when the local search stalls.** When `step` shrinks below ~1e-3 without improvement, teleport a randomly chosen point from the worst triplet to a fresh uniform barycentric location (reuse `_init_points`' sqrt-transform for a single point) before decaying the step further, accepting only if global min-area improves. This directly attacks the diminishing-returns behavior of pure local perturbation without abandoning the proven discrete-search paradigm.

5. **Add a strictly-positive min-area validation guard against silent fallback failures.** Before returning, assert `_min_area(best_pts, triples)[0] > 0`; if the search somehow produced a degenerate configuration, re-run at least one restart rather than returning it. Given that all five 0.00-scoring generations failed via swallowed exceptions/degenerate fallbacks, and Gen 12's 7.12s runtime has ample budget headroom, this cheap guard eliminates the dominant failure mode at essentially zero cost.
