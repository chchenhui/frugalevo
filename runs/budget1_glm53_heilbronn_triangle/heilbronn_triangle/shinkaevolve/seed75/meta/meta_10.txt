# Optimization Insights: Heilbronn Triangle Problem (n=11)

## Successful Algorithmic Patterns
- **Random-restart local search with random interior initialization is the only pattern that scored.** The current best program ("Random-Restart Local Search for Heilbronn Triangle," Gen 3, combined_score 0.77, min_area 0.03) and the softmax-based program (Gen 5, 0.76) are the only nonzero scores. Both use multi-start strategies (12 restarts / 4 starts) and avoid hand-crafted symmetric seeds.
- **Guaranteeing feasibility by construction works better than clipping.** Gen 5's softmax convex parametrization of triangle vertices makes every candidate feasible by construction and scored 0.76; the best program's barycentric projection is simple, vectorized, and never triggered exceptions (7.12s, clean run).
- **Perturbing the worst triplet's points with shrinking steps (0.6× decay, 24 attempts per point) is effective for escaping local minima** when started from a non-degenerate random configuration — this is the core loop of the 0.77-scoring best program.
- **Correct vectorized triple-area computation via cross products over precomputed C(11,3)=165 triples** is shared by the top scorers (Gen 3, Gen 5) and runs fast enough for thousands of evaluations.

## Ineffective Approaches
- **Structured/symmetric seeds with collinear triples are fatal.** Gen 10's warm start (vertices + edge midpoints + interior points) guaranteed a zero-area collinear triple from the outset — local search cannot escape a zero baseline, giving score 0.00. Gen 2 and Gen 8's centroid-plus-rings seeds similarly produced 0.00 despite valid-looking geometry.
- **Silent exception fallbacks mask total failure.** Gen 1, Gen 7, and Gen 9-style programs all returned score 0.00 with suspiciously fast eval times (0.04–0.06s), indicating the main optimization path crashed into a lattice fallback whose configuration also scored zero.
- **Smooth/soft-min relaxation with gradient-based optimizers underperforms or breaks.** Gen 6's SLSQP soft-min collapsed to degenerate configurations (score 0.03, min_area 0.00) due to an inverted objective sign; Gen 5's softmin + Powell (0.76, 15.82s) got stuck in local optima and was slower than the discrete search.
- **Incorrect triple enumeration is a recurring crash bug.** Gen 4 failed validation with "not enough values to unpack" from `np.triu_indices(n, 3)` — use `itertools.combinations` or explicit index arrays instead.

## Implementation Insights
- The best program's `_min_area` gathers all 165 triples at once (`points[triples]` → vectorized cross products → `argmin`) and returns the worst index, enabling targeted perturbation of only the offending triplet — cheap and effective per-iteration.
- Barycentric projection `_project` (clip weights to [0,1], renormalize, recombine with vertices) is a robust, vectorized feasibility repair used by the best program without issue.
- Uniform random triangle sampling via the sqrt-transform (`su = sqrt(u0)` barycentric coords) in `_init_points` guarantees a non-degenerate, general-position start — the key differentiator from the 0.00-scoring lattice/ring seeds (Gen 2, 8, 10).
- The best program avoids any try/except fallback in the hot path, so failures would be visible rather than silently degrading to a zero-scoring fallback (contrast Gen 1, 7).

## Performance Analysis
- Score distribution is starkly bimodal: 0.00–0.03 combined for all structured-seed/exception-prone/soft-min variants (Gens 1, 2, 4, 6, 7, 8, 10) vs. 0.76–0.77 for random-restart discrete search (Gen 3) and softmax relaxation (Gen 5).
- The best program (0.77, 7.12s) beats the softmax+Powell approach (0.76, 15.82s) while being ~2.2× faster — discrete triplet-targeted perturbation is both more effective and cheaper than smooth relaxation.
- min_area_normalized of 0.03 is the observed ceiling across all evaluated programs; feedback on Gen 3 notes the single-triplet perturbation strategy and pure random restarts show diminishing returns, motivating stronger global moves for further gains.
- Eval time near ~0.05s correlates perfectly with score 0.00 — an instant fallback path is a reliable diagnostic signal that the main search crashed or was never entered.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Perturb the k-worst triplets jointly, not just the single worst.** The feedback notes that single-triplet perturbation shows diminishing returns. Extend the core loop: after identifying the worst triplet via `_min_area`, collect the bottom 5–10 triplets by area and attempt moves that improve the minimum over that whole set simultaneously (accept only if the global min area improves), which gives the search more escape directions from local minima while reusing the existing vectorized area computation unchanged.

2. **Add global relocation moves alongside local perturbation.** When step-size shrinks below ~1e-3 without improvement, instead of immediately decaying further, occasionally pick the point involved in the worst triplet and teleport it to a fresh uniform barycentric location (using the existing `_init_points` sqrt-transform sampling for a single point), accepting if min_area improves. This hybrid local/global move directly addresses the diminishing-returns observation on pure random restarts.

3. **Increase restart count with an anytime budget check.** The best program uses 12 restarts in 7.12s, well under typical time limits. Scale to 24–36 restarts (or wrap restarts in a time-budget loop, e.g. `while time.time() - t0 < 25`), keeping everything else identical. Since scores vary across random starts and the search is the proven pattern, more restarts is the lowest-risk path to a higher best-of-N score.

4. **Try a deterministic crossover/merge between restart results.** After several restarts complete, take the two best configurations and construct a merged candidate (e.g., keep the 5–6 points from each config that participate in the largest-area triplets, project the rest), then run the shrinking-perturbation loop on the merged configuration as a final polish. This exploits the fact that good configurations may contain complementary sub-arrangements that neither pure restart achieves.

5. **Target constrained moves rather than isotropic Gaussian perturbation.** When perturbing a worst-triplet point, move it along directions that specifically increase that triplet's area (e.g., away from the line through the other two points, scaled by the current step), or move all three worst-triplet points outward from their centroid simultaneously. The isotropic random move wastes most of its 24 attempts; a gradient-informed direction for the offending triplet (computable analytically from the cross product) should improve acceptance rates and converge faster per restart.
