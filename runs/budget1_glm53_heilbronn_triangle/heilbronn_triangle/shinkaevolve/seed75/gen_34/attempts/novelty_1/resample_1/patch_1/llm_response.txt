<DESCRIPTION>
The current program is slow (7.12s) because it evaluates candidate perturbations one at a time with a Python-level triple loop. The prior faster programs show that vectorizing candidate evaluation is the key to both speed and quality: with a batched best-of-K move we can afford many more restarts and a finer multi-scale step schedule within the same wall time, which directly improves min_area (the primary objective). Additionally, focusing moves on the points of the K worst triplets (rather than only the single worst) helps escape poor basins. I therefore: (1) add `_areas_all` and a `_min_area_batch` helper, (2) replace the scalar inner loop with a vectorized best-of-24 perturbation over the movers of the 6 worst triplets plus a fallback global sweep, and (3) increase restarts to 25 with early bail-out on hopeless starts so time budget is spent on good basins.

def _areas_all(points, triples):
    p = points[triples]
    a = p[:, 1] - p[:, 0]
    b = p[:, 2] - p[:, 0]
    return 0.5 * np.abs(a[:, 0] * b[:, 1] - a[:, 1] * b[:, 0])


def _min_area_batch(batch, triples):
    """Minimum triangle area for each of K configurations, shape (K, n, 2)."""
    p = batch[:, triples]  # (K, T, 3, 2)
    a = p[:, :, 1] - p[:, :, 0]
    b = p[:, :, 2] - p[:, :, 0]
    areas = 0.5 * np.abs(a[:, :, 0] * b[:, :, 1] - a[:, :, 1] * b[:, :, 0])
    return areas.min(axis=1)

        if best_val > 0 and cur_val < 0.4 * best_val:

        while step > 1e-7:
            improved = False
            areas = _areas_all(pts, triples)
            worst_order = np.argsort(areas)[:KWORST]
            movers = sorted(set(triples[worst_order].ravel().tolist()))
