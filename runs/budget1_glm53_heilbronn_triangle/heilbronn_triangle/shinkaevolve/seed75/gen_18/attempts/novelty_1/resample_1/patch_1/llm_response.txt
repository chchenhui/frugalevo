<DESCRIPTION>
The current random single-point polish is undirected: it picks a random point and hopes it helps. Following the recommendation, we should identify the bottom-k worst triplets and concentrate the search effort on the points participating in them, evaluating many candidate displacements vectorized at once. Concretely: (1) compute all triplet areas, (2) take the worst triplet's three vertices as the "hot" point set (plus occasionally the bottom-10 triplets' union for wider moves), (3) generate a batch of candidate perturbations for each hot point, evaluate all of them with one vectorized area computation, and accept the best improving candidate. This gives the search many escape directions from local minima while reusing the existing vectorized `_areas` machinery, and it evaluates dozens of moves for the cost of roughly one. We also raise the polish budget slightly since batched evaluation is cheap, and keep a global-best tracker to never lose an improvement.

        yhi = SQRT3 * x if x <= 0.5 else SQRT3 * (1.0 - x)
        return np.array([x, np.clip(p[1], 0.0, yhi)])

    def _min_area_batch(base_pts, move_idx, move_pts):
        """Vectorized min area over a batch of candidates, each moving one point.
        base_pts: (n,2); move_idx: (B,); move_pts: (B,2). Returns (B,) min areas."""
        B = move_idx.shape[0]
        P = np.broadcast_to(base_pts, (B, n, 2)).copy()
        P[np.arange(B), move_idx] = move_pts
        A = P[:, TRIPLES[:, 0]]
        Bv = P[:, TRIPLES[:, 1]]
        Cv = P[:, TRIPLES[:, 2]]
        cross = (Bv[:, :, 0] - A[:, :, 0]) * (Cv[:, :, 1] - A[:, :, 1]) - \
                (Bv[:, :, 1] - A[:, :, 1]) * (Cv[:, :, 0] - A[:, :, 0])
        return 0.5 * np.abs(cross).min(axis=1) / TRI_AREA
