<DESCRIPTION>
The current search has two weaknesses. First, it only accepts strictly-improving moves and returns the *last* configuration, so a bad accepted move can never be undone — we must track the global best configuration separately (current version even has a bug: `best_points` is compared after the loop but `points` may have drifted below it, and the final comparison logic returns the worse of the two). Second, the warm start uses a coarse triangular lattice that leaves points clustered, giving a poor basin. I propose: (1) an improved warm start using a refined symmetric construction spread across the whole triangle, (2) correct global-best tracking during the search, (3) a two-phase schedule: coarse exploration with occasional simultaneous two-point moves (which escape one-point local optima typical in Heilbronn arrangements), then fine refinement, and (4) bounded restarts from perturbed copies of the best solution if the search stalls. All moves are still clipped into the triangle and evaluated with the same fast vectorized triplet computation, keeping determinism via the fixed seed.
