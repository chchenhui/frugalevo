<DESCRIPTION>
The primary problem is quality, not speed: min_area_normalized is stuck at 0.01 while the benchmark is 0.0365. Random jitter local search easily gets trapped: the minimum-area ("bottleneck") triangle involves specific points, and random single-point moves rarely relieve it. Expert practice for Heilbronn-type max-min problems is (a) to identify the bottleneck triangle each iteration and move only its vertices with a multi-scale line/grid search (this is far more effective than blind jitter), and (b) to finish with a fine polish pass on the bottleneck. I add a `_bottleneck` helper, a `_polish` routine that performs coordinate-wise multi-scale moves on the bottleneck triangle's points (accepting only strict improvements), and hook it after the local search for each seed. This uses only ~12 candidate evaluations per bottleneck step, keeping runtime comparable while dramatically improving the achievable minimum area. I also add one extra structured (near-symmetric) seed, since symmetric configurations are known to be good starting points for Heilbronn problems.

def _min_doubled_area(b):
    xy = _to_xy(b)
    p = xy[_TRIPLETS[:, 0]]
    q = xy[_TRIPLETS[:, 1]]
    r = xy[_TRIPLETS[:, 2]]
    cross = np.abs((q[:, 0] - p[:, 0]) * (r[:, 1] - p[:, 1])
                   - (q[:, 1] - p[:, 1]) * (r[:, 0] - p[:, 0]))
    return cross.min()


def _bottleneck(b):
    """Return (min doubled area, index of worst triplet)."""
    xy = _to_xy(b)
    p = xy[_TRIPLETS[:, 0]]
    q = xy[_TRIPLETS[:, 1]]
    r = xy[_TRIPLETS[:, 2]]
    cross = np.abs((q[:, 0] - p[:, 0]) * (r[:, 1] - p[:, 1])
                   - (q[:, 1] - p[:, 1]) * (r[:, 0] - p[:, 0]))
    k = int(np.argmin(cross))
    return float(cross[k]), k


def _polish(b, rounds=400):
    """Greedy multi-scale moves targeting the points of the bottleneck triangle."""
    cur = _clamp_simplex(b.copy())
    cur_val, tri = _bottleneck(cur)
    steps = [0.01, 0.003, 0.001, 3e-4, 1e-4, 3e-5, 1e-5]
    for _ in range(rounds):
        improved = False
        for k in _TRIPLETS[tri]:
            for comp in range(2):
                for s in (+1, -1):
                    for h in steps:
                        cand = cur.copy()
                        cand[k, comp] += s * h
                        cand = _clamp_simplex(cand)
                        val, t2 = _bottleneck(cand)
                        if val > cur_val + 1e-14:
                            cur, cur_val, tri = cand, val, t2
                            improved = True
                            break
                    if improved:
                        break
                if improved:
                    break
            if improved:
                break
        if not improved:
            break
    return cur, cur_val
