# Optimization Insights Analysis

## Successful Algorithmic Patterns
- **Multi-start pattern search over perturbed lattice seeds is the current best strategy**: Generation 6 (`local_search_heilbrilbronn11`, combined score **0.55**, min_area 0.02, 1.72s) uses 6 perturbed order-3 triangular lattice seeds + centroid, with 12-direction pattern search over shrinking steps (0.04→0.0005). This beat both simulated annealing variants.
- **Vectorized minimum-area computation over all C(11,3)=165 triplets** with precomputed triplet indices (as in the current best program) is a consistent component of all scoring programs (Gen 5, 6, 9) — it enables thousands of fast objective evaluations.
- **Fast greedy refinement with curated seeds pays off quickly**: Generation 9 (`Curated-seed maximin hill-climbing`, score 0.41, min_area 0.02) achieved nearly the same min_area in **0.05s** via deterministic hill-climbing with two perturbation scales and early stagnation exit — 30× faster than Gen 6 at a small score cost.
- **Perturbing lattice seeds to break collinearity is essential**: the current best program explicitly adds Gaussian noise (σ=0.02) to the lattice before refinement, avoiding the zero-area degeneracy that plagued Gen 1 and Gen 7.

## Ineffective Approaches
- **Buggy/insufficient triangle projection causes total failure**: Gen 4 (wrong normal direction on the left slanted edge) and Gen 8 (initial points at y=5h/12 with x=0.125/0.875 outside the triangle) both scored 0.00 solely because points escaped the container. Gen 3's clipping also failed for the same reason.
- **Pinning points on edges/vertices creates degenerate zero-area triangles**: Gen 1 (pinned vertices + edge points) and Gen 7 (anchored vertices + fallback edge points like [0.25,0], [0.75,0]) both passed validation but scored **0.00** because collinear edge/axis points produced zero-area triplets.
- **Cold or poorly tuned annealing wastes compute**: Gen 5 (`annealed_graded_lattice_11`, 10.62s) scored only 0.38 despite the largest time budget — its acceptance temperature (T*1e-3) was far too cold for effective exploration, and its heavy per-iteration Python `_in_triangle` loop over all points was a major bottleneck.
- **Structured starts with wrong point counts**: Gen 2 returned (6,2) arrays instead of (11,2), failing shape validation entirely.

## Implementation Insights
- **The current best program's winning elements**: (1) a mathematically correct explicit barycentric clip (l2=y/h, l1=x−0.5·l2, l0=1−l1−l2, clamp-and-renormalize); (2) try/except fallback that still returns a valid 11-point configuration rather than failing; (3) precomputed `_TRIP` triplet index array avoiding repeated `combinations` calls; (4) accepting moves only when strictly better (v > best_val + 1e-12).
- **Apply inside-triangle validation to ALL points including seeds**: Gen 8's failure showed that validating only perturbed candidates while the initial configuration is illegal propagates invalid points to the output. The best program clips both the initial configuration and every candidate.
- **Projection should be incremental, not all-points**: Gen 5's per-iteration full-array projection loop made each of 24k iterations O(n) in Python; Gen 6/9 only clip the moved point (or clip candidate arrays cheaply via vectorized barycentric formulas).
- **Try/except masking can hide optimization failure**: Gen 7's fallback configuration (edge points, symmetry-axis points) was silently returned, producing a valid but zero-scoring result — fallbacks must themselves be verified for nonzero min-area.

## Performance Analysis
- **Score trend across generations**: 0.00 (Gen 0-4) → 0.38 (Gen 5, annealing, 10.62s) → **0.55 (Gen 6, pattern search, 1.72s)** — the current best. Gen 7 regressed to 0.00 via a degenerate fallback; Gen 9 recovered to 0.41 with a much faster (0.05s) hill-climber.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Vectorize the `_clip` function** to operate on all 11 points at once via the existing barycentric formulas (l2=y/h, l1=x−0.5·l2, l0=1−l1−l2, clamp-and-renormalize), eliminating the per-point Python loop. Since `_clip` is called for every candidate move in `_refine`, this is the hot path — an all-Numpy clip could cut eval_time significantly (Gen 5's 10.62s vs Gen 6's 1.72s showed how much per-iteration Python costs), freeing budget for more multi-start seeds or finer refinement steps.

2. **Add a "move all points at once" coarse phase before the single-point pattern search**: propose global perturbations of the whole configuration (e.g., random displacement of all points with σ=0.01–0.02, re-clipped) and accept if min_area improves. The feedback shows all top programs plateau at min_area≈0.02 due to local optima from lattice-like initializations; coordinated multi-point moves escape single-point local traps that the 12-direction single-point search cannot.

3. **Diversify seed geometry beyond the order-3 lattice**: in addition to the perturbed lattice + centroid, generate initializations from a "repulsion" layout (points pushed away from each other via a few iterations of electrostatic-style repulsion inside the clipped triangle), and a deterministic asymmetric layout (e.g., golden-ratio jitter) — run the same `_refine` on each. Multi-start over more diverse geometry addresses the identified bottleneck (initialization strategy), not the local refiner.

4. **Use randomized directional steps instead of the fixed 12-direction fan**: replace the deterministic 12 directions with ~8 random directions per point per step scale (or 12 random angles regenerated per sweep), plus occasionally random per-coordinate jitter. Gen 5's failure was temperature, not stochasticity; randomized moves let the search squeeze through asymmetric gaps in the constrained triangle geometry that a fixed fan may miss, at similar or lower cost.

5. **Add a strict safeguard against degenerate fallbacks and enforce a nonzero-area floor in `_refine`**: after refinement, verify min_area > 0; if the best result is below a floor (e.g., 0.01), restart refinement with a fresh perturbed seed rather than returning the degenerate result. Gen 7 and Gen 8 showed that invalid or degenerate configurations silently score 0.00 — adding an explicit `if best_val < 1e-6: continue/retry` check on both the fallback path and each multi-start candidate guarantees the returned configuration is always non-degenerate.
