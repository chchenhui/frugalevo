<DESCRIPTION>
The current hill-climber wastes most of its time in a triple-nested Python loop inside `point_scores` (called every iteration over all 165 triples × 3 points), and only tries one candidate move per scale for the whole group of worst points. Two targeted fixes:

1. Vectorize `point_scores` using `np.minimum.at` scatter-min, eliminating the Python triple loop. This frees eval_time budget for more iterations.
2. Strengthen the search: try multiple independent random moves for each of the worst points individually at each scale, and add a finer final scale level plus more iterations. Moving one point at a time with several attempts is much more effective for maximin problems than perturbing 3 points simultaneously, since the objective is limited by the single binding smallest triangle.

Both changes keep determinism (fixed seeds) and error handling intact.

        def point_scores(bb):
            # min area per point: the worst triangle each point belongs to
            a = self.geom.areas(self.geom.to_xy(bb), self.tri)
            pmin = np.full(self.n, np.inf)
            # scatter-min: for each point, the smallest area over all
            # triples that contain it (fully vectorized, no Python loop)
            np.minimum.at(pmin, self.tri[:, 0], a)
            np.minimum.at(pmin, self.tri[:, 1], a)
            np.minimum.at(pmin, self.tri[:, 2], a)
            return a, pmin
