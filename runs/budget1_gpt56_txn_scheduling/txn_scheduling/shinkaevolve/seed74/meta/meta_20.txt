# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **The current best, Generation 18 “Exact Beam and Local-Search Scheduler,” demonstrates that a bounded variable-neighborhood local search improves materially beyond insertion/swap/reversal alone.** It achieved the highest valid result: **4132.23 combined score** and **241.00 makespan**. Its distinguishing addition is short **contiguous block relocation** (block lengths 2–4), layered on top of insertion, swap, and interval reversal. This outperformed Generation 16’s insertion/swap/reversal/perturbation approach (**3906.25**, makespan **255**) and Generation 13’s similar iterated descent (**3891.05**, makespan **256**).

- **Direct optimization of `workload.get_opt_seq_cost()` remains the strongest consistent design choice.** Generation 18 ranks beam prefixes, evaluates perturbations, and accepts local moves using the real simulator makespan. This is consistent with the other strong valid programs: Generation 12 reached **4032.26 / 247.00** with direct-cost beam search plus insertion, block relocation, and swaps; Generation 16 reached **3906.25 / 255.00** using direct-cost multi-neighborhood search. The evaluated evidence continues to favor simulator-objective search over proxy conflict scores or sampled greedy selection.

- **Exact-small-instance plus bounded beam-large-instance is a robust high-performing hybrid.** Generation 18 exhaustively evaluates all permutations through seven transactions, then uses a deterministic beam for larger workloads. This same cutoff pattern was valid across Generations 11, 12, 13, 14, 16, and 18. It preserves provable optimality on small cases while avoiding the validation/performance risks associated with a more aggressive exact branch such as the previously invalid nine-transaction expansion.

- **Diversified seeds and deterministic escape moves improve over optimizing only the top beam order.** The current program refines several top beam schedules, then adds deterministic interval reversals, a block relocation, and endpoint exchange perturbations of the best beam result. Generation 18’s **241** makespan supports the value of escaping strict local optima; simpler beam-plus-insertion implementations such as Generation 10 reached only **290.00**, while Generation 19’s broader beam/insertion/swap design reached **287.00**.

## Ineffective Approaches

- **Complexity did not compensate for correctness failures.** Generation 15 (“Beam Search Variable-Neighborhood Scheduler”) used a very similar concept—relocations, block moves, swaps, exchanges, perturbations, impact-guided sampling, and direct simulator scoring—but received **0.0** because it failed validation. Generation 17 likewise used beam search, cached exact scoring, insertion, swap, reversal, and perturbation, but was invalid and scored **0.0**. These results show that advanced neighborhood logic only contributes when schedule construction and edge-case behavior remain fully correct.

- **Insertion-only local search was substantially weaker than richer neighborhoods.** Generation 10’s cost-aware beam plus insertion/swap refinement produced **3436.43** with makespan **290**, and Generation 19’s two-stage diverse beam reached **3472.22 / 287**. In comparison, Generation 18’s additional reversals and bounded block relocation reduced makespan to **241**, a **46–49 point** reduction versus these insertion-centered variants.

- **Perturbation and restart mechanisms alone were not enough to reach the best result.** Generation 14 added perturbed local seeds but remained at **3663.00 / 272**, matching Generation 11’s score rather than surpassing it. Generation 13’s deterministic kicks plus insertion/swap/reversal improved to **3891.05 / 256**, but still trailed Generation 18. The performance evidence indicates that perturbations are most effective when paired with the stronger block-relocation neighborhood, not as a replacement for it.

- **Uncontrolled or fragile search expansions have repeatedly produced zero-score outcomes.** The prior evaluations noted invalid implementations with unreachable code, uninitialized state, excessive exact search, or unspecified edge-case failures. Generations 15 and 17 reinforce that richer search code increases the surface area for move-index, permutation-preservation, runtime, and API-semantics errors; their algorithm descriptions were sophisticated, but their validity was **0.00**.

## Implementation Insights

- **Generation 18’s objective cache is central because every phase depends on simulator calls.** Its `evaluate(sequence)` function memoizes tuple-keyed calls to `workload.get_opt_seq_cost(list(key))`. The same cache covers beam prefixes, full candidate schedules, removal-impact calculations, perturbations, and all local-search neighborhoods. This enables extensive exact-cost comparisons without repeatedly simulating identical orders.

- **The beam is deliberately deterministic and bounded.** The current best initializes one prefix per transaction, expands all unused transactions from retained prefixes, sorts by `(cost, prefix)`, and keeps a width of `max(8, min(48, num_seqs * 5))`. This avoids Generation 0-style random sampled greedy discard while preventing unbounded breadth. Deterministic lexical tie-breaking also makes repeated runs stable.

- **The local search applies best improvement across complementary move types rather than accepting the first improvement.** For each round, Generation 18 searches insertion, pairwise swap, interval reversal, and short block-relocation candidates, retains the lowest-cost candidate found, and accepts it only if it strictly improves the current cost. This strict-improvement policy prevents cycling, while the move portfolio changes different sets of transaction relationships: insertion relocates one transaction, reversal reorders an interval, and block relocation preserves useful internal block order while moving that block across a conflict region.

- **Large-workload scaling is structured rather than random.** Above 30 transactions, Generation 18 limits source and destination positions using evenly spaced anchor positions plus positions with high estimated removal impact. It computes impact as `current_cost - evaluate(reduced_schedule)`, so sampling remains tied to the actual simulator objective. Generation 12 used a comparable sampled impact-based strategy and achieved **4032.26**, while Generation 18’s stronger final neighborhood set pushed performance further to **4132.23**.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Add bounded ejection-chain moves after the existing best-improvement neighborhood scan.** Implement a two-transaction chain such as: remove transaction `a`, insert it at position `p`, then remove a second displaced/high-impact transaction `b` and reinsert it at position `q`; evaluate the final complete permutation directly and accept only strict improvements. Restrict this expensive neighborhood to high-removal-impact transactions and anchor destinations on large instances, extending the demonstrated value of block relocation without opening an uncontrolled exhaustive search.

2. **Select local-search seeds for structural diversity rather than taking only the top-ranked beam entries.** Keep the best beam schedule, then choose further seeds from a larger prefix of the final beam (for example top `min(len(beam), 3 * local_seed_count)`) by maximizing positional or pairwise-order distance from already selected seeds while maintaining a reasonable beam-cost threshold. Generation 18 already benefits from multiple seeds and deterministic perturbations; explicitly avoiding near-duplicate beam schedules should expose additional basins of attraction to the strong insertion/swap/reversal/block-relocation descent.

3. **Use an adaptive beam-width schedule that is wider only during early and middle prefix construction.** Retain more prefixes—for example 64–80—until roughly half of the transactions have been placed, then taper deterministically toward the current 48-state width near full schedules. Early prefix decisions have the greatest downstream ordering impact, while narrowing late preserves runtime and keeps the final local-search seed count bounded; this is a low-risk extension of the already successful deterministic direct-cost beam.

4. **Expand deterministic perturbation-reoptimization from one base beam schedule to a small set of locally optimized elite schedules.** After ordinary descent, generate a fixed number of controlled kicks from each of the best few distinct local optima: medium interval reversal, 2–4 item block relocation across distant anchors, and a distant exchange, then rerun the same strict best-improvement VND. This preserves the current program’s validity-safe permutation operations and simulator-objective acceptance rule, while making perturbation useful at the stronger post-local-search stage rather than only from the initial best beam order.

5. **Make large-instance move sampling dynamically focus on transactions involved in recently improving moves.** In addition to evenly spaced anchors and removal-impact positions, record indices/transaction IDs touched by the last accepted insertion, reversal, swap, or block move and prioritize them plus nearby positions in the next local-search round. Since successful improvements often reveal a conflict-heavy region, this concentrates the bounded direct-cost evaluations where the current schedule has already shown sensitivity, while retaining anchor positions to allow long-distance escape moves.
