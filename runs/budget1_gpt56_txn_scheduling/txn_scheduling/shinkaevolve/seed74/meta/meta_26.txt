# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **The current best, Generation 18 “Exact Beam and Local-Search Scheduler,” remains the strongest validated design at 4132.23 combined score and 241.00 makespan.** Its decisive combination is: exact permutation enumeration through seven transactions; deterministic, exact-objective beam search thereafter; best-improvement local descent over insertion, swap, reversal, and contiguous block relocation; and deterministic perturbation seeds. The short block-relocation neighborhood (lengths 2–4) remains the clearest differentiator over insertion/swap/reversal-only approaches.

- **Generation 23 “Conflict-Aware Beam Search with Local Descent” nearly reproduces the best result, reaching 4115.23 and makespan 242.00.** It also uses direct `get_opt_seq_cost()` evaluation, diversified beam retention, insertion/swap/reversal descent, and block-oriented perturbations. Its result—only 1 makespan unit behind Generation 18—strongly confirms that exact objective ranking plus diversified beam candidates and multi-neighborhood local descent is the most successful family of methods.

- **Direct simulator-objective optimization consistently outperforms proxy-driven scheduling.** Generations 18, 23, 21, and 20 all rank candidates with `workload.get_opt_seq_cost()` and all are valid, with makespans of 241, 242, 252, and 268 respectively. Generation 21’s objective-guided beam, VND, and elite perturbations reached 3952.57/252, demonstrating that even without Generation 18’s especially strong bounded block-relocation descent, exact objective guidance produces high-quality schedules.

- **Beam diversification and multiple refined seeds improve over optimizing only one greedy/beam result.** Generation 18 refines several leading beam schedules and adds interval reversal, block relocation, and endpoint-swap perturbations. Generation 23 similarly preserves elite prefixes plus endpoint diversity and refines several completed beam schedules. These designs substantially exceed Generation 25’s narrower beam/local insertion and swap strategy, which reached only 3412.97 with makespan 292.00.

## Ineffective Approaches

- **Reducing local-search expressiveness substantially worsened valid performance.** Generation 25’s “Cost-Aware Beam Search with Local Insertion” used exact cost evaluation, adaptive beam width, and bounded insertion/swap search, but reached just 3412.97/292.00. Relative to Generation 18, this is a 109.26-point combined-score deficit and 51 additional makespan units. The missing reversal, short block-relocation, multi-seed perturbation, and broader variable-neighborhood descent align with that gap.

- **Broader beam search alone did not match the stronger local-search portfolio.** Generation 20’s width-adaptive conflict-aware beam plus insertion/swap refinement reached 3717.47 with makespan 268.00. It improved materially over insertion-centered methods such as Generation 25, but remained 27 makespan units behind Generation 18, indicating that early beam breadth cannot substitute for block relocation, reversal, and structured escape moves after a full schedule is formed.

- **Complex search logic that breaks control flow receives no value regardless of its intended heuristic quality.** Generation 22 scored 0.00 because the small-instance path falls through into ejection-chain code before `descend` exists, while an unconditional return makes the large-instance pipeline unreachable. The intended exact-cost beam search and ejection-chain local search were therefore never reliably executed.

- **Fragile schedule-construction code also caused complete failure.** Generation 24 scored 0.00 despite proposing exact-cost beam search with reversals, relocations, swaps, and block moves. Evaluation feedback identifies the greedy insertion loop’s complicated transaction-removal logic as likely faulty. This reinforces the prior evidence from invalid Generations 15 and 17: neighborhood sophistication only matters when every candidate remains a valid permutation and all branches are reachable.

## Implementation Insights

- **Generation 18’s tuple-keyed objective cache supports every expensive search stage.** `evaluate(sequence)` converts each candidate to a tuple and memoizes `workload.get_opt_seq_cost(list(key))`. The cache covers beam prefixes, full schedules, local moves, reduced schedules used for removal-impact calculation, and perturbations. Since candidate ranking always uses the simulator’s conflict-aware objective, cached reuse makes a much richer search practical without changing the optimization target.

- **The best program uses bounded, deterministic beam search rather than random construction.** It starts from every singleton transaction, expands each retained prefix with every unused transaction, sorts by `(cost, prefix)`, and keeps `max(8, min(48, num_seqs * 5))` candidates. This produces repeatable selection and avoids randomly discarding promising prefix continuations. Generation 23’s elite-prefix and endpoint-diversity beam achieved a nearly identical 242.00 makespan, validating the importance of retaining diverse high-quality prefixes.

- **Generation 18’s best-improvement VND is broader than the weaker valid variants.** In every local-search round, it scans insertion moves, pairwise swaps, interval reversals, and contiguous block moves of lengths 2–4, then accepts only the best strictly improving candidate. This differs from Generation 20’s insertion/swap-oriented refinement and Generation 25’s bounded insertion/swap refinement. The result is consistent with the performance hierarchy: 241 for Generation 18, 268 for Generation 20, and 292 for Generation 25.

- **Large-instance scaling is objective-informed rather than purely random or uniformly exhaustive.** Above 30 transactions, Generation 18 evaluates removal impacts as `current_cost - evaluate(reduced_schedule)`, combines high-impact positions with evenly spaced anchors, and restricts source/destination positions accordingly. This preserves long-range move coverage while avoiding full cubic-or-higher neighborhood enumeration. The approach retains exact simulator scoring even under bounded search.

## Performance Analysis

- **Generation 18 remains the best evaluated valid program, but Generation 23 provides strong independent confirmation of its design.** Generation 18 scored 4132.23 with a 241.00 makespan; Generation 23 scored 4115.23 with 242.00. The difference is only 17.00 combined-score points and 1 makespan unit, while both use exact-objective beam search, diversified candidates, and rich local search. Their near tie establishes this as the dominant evaluated algorithmic pattern.

- **The new evaluations reinforce a clear local-search-expressiveness trend.** Generation 25’s insertion/swap-focused approach scored 3412.97/292; Generation 20’s adaptive beam with insertion/swap refinement improved to 3717.47/268; Generation 21’s beam plus insertion/swap/reversal descent and elite kicks improved further to 3952.57/252; Generation 23’s diversified beam and stronger descent reached 4115.23/242; and Generation 18’s bounded block relocation plus perturbation strategy leads at 4132.23/241.

- **Generation 18 exceeds Generation 21 by 179.66 combined-score points and 11 makespan units.** Both programs directly optimize `get_opt_seq_cost()` and use multiple seeds/escape mechanisms. The remaining difference corresponds closely to Generation 18’s more complete best-improvement move set, especially contiguous block relocation integrated directly into repeated descent rather than relying mainly on kicks to escape local optima.

- **Validity is still a hard performance boundary.** Every positive-scoring program in these results has validity 1.00 and schedule metric 3.00, so makespan differences explain score differences among successful implementations. Conversely, Generations 22 and 24 both scored 0.00 despite intended exact-cost beam and sophisticated local neighborhoods, because control-flow and schedule-construction defects prevented valid execution.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Diversify local-search seed selection from the final beam instead of refining only the top-cost entries.** Keep the best beam completion, then select additional seeds from the top `3 * local_seed_count` beam schedules by maximizing positional/Hamming or pairwise-order distance from already selected seeds, subject to a modest cost threshold. Generation 18 already benefits from multiple refined seeds, while Generation 23 confirms beam diversity is valuable; explicitly avoiding near-duplicate beam schedules should reach more distinct local-optimum basins.

2. **Apply deterministic perturb-and-descend to several elite locally optimized schedules, not only the initial best beam order.** After VND finishes for each seed, retain a small elite set of distinct local optima and generate controlled kicks from each: a medium interval reversal, a distant 2–4 transaction block relocation, and a distant swap, followed by the same strict insertion/swap/reversal/block VND. This extends the current validity-safe perturbation design and is more targeted than perturbing only `best_tuple`, because the strongest escape moves are likely to differ across already-refined basins.

3. **Add a bounded two-transaction ejection-chain neighborhood after ordinary VND stalls.** For a selected high-removal-impact transaction `a`, move it to a candidate anchor destination, then move a second transaction `b` from the affected interval or another high-impact position to a second anchor destination; evaluate only the final full permutation and accept strict improvements. Restrict this to a small deterministic set of source transactions and destinations, preserving the current exact-objective strategy while enabling coordinated changes that short block relocation may not express.

4. **Use a wider, depth-dependent diversified beam during early and middle prefix construction, then taper to the current width near completion.** For example, retain 64–80 candidates through roughly the first half of prefix depths, optionally preserving a few candidates with unusual endpoints or pairwise orders, then reduce toward the existing `max(8, min(48, num_seqs * 5))` width. Generation 23’s diversified retention nearly matched the best result, and broader early exploration can improve the starting structures supplied to the exceptionally effective VND stage without multiplying late-stage work as much.

5. **Make large-instance neighborhood sampling adaptive to recently successful moves as well as removal impact.** When an insertion, swap, reversal, or block relocation improves the schedule, record the transaction IDs and affected interval positions; in the next VND round, add those positions, nearby indices, and their current transaction locations to `source_positions` and `destination_positions`. This builds directly on the current impact-plus-anchor scaling mechanism, concentrating expensive exact simulator evaluations around conflict-sensitive regions while retaining evenly spaced anchors for long-range moves.
