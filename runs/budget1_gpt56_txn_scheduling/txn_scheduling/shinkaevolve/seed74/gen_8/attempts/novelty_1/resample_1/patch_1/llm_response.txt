<DESCRIPTION>
Add a reversal-neighborhood phase to the existing local search.

1. The current optimizer evaluates insertions and arbitrary exchanges. Those moves are effective for moving one or two transactions, but they can be trapped when a whole consecutive region has the wrong conflict direction.
2. A segment reversal changes the relative order of every pair inside a contiguous block in one move. This can simultaneously shorten multiple read/write and write/write dependency chains, which is particularly useful when beam search selected a promising set of transactions but arranged a conflicting subsequence poorly.
3. The reversal is evaluated with `workload.get_opt_seq_cost`, exactly like all existing moves. Therefore acceptance remains based on the true conflict-aware makespan rather than a proxy heuristic.
4. Length-two reversals are omitted because they are already covered by the existing swap neighborhood. Larger reversals add genuinely new candidate schedules.
5. The existing structured position subset is retained for large workloads, so this additional neighborhood follows the same scalability policy as insertion and swap search.

</DESCRIPTION>
