<DESCRIPTION>
Add an exchange neighborhood to the existing insertion-based local search.

1. The current local search only accepts improving insertion moves. Although insertion moves are expressive, a schedule can be a local optimum under every single insertion while exchanging two transactions simultaneously reduces conflict-induced waiting.
2. Transaction ordering has non-linear conflict effects: moving one transaction alone can expose another dependency, while swapping two conflicting transactions can resolve both delays at once.
3. Evaluate pairwise exchanges using the same exact conflict-aware `get_opt_seq_cost` objective. This preserves correctness and avoids proxy heuristics.
4. For large workloads, use the same structured position subset already used for insertion moves, keeping the added search bounded while still testing long-distance exchanges.

This expands the local-search basin explored from each beam solution and can escape insertion-only local minima, producing lower makespan schedules.
</DESCRIPTION>
