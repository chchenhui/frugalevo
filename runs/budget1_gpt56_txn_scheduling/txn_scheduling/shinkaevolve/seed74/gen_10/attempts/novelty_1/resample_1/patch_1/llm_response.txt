<DESCRIPTION>
Add pairwise-swap best-improvement evaluation to the existing insertion descent.

1. Insertion moves are effective for relocating a transaction around a conflict chain, but they can be trapped when two transactions must exchange positions together.
2. A swap directly tests the alternative serialization order of every selected transaction pair using `get_opt_seq_cost`, preserving the simulator’s actual makespan as the sole objective.
3. The swap search shares the existing evaluation budget, so it remains bounded. It evaluates pairs deterministically and only considers an improving schedule.
4. This complements insertion search: after identifying the best insertion candidate in a round, the optimizer can select an even better pairwise exchange before committing the next schedule. This is especially useful for read/write conflict patterns where a writer and a reader have incompatible effects on several downstream transactions.
</DESCRIPTION>
