<DESCRIPTION>
For workloads above 30 transactions, the existing local search evaluates only evenly spaced source and destination positions. This can miss the few transactions responsible for most conflict-induced delay when they fall between the stride positions.

This edit retains the structured positions for broad long-distance coverage, then supplements them with conflict-informed positions. For every transaction, it evaluates the actual makespan after temporarily removing that transaction. The resulting makespan reduction is an exact workload-specific estimate of that transaction's current contribution to the bottleneck, rather than a proxy such as operation count or write count.

Step by step:
1. Keep evenly spaced anchor positions so the search continues to consider global moves.
2. Evaluate one-transaction removals and rank transactions by their actual makespan impact.
3. Add the highest-impact transactions as move sources.
4. Add positions immediately before and after those transactions as candidate destinations, allowing moves to cross likely conflict bottlenecks.
5. Continue using the existing exact `get_opt_seq_cost` objective for every accepted local-search move.

This focuses the limited large-instance neighborhood budget on transactions most likely to reduce makespan while preserving the previous broad sampling behavior.
