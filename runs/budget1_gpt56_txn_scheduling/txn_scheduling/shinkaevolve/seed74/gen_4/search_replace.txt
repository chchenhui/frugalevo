<DESCRIPTION>
Add a direct transaction-swap neighborhood to the existing insertion local search.

1. Insertion moves are strong, but they cannot represent every useful ordering change in one step. In particular, swapping two transactions separated by other transactions changes only the relative order of that pair, whereas moving one transaction also shifts every transaction in between.
2. For read/write-conflict schedules, a pair of transactions can form a conflict barrier: exchanging only those two may remove a critical-path dependency without perturbing beneficial ordering among the intervening transactions.
3. The new search evaluates direct swaps using `get_opt_seq_cost`, exactly as the rest of the scheduler does. Therefore it optimizes the true conflict-aware makespan rather than a heuristic.
4. The swap candidates compete with insertion candidates in the same best-improvement round. If a swap reaches a new basin of the search space, later rounds of insertion search refine it further.
5. For large workloads, the code reuses the existing structured position sample, preserving the current bounded-search behavior.
</DESCRIPTION>
