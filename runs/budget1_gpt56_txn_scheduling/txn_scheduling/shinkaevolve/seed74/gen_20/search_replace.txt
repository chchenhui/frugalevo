adaptive_beam_width

<DESCRIPTION>
Use a two-stage beam search that preserves substantially more partial schedules during the early half of construction, where transaction ordering choices create the major conflict-dependency structure.

1. Prefix makespan is not a reliable final-ranking signal early in the schedule: a slightly worse prefix can enable substantially more overlap once its remaining conflicting transactions are placed.
2. The previous fixed 48-state beam prunes these alternatives too aggressively from the first depth onward.
3. Retaining up to 96 diverse conflict-aware prefixes in the first half allows the subsequent full-order evaluation and local insertion/swap improvement to start from stronger schedules.
4. The beam narrows back to the existing 48-state cap in the later half, where the prefix is already constrained and additional states have less opportunity to diverge. This controls the number of expensive complete candidates and local-search seeds.

All ranking remains based on `get_opt_seq_cost`, so the wider early search is guided directly by actual simulated makespan rather than operation-count heuristics.
</DESCRIPTION>
