<DESCRIPTION>
Refine several strong greedy seeds instead of only the single best initial order, and add non-adjacent transaction exchanges to the local-search neighborhood.

1. The makespan landscape for conflict-constrained transaction orders is non-convex: a schedule that is slightly worse before local search can reach a better basin after transactions are moved.
2. The current code discards all but one greedy result before refinement. Retaining the best three independent greedy constructions provides diversification with bounded additional work.
3. Insertion moves and adjacent swaps cannot always improve an ordering when two distant transactions must exchange positions together. An exhaustive pairwise exchange pass for small workloads directly tests these coordinated changes.
4. Exact objective evaluation remains cached, so candidates encountered in more than one neighborhood or elite refinement are not recomputed.

This improves the chance of removing long conflict chains that greedy prefix construction leaves behind, while preserving the existing exact makespan objective as the sole optimization criterion.
</DESCRIPTION>
