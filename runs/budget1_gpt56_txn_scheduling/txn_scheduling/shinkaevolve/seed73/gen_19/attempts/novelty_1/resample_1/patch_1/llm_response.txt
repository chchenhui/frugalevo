<DESCRIPTION>
Replace purely myopic greedy selection with an exact two-transaction rollout score. The existing greedy constructor selects the next transaction only by the makespan of the current prefix. A transaction that is inexpensive immediately can nevertheless force a costly conflict chain with all subsequent transactions.

For every possible next transaction, this edit evaluates a bounded set of possible follow-up transactions using the simulator’s exact objective. It ranks the next transaction by the best achievable depth-two prefix makespan, while retaining the one-step score as a tie-breaker. This directly accounts for whether selecting a transaction now creates avoidable read/write conflict delay at the next scheduling decision.

The follow-up set is exhaustive for small remaining sets and sampled for large workloads, preserving practical runtime while substantially reducing early greedy mistakes. Beam search and local search remain intact, so this adds higher-quality diversified seed schedules for later refinement.
