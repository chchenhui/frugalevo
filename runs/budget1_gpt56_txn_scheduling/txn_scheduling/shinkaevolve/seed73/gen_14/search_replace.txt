<DESCRIPTION>
Add a deterministic segment-reversal neighborhood to the existing variable-neighborhood descent.

Step-by-step rationale:
1. The current search evaluates single-transaction relocations and pairwise exchanges. These moves repair isolated ordering mistakes but can remain trapped when several transactions participating in the same read/write dependency chain need to change their relative order together.
2. A contiguous reversal changes the precedence relationship of every pair within a congested region in one evaluated move. This is especially useful when greedy construction placed a group of writers/readers in approximately the opposite dependency-friendly order.
3. Each reversal is scored by `sequence_cost`, which calls the real simulator cost rather than a transaction-size or conflict-count proxy. Therefore, the move is accepted only when it directly reduces makespan.
4. This is a complete deterministic O(n²) neighborhood, substantially cheaper than exhaustive multi-transaction insertion while complementing the existing random destroy-and-repair phase. It can also provide a better incumbent before destroy-and-repair begins.
</DESCRIPTION>
