# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **The current best, Generation 17 “Hybrid Beam-Greedy Transaction Scheduler,” establishes the strongest validated hybrid pattern.** It achieved **3937.01 combined score** and **253 makespan** with schedule metric **3.00** and validity **1.00**, improving on the prior reported best Generation 9’s **261 makespan / 3816.79 score** by **8 makespan points** and **120.22 score points**. Its effective combination is: exact permutation search for `<= 8` transactions, bounded prefix beam search, randomized greedy/GRASP seeds, VND with insertion/swap/reversal, and destroy-and-repair refinement.

- **Diversification combined with exact simulator scoring consistently produced the best schedules.** Generation 17 does not rely on a single greedy path: it builds a beam from high-quality and randomized starts, then adds independent greedy constructions with restricted candidate-list diversity. This extends the earlier successful Generation 12 hybrid beam/GRASP/VND approach (**256 makespan, 3891.05**) and Generation 16 beam/local/ruin-recreate approach (**257 makespan, 3875.97**). The narrow improvement range among these top systems indicates that diversified construction plus strong local search is the dominant high-quality design.

- **Large-neighborhood repair is especially valuable when paired with post-repair descent.** Generation 17’s destroy-and-repair removes either contiguous or dispersed transaction sets, reinserts each removed transaction at simulator-scored positions, and then applies two rounds of local refinement. This pattern is consistent with Generation 14’s multi-start greedy plus reversal/destroy-repair result (**254 makespan, 3921.57**) and improves substantially over Generation 11’s greedy/local-search/destroy-repair implementation (**273 makespan, 3649.64**). Repair alone is not the differentiator; repair combined with elite seeds, beam alternatives, and exact polishing is.

- **Exact optimization on small workloads remains a reliable correctness and quality foundation.** Generation 17, 16, 12, and the earlier Generation 9 all exhaustively evaluate every permutation for at most eight transactions. This removes random variation for instances where full search is practical, while the bounded heuristic pipeline handles larger instances. All these high-performing variants retained full validity, unlike some sophisticated but failing randomized implementations.

## Ineffective Approaches

- **Sophisticated heuristic search without reliable validation behavior can collapse to zero value.** Generation 13’s Adaptive Large-Neighborhood Transaction Scheduler used exact small-instance search, randomized greedy construction, relocation/swap search, elite populations, and adaptive repair, yet received **0.0** because it failed validation. Likewise, Generation 18’s greedy/local-search/destroy-repair scheduler received **0.0** despite exact-cost caching and multiple neighborhoods. The evaluation feedback specifically points to nondeterminism and/or unmet scheduling or interface requirements rather than a lack of heuristic sophistication.

- **Narrower beam/greedy hybrids were valid but clearly weaker than the current best’s full hybridization.** Generation 10’s beam-greedy local optimizer reached only **283 makespan / 3521.13**, and Generation 19’s two-step-lookahead beam-greedy version reached **286 / 3484.32**. Both used beam search and local moves, but neither matched Generation 17’s **253**. The results support the previous finding that beam search alone, even with lookahead, is weaker than beam plus independent GRASP-style seeds, richer VND, and coordinated repair.

- **Multi-start greedy local search is competitive but generally lacks the last improvement supplied by beam-preserved alternatives.** Generation 15 achieved **271 makespan / 3676.47**, and Generation 11 achieved **273 / 3649.64**, despite exact simulator-based greedy selection and destroy-repair. Generation 14 was an exception at **254**, nearly matching the best, but Generation 17 still won by one makespan point. Across the family, preserving competing prefix structures through beam search appears to reduce the risk that construction starts in an unrecoverable ordering basin.

## Implementation Insights

- **Generation 17 uses a single exact-cost cache across every search phase.** `schedule_cost(order)` keys costs by `tuple(order)` and shares the cache across exhaustive search, prefix beam expansion, greedy construction, VND moves, and repair insertion scoring. This is critical because the implementation repeatedly revisits overlapping prefixes and closely related complete permutations. The program retains objective fidelity by always using `workload.get_opt_seq_cost`, rather than substituting proxy conflict measures.

- **Its beam is deliberately diverse rather than a fixed deterministic top-prefix list.** The program scores every one-transaction start, keeps the strongest starts, replaces part of them with shuffled alternatives, samples only when remaining candidates are large, and shuffles equal-cost beam ties. Its greedy construction additionally uses a restricted candidate list within roughly **2.5%** of the best prefix cost. These details preserve alternative transaction-conflict orientations without accepting fully random low-quality extensions.

- **The VND implementation combines several complementary move geometries and uses strict best improvement.** Each refinement round checks adjacent swaps, insertion moves, arbitrary swaps, and reversals; it uses exhaustive move sets through 30 transactions and sampled sets above that size. A move is accepted only if it strictly reduces exact simulator cost, then the neighborhoods are reconsidered from the new incumbent. This extends the prior successful insertion/swap pattern and helps explain why Generation 17 exceeded Generation 12 (**256**) and Generation 16 (**257**).

- **Destroy-and-repair is carefully bounded and applied to refined elites rather than all candidates.** Generation 17 repairs only the top locally refined schedules, removes a bounded count of transactions, preserves the unaffected order, evaluates insertion positions with the actual simulator, and allows a first repaired state to become a temporary base even if worse. This creates a controlled mechanism for crossing multi-move barriers while limiting expensive full schedule simulations—an important contrast with failed or potentially overextended randomized large-neighborhood variants.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Add deterministic, metadata-free pairwise precedence seeds using exact two-transaction probes.** Before beam construction, evaluate both `[i, j]` and `[j, i]` for selected transaction pairs, derive a lightweight “preferred-before” score per transaction, and generate several full seed orders by sorting on net pairwise preference, singleton cost, and randomized tie breaks. Feed these structured orders into `seeds` alongside beam and GRASP schedules; this extends Generation 17’s successful heterogeneous seed population without relying only on randomized starts.

2. **Use selective depth-2 lookahead during early beam and greedy construction.** For the first roughly `min(10, num_txns // 2)` positions, score each candidate extension by its best or average sampled second extension, e.g. `min(schedule_cost(prefix + [a, b]))` over a bounded set of `b`. Apply this only to the top immediate-prefix candidates so it remains affordable; it directly addresses the current one-step prefix-cost myopia while retaining exact simulator-based decisions.

3. **Introduce an adaptive beam policy based on prefix-cost ambiguity and diversity.** Rather than always using `beam_width = min(max(6, num_seqs), 12)`, retain a larger beam when the scores around the cutoff are close or when retained prefixes share the same first few transactions, and shrink it when there is a decisive cost gap. Preserve at least a few prefixes from distinct starting transactions or distinct early two-transaction orientations, since the best program’s advantage over narrower beam variants comes from maintaining competing structural alternatives.

4. **Make large-instance VND sampling impact-guided rather than mostly uniform random.** After adjacent-swap probing, assign each position an impact score from the improvement available through local swaps, removal-and-reinsert probes, or short segment reversals; bias sampled insertion, swap, and reversal moves toward high-impact positions while reserving some uniform samples for exploration. This keeps Generation 17’s exact-cost VND and bounded runtime, but should improve the quality of the sampled neighborhoods when `num_txns > 30`.

5. **Strengthen destroy-and-repair with multiple removal profiles and elite crossover-style repair.** For each elite local optimum, alternate between contiguous removal, dispersed high-impact removal, and two short separated segments; then reinsert removed transactions in an order based on their estimated insertion difficulty rather than always shuffled order. Additionally, use one elite schedule’s retained subsequence as the repair backbone and insert transactions ordered according to a second elite schedule, exploiting the current beam/refinement population to cross basins more deliberately than purely random ruin-and-recreate.
