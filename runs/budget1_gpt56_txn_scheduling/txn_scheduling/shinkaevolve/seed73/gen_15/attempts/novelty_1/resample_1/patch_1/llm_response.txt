<DESCRIPTION>
Add a simulator-guided destroy-and-repair phase after the existing local search.

1. The current refinement stops at a local optimum under swaps and insertions. Transaction-ordering objectives commonly contain larger basins where several transactions must move together before an improvement becomes visible.
2. Each destroy attempt removes a small group of transactions from the incumbent schedule. The group is selected partly from a contiguous region, which targets correlated conflict decisions, and partly from dispersed positions, which targets independent long-range interactions.
3. The removed transactions are greedily reinserted into every possible position using the exact simulator objective already cached by `schedule_cost`. This ensures repair decisions optimize actual makespan rather than proxy features such as transaction length or write count.
4. Any improved repaired schedule is locally refined again. Thus, destroy-and-repair creates an escape move while the existing swap/insertion VND exploits the new promising region thoroughly.
5. The phase is bounded by both transaction count and `num_seqs`, preserving predictable runtime while providing several structurally different escapes from the initial local minimum.
</DESCRIPTION>
