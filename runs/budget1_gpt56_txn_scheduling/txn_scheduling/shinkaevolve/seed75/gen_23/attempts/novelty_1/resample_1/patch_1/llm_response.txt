<DESCRIPTION>
Add a restricted two-transaction relocation neighborhood after one-transaction relocation and swap moves stagnate.

1. The existing relocation move can only reposition one transaction. Some conflict chains require two non-adjacent transactions to move together before the critical conflicting transactions, so neither transaction has an improving individual relocation.
2. The new move first identifies a small set of high-impact transaction positions. Impact is measured with the authoritative simulator by removing each transaction and observing the resulting prefix/order makespan; transactions whose removal reduces cost most are likely contributors to the current critical path.
3. It considers every pair among these promising positions, removes both while retaining their current relative order, and reinserts the pair as a block at every possible destination.
4. This broadens the search beyond adjacent swaps and individual relocation without the prohibitive cost of testing every transaction pair. Every candidate is scored by `get_opt_seq_cost`, preserving exact makespan optimization and schedule validity.
5. The pair move is only invoked after the ordinary local neighborhoods fail, so it acts as an efficient basin-escape mechanism rather than adding unnecessary work to every descent pass.
</DESCRIPTION>

    def best_pair_relocation(schedule, current_cost):
        """
        Move two potentially cooperating transactions together.  Candidate
        sources are restricted to transactions with the greatest measured
        critical-path impact, keeping this richer neighborhood affordable.
        """
        if n < 2:
            return current_cost, schedule

        # A transaction whose removal most reduces the simulated makespan is a
        # useful candidate for a coordinated move.  Include all transactions
        # on small workloads and a focused subset on larger ones.
        impacts = []
        for source in range(n):
            reduced = schedule[:source] + schedule[source + 1:]
            impacts.append((cost(reduced), source))
        source_limit = min(n, 8)
        promising = sorted(impacts, key=lambda item: (item[0], item[1]))[
            :source_limit
        ]
        positions = sorted(source for _, source in promising)

        best_value = current_cost
        best_order = schedule
        for first_index in range(len(positions) - 1):
            first = positions[first_index]
            for second in positions[first_index + 1:]:
                # positions are sorted, so the pair retains its established
                # relative order when it is moved as a block.
                pair = [schedule[first], schedule[second]]
                reduced = [
                    txn for index, txn in enumerate(schedule)
                    if index != first and index != second
                ]
                for destination in range(len(reduced) + 1):
                    candidate = (
                        reduced[:destination] + pair + reduced[destination:]
                    )
                    if candidate == schedule:
                        continue
                    candidate_cost = cost(candidate)
                    if candidate_cost < best_value:
                        best_value = candidate_cost
                        best_order = candidate

        return best_value, best_order
