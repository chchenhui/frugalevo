# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Diversified greedy construction plus variable-neighborhood descent produced the best accepted result.** The current best, **Diversified Greedy Permutation Descent** (Generation 2), achieved **3623.19** combined score and **275.00 makespan**. It creates several greedy schedules from distinct starting transactions, evaluates every append choice with the authoritative `workload.get_opt_seq_cost`, then improves the best result using complete relocation moves and swap moves. This combination outperformed all other validated programs.

- **Direct simulator-cost evaluation is consistently associated with strong valid schedules.** Generation 2 uses exact `get_opt_seq_cost` both during construction and local search. Other correct programs using the same core signal also performed well: **Diversified Greedy Local Schedule Search** (Generation 6) reached **3496.50 / 285.00**, **Conflict-Aware Beam Search Scheduler** (Generation 4) reached **3472.22 / 287.00**, and **Simulator-Guided Beam and Relocation Scheduling** (Generation 7) reached **3424.66 / 291.00**.

- **Multi-start diversification materially improves over a single sampled greedy path.** The baseline **Randomized Sampled Greedy Scheduler** (Generation 0) scored **2754.82** with **362.00 makespan**. Its sample-of-10 append strategy limits evaluations but can miss important candidates. In contrast, Generation 2 evaluates all remaining transactions at each greedy step and diversifies through multiple initial transactions, reducing makespan by **87** versus Generation 0.

- **Relocation refinement is a reliable effective local-search operator; swaps add useful escape behavior.** The best program searches the full one-transaction relocation neighborhood and only invokes complete pairwise swaps when relocation no longer improves. This is stronger than construction-only scheduling and plausibly explains why Generation 2’s **275.00** makespan beats the relocation-focused valid beam methods, which remained at **287.00** (Generation 4) and **291.00** (Generation 7).

## Ineffective Approaches

- **Several sophisticated beam/local-search variants failed validation entirely despite using simulator costs.** Generations 1, 3, 5, 8, and 9 all received **0.0** because they were incorrect. This shows that heuristic sophistication alone was not sufficient: beam search, caching, relocation, swaps, and even exhaustive small-instance handling did not earn performance credit when validation behavior failed.

- **Prefix-ranked beam search was especially inconsistent.** Generation 1 (**Conflict-Aware Beam and Insertion Scheduler**) and Generation 3 (**Beam Search with Relocation Optimization**) ranked partial permutations using `get_opt_seq_cost` and then refined full schedules, yet both were invalid. Evaluation feedback specifically flags that full scheduling cost applied to prefixes may not provide valid/effective prefix guidance or may conflict with required scheduler behavior. By comparison, beam methods that did validate—Generation 4 and Generation 7—were respectable but still weaker than the diversified greedy descent approach.

- **Randomized sampled construction without exhaustive per-step candidate evaluation was much weaker.** Generation 0 was correct but had the worst accepted makespan, **362.00**. Sampling at most ten candidates per placement reduces evaluation cost, but it gives up many potentially beneficial append choices. The current best instead evaluates every remaining transaction for each append decision.

- **More aggressive search did not compensate for correctness incompatibilities.** Generation 9 combined exact search for small workloads, beam search, relocation, swaps, reversal moves, caching, and randomized tie-breaking, but still scored **0.0** due to validation failure. Likewise, Generation 5’s multi-start greedy relocation/swap descent and Generation 8’s repeated greedy-plus-insertion search were invalid despite superficially resembling the successful Generation 2 structure.

## Implementation Insights

- **The current best uses caching at every stage where sequence overlap is common.** `cost_cache` is keyed by `tuple(sequence)`, and the same `cost()` wrapper is used during greedy construction, relocation evaluation, swap evaluation, and the final return. This is particularly important because local-search neighborhoods repeatedly recreate candidate permutations and because multiple diversified starts can share prefixes.

- **Its construction strategy combines deterministic coverage with randomized diversification.** For `n <= seed_count`, Generation 2 tries every possible starting transaction. Otherwise, it always includes start transaction `0` and samples the remaining starts after shuffling. Within each construction, it shuffles candidates before choosing the strictly lowest-cost append. This preserves a reproducible anchor while allowing different tie resolutions and start points to expose alternative greedy basins.

- **The local-search control flow is narrowly targeted rather than indiscriminately expensive.** The implementation performs `max(2, min(6, n))` relocation passes. It accepts only strict makespan improvements, then tests swaps only after relocation stagnates. This makes relocation the primary optimization mechanism and treats swaps as an escape move, matching the feedback that relocation and swap refinement likely contributed to the strong valid result.

- **Correctness-preserving schedule handling is explicit.** Construction starts with one valid transaction, removes each selected transaction from `remaining`, and appends exactly one transaction per loop. Relocation removes one element and reinserts it into every applicable destination; swaps preserve membership. The result is finally re-evaluated through the same simulator model. These details are consistent with its **validity 1.00**, unlike the five zero-score implementations whose failures were not explained by simple objective quality.

Therefore, their combined-score differences are driven by makespan quality rather than output-format or validity advantages. # META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Apply the existing relocation/swap descent to more than just the single best greedy construction.** Retain the top 2–4 distinct schedules from `constructed` (with deduplication by tuple) and run the exact same cached local search on each, returning the best final result. Multi-start construction is already a major success factor, but the current code discards all but one basin before refinement; a slightly worse greedy schedule may have a substantially better relocation-local optimum.

2. **Strengthen local search with a bounded variable-neighborhood move after relocation and swap stagnate.** Add an exact-cost “two relocation” or block-move neighborhood: remove a contiguous block of length 2 (optionally 3 for small `n`) and reinsert it at every legal destination, accepting only strict makespan improvements. This preserves the current program’s validation-safe permutation operations while addressing cases where beneficial interacting transactions must move together and neither a single relocation nor a pairwise swap can reach the improvement.

3. **Use iterative improvement until true stagnation, with a workload-size-aware evaluation budget rather than the fixed 2–6 pass limit.** Continue alternating full relocation descent and swaps while strict improvements occur, but cap the total number of `get_opt_seq_cost` cache misses or accepted moves to control runtime. The best program’s relocation-first, swap-on-stagnation structure is empirically strong; allowing additional productive passes can correct more independent greedy mistakes without blindly expanding search when no new schedules are being found.

4. **Diversify construction tie-breaking more deliberately while keeping exhaustive append evaluation.** For every greedy step, continue evaluating every remaining transaction with `get_opt_seq_cost`, but select uniformly among all candidates tied for the minimum cost or within a very small cost threshold, rather than relying only on shuffled iteration and strict `<`. This keeps the key strength of Generation 2—authoritative exhaustive append scoring—while generating genuinely distinct greedy basins when simulator costs are flat or heavily tied.

5. **Add a validation-safe destroy-and-repair restart around the best schedule.** Starting from the current best permutation, remove a small set of positions (for example 2–4 transactions), keep the residual order fixed, and greedily reinsert removed transactions one at a time by evaluating every insertion position with `get_opt_seq_cost`; then run the established relocation/swap descent. This extends the proven exact-cost local-search approach with a controlled escape mechanism, rather than relying on prefix-ranked beam search patterns that have been inconsistent or invalid.
