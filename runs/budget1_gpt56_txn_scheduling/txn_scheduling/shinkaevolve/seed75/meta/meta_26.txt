# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **The current best remains Generation 18’s diversified greedy construction plus exhaustive strict local descent.** It achieved **3787.88 combined score** and **263.00 makespan**, outperforming every newly evaluated valid program. Its key pattern is simple but effective: construct several greedy schedules from different starting transactions using exact `workload.get_opt_seq_cost` evaluations, then repeatedly take the best strict improvement from complete relocation, swap, and adjacent-pair relocation neighborhoods.

- **Exact simulator scoring consistently correlates with correctness and strong makespans.** All valid programs in this group score candidate schedules with the authoritative simulator and preserve full transaction permutations. Generation 24, *Beam Search Transaction Schedule Optimizer*, reached **3676.47 / 271.00**, and Generation 21, *Simulator-Scored Beam and Local Search*, reached **3636.36 / 274.00**. Their valid results reinforce that scheduling decisions should be based on actual simulator makespan rather than a proxy conflict metric or assumptions about partial-prefix behavior.

- **Coupled transaction moves improve over single-move-only search, but the current best’s focused pair relocation is especially effective.** Generation 24’s relocation, swap, reversal, block relocation, and destroy-repair refinement produced **271.00**, while Generation 25’s block relocation and pair destroy-repair reached **281.00**. The current best’s adjacent-pair block relocation, combined with complete relocation and swap search, reached **263.00** without requiring broader or more expensive perturbation machinery.

- **Diversified starts are more productive than beam-heavy construction in the measured outcomes.** The current best explores starts determined by `num_seqs`, trying all starts when possible and otherwise retaining transaction `0` plus randomized additional starts. This produced a better basin for descent than the valid beam-centered methods: Generation 24 (**271.00**), Generation 21 (**274.00**), and Generation 25 (**281.00**). Generation 23’s diversified greedy local search also validates this direction with **3508.77 / 284.00**, though its bounded improvement process was materially weaker than Generation 18’s exhaustive descent.

## Ineffective Approaches

- **Incorrect scheduling logic causes a complete evaluation collapse, regardless of heuristic sophistication.** Generation 20, *Beam Search with Local Schedule Optimization*, and Generation 22, *Beam Search with Variable-Neighborhood Descent*, both scored **0.0** and failed validation. Generation 20’s feedback specifically identifies heuristic logic or partial-sequence cost assumptions as invalid. Generation 22 used randomized beam pruning and heuristic search above eight transactions, which could not meet the correctness requirement expected by validation.

- **More complicated beam, perturbation, and destroy-repair mechanisms did not surpass the current best’s deterministic exhaustive descent.** Generation 24’s broad move set and destroy-and-repair was the strongest new beam-based result, but its **271.00 makespan** was still **8 units worse** than Generation 18. Generation 21’s multistart greedy, beam search, VND, and perturb-and-descend diversification reached **274.00**, **11 units worse**. The results do not show that these extra mechanisms compensate for weaker initial basins or less exhaustive final neighborhood coverage.

- **Bounded and sampled search sacrifices solution quality.** Generation 23 limits local-improvement passes and focuses pair moves only on transactions estimated to be influential; it remains correct but finishes at **284.00**, **21 units worse** than the current best. Generation 25 samples neighborhoods and beam expansions for large workloads and reports **281.00**, again behind the exhaustive current-best descent. This extends the previous evidence that limiting exact neighborhood coverage tends to increase final makespan.

- **Randomized beam selection is risky both for quality and correctness when not structurally disciplined.** Generation 22 combined randomized tie-broken beam search with extensive VND and iterated perturbation, yet failed validation entirely. By contrast, valid randomized elements in Generation 18 are narrow and safe: randomness only changes candidate/start ordering, while construction and every local move remain permutation-preserving and are evaluated against the exact cost function.

## Implementation Insights

- **Generation 18’s cache supports exhaustive search over expensive neighborhoods.** Its `cost(sequence)` wrapper memoizes `workload.get_opt_seq_cost` by `tuple(sequence)` and is used for greedy append evaluation, relocation, swaps, pair-block relocation, and the final returned result. This is crucial because the complete neighborhoods create many overlapping candidate schedules. The result—**263.00**—shows that exact objective evaluation can remain practical when repeated candidates are cached.

- **The current best maintains validity structurally at every stage.** Greedy construction starts from one transaction, removes it from `remaining`, and appends each remaining transaction exactly once. Local moves only transform an existing permutation: relocation removes/reinserts one item, swap exchanges positions, and block relocation removes/reinserts an existing adjacent pair. This directly explains its **validity 1.00**, unlike Generations 20 and 22, where the evaluator found correctness failures.

- **Strict best-improvement control flow makes the local search both stable and thorough.** Generation 18 accepts only candidates with `candidate_cost < best_value`, avoiding equal-cost cycling. It exhausts relocation first; if no relocation improves, it computes the best swap and best block relocation, chooses the better strict improvement, and restarts from relocation. This matters because a swap or pair move can expose a newly improving relocation. Generation 23 also uses exact simulated local moves, but bounded passes prevent the same exhaustive convergence behavior and it reaches only **284.00**.

- **The newer valid beam programs use many of the same reliable foundations but with less favorable search allocation.** Generation 24 correctly combines cached exact sequence costs, permutation-safe moves, beam seeds, and coupled neighborhoods, yielding a strong **271.00**. Generation 21 similarly uses cached simulator scoring and multiple exact move operators for **274.00**. Their validity confirms the implementation foundation, while their lower results relative to Generation 18 indicate that beam-prefix breadth and sampled refinements were less effective than investing effort in multi-start greedy basins plus full descent.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Refine several top distinct greedy seeds instead of only `constructed[0]`.** Deduplicate greedy schedules by `tuple(schedule)`, retain the best 2–4 constructed schedules by exact cost, and run the existing exhaustive relocation/swap/adjacent-pair descent independently from each. The current method’s diversified starts are a major strength, but selecting only the lowest-cost *unrefined* seed can discard a slightly worse greedy schedule that lies in a substantially better local-search basin.

2. **Add exhaustive contiguous length-3 block relocation after pair-block stagnation.** For each source interval `schedule[source:source+3]`, remove it and reinsert it at every legal destination in the reduced schedule, evaluate each full permutation through the existing cached `cost`, and accept only strict best improvements. This is a safe extension of the best program’s highly successful pair relocation: it preserves transaction order within a cooperating group while enabling a three-way dependency pattern to cross another region of the schedule.

3. **Use deterministic exact-cost destroy-and-repair restarts from locally optimal schedules.** After VND reaches stagnation, remove a small contiguous block—initially lengths 2, 3, and 4—from the incumbent, then greedily reinsert the removed transactions one at a time by testing every legal insertion position with `cost`; apply the full exhaustive descent to each repaired result. This retains the authoritative simulator and permutation invariants while providing a controlled way to escape strict local optima, borrowing the promising restart idea from destroy-repair methods without replacing the proven descent core.

4. **Generate stronger seed diversity through bounded greedy tie/near-tie branching.** During greedy construction, retain a small branch set whenever multiple append candidates tie for minimum exact cost, or lie within a narrowly defined threshold such as one makespan unit; continue greedy completion for each branch and deduplicate finished schedules. The current randomized tie order gives some diversity, but explicit branching is more likely to preserve multiple genuinely different exact-cost prefixes and can expose better descent basins without relying on broad beam search.

5. **Add a restricted non-adjacent two-transaction relocation neighborhood as a late escape operator.** Once relocation, swap, and contiguous block moves all stagnate, choose pairs of positions from a bounded candidate set—for example, the transactions whose single removal/reinsertion candidates most nearly improve—and remove both transactions, preserving their relative order while testing all reinsertion positions. This directly extends the demonstrated benefit of coupled moves beyond adjacency, while keeping the neighborhood much cheaper and more disciplined than unrestricted multi-transaction search.
