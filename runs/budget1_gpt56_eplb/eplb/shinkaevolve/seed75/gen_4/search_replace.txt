<DESCRIPTION>
Replace the nested Python loop over layers and groups in `balanced_packing` with a batched greedy packing loop. The original algorithm independently performs the same greedy choice for every layer, but executes tensor indexing, Python `min`, generator construction, and scalar updates once per `(layer, group)` pair.

The replacement keeps the same descending-weight greedy policy and exact per-pack capacity constraint, while processing all layers simultaneously at each sorted-group position. This substantially reduces Python overhead, avoids CPU scalar/tensor synchronization, and allows PyTorch to efficiently execute the per-layer pack selection and updates. Better algorithm execution time directly improves the speed component without changing the placement policy or its load-balancing semantics.
</DESCRIPTION>

    indices = weight.float().sort(-1, descending=True).indices
    pack_index = torch.empty_like(weight, dtype=torch.int64)
    rank_in_pack = torch.empty_like(pack_index)
    pack_weights = torch.zeros((num_layers, num_packs),
                               dtype=torch.float32,
                               device=weight.device)
    pack_items = torch.zeros((num_layers, num_packs),
                             dtype=torch.int64,
                             device=weight.device)
    unavailable = torch.finfo(pack_weights.dtype).max

    for position in range(num_groups):
        group = indices[:, position]
        # `min` returns the first pack on ties, matching the original Python
        # min(..., key=...) behavior.
        pack = pack_weights.masked_fill(
            pack_items >= groups_per_pack, unavailable).min(dim=-1).indices
        current_rank = pack_items.gather(-1, pack.unsqueeze(-1)).squeeze(-1)
