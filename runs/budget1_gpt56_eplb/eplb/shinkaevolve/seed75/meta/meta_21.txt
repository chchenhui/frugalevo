# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **The current best, Generation 19 `fast_refined_lpt`, preserves the strongest validated quality profile:** **combined 0.13**, **GPU balancedness 0.66**, and **expert balancedness 0.25**. Its hierarchy is important: it assigns logical expert groups to nodes first, performs replica allocation independently within each node, then packs physical replicas across GPUs within that node. This is the same successful structural family as Generations 9, 11, 12, 14, 15, 17, 18, and 20, none of which exceeded the 0.66/0.25 balance result.

- **Exact-cardinality LPT packing is a reliable quality and correctness primitive.** In `balanced_packing`, groups are processed in descending weight order and assigned to the currently lightest non-full pack through `heapq`. A pack is removed from `available` once it reaches `groups_per_pack`, guaranteeing exact occupancy without any repair stage. The current program’s LPT approach reaches **0.66 GPU balancedness**, matching related heap-based implementations in Generations 16 and 18.

- **Greedy replica allocation remains the best validated expert-allocation approach.** `replicate_experts` repeatedly selects the largest current marginal replica load using `(weight / logcnt).max(dim=-1)`. This policy achieves the current best’s **0.25 expert balancedness**, matching the stable successful generations. It is notably better than Generation 13’s dense discrete marginal/top-k water-filling variant, which fell to **0.13 expert balancedness** and **0.07 combined score**.

- **Bounded refinement is compatible with the best observed result.** Generation 19 performs at most two pairwise swap passes only when `num_groups <= 64`, accepting a swap only when it reduces the selected pair’s absolute load gap. This retains the best validated **0.13 combined score** while avoiding the unrestricted or tensor-heavy refinement behavior seen in other variants. Its **0.27 inference metric** is also better than the reported values for Generations 9 (0.33), 11 (0.37), 12 (0.29), 13 (0.35), 14 (0.30), 15 (0.31), 16 (0.42), and 18 (0.41).

## Ineffective Approaches

- **More elaborate swap optimization did not improve balancedness beyond Generation 19’s result.** Generation 11’s four vectorized high/low-pack swap refinements, Generation 12’s tensorized rounds, and Generation 14’s bounded pairwise searches all remained at **0.66 GPU**, **0.25 expert**, and **0.13 combined**. Their additional refinement complexity did not break the GPU or expert balance plateau and generally retained very low speed scores.

- **Generation 13’s dense marginal water-filling/top-k allocation was materially worse.** It reduced GPU balancedness from the successful family’s **0.66** to **0.65**, reduced expert balancedness from **0.25** to **0.13**, and produced only **0.07 combined**. The dense top-k/sorting strategy therefore failed to improve discrete replica allocation quality despite being more globally structured than the current program’s greedy marginal selection.

- **Removing refinement alone did not solve the runtime problem.** Generation 18 removed costly packing refinement but still reported **0.11 algorithm time**, **0.41 inference**, and **0.00 speed score**, with the same **0.13 combined** score. This supports the conclusion that host-side sorting, Python scheduling, and repeated CPU planning are more consequential than the current best’s tightly capped local swaps.

- **Device-side mapping work alone was insufficient to improve speed.** Generation 15 used tensor/device-side mapping construction but still had **0.02 algorithm time**, **0.31 inference**, **0.01 speed**, and **0.13 combined**. Since planning still involved Python-side LPT and replica loops, moving only the final mapping operations did not materially alter the dominant overhead.

## Implementation Insights

- **Generation 19’s exact-cardinality heap behavior is a key correctness-preserving detail.** `available` contains only packs that have capacity remaining. Each selected pack is reinserted only if `len(members[pack]) < groups_per_pack`. Consequently, `rank_in_pack` is guaranteed to be a valid local physical-expert rank, allowing the direct conversion  
  `phy2pphy = pack_index * phy_experts_per_gpu + rank_in_pack`.  
  This avoids a separate occupancy repair phase while supporting the program’s validation-passing result.

- **The current best uses a useful degenerate-layout fast path.** When `groups_per_pack == 1`, `balanced_packing` directly returns an expanded `arange` for pack indices and all-zero ranks. It skips CPU conversion, sorting, heap operations, member-list construction, and swap testing. This matches the successful fast-path pattern noted in Generation 20, while retaining the current program’s **0.13 combined** result.

- **Its mapping construction is compact and structurally robust.** The `inverse` helper builds inverse permutations through `scatter_`; `mlog2log` and `log2mlog` translate between original and node-local logical expert order; and the padded logical-to-physical table is built using one flattened scatter index, `phy2log * maxlogcnt + phyrank`. This is consistent with the validated mapping strategy used across the successful hierarchy-aware implementations, including Generations 11, 15, 17, and 20.

- **The dominant implementation cost remains explicit CPU/Python planning.** Generation 19 immediately performs `weight = weight.float().cpu()`. Nontrivial packing then uses `.sort(...).indices.tolist()`, `cpu_weight[layer].tolist()`, Python lists, `heapq`, per-layer loops, per-redundant-replica iterations, and optional nested swap loops. These choices align with its very low **times_algorithm 0.01** and **speed_score 0.01**, despite its comparatively favorable **0.27 inference** metric.

## Performance Analysis

- **Generation 19 is tied for the best combined score but is comparatively favorable on reported inference performance.** It achieves **0.13 combined**, **0.66 GPU balancedness**, **0.25 expert balancedness**, **0.01 algorithm**, **0.27 inference**, and **0.01 speed**. The other correct hierarchical variants consistently reached the same **0.13 combined** ceiling, but reported inference values were generally worse: 0.29 to 0.42 where supplied.

- **GPU balancedness is saturated among correct hierarchy-aware designs.** Heap LPT variants, vectorized swap variants, tensorized swap variants, device-oriented mapping variants, and the current bounded-refinement implementation all converge at **0.66 GPU balancedness**. The evaluation evidence does not show a GPU-balance benefit from substantially more expensive refinement or mapping changes.

- **Expert balancedness is the main persistent quality limitation.** The current program and the broader greedy marginal replication family stabilize at **0.25 expert balancedness**. No cited correct implementation improved on that value, while Generation 13’s alternative allocation logic dropped to **0.13**. Thus, the quality ceiling in the successful programs is more strongly associated with replica allocation than with the final GPU-pack local-search policy.

- **Timing-related implementation changes have not shifted the aggregate score ceiling.** Generation 19’s **0.01 speed score** remains low despite having the best reported inference metric among the directly comparable later programs. Generations 11, 15, 16, and 18 demonstrate that different degrees of vectorization, device mapping, heap packing, or refinement removal still leave the combined score at **0.13** when the same 0.66/0.25 balancing profile is retained.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Keep the three-stage hierarchy unchanged, but add a device-preserving execution path for `balanced_packing`.** Remove the unconditional `weight.float().cpu()` in `rebalance_experts` and have `balanced_packing` return tensors on `weight.device`; retain the CPU heap-LPT fallback only for layouts where a device implementation is not beneficial. The node-first grouping, node-local greedy replication, and GPU-local packing are the repeatedly validated source of the 0.66 GPU / 0.25 expert profile, so optimize data movement without altering that ordering.

2. **Add an exact-cardinality tensor fast path for two groups per pack.** When `groups_per_pack == 2`, sort each layer descending, pair selected high-weight groups with low-weight groups using a deterministic permutation, and construct `pack_index`/`rank_in_pack` via vectorized `scatter_`; benchmark a few pairing rules such as descending-with-ascending and adjacent sorted pairs. Preserve the current heap-LPT implementation as the general fallback, but this specialization can avoid `.tolist()`, Python heaps, member lists, and nested swap loops in a common small-layout case.

3. **Make refinement adaptive and strictly cheaper than the current two full passes.** Compute the initial LPT pack-load range and run one swap pass only when the normalized gap exceeds a conservative threshold; within that pass, inspect only the heaviest/lightest few packs rather than every pack pair. Generation 19 shows bounded refinement is safe and compatible with the best inference metric, while prior broad refinement variants did not improve the 0.66 GPU plateau, making conditional refinement a low-risk latency mutation.

4. **Explore deterministic near-tie handling in greedy replica allocation without replacing the marginal rule.** Continue selecting `argmax(weight / logcnt)`, but when candidates are within a small tolerance of the best marginal load, choose the candidate with lower node-local aggregate replica load, then lower logical-expert ID for determinism. This preserves the successful greedy marginal allocation that reaches 0.25 expert balancedness, while targeting its persistent limitation through tie decisions rather than adopting the unsuccessful dense top-k water-filling approach.

5. **Reduce mapping temporary tensors by directly materializing final physical positions from packed local IDs.** Retain the validated flattened scatter formula for `log2phy`, but avoid storing inverse permutations longer than necessary: use `scatter_` into reusable buffers for `mlog2log`/`pphy2phy`, immediately consume them in gathers, and release or overwrite intermediates. This is an algorithmic memory-traffic reduction that preserves exact rank and occupancy semantics, potentially improving planning and inference-side mapping overhead without changing placement quality.
