# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Global rather than node-local replica allocation and placement is the clearest quality improvement.** The current best program obtains **0.15 combined**, **0.76 GPU balancedness**, and **0.29 expert balancedness** by calling `rebalance_experts_hierarchical(weight, num_replicas, 1, 1, num_gpus)`: it deliberately collapses the hierarchy to one global group and one node. This removes node-local replica-capacity constraints while retaining the validated replica/map machinery. It improves on the repeated hierarchical result of roughly **0.13 combined / 0.66 GPU / 0.25 expert** in Generations 11–14, 17, and 19.

- **Global LPT placement consistently outperforms hierarchical GPU packing in balance metrics.** The current best uses cardinality-constrained LPT across all GPUs after globally allocating replicas. Generation 15’s global-waterfill design reached the same leading **0.76 GPU** and **0.29 expert** scores. Generation 18 likewise globally bypassed hierarchy and achieved **0.76 GPU / 0.29 expert**, although with a lower **0.14 combined** due to slower measured algorithm and inference timing. These results reinforce the prior finding that global scheduling is more valuable than preserving group/node locality under this benchmark.

- **Greedy discrete water-filling is effective when allowed to operate globally.** In the current program, `replicate_experts` repeatedly selects `argmax(weight / logcnt)`, assigning each extra copy to the expert with the largest current per-replica load. Although this loop is not especially fast, it produces the best observed expert balancedness, **0.29**, versus the **0.24–0.25** common to hierarchical water-filling variants. The quality gain comes from replica allocation being unconstrained by per-node partitions.

- **Scatter-based map construction remains a reliable correctness-preserving implementation pattern.** The current best forms inverse permutations through `scatter_`, then builds `log2phy` with flattened indices `phy2log * maxlogcnt + phyrank`. This preserves the required padded logical-to-physical representation while avoiding Python-side mapping construction. It contrasts with Generation 10’s invalid mapping/index computation, which failed validation entirely with `index 9 is out of bounds for dimension 1 with size 8`.

## Ineffective Approaches

- **Hierarchical group-to-node assignment repeatedly caps balance quality.** Generations 11–14, 16, 17, and 19 all retain node-aware group placement and local replica/GPU packing. Despite variations including LPT, water-filling, direct slot layouts, and swaps, they consistently cluster near **0.66 GPU balancedness**, **0.25 expert balancedness**, and **0.13 combined**. The current best’s global fallback improves these to **0.76**, **0.29**, and **0.15**, respectively, indicating that the hierarchy’s intermediate placement commitment is harmful on the evaluated workloads.

- **Swap/exchange refinement added cost without producing superior measured balance.** Generation 11 used up to two all-pairs improving swaps; Generation 12 used targeted exchanges; Generation 13 and 19 used bounded/vectorized swap refinement. All remained at approximately **0.13 combined** and **0.66/0.25** balance. Feedback repeatedly identifies pairwise searches, candidate expansions, and repeated refinement tensor operations as runtime costs. Generation 18’s two-round targeted exchange global design reached only **0.14 combined**, below the current best’s **0.15**, despite matching its balance metrics.

- **CPU planning plus iterative packing remains a speed bottleneck.** The current best converts weights with `weight.float().cpu()`, uses sorting in `balanced_packing`, and runs one LPT step for every physical replica. It still has only **0.01 speed score** and **0.02 algorithm-time score**, though its inference score is relatively good at **0.30**. The hierarchical CPU planners were no faster in score terms—mostly **0.01** algorithm/speed—but had worse balance, so CPU planning is a shared limitation rather than the explanation for global placement’s quality advantage.

- **Mapping arithmetic that is not dimensionally consistent is catastrophic.** Generation 10’s proportional snake-stripe layout scored **0.00** across all measurements because validation failed before performance evaluation. Its reported out-of-bounds indexing error shows that sophisticated replica-rank/slot schemes are not useful unless forward and reverse map dimensions remain exactly aligned.

## Implementation Insights

- **The current best reuses validated hierarchical internals while disabling the quality-limiting hierarchy at the entry point.** `rebalance_experts_hierarchical` still provides the tested sequence of replication, replica-load calculation, LPT packing, inverse permutation, and rank construction. However, passing `(num_groups=1, num_nodes=1)` means group packing becomes trivial and all physical copies compete for all GPU slots. This is a concise implementation change with the strongest measured outcome: **0.15 combined**, higher than all listed hierarchical variants.

- **Cardinality-constrained LPT is central to valid fixed-capacity layouts.** In `balanced_packing`, every pack is capped at `groups_per_pack`; each sorted item is assigned to the least-loaded eligible pack. This maintains exactly equal replica counts per GPU while balancing aggregate load. The same core scheduling primitive supports both the current best’s leading GPU score of **0.76** and the validated, though weaker, hierarchical implementations’ **0.66** GPU score.

- **The current water-filling implementation prioritizes balance quality over allocation throughput.** `replicate_experts` initializes one copy per logical expert and iterates over each redundant physical slot, using `weight / logcnt` to choose the next duplication. It directly implements discrete equalization of replica loads and gives the best observed **0.29 expert balancedness**. In contrast, prior insights identified batched `topk` marginal-copy selection as a way to represent the same allocation principle with less loop overhead; the current evaluated code demonstrates that the global allocation domain, rather than a particular water-filling implementation, is the dominant measured quality factor.

- **Flattened scatter indexing makes reverse maps compact and robust.** The final inverse map uses a dense allocation of shape `[layers, logical_experts, maxlogcnt]`, initializes unused entries to `-1`, and scatters physical replica IDs using expert ID and replica rank. This avoids costly Python-side list assembly and correctly supports uneven replica counts, a property validated by the current program and the other correct implementations.

## Performance Analysis

- **The current best is the strongest evaluated result in this batch.** Its **0.15 combined score** exceeds Generation 18’s global implementation (**0.14**) and all correct hierarchical implementations (**0.12–0.13**). It is also the only listed result combining **0.76 GPU balancedness** with **0.29 expert balancedness** and an inference score of **0.30**; Generation 18 matches the balance figures but has slower measurements (**0.18 algorithm time, 0.52 inference**) and therefore lower combined score.

- **Globalization improves both balance dimensions, not merely GPU placement.** The hierarchical family generally reaches **0.66 GPU / 0.25 expert**. The current program reaches **0.76 / 0.29**, gains of **+0.10 GPU balancedness** and **+0.04 expert balancedness**. This supports the conclusion from previous evaluations that global replica capacity helps hot experts receive useful copies and gives final placement enough flexibility to spread all loads.

- **More elaborate hierarchical refinement did not close the gap.** Generation 16’s adaptive candidate expansion produced **0.66 GPU**, **0.24 expert**, **0.42 algorithm time**, **0.79 inference**, and **0.12 combined**. Generations 11–14, 17, and 19 used different water-filling and swap methods but converged around **0.13 combined**. Thus, implementation complexity within a node-constrained planner did not translate into improved benchmark balance or speed.

- **Speed remains weak across all correct designs, while quality differences are algorithmic.** The current best’s **0.01 speed score** is the same low ceiling seen in most correct candidates, including Generation 15 and hierarchical LPT/water-filling designs. Since the current best nevertheless leads combined score, its advantage is not systems throughput; it is the better global allocation and global fixed-capacity placement policy.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Keep global replica allocation and global GPU placement as the default invariant.** Continue calling the validated placement path with `num_groups=1, num_nodes=1`, since this is the only demonstrated approach to reach `0.76` GPU and `0.29` expert balancedness. If topology awareness is revisited, use it only as a deterministic tie-breaker among equally good global placements, never as a constraint that partitions replica capacity before water-filling.

2. **Replace the sequential `replicate_experts` loop with batched marginal-copy selection while preserving the exact water-filling objective.** For expert \(e\), the marginal benefit of its next copy is `weight[e] / k` for replica count `k`; construct candidate values for useful `k` values, select the global top `num_redundant` candidates per layer with `topk`, and recover `logcnt` via scatter/count accumulation. This directly targets the current best program’s per-extra-replica `max` loop, retaining global discrete equalization that produced the leading expert score while reducing Python-loop and repeated reduction overhead.

3. **Prototype a batched LPT placement schedule that assigns several replicas per iteration without relaxing per-GPU cardinality.** Sort replica loads once, then process blocks of up to `num_gpus` replicas by matching heavy replicas to GPUs ordered by current load, masking GPUs whose `phy_experts_per_gpu` capacity is exhausted. Compare its balance against exact one-at-a-time LPT; the current sequential `balanced_packing` is a likely algorithm-time bottleneck, while global LPT itself is clearly valuable and should be preserved as the baseline quality policy.

4. **Add a same-expert-spread tie-breaker inside global LPT for equal or near-equal GPU load choices.** Maintain a compact `[layers, num_gpus, num_logical_experts]` presence/count state, and when multiple eligible GPUs have the minimum current load, prefer the GPU with fewer copies of the selected logical expert; then break remaining ties by GPU index. This is compatible with the successful global placement design and may improve resilience or expert-level distribution without the failed cost of broad swap/exchange refinement.

5. **Specialize and simplify the global-only execution path instead of routing through hierarchy-oriented intermediate tensors.** Implement a direct global routine: globally compute `phy2log`, derive replica weights as `weight.gather(...)/logcnt.gather(...)`, globally pack into GPUs, then construct `phyrank`, `logcnt`, and `log2phy` using the existing flattened scatter pattern. The current call through `rebalance_experts_hierarchical(..., 1, 1, ...)` is correct and effective, but bypassing trivial group/node packing, inverse permutations, reshapes, and gathers can reduce overhead while preserving the exact policy responsible for the best measured balance.
