# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Multi-candidate greedy + local search is now the dominant architecture**: The current best (Gen 19, score **26.22**, max_kvpr 25.22) builds multiple greedy placements from different model orderings (load, size, density) with both post-placement and current-KVPR best-fit scoring, refines each with moves/swaps, then applies iterated local search with 1-3 random relocations per perturbation over 300 rounds. This extends the previous best pattern (Gen 9's five-candidate enumeration, 23.61) with stronger perturbation-based search for a +2.61 gain.
- **Swaps complement moves in refinement**: Gen 12 (moves + pairwise swaps, 25.81) and Gen 18 (indexed moves + swaps, 25.60) both outperform move-only refinement (Gen 7/16 at 22.52, Gen 13 pure greedy at 22.34). Adding pairwise swaps off the hottest GPU broke the ~22.5 plateau that pure move-based local search could not.
- **Perturb-and-refine (ILS) squeezes the last gains**: Gen 14 (multi-start + perturbation, 24.35, 0.01s) and Gen 19 (300 perturbation rounds, 26.22, 0.02s) show randomized relocation around the incumbent, repaired by greedy refinement, yields additional max-KVPR reductions at trivial runtime cost. Seeded RNG (12345) keeps results deterministic.
- **Focusing refinement on the bottleneck GPU**: Gen 18's insight — restricting moves/swaps to GPUs at the current maximum KVPR — focuses search efficiently; Gen 19 retains this plus targeting the two hottest GPUs.

## Ineffective Approaches

- **Division-by-zero from zero remaining memory remains the #1 killer**: Gen 17 scored **0.00** ("float division by zero") because `kvpr()` guarded memory only *before* assignment but a fully-filled GPU (remaining = 0) crashed final evaluation. This repeats Gen 1/5's failure mode; the current best's `if self.remaining_mem <= 0: return float('inf')` guard is mandatory.
- **Indentation/scope bugs make structurally sound algorithms score 0**: Gen 20 scored **0.00** ("name 'shared_kv' is not defined") — a misplaced `return` and loop body outside `build_placement` meant the local search never ran. As with Gen 2's state-mutation bug, a single crash wipes the entire score regardless of algorithm quality.
- **Pure greedy without refinement plateaus**: Gen 13 (greedy only) at 22.34 vs. Gen 12 (same base + local search) at 25.81 — a +3.47 gap confirming refinement is essential, not optional.
- **O(n²) full recomputation in local search limits scalability** (Gen 17 feedback) though at current problem scale it's tolerable; the current best uses analytic pre-move evaluation (`new_hot`, `new_other` computed before committing) to avoid it.

## Implementation Insights

- **Current best's layered pipeline**: 5+ heuristic orderings → greedy best-fit build → steepest-descent refine (moves, then swaps, epsilon-guarded `max(new) < kvs[hot] - 1e-12`) → 300-round ILS (clone, 1-3 random relocations, refine, keep if strictly better). Each layer is cheap and strictly improves or keeps the incumbent.
- **Safe perturbation rollback**: Gen 19 restores the model to its original index when no destination fits (`models.insert(m_idx, model)` with symmetric memory/load updates), preserving feasibility — avoiding Gen 17's class of state bugs.
- **Index-based state bookkeeping**: Gen 18's index-based tuples avoid duplicate-model comparison bugs during swaps; Gen 19's swap uses direct list-index assignment (`gpus[hot].models[idx] = m_other`) with exact memory/load deltas, mirroring the successful pattern from Gen 9.
- **Determinism via fixed seed**: Both Gen 14 and Gen 19 use `random.Random(12345)` — reproducible perturbation without risking nondeterministic test failures.

## Performance Analysis

- **Score progression confirms layered gains**: 21.89 (pure greedy) → 22.34 (Gen 13) → 22.52 (move-only refine, Gen 7/16) → 25.60-25.81 (moves + swaps, Gen 18/12) → 26.22 (multi-start + ILS, Gen 19). Swaps contributed ~+3, perturbation-based ILS ~+0.4-1.9.
- **Runtime remains a non-factor**: Best program runs at 0.02s despite 5 candidates + 300 ILS rounds — the +2ms over simpler variants costs nothing, validating that search effort is essentially free.
- **Crash = zero, robustness = precondition**: Gen 17 and Gen 20 both scored 0.00 despite sound designs (Gen 20's design was explicitly judged "sound" post-analysis). Success rate 1.00 across all scoring programs confirms epsilon guards, inf-on-zero-memory, and error-on-infeasibility are load-bearing.
- **Placement quality is the sole remaining lever**: With success_rate saturated at 1.00 and execution time ~0, all score variance now comes from max_kvpr itself — feedback on Gen 19 explicitly notes stronger metaheuristics or better load-aware partitioning as the path forward.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Replace the random ILS perturbation with structured "worst-fit destroying"**: Instead of relocating 1-3 uniformly random models, perturb by relocating the model with the highest req_rate/slo from one of the two hottest GPUs, plus one random model (kicks escape the exact local optimum that blocks refine()). Gen 19 shows perturbation quality drives gains; targeted kicks typically outperform uniform-random ones in ILS literature and reuse the same safe-rollback machinery.

2. **Apply the full candidate-pool + ILS pipeline to the top-2 candidates, not just the best**: Currently ILS starts only from best_score's placement. Run 150 ILS rounds from each of the two best candidates (fixed RNG seed). This hedges against a single greedy ordering landing in a poor basin — cheap since runtime is 0.02s and clones are already implemented.

3. **Add a third move type to refine(): rotate three models across three GPUs**: When moves and pairwise swaps both fail, try a 3-cycle relocation (A→GPU2, B→GPU3, C→hot) which escapes optima that 2-model swaps cannot. Keep the strict-improvement epsilon guard `max(new_kvs) < kvs[hot] - 1e-12` for termination; restrict models to the two hottest GPUs to bound the O(n³) search.

4. **Make ILS accept equal-score solutions occasionally**: Accept a perturbed candidate when `score < best_score + 1e-9` (not strictly better), tracking the best separately — this enables basin-hopping. Gen 19's strict acceptance may trap the incumbent in one basin; ties-diversification is a standard ILS fix and costs nothing at 0.02s runtime.

5. **Add tie-breaking lookahead to build_placement**: When two GPUs have post-placement KVPR within 1e-9, pick the one with larger remaining memory after placement. This extends the best-scoring candidate spec (post-KVPR best-fit) with memory-flexibility tie-breaking, addressing greedy myopia at zero cost while preserving the proven ordering keys. Also verify all new code paths guard `remaining_mem <= 0` with inf — Gen 17/20 proved a single crash zeroes the score.
