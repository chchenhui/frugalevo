# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Multi-seed greedy + move/swap local search + ILS remains the dominant architecture**: The current best (Gen 21/24, score **26.22**, max_kvpr 25.22) builds 5 greedy candidates from varied orderings, refines each with move/swap local search, then applies 300 rounds of seeded ILS. Gen 26's variant with 400 ILS rounds scored 26.19 — essentially tied, confirming the approach's robustness rather than a single lucky configuration.
- **Swaps are essential to break the ~22.5 plateau**: Programs with move+swap refinement (Gen 15: 26.13; Gen 27: 25.60; Gen 31: 25.79) all land in the 25.6–26.2 band, while move-only refinement (Gen 23, single-ordering greedy + moves, 22.34) stays far below. Gen 25's two-ordering + move-only version scored 22.70 — confirming swaps, not more orderings, drive the jump.
- **ILS perturbation adds the final ~0.5–1.0**: Comparing Gen 15 (26.13, refine+swap only) vs Gen 21/24 (26.22, + 300-round ILS) shows a modest but consistent gain from perturb-and-repair, at only +0.03s runtime.
- **Escalating neighborhoods help when cheap**: Gen 27's 3-cycle rotation restricted to the three hottest GPUs (25.60) and Gen 31's 1-opt → swap → 3-cycle escalation (25.79) show richer neighborhoods help when confined to the bottleneck GPUs.

## Ineffective Approaches

- **Single missing import destroys everything**: Gen 22 scored **0.00** with "name 'random' is not defined" despite an algorithmically sound multi-start greedy + local search design — the entire score was wiped by one missing `import random`. This extends the pattern: Gen 17 (division by zero), Gen 20 (scope bug) all scored 0.00 from single-line defects.
- **Single-ordering greedy with move-only refinement plateaus low**: Gen 23 (22.34) and Gen 25 (22.70) vs multi-seed counterparts (26.13–26.22) confirm that one greedy ordering without swaps caps around 22.3–22.7 regardless of refinement effort (up to 100 iterations).
- **Too-few refinement rounds in single-start variants**: Gen 27/31 use only 20 refinement rounds — adequate but leaves ~0.4–0.6 on the table vs multi-start + ILS variants.
- **All non-crash failures were quality-capped, never robustness-capped**: every scoring program had success_rate 1.00 and ~0s runtime — placement quality is the sole differentiator.

## Implementation Insights

- **The current best's layered pipeline is the winning formula**: 5 orderings (req/slo desc ×2 modes, size desc/asc, density desc) → greedy best-fit → epsilon-guarded refine (moves, then swaps, `max(new) < kvs[hot] - 1e-12`) → 300-round ILS with 1–3 random relocations per perturbation, cloned state, and strict-improvement acceptance. Each layer is cheap and monotone-improving.
- **Analytic pre-move evaluation avoids full recomputation**: `new_hot`/`new_other` KVPR values are computed *before* committing any move/swap — keeping 300 ILS rounds + 5 candidates at 0.03s total.
- **Safe rollback in ILS preserves feasibility**: when no destination fits, the model is re-inserted at its original index with symmetric memory/load updates — avoiding the state-corruption class of bugs that killed Gen 17/20.
- **Determinism via `random.Random(12345)`**: shared across Gens 21, 24, 26 — ensures reproducible ILS results, and each clones the incumbent before perturbing, so the best solution is never destroyed by a bad kick.

## Performance Analysis

- **Score progression by architecture**: single greedy + move refine: 22.34–22.70 (Gen 23/25) → multi-start + move/swap refine: 25.60–26.13 (Gen 27/31/15) → multi-start + refine + ILS: 26.18–26.22 (Gen 32/21/24/26). Each layer adds concretely; ILS variants cluster tightly (26.18–26.22), suggesting a convergence ceiling near ~26.2 for this neighborhood structure.
- **Runtime is saturated**: all scoring programs run in 0.00–0.04s; there is massive headroom for more search effort (more ILS rounds, larger perturbations, restarts) at zero score cost — Gen 26's 400 rounds ran in the same 0.03s.
- **Crash = zero remains the dominant risk asymmetry**: Gen 22 (missing import) proves even structurally correct algorithms score 0.00 on a single NameError. Robustness checks (inf on zero remaining memory, feasibility guards, error on infeasibility) are prerequisites, not optimizations.
- **The best program wins by ~0.03–0.09 over its nearest competitors** (Gen 15: 26.13, Gen 26: 26.19, Gen 32: 26.18) — margins are thin at the top, meaning further gains likely require stronger metaheuristics or fundamentally better load-aware construction, not parameter tuning of the existing pipeline.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Replace random ILS perturbation with targeted "hottest-GPU destroy"**: In the ILS loop, instead of picking a uniformly random source GPU, pick the GPU with the current highest KVPR in `cand` (with probability ~0.8) and relocate its highest `req_rate/slo` model (plus one random model elsewhere) to the best-fitting destination by post-placement KVPR rather than a random one.
