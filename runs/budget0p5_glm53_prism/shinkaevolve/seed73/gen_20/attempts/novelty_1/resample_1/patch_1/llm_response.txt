The current program commits to a single greedy ordering (req_rate/slo descending). Following the recommendation, we can enumerate several candidate orderings (density = (r/s)/model_size ascending, req_rate descending, slo ascending, and seeded random shuffles), run the same greedy + local search pipeline for each, and keep the placement with the lowest resulting max KVPR. Since runtime is ~0.00s, this diversity is nearly free and can escape poor greedy basins. We factor the greedy+local-search into a helper `build_placement(order)` and select the best candidate at the end.</DESCRIPTION>
