# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Binary-search-on-threshold with first-fit feasibility remains the winning pattern**: The current best program (Gen 16, "Binary-Search Threshold Packing with Local-Search Refinement", 25.71) confirms Gen 1's earlier finding (25.69) that searching for the tightest feasible λ directly encodes the max-KVPR objective `(W + w) ≤ λ·(rem − s)` — a ~3-point jump over all greedy variants (best greedy: Gen 12 at 24.64; most greedy variants 21.9–22.5).
- **Layered fallback chains guarantee 100% success**: Gen 16 uses λ-constrained packing → memory-only best-fit → raise ValueError, mirroring the previous best's layered fallback (λ → memory-only → any-fit → raise). Gen 13's separate "exact-fit fallback" also achieved 22.34 with no crashes.
- **Density-sorted ordering (req_rate/slo descending) is universal**: Every scoring program (Gen 13–17, 19, 20) uses this ordering as the base; both binary-search winners rely on it for packing order.
- **Local search refinement adds only marginal gains on top of greedy**: Gen 12 (24.64), Gen 14 (22.52), Gen 20 (22.31), Gen 19 (24.22) all pair greedy with moves/swaps; gains over plain greedy are ~0–2 points, far less than the binary-search jump. Gen 16's local search on top of binary search added ~0.02 over Gen 1's pure binary search (25.71 vs 25.69).

## Ineffective Approaches

- **Missing imports zero out otherwise sound algorithms**: Gen 11 ("Multistart Greedy with Local Search") scored 0.00 purely because `time` and `random` were never imported ("name 'time' is not defined"), plus a garbled swap expression (`free[src] - dfuse_free if False else ...`) indicating corrupted code.
- **Unguarded division remains the top killer**: Gen 10 scored 0.00 from "float division by zero" at Placement 3 (zero SLO or exact-fit memory), consistent with the previous generation's pattern (Gens 2, 6–9 all crashed identically). The greedy heuristic was sound; only the missing epsilon guards failed.
- **Multi-start / many orderings don't beat threshold search**: Gen 19's four-ordering multi-start with move+swap refinement scored 24.22 — decent, but still ~1.5 points below Gen 16's binary search. Diverse orderings help greedy avoid local optima but cannot match direct λ optimization.
- **Local search with only moves (no swaps) underperforms**: Gen 20's move-only refinement scored 22.31, below Gen 19's move+swap (24.22) and Gen 16's binary search, suggesting swap operations matter when GPUs are memory-full.

## Implementation Insights

- **Gen 16's key techniques**: 60-iteration binary search over λ ∈ [0, 1e9]; first-fit packing among opened GPUs with a best-fit fallback; `1e-12` epsilon tolerances in feasibility checks; re-packing at final λ with `record=True`; local search with a 5000-iteration guard, `safe_ratio` returning `float('inf')` for free memory ≤ 1e-9 (preventing all division-by-zero crashes); early break when the max-KVPR GPU has `kvpr == inf`.
- **Tolerance constants are validated as the crash fix**: Gen 13 ("fix_zero_division_simple_greedy", 22.34) explicitly fixed Gen 10's zero-division crash with fit-feasibility checks and exact-fit fallback, moving 0.00 → 22.34. Small epsilons (1e-9 to 1e-12) consistently separate scoring programs from crashing ones.
- **`safe_ratio` guards are the robustness pattern**: Wrapping every division in a free-memory check (returning `inf` or skipping) is present in all top scorers (Gen 12, 13, 16) and absent in Gen 10's crash.
- **Instant execution (0.00–0.01s) across all scoring programs** confirms runtime is not a differentiator; combined score = max_kvpr + 1 for success, so placement quality is the sole driver.

## Performance Analysis

- **Score distribution**: Binary search + local search (Gen 16: 25.71) > greedy + local search rebalancing (Gen 12: 24.64) > multi-start + local search (Gen 19: 24.22) > binary search with multi-seed orderings (Gen 17: 22.93) > greedy + local search (Gen 14: 22.52, Gen 13: 22.34, Gen 20: 22.31) > crashed (Gen 10, 11: 0.00).
- **The two crashes (Gen 10, 11) were entirely preventable**: a missing `import` and a missing zero-denominator guard, matching the previous generation's finding that robustness, not algorithmic sophistication, determines whether an algorithm gets scored at all.
- **Binary search's ~3-point advantage over greedy is stable across generations**: Gen 1 (25.69) and Gen 16 (25.71) both beat the best greedy-family programs (22.5 range) by ~3 points; adding local search on top of binary search yields negligible further gain (+0.02).
- **Greedy family scores cluster tightly (21.9–24.6)**, with the spread likely from refinement details (move+swap > move-only; rebalancing from the worst GPU helps — Gen 12's 200-iteration worst-GPU rebalancing was the greedy family's best at 24.64).

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Warm-start the binary search bounds analytically instead of `[0, 1e9]`.** Compute `lo = max(w / (GPU_MEM_SIZE - s))` over all models (the theoretical per-model lower bound on λ) and `hi = max_kvpr` achieved by the existing memory-only fallback packing. This brackets the optimal λ tightly, letting 60 iterations converge to machine precision on the true optimum rather than wasting iterations in the enormous infeasible range — a pure-precision improvement with zero crash risk since the feasibility code is unchanged.

2. **Run the full λ binary search over multiple candidate orderings and take the minimum feasible λ.** Keep the density-desc base order, but also try model_size-desc, w-desc, and a composite key `(s + w)`, each reusing the exact same `pack()` function and `1e-12` guards. Gen 17 (22.93) showed multi-seed orderings alone underperform, but combining orderings with the binary-search core (which Gen 17 did not fully do) lets first-fit find tighter packs that density-sort alone misses. The final placement should be re-packed at the best λ found across all orderings.

3. **Add swap moves to the local-search refinement phase.** The current refinement only moves single models off the hottest GPU; Gen 19 (24.22) vs Gen 20 (22.31) showed swaps matter when GPUs are memory-full. Extend the refinement to also try pairwise swaps between the hottest GPU's models and models on other GPUs — where memory constraints block moves — accepting a swap only when the resulting max KVPR strictly decreases, keeping the existing `safe_ratio`/`1e-9` guards and the 5000-iteration cap.

4. **Add a Las Vegas restart loop with order jitter around the binary search.** Since runtime is 0.00s, run the entire binary-search + refinement pipeline 20–50 times with small random perturbations (shuffle models within equal-density groups, or ±1% jitter on the sort key), retaining the assignment with the lowest final max KVPR. Every candidate uses the crash-proof `pack()` path, so this can only improve the score; it exploits first-fit's order sensitivity that Gen 16's single deterministic ordering leaves on the table.

5. **Add a worst-pair rebalancing pass inspired by Gen 12's greedy best (24.64).** After the binary search and before local search, run a 200-iteration pass targeting the two highest-KVPR GPUs simultaneously: for each model on the top GPU, try both moving it to any GPU and swapping it with a model on the second-highest GPU, accepting any strict max-KVPR decrease. Gen 12 showed worst-GPU rebalancing was the strongest greedy-family refinement; combining it with the binary-search core (which greedy never had) is the most promising hybrid of the two successful families.
