# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Add hybrid threshold-construction restarts to the multistart pool.** Keep Gen 33's 20 greedy multistarts, but replace 8–10 of them with binary-searched-λ first-fit constructions (Gen 25/28 pattern): binary search the KVPR threshold, place each model on the first GPU where resulting ratio ≤ λ, then run the same full-lexicographic `refine()`. These threshold constructions land in different basins than greedy, and with ILS perturbation on top of whichever incumbent wins, the combined pool could break the 26.26 plateau.

2. **Vary the perturbation strength adaptively in the ILS loop.** Gen 33's fixed 1–3 random moves is a narrow kick. Run the 20 perturbation rounds in escalating waves: rounds 1–7 use small kicks (1 move), rounds 8–14 medium (2–3 moves), rounds 15–20 large kicks (4–6 moves or a full swap of two random GPU partitions). Keep the feasibility guard and re-refine from each perturbed state; large kicks explore far basins while small kicks polish — a classic basin-hopping intensification/diversification balance at negligible runtime cost.

3. **Use best-improvement acceptance for moves instead of first-accept.** In `refine()`, for each iteration evaluate all feasible single moves from the currently-hottest GPU and accept the one with the lexicographically best full sorted vector, rather than taking the first improving move and restarting the scan. This converges to stronger local optima per refine call; keep first-accept for swaps (quadratic scan) and the 3000-iteration guard. Given each refine is only ~0.002s, the extra pass is affordable within the 40-call budget.

4. **Add structured restart orderings beyond density-based ones.** Supplement the current three ordering modes (deterministic density, shuffle, ±20%-jittered density) with: `model_size` descending, `(req_rate/slo + model_size)` composite descending, and density-sorted with shuffle only within tie groups. Gen 25/28 showed multiple fixed orderings are robust, and each ordering seeds a distinct basin family for the ILS layer to exploit — pure shuffle restarts are the weakest of the three current modes and structured keys may replace them at no cost.

5. **Intensify ILS on the best incumbent with a lexicographic (not max-only) acceptance test.** Currently the perturbation loop accepts a new incumbent only if the *max* KVPR strictly decreases (`v < best_val - 1e-15`), which discards placements that improve mid/lower tiers without moving the max. Since the refinement objective is full-vector leximin, track the best incumbent by `sorted(kvs, reverse=True)` lexicographic comparison too — accept perturbed-refined results whose full vector is lexicographically smaller even when the max is unchanged. This aligns acceptance with the objective that produced the current ceiling and may capture the marginal +0.01–0.05 the plateau is hiding.
