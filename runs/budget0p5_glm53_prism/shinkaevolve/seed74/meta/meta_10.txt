# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns
- **Binary-search-on-threshold with first-fit feasibility is the current best**: Generation 1's "Binary Search KVPR with First-Fit-Decreasing Packing" (combined score 25.69, max_kvpr 24.69) outperforms all greedy variants (best greedy: Generation 4 at 22.52). The threshold formulation `(W + w) ≤ λ·(MEM − S − s)` directly encodes the KVPR objective and binary-searches the tightest feasible λ.
- **Density-sorted ordering (req_rate/slo descending) is universal**: Every scoring program (Gen 0: 21.89, Gen 3/5: 22.34, Gen 4: 22.52, Gen 1: 25.69) uses this ordering, and it appears in both greedy and binary-search approaches.
- **Greedy alone plateaus around 21.9–22.5**: Gen 0 (21.89), Gen 3/5 (22.34), Gen 4 with local search (22.52) show incremental gains only; the jump to 25.69 came from binary search + feasibility packing, not from greedy refinement.
- **Exact-fit epsilon guards in the best program**: The current best uses `+1e-12` tolerance in feasibility checks, allowing placements at exactly the λ boundary.

## Ineffective Approaches
- **Unguarded division by zero is catastrophic**: Generations 2, 6, 7, 8, and 9 all scored 0.00 due to "float division by zero" — from dividing by `req_rate/slo` with zero SLO, zero remaining memory, or exact-fit models filling a GPU. Logically identical algorithms crashed purely on missing edge-case guards.
- **Placing a model that exactly fills GPU memory crashes the evaluator**: Gen 8's feedback explicitly notes the evaluator's `calculate_kvcache_pressure` divides by zero when remaining memory is 0. Greedy Gen 0/3/5 succeeded while multi-start Gen 8 failed, suggesting greedy happened to avoid exact fills while other strategies didn't.
- **Local search refinement yields only marginal gains**: Gen 4's 50-iteration single-model relocation improved the greedy score only from 22.34 to 22.52, and Gen 6's refinement variant crashed entirely (0.00) due to zero denominators in refinement calculations.
- **Adding more candidate orderings (multi-start) didn't help**: Gen 8's four-ordering multi-start approach scored 0.00, offering no benefit over simpler strategies.

## Implementation Insights
- **The current best program's key technique**: 60-iteration binary search over λ ∈ [0, 1e9] with a first-fit feasibility check, recording assignments by re-running packing at the final λ with a `1e-9` tolerance, plus a memory-only first-fit fallback and last-resort any-GPU-that-fits assignment. This layered fallback chain (λ-constrained → memory-only → any-fit → raise) guarantees 100% success rate.
- **Robustness matters more than sophistication**: 5 of 10 programs scored 0.00 despite sound algorithms; the successful ones (Gen 0, 1, 3, 4, 5) all validated memory fit before dividing and avoided zero-denominator paths.
- **Tolerance constants matter**: The best program uses `1e-12` in feasibility and `1e-9` in re-packing — small tolerances that prevent both false rejections and boundary crashes.
- **Instant execution across all scoring programs (0.00s)** shows runtime is not a differentiator; placement quality (max_kvpr) is the sole meaningful score driver (combined = max_kvpr + 1 for success).

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Add best-fit (min-slack) selection instead of first-fit within the feasibility check.** The current best uses pure first-fit packing; a variant that, at each model, chooses the GPU minimizing `(rem - s)` among those satisfying the λ constraint would produce tighter packs and may lower the feasible λ for the same GPU count. Keep the exact same `1e-12` tolerance and `feasible()` structure to preserve the robustness that made this program succeed.

2. **Iterate over multiple candidate orderings inside the binary search.** Since density-sort (req_rate/slo) is universal but the binary search dominates, try running the same λ binary search on 3–4 orderings (density-desc, model_size-desc, w-desc, and a size/w composite) and take the minimum feasible λ across all of them. Unlike Gen 8's failed multi-start (which crashed from missing guards), reuse the proven guard structure so each ordering shares the same zero-denominator-safe feasibility code.

3. **Warm-start the binary search bounds instead of `[0, 1e9]`.** Compute `lo` as the max single-model pressure `max(w / (MEM - s))` (the theoretical lower bound on λ) and `hi` as the λ achieved by the current fallback memory-only packing. This tightens the bracket, letting 60 iterations of binary search converge to machine precision on the actual optimal λ rather than wasting iterations in an enormous infeasible range.

4. **Add a post-binary-search local repair phase with strict zero guards.** Gen 4 showed local search adds ~0.2 on greedy; applying the same idea to the binary-search result — after final packing, try moving single models between GPUs (or pairwise swaps) whenever it lowers the actual max KVPR `W[i]/rem[i]`, accepting only moves where the target's remaining memory stays strictly positive — could squeeze gains beyond the λ-optimal first-fit solution. Guard every division with `if rem > 1e-9` to avoid the crash pattern that killed Gen 6.

5. **Implement a randomized (Las Vegas) restart loop over first-fit with shuffled tie-breaking.** Since runtime is 0.00s and irrelevant, run the full λ binary search 20–50 times with small random perturbations to the sorted order (e.g., shuffling models within equal-density groups, or ±1% jitter on the sort key), keeping the best final max-KVPR assignment. This exploits the fact that first-fit is order-sensitive while never risking the score, since every candidate uses the crash-proof feasibility path.
