post_placement_kvpr_and_local_search</NAME>
<DESCRIPTION>
The current greedy picks the GPU with the lowest *current* KVPR (weighted_req_rate / remaining memory), which ignores both the new model's contribution and the fact that denominator should be total used memory (GPU_MEM_SIZE - free), not remaining. This biases placements badly. I fix the selection criterion to the *post-placement* KVPR: (load + r/s) / (GPU_MEM_SIZE - (free - size)), matching the evaluator's KVPR definition. Then I add a lightweight local-search pass that repeatedly moves a model off the hottest GPU (highest KVPR) whenever it strictly lowers the max KVPR across all GPUs, with bounded iterations. This directly minimizes the objective.
