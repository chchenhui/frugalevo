# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **The current best program (Gen 39, "randomized_restarts_eps_tiebreak", 26.26) confirms that bounded randomization layered on the multi-ordering backbone breaks deterministic plateaus.** It runs 4 orderings × 8 randomized restarts (32 greedy pipelines) with a fixed seed (1234), shuffling only a bounded prefix of the sorted list (the first `restart` elements via partial Fisher-Yates) and epsilon-random tie-breaking (`rng.choice` among candidates within `1e-9`). This +0.11 gain over the 26.15 plateau held by Gens 34/35/36 shows diversification compounds with — rather than replaces — the multi-start backbone.
- **Gen 38 ("random_multistart_local_search", 26.23, 0.03s, 100% success) independently validates the multi-restart + multi-size swap architecture**, achieving within 0.03 of the best with four deterministic orderings plus ~20 noise-perturbed restarts and the full escalating neighborhood (moves → 1-1 → 2-1 → 2-2 swaps → pairwise polish on (max KVPR, 2nd max KVPR)). Two programs built on the same skeleton landing at 26.23–26.26 confirms the design is robust, with Gen 39's tie-breaking randomization supplying the marginal edge.
- **Lazy escalation of the 3-way cyclic rotation keeps the O(n³) scan free when cheaper ops exist**: in Gen 39, the rotation scan (hot→A, A→B, B→hot) only runs `if best_op is None` — after moves, swaps, and 2-for-1 exchanges are exhausted. Execution stayed at 0.03s despite 32 pipelines, matching Gen 38's runtime.
- **Strict-improvement atomic op selection remains the correctness backbone across both top programs**: evaluate all ops against the current hot GPU, apply exactly one op with `gain > best_gain + 1e-12` gating and symmetric incremental load/free_mem updates, then rescan from the fresh state.

## Ineffective Approaches

- **Type inconsistencies between scalar and structured state remain a total-failure mode**: Gen 37 ("greedy_plus_refine_and_second_target", 0.00) crashed on `'>' not supported between instances of 'float' and 'list'` — comparing scalar KVPR against a malformed list slice. As with Gens 20/22/23/27, one bookkeeping bug erased a structurally sound greedy + local-search algorithm.
- **Randomization without ordering diversity underperforms**: Gen 30 (25.95) used epsilon tie-breaking with 12 restarts but a single sort order (req_rate/slo), landing below the deterministic multi-order tier (26.15). Gen 39's win came specifically from combining both axes.
- **Multi-start without genuine diversification stagnates or regresses**: Gen 40 ("rotation_enhanced_pipeline", 25.55) used the same four orderings plus rotations yet scored *below* the 26.15 tier — restart count alone caps out, and implementation details (targeting only worst + runner-up vs. the full lexicographic polish in Gen 38, operator ordering) determine whether richer neighborhoods pay off.
- **Single-ordering configurations persistently trail multi-ordering by ~0.3 points**: Gen 31 (25.83) and Gen 33 (25.83) both topped out with one greedy order plus move/swap/2-for-1 refinement.

## Implementation Insights

- **Gen 39's two disciplined randomization mechanisms are the specific differentiators over Gen 38's 26.23**: (1) greedy-phase near-ties (within `1e-9`) are collected into a candidate list and broken via `rng.choice`, diversifying without ever accepting a worse-than-best GPU; (2) restart-phase prefix shuffling perturbs only the first `restart` positions of the sorted list, preserving heavy-model priority order while diversifying the tail. Both share one fixed-seed `rng`, keeping results deterministic.
- **The zero-safe `kvpr_of` guard (`inf`/`0.0` when `denom <= 0`) is universal among survivors** — present in both Gen 38 and Gen 39 and credited since Gen 25; its absence caused Gen 20's division-by-zero zero-score.
- **Graceful infeasibility with best-of selection across all 32 pipelines underpins the 100% success rate**: a pipeline that can't place a model returns `(None, inf)` and is skipped; only if all 32 fail does the program raise. Gen 38 mirrors this with its 100% success rate.
- **Strict-improvement gating (`gain > best_gain + 1e-12`) plus symmetric incremental load/free_mem updates** avoids the simulate/revert drift that killed Gen 27 and the `list.remove` crash that killed Gen 22 — both top programs (38, 39) recompute `state_kvprs()` fresh after each applied op.

## Performance Analysis

- **Score progression confirms two orthogonal quality axes — neighborhood richness and start diversity — compounding**: single-order + swaps/2-for-1 = 25.83 (Gens 31, 33) → multi-order + 2-for-1 = 26.15 (Gens 34/35/36) → multi-order + noise restarts, no tie-breaking = 26.23 (Gen 38) → **multi-order + prefix-shuffled restarts + epsilon tie-breaking = 26.26 (Gen 39, current best)**.

- **The 32-pipeline ensemble costs 3× deterministic runtime (0.03s vs 0.00–0.01s for Gens 30–36) but remains negligible**, so score differentiation is entirely placement quality (max_kvpr = 25.26 for Gen 39 vs 25.23 for Gen 38).

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Scale the ensemble to 4 orderings × 16 restarts with varying prefix-shuffle depth.** Gen 39's win came from combining ordering diversity with bounded restart randomization, and runtime is only 0.03s for 32 pipelines — doubling to 64 is nearly free. Vary shuffle depth per restart (e.g., shuffle the first `min(len, restart * 2)` elements) so early restarts stay near the proven greedy order while later ones explore more diversified seeds, keeping the fixed-seed `rng` for determinism.

2. **Add a lexicographic top-2 polish phase after the hot-GPU loop breaks.** Gen 38's pairwise polish on (max KVPR, 2nd max KVPR) was part of its near-best 26.23 architecture but is missing from Gen 39. After `best_op is None`, run a bounded (≤20 iteration) phase scanning all GPU pairs for 1-for-1 swaps that reduce `sorted(kvprs)[-2]` without raising the max — with atomic apply-then-rescan discipline and `best_gain > 1e-12` gating.

3. **Widen the greedy tie-breaking epsilon to a relative threshold.** Gen 39's epsilon-random tie-breaking is its differentiator over Gen 38; widening the band from absolute `1e-9` to `best_kvpr * 1e-7` admits more genuine near-ties into the candidate list, which is exactly where placement choice matters most for downstream refinement. Never accept a candidate outside the relative band, preserving the "no meaningfully worse GPU" invariant.

4. **Add a second-target refinement phase on the runner-up GPU.** After the main loop converges, set `hot` to the second-max KVPR GPU for a bounded (≤30 iteration) phase, reusing all existing operator blocks unchanged but gating acceptance on `new_max < cur_global_max - 1e-12` so ops never raise the global max. Gen 40's failure shows the op ordering matters — keep the full lexicographic objective, not just max-reduction, and reuse the proven operator ladder (move → swap → 2-for-1 → rotation).

5. **Add explicit float casts and index-based list manipulation as crash insurance.** Five programs (Gens 20, 22, 23, 27, 37) died on bookkeeping bugs, not algorithmic flaws. Cast `model.req_rate`, `model.slo`, and `model.model_size` to `float` at pipeline entry, and replace `placement[g].remove(model)` with index-based removal (`del placement[g][idx]`) to avoid equality-based remove failures if models define `__eq__` — cheap safeguards protecting the structurally sound backbone.
