# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **The new best program (Gen 39, "randomized_restarts_eps_tiebreak", 26.26) validates randomized diversification when layered on top of the multi-ordering backbone** — a key update to prior insight that randomization was unvalidated. Gen 39 runs 4 orderings × 8 randomized restarts (32 greedy pipelines), with a fixed seed (1234), light prefix-shuffling of the sorted model list (`restart` leading elements shuffled per Fisher-Yates), and epsilon-random tie-breaking among near-tied greedy candidates (`rng.choice(candidates)` within a `1e-9` band). This pushed past the 26.15 plateau held by Gens 34/35/36.
- **Combination matters: randomization alone is not enough.** Gen 30 (25.95) used epsilon=0.05 tie-breaking with 12 restarts but only a single sort order (req_rate/slo), landing below the deterministic multi-order variants. Gen 39's gain (+0.11 over 26.15) came specifically from combining ordering diversity with randomized tie-breaking and restarts — randomization amplifies the multi-start backbone rather than replacing it.
- **Lazy escalation of the 3-way cyclic rotation keeps cost negligible while escaping deeper local optima**: in Gen 39, the O(n³) rotation scan (hot→A, A→B, B→hot) is only attempted `if best_op is None` — i.e., only after moves, swaps, and 2-for-1 exchanges are exhausted. This yields the richer neighborhood's benefit without paying its scan cost every iteration (execution time stayed at 0.03s).
- **The escalating neighborhood chain (moves → swaps → 2-for-1 exchanges → 3-way rotations) remains the proven refinement stack**: Gen 34 (26.15) first demonstrated rotations add value over the 26.15-tier 2-for-1 configurations; Gen 39 carries it forward atop the randomized multi-start.

## Ineffective Approaches

- **Type inconsistencies between scalar and structured state are a new total-failure mode**: Gen 37 ("greedy_plus_refine_and_second_target", 0.00) crashed on the first test with "'>' not supported between instances of 'float' and 'list'" — comparing a scalar KVPR against a list-structured value (likely a malformed kvprs slice). Like Gens 20/22/23/27, an otherwise-sound greedy + local-search algorithm was reduced to zero by a single bookkeeping/type bug.
- **Multi-start without diversification stagnates below the best**: Gen 40 ("rotation_enhanced_pipeline", 25.55) used the same four orderings plus rotations yet scored *worse* than the 26.15 tier — indicating restart diversity alone caps out, and implementation details (targeting only worst + runner-up, operator ordering) determine whether the richer neighborhood actually pays off. Gen 34's feedback also notes local search targeting only the single hottest GPU "may miss improving moves involving second-tier GPUs."
- **Single-ordering configurations persistently underperform multi-ordering**: Gen 31 (25.83) and Gen 33 (25.83) both used a single greedy order with move/swap/2-for-1 refinement and topped out at 25.83, confirming the ~0.3-point gap that multi-ordering multi-start provides.

## Implementation Insights

- **Gen 39's two disciplined randomization mechanisms are the differentiators**: (1) in the greedy phase, ties within `1e-9` are collected into a candidate list and broken via `rng.choice`, diversifying placements without ever accepting a worse-than-best GPU; (2) in the restart phase, only the first `restart` positions of the sorted list are shuffled (a bounded prefix perturbation), preserving the high-priority heavy-model ordering while diversifying the tail. Both use the same fixed-seed `rng`, keeping results deterministic across runs.
- **The zero-safe `kvpr_of` guard (returning `inf`/`0.0` when `denom <= 0`) is now universal among survivors** — present in Gen 39 and consistently credited since Gen 25. Its absence is a known zero-score crash mode (Gen 20's division-by-zero), and every program in this generation that scored >0 implements it.
- **Atomic best-operation selection with strict-improvement gating (`gain > best_gain + 1e-12`) remains the correctness backbone**: Gen 39 evaluates all candidate moves/swaps/2-for-1/rotation ops against the current worst GPU, applies exactly one confirmed-gain operation with symmetric incremental load/free_mem updates, then rescans from the fresh state. This avoids the simulate/revert drift that killed Gen 27 and the swap-phase crash that killed Gen 22 (`list.remove` by equality).
- **All 32 pipelines in Gen 39 are best-of selection, with graceful infeasibility handling**: a pipeline that cannot place a model returns `(None, inf)` and is skipped; only if all 32 fail does the program raise — consistent with the 100% success rate pattern of every top scorer.

## Performance Analysis

- **Score progression confirms neighborhood richness + start diversity as the two orthogonal quality axes**: single-order + swaps/2-for-1 = 25.83 (Gen 31, 33) → multi-order + 2-for-1 = 26.15 (Gen 34, 35, 36) → multi-order + randomized restarts + rotations = **26.26 (Gen 39, current best)**. Each axis added independently, and Gen 39 shows they compound (+0.11 over the deterministic plateau).
- **Randomization carries a small but acceptable time cost**: Gen 39's 0.03s execution is 3× the 0.00–0.01s of deterministic variants (Gens 30–36), reflecting the 32-pipeline ensemble — still negligible, so score differentiation remains entirely placement quality (max_kvpr).
- **Zero-scores continue to be implementation failures, not algorithmic ones**: Gen 37 (0.00) had a structurally identical algorithm to successful peers but crashed on a float-vs-list comparison, echoing the binary-correctness gating pattern (Gens 20, 22, 23, 27) — one type bug erases all algorithmic merit.
- **Gen 32's reported "combined score 1.00 / max_kvpr 0.00" is a metric-inverted/differently-scaled evaluation run, not a comparable result** — the same anomaly previously seen for Gens 9/15/18; its underlying algorithm (greedy + move/swap/3-cycle) is sound but provides no valid score signal.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Add a 2-for-2 exchange phase after the 2-for-1 scan, gated like the rotation block (`if best_op is None`).** Extend the neighborhood ladder (move → swap → 2-for-1 each added value; 2-for-1 → 3-way rotation added +0.11) with a 2-for-2 exchange: one model from hot for one model from `g`, plus a second model pair, evaluated pairwise `(m1,m2) on hot × (m3,m4) on g` with the same feasibility guards (`src_used <= 0 or dst_used <= 0` skip) and atomic best-op application with symmetric `load`/`free_mem` updates. Keep it lazy (only when cheaper operators stall) so runtime stays near 0.03s.

2. **Tune the restart/perturbation schedule: increase restarts to 16 and vary the prefix-shuffle depth per ordering.** Gen 39's gain came from combining 4 orderings × 8 restarts with bounded prefix shuffling; runtime is still only 0.03s (3× deterministic), so doubling to 64 pipelines is nearly free. Vary the shuffle depth — e.g., use `restart` directly as the shuffled-prefix length scaled by list size (`min(len, restart * 3)`) — so later restarts explore progressively more diversified seeds while early ones stay near the proven greedy order.

3. **Add a second-target refinement phase after the hot-GPU loop breaks.** Gen 40's failure and Gen 34's feedback both note that targeting only the hottest GPU misses moves involving second-tier GPUs. After the main loop exits with `best_op is None`, run a bounded (≤30 iteration) phase with `hot` set to the runner-up GPU (second-max KVPR), accepting only ops that don't raise the global max (gate: `new_max < cur_global_max - 1e-12`), reusing all existing operator blocks unchanged.

4. **Add a lexicographic pair-swap polish phase minimizing the top-2 KVPRs.** After the main loop converges, scan all GPU pairs `(g1, g2)` and model pairs for 1-for-1 swaps that reduce the second-highest KVPR without raising the max — i.e., minimize `(sorted(kvprs)[-1], sorted(kvprs)[-2])` lexicographically. Run as a separate bounded phase (≤20 iterations) with the same atomic apply-then-rescan discipline and index-based list manipulation (never `list.remove` on equality-prone objects) to isolate any bug from the proven main loop.

5. **Widen the tie-breaking epsilon band in the greedy phase from `1e-9` to a small relative threshold.** Gen 39's two randomization mechanisms (epsilon tie-breaking + prefix shuffling) are the differentiators over the 26.15 deterministic plateau; a relative band like `best_kvpr * 1e-7` would allow more genuine near-ties (where placement choice matters most for downstream refinement) into the candidate list while still never accepting a meaningfully worse GPU. Keep the fixed-seed `rng` and route all ratios through the zero-safe `kvpr_of` guard to preserve the 100% success rate.

6. **Guard against Gen 37's float-vs-list crash by adding a type-assertion sanity check on all model-derived state.** Before the local search loop, validate that `load[g]` is always a scalar float and `model.model_size` is numeric per model (e.g., `float(model.model_size)` with an explicit cast), since one comparison bug erased an otherwise-sound program. Explicit casting of `req_rate`, `slo`, and `model_size` to `float` at pipeline entry is cheap insurance for the binary correctness gating that has killed Gens 20, 22, 23, 27, and 37.
