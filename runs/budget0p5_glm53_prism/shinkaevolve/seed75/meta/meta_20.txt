# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **The current best program (Gen 16, "kvpr_greedy_move_swap_search", 25.83) combines three proven elements**: (1) density ordering by req_rate/slo with model_size as a secondary descending tiebreak, (2) greedy best-fit on the GPU minimizing *resulting* KVPR (rate/free-memory after hypothetical placement), and (3) a two-phase local search (single-model moves off the worst GPU, then pairwise swaps) with strict improvement thresholding.
- **Adding a swap phase to move-only local search is a measurable gain.** Gen 16 (moves + swaps, 25.83) and Gen 11 ("add_swap_moves_local_search", 25.83) and Gen 19 ("add_swap_local_search", 25.81) all cluster at ~25.8, while move-only variants (Gen 12: 22.52, Gen 13: 22.44, Gen 17: 23.51) plateau around 22–23.5. Swaps escape local optima that single-model moves cannot.
- **Multi-start over different orderings helps moderately but less than swaps**: Gen 17 ("multi_order_greedy_local_search") tries four orderings and reaches 23.51 — better than single-ordering move-only (22.44–22.52) but below swap-enabled variants (~25.8).
- **Strict memory feasibility with explicit error raising** remains a shared trait of all 100%-success programs; the current best continues this with a `ValueError` when no GPU fits a model.

## Ineffective Approaches

- **Syntax/indentation errors are fatal**: Gen 14 ("seed_perturbation_restarts") scored 0.00 with 0% success purely from a dedented `continue` outside its loop, despite algorithmically sound 15-restart perturbation logic. Restart-based randomization remains unproven — no surviving program validated it.
- **Move-only local search converges prematurely**: Gen 13's feedback explicitly notes its strict-improvement check "may terminate at local optima," explaining its 22.44 score vs. 25.83 for move+swap.
- **Single-model moves only, even across multiple greedy orderings, limit quality** (Gen 17: 23.51) — cases needing swaps between GPU pairs remain unsolved.
- Reaffirming previous insights: unguarded division by zero (Gen 5) remains the only historical total-failure mode; the zero-safe `kvpr` helper pattern is essential.

## Implementation Insights

- **The swap phase in the current best program is correctly implemented**: it recomputes both GPUs' free memory (`free_worst`, `free_g`) *including* the size exchange, skips candidates where either drops to ≤0, and updates all state (placement, free_mem, rate) atomically upon improvement — with `1e-12` epsilon strict-improvement gating to prevent thrashing.
- **Efficient delta evaluation**: like the champion, Gen 18's feedback credits recompute of only the two affected GPUs' ratios plus cached others ("ratios"), keeping 300-iteration searches at 0.00s execution time.
- **Restarts scan from the recomputed worst GPU after each accepted move** (breaking out and re-entering with fresh ratios), the same pattern as the previous champion Gen 6 (22.85) and perfect-scoring Gen 9/15/18.
- **Size-descending tiebreak in the sort key** (from Gen 6, retained in Gen 16) packs large high-pressure models first, contributing to strong greedy seeds.

- **Score progression across generations**: greedy-only 21.89 → greedy + move search 22.34–22.85 → multi-ordering 23.51 → **move + swap search 25.81–25.83 (current best Gen 16)**. The swap phase added roughly +3 points over move-only — the single largest algorithmic gain observed.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Run the full greedy + move + swap pipeline under multiple greedy orderings and keep the best result.** Multi-ordering helped move-only search (Gen 17: 23.51 vs 22.44–22.52), and the swap phase is the single largest gain (+3 points). Wrap the entire `compute_model_placement` body in a loop over 3–4 sort keys (`req_rate/slo` + size tiebreak as current, `req_rate/slo` only, `model_size` only, and density `req_rate/(slo·model_size)`), evaluate max KVPR of each resulting placement, and return the best. Runtime stays at 0.00s, so this is essentially free upside on top of Gen 16.

2. **Extend the swap phase to consider the second-worst GPU as well.** The current swap operator only targets models on the single worst GPU, so improvements requiring an exchange between two non-worst GPUs (e.g., where fixing the new max after a move requires rebalancing mid-tier GPUs) are unreachable. After the worst-GPU swap phase stalls, repeat the move+swap loop with `worst` replaced by the runner-up GPU, using the same `1e-12` strict-improvement gating and atomic state updates. This generalizes the proven swap pattern without new machinery.

3. **Add a cyclic-moves operator (3-way rotation) as a third local-search phase.** Swaps beat moves because they escape pairwise local optima; a bounded 3-GPU rotation (move m1 from worst→A, m2 from A→B, m3 from B→worst) can escape optima that both moves and swaps cannot. Keep it strictly feasibility-checked (all intermediate free memories > 0) and delta-evaluated via cached `ratios` plus only the three affected GPUs, restarting the outer loop on any accepted improvement. Cap candidate depth to keep the O(n³) scan cheap given the observed 0.00s runtime budget.

4. **Add a best-of-N greedy seed perturbation with randomized tie-breaking, guarded by the zero-safe `kvpr` helper.** Gen 14's restart logic was algorithmically plausible but died from a dedent syntax error — reimplement it carefully: when placing a model, among GPUs whose resulting KVPR is within a small epsilon of the best, pick uniformly at random, run the full pipeline N=10–15 times, keep the lowest max KVPR. This diversifies beyond deterministic greedy lockstep at negligible cost, and all ratio computations must route through the existing `kvpr(rate, free)` guard (returning `inf` when `free <= 0`) to preserve the 100% success rate.

5. **Try swap-with-two-models (2-for-1 exchanges) in the swap phase.** The current swap exchanges one model for one, which fails when the worst GPU needs to shed a large model but no single other-GPU model both fits back and balances rate. Extend the swap loop's inner scan to also try replacing one model on the worst GPU with two smaller models from GPU `g` (and vice versa), reusing the exact feasibility pattern — recompute both GPUs' free memory including the size exchange, skip if either drops to ≤0, accept only on strict `1e-12` improvement of the global max. This handles size-vs-rate asymmetries that 1-for-1 swaps provably cannot.
