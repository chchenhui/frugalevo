# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **The current best program (Gen 25, "swap_and_2for1_local_search", 26.15) extends the proven multi-start + move + swap formula with 2-for-1 exchanges** — four greedy orderings (KVPR weight, model size, density ratio, composite tuple), best-fit on resulting KVPR, then up to 60 local-search iterations with moves, 1-for-1 swaps, and 2-for-1 exchanges targeting the max-KVPR GPU. The 2-for-1 neighborhood pushed the score from ~25.8 (Gen 26's move+swap variant, 25.83) to 26.15 — a modest but real gain from a richer exchange neighborhood.
- **Multi-ordering multi-start remains the robust backbone**: Gen 25, Gen 21 ("multi_ordering_pipeline", 23.51), and Gen 29 ("swap_and_second_worst_search", 25.00) all use 4 different sort keys and keep the best pipeline result. Gen 29 confirms that dual-target refinement (worst GPU, then runner-up) also works well.
- **Neighborhood richness correlates with score**: multi-ordering + move-only = 23.51 (Gen 21); + swaps = 25.00–25.83 (Gen 29, Gen 26); + 2-for-1 exchanges = 26.15 (Gen 25, current best). Each neighborhood expansion escaped additional local optima.
- **Zero-safe KVPR computation guards feasibility**: Gen 25's `kvpr_of` returns `inf`/`0.0` when `denom <= 0` — precisely the guard whose absence crashed Gen 20 (0.00, "float division by zero").

## Ineffective Approaches

- **State-tracking bugs in incremental bookkeeping are a recurring total-failure mode**: Gen 27 ("multi_order_greedy_move_swap", 0.00) failed with "GPU memory constraint violated" despite explicit free-memory checks — its incremental `free_mem`/`load` updates (likely swap revert logic) corrupted state. Gen 22 (0.00) crashed in its swap phase via `list.remove(x): x not in list`, showing remove-by-equality is unsafe for mutated/equal-comparing objects.
- **Duplicate function definitions with undefined helpers**: Gen 23 (0.00) shadowed its first `compute_model_placement` with a second definition calling an undefined `_run_attempt` — the entire program failed despite a correct first implementation being present in the same file.
- **Unguarded division at full GPU capacity**: Gen 20 (0.00) crashed because greedy packing could fill a GPU exactly to capacity, dividing by zero free memory. The epsilon/zero-safe guard is mandatory, not optional.
- **Randomized restarts without tie-breaking discipline added no validated gain**: Gen 22's 20 seeded restarts never ran due to its crash; surviving evidence favors deterministic multi-ordering restarts (Gen 25, 29) over randomized ones.

## Implementation Insights

- **Gen 25's atomic best-operation selection is the key correctness pattern**: each iteration evaluates *all* candidate moves/swaps/2-for-1 exchanges with delta KVPR math, picks the single best `best_op` (gated by `gain > best_gain + 1e-12`), applies it once with correct incremental updates, then restarts the scan from the fresh worst GPU. This avoids partial revert bugs that killed Gen 27.
- **2-for-1 feasibility checks mirror the swap logic**: `s2 > free_mem[hot] + s1 or s1 > free_mem[g] + s2` plus `src_used/dst_used > 0` guards — the same ≤0 guard that protects against Gen 20's crash mode.
- **All state mutations in Gen 25 are symmetric and self-consistent** (`load[hot] += w2 - w1; free_mem[hot] += s1 - s2` etc.), executed only after a strict-improvement win is confirmed — unlike Gen 27's speculative simulate/revert flow that allowed drift.
- **Cost of the O(n³) 2-for-1 pair scan is negligible**: execution_time is 0.00s, consistent with prior generations — richer neighborhoods cost nothing measurable at these problem sizes.

## Performance Analysis

- **Score progression by neighborhood**: multi-order move-only 23.51 (Gen 21) → multi-order + swaps 25.00 (Gen 29) → single-order + moves/swaps 25.83 (Gen 26) → **multi-order + moves/swaps/2-for-1 26.15 (Gen 25, current best)**. 1. **Generalize the 2-for-1 exchange to 1-for-2 (one hot model swapped for one model plus splitting): or more precisely, a 2-for-2 exchange phase.** The current neighborhood stops at 2-for-1; extend the scan in the same atomic `best_op` style to exchange two models on the hot GPU with two models on GPU `g` (all pairs `(m1, m2) × (m3, m4)`), reusing the exact feasibility guards (`src_used <= 0 or dst_used <= 0` skip) and symmetric state updates. This is the next step in the proven neighborhood-richness ladder (move → swap → 2-for-1 each added ~+0.3–3 points) and costs nothing at 0.00s runtime.

2. **Add a second-target refinement phase after the hot-GPU loop stalls.** Gen 29 ("swap_and_second_worst_search", 25.00) showed dual-target refinement works: after the move/swap/2-for-1 loop breaks with `best_op is None`, re-run up to 30 iterations with `hot` set to the runner-up GPU (second-max KVPR), accepting ops that don't push any GPU above the current global max (gate on `new_max < cur_global_max - 1e-12`). Reuse all existing operator code — only the target selection and gain reference change.

3. **Add a bounded 3-way cyclic rotation operator.** Moves and swaps can't escape optima requiring a rotation (m1: hot→A, m2: A→B, m3: B→hot). Implement as a fourth candidate block in the same `best_gain/best_op` scan: for each hot model, pick destination `A`, for each model on `A` pick destination `B`, for each model on `B` check it fits `hot`'s freed space; compute the three affected GPUs' new KVPRs with cached ratios, accept on strict `1e-12` improvement. Apply atomically with symmetric `load`/`free_mem` updates exactly like the existing `swap2` branch to avoid Gen 27's drift bugs.

4. **Add best-of-N randomized greedy restarts with epsilon tie-breaking, routed through the zero-safe `kvpr_of`.** During best-fit placement, collect all GPUs whose KVPR is within `1e-9` of the best and choose uniformly at random (seeded RNG for reproducibility); run the full pipeline (all 4 orderings × N=8 restarts) and keep the lowest max KVPR. This diversifies the seeds the local search starts from, and since runtime is uniformly 0.00s, ~32 pipeline runs remain free. All ratio computations must go through the existing `kvpr_of` guard to preserve the 100% success rate.

5. **Add a final pair-swap polish phase across non-hot GPUs.** After the hot-targeted loop converges, scan all pairs of GPUs `(g1, g2)` and all model pairs for 1-for-1 swaps that reduce the *second-highest* KVPR without raising the max — i.e., minimize `sorted(kvprs)[-1]` and `sorted(kvprs)[-2]` lexicographically rather than just the max. Use the same atomic best-op application and symmetric state updates; keep the scan as a separate bounded phase (≤20 iterations) so any bug is isolated from the proven main loop, and never use `list.remove` on equality-compared objects (index-based removal) to avoid Gen 22's failure mode.
