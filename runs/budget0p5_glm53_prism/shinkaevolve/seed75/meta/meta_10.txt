# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns
- **Greedy best-fit with density ordering + local search is the dominant winning pattern.** The current best program (Gen 6, "greedy_resulting_kvpr_plus_local_search", 22.85) and all top-scoring variants (Gen 1, 3, 7, 8, 10 at 1.00/perfect) use: sort by req_rate/SLO descending, greedy placement on the GPU minimizing post-placement KVPR (load/used-memory), then a bounded local-search phase moving models off the worst-KVPR GPU when it strictly reduces the global max.
- **Strict memory-fit validation with explicit error raising** is used consistently by every 100%-success program (Gen 0, 2, 4, 6, 7, 8), guaranteeing feasibility rather than overcommitting memory.
- **Best-fit tie-breaking on *resulting* KVPR** (computing the ratio after hypothetical placement) outperforms simpler load-balancing heuristics, per feedback across Gen 0–10.
- **Bounded, strict-improvement local search** (caps of 20–200 iterations, improvement threshold like `1e-12`) guarantees termination with negligible runtime cost (execution_time 0.00 across all programs).

## Ineffective Approaches
- **Unguarded division by zero memory** caused the only total failure: Gen 5 ("best-fit-placement-with-refinement") scored 0.0 with success_rate 0.00 due to "float division by zero" when a model exactly filled a GPU — the source-side check existed but the destination-side and gpu_kvpr paths lacked protection.
- **Greedy-only (no local search) tops out lower:** Gen 0 (21.89), Gen 2 (22.34), and Gen 4 (22.34) all score below Gen 6's 22.85, showing local-search refinement adds measurable gains (+0.51 to +0.96 over greedy-only).
- **Overwriting/mutating state without reverting simulated moves** is a risk in local search; Gen 7's feedback explicitly credits "reverting simulated moves in-place" for correctness.

## Implementation Insights
- The current best program (Gen 6) adds a secondary sort key `model.model_size` descending within the req_rate/slo ordering, which may contribute to its edge over the otherwise similar Gen 2/4 (22.34) — larger high-pressure models placed first create better packing.
- **Zero-safe KVPR helper**: the best program defines `kvpr(rate, free) = rate/free if free > 0 else inf`, exactly the guard Gen 5 lacked; this is the key robustness fix that all correct programs implicitly or explicitly employ.
- **Local search move evaluation** should recompute only the two affected GPUs' ratios plus cached ratios for others (as in the best program), keeping the search cheap while correctly comparing `new_max < old_max - 1e-12` for strict improvement and guaranteed termination.
- Local search restarts its scan from the (recomputed) worst GPU after each accepted move (`improved=True; break`), matching the pattern in Gen 1/7/10 that achieved perfect scores.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Add swap-based local search (pairwise exchange) after the move-based phase.** The current local search only moves single models; extend it with a swap operator that exchanges one model on the worst-KVPR GPU with a smaller/equal model on another GPU (respecting memory feasibility both ways) when it strictly reduces the global max KVPR. This is a direct extension of the proven bounded, strict-improvement pattern (same `1e-12` threshold and `improved=True; break` restart) and could escape local optima that single moves cannot.

2. **Try multiple greedy ordering variants and keep the best result.** Gen 6's edge over Gen 2/4 likely comes from the `model_size` secondary sort key. Generalize this: run the greedy + local-search pipeline with 3–4 ordering keys (e.g., `req_rate/slo` only, `model_size` only, density `req_rate/(slo·model_size)`, and the current composite), then return the placement with the lowest resulting max KVPR. Runtime stays negligible (~0.00s per all evidence), so this is essentially free score upside.

3. **Insert a seed-perturbation restart loop when the max KVPR is high.** After convergence, if the worst GPU's KVPR exceeds the average by more than some factor, re-run greedy with a randomized tie-break among near-equal best-fit GPUs and keep the best of N (e.g., 10–20) restarts. Restart-from-scratch patterns are what distinguished perfect-scoring variants (Gen 1/7/10) and diversify beyond the deterministic best-fit, which can get stuck in greedy lockstep.

4. **Harden all KVPR computations with the zero-safe helper, including simulated paths.** Gen 5's total failure proves one unguarded division is catastrophic. Add a module-level `kvpr(rate, free)` guard (returning `float('inf')` when `free <= 0`) and route *every* ratio computation — including `new_r_g`, `new_r_worst`, and cached `ratios` — through it. Also wrap the destination check `m.model_size <= free_mem[g]` to skip GPUs where `free_mem[g] == 0` entirely, since inf arithmetic in `max()` can mask infeasible comparisons.

5. **Improve local-search efficiency with a target-driven move filter.** Rather than scanning all models on the worst GPU, precompute the KVPR the worst GPU must shed (`target = max(ratios of others)`), then only consider models whose removal brings the worst GPU below target *and* whose placement on the destination does not push it above target. This preserves the exact strict-improvement acceptance criterion from the champion while pruning the candidate set, enabling a higher iteration cap (e.g., 200) at zero measured runtime cost, potentially finding more improvement moves.
