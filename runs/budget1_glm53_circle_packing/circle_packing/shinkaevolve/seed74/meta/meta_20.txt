# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns
- **LP-based radius optimization at fixed centers remains the decisive foundation**: Every correct LP-based program scores 0.77–0.91, versus 0.17–0.74 for heuristic radii methods. The current best program (`triangular_lattice_plus_hill_climb_lp`, sum 2.40, score 0.91) uses a vectorized sparse CSR `linprog` (HiGHS) — as do Gen-13 (2.36/0.90), Gen-15 (2.37/0.90), Gen-17 (2.36/0.90), and Gen-18 (2.37/0.90), all clustered tightly around 2.36–2.40.
- **True triangular-lattice seeding beats ad-hoc stagger**: The current best computes row spacing g = s·√3/2 and margin r = s/2 so neighboring rows form equilateral triangles (optimal local geometry), and screens multiple row patterns ([5,4,5,4,5,3], [4,5,4,5,4,4], [3,5,4,5,4,5]) × scales (0.98, 1.0). This strict-lattice seeding plus hill-climb achieved the highest sum yet (2.40 vs. the 2.34–2.37 plateau of Gen-8/13/15/18).
- **Randomized hill-climb with multi-circle moves (1–3 perturbed centers) outperforms single-center moves**: The current best perturbs up to 3 circles per step with adaptive step size (shrink ×0.92 on failure with 70% probability, grow ×1.4 up to 0.05 otherwise) — this matches previous feedback that single-center hill-climbs plateau at ~2.34 and directly contributed to the new best 2.40.
- **Greedy fallback retained only as safety, never as the primary path**: The current best seeds `lp_radii` with `compute_max_radii` (proportional shrinking) and only accepts LP output if it improves the sum — this guard prevented the degenerate-fallback collapse seen in Gen-10 (0.00) and kept validity 1.00.

## Ineffective Approaches
- **Buggy LP/pipeline construction still scores 0.00**: Gen-19 (`lp_radii_hill_climb_pipeline`) had "placeholder columns" and redundant `np.minimum.at` code — convoluted index construction broke the LP and the per-iteration full LP re-solve exceeded the budget, yielding 0.00 across all metrics. Same for Gen-3 (`multiscale_hex_relax_constructor`, 0.00): dead-code branches and pressure repulsion with clipping drove radii invalid. LP implementations must be simple and verified.
- **Fixed uniform radii/lattices cap scores early**: Gen-6 (`hex_grid_packing_26`) fixed r = 1/11 for all circles — valid but only sum 0.45 (score 0.17). Uniform radii waste the huge headroom the LP exploits.
- **Conservative annealing and short local searches stall**: Gen-16 (`annealed_radii_maximizer`, 1.95/0.74) used heuristic radius scaling with small move scales; the ~0.9–1.4s time-boxed hill-climbs/annealings (Gen-14, 17) all converge to the 2.36–2.40 plateau, ~10% short of AlphaEvolve's 2.635. Single-row rigid layouts with greedy gradient search (Gen-12, 1.69/0.64) get stuck in poor basins.
- **Redundant computation in the pipeline**: hill-climb re-solves the full LP per perturbation (~1.5s of the 1.46s budget) — effective but the dominant runtime cost; multi-seeding beyond 4 row patterns showed no further benefit in Gen-8.

## Implementation Insights
- **Current best's architecture (clean and minimal)**: (1) `hex_layout` with exact equilateral-triangle geometry parameters; (2) `lp_radii` building a sparse CSR matrix via `np.triu_indices`, filtering d > 1e-9, with pairwise rows (r_i + r_j ≤ d_ij) plus n border rows (r_i ≤ min(x, y, 1−x, 1−y)), c = −ones, bounds (0, None), method "highs"; (3) 0.9s deadline hill-climb with multi-circle Gaussian perturbation and LP re-solve. The greedy `compute_max_radii` fallback is only accepted if the LP fails or underperforms.
- **Vectorized sparse LP assembly is essential for speed**: The current best's CSR construction keeps eval at 1.46s despite ~hundreds of LP solves during hill-climb; Gen-19's non-vectorized/broken assembly timed out entirely. Contrast Gen-12's LP-per-step design at 4.27s — nearly 3× slower for a worse score (0.64).
- **Adaptive step-size scheduling matters**: The current best's stochastic shrink/grow rule (0.92×/1.4×, floor 0.002, ceiling 0.05) escaped local optima better than fixed decay (Gen-1's 0.03→1e-4) — the best-of-cluster result 2.40 vs 2.37.
- **Exact water-filling vs heuristic scaling**: Gen-16's feedback notes heuristic pairwise-shrinking under-estimates maximal radii; the LP guarantee is why all LP programs cluster at 2.36–2.40 while heuristic-based ones scatter at 1.95 and below.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Add slack-directed targeted moves to the hill-climb alongside the isotropic Gaussian.** After each LP solve, compute each circle's slack (d_ij − r_i − r_j for nearest neighbors, and border distance − r_i), then with ~60% probability perturb along the direction of maximum slack instead of a random Gaussian (e.g., 70% of the step along that direction, 30% random). This makes each of the ~300–500 LP re-solves during the 0.9s budget more likely to be accepted, and directly addresses the wasted-evaluation problem identified in the plateau analysis.

2. **Add row-shift and block-shift moves to escape lattice-aligned local optima.** With ~10% probability, translate an entire hex row horizontally by a small delta (±0.005–0.02), and with ~10% probability shift a spatially-coherent cluster (all centers within 0.25 of a chosen one) by a common delta. Since all four refinement strategies plateau at 2.36–2.40, rigid multi-circle rearrangements that preserve local triangular geometry while repositioning whole rows are the most plausible lever to reach toward 2.635.

3. **Restructure the time budget into multi-start of cheap jittered variants followed by long refinement of the winner.** Run 3 starts where the best base layout gets ±0.01 per-center jitter with a 150-step anneal each (~0.25s), then spend the remaining ~1.2s on the winner. Keep the time-based deadline (never fixed step count) and total budget under ~2.5s, exploiting the ~1.5s of unused headroom — but with cheap variants of the strong base rather than diverse layouts, per Gen-8's lesson.

4. **Add temperature-based acceptance with reheating to the multi-circle hill-climb.** Accept slightly worse candidates with probability exp((s_new − s_cur)/T), T decaying from 0.01 to 1e-4 geometrically, with reheat (T reset to 0.01) after ~50 consecutive rejections, capped at 2 reheats. The adaptive step-size rule (0.92×/1.4×) already proved stochastic scheduling beats fixed decay; annealed acceptance is the natural extension and was only previously tried with heuristic radii (Gen-16), never with the exact LP evaluation.

5. **Deduplicate the candidate list and expand it with genuinely different row structures.** The current list contains [5,4,5,4,5,3] twice, wasting one LP solve of the 8-seed screen. Replace with distinct patterns such as [6,5,4,5,6], [4,4,5,4,5,4], [3,4,5,4,5,5], and add scales (0.96, 1.02) — the screen costs microseconds relative to the hill-climb, and AlphaEvolve-level configurations reportedly favor boundary clustering, which denser outer rows (6-count edge rows) would provide.
