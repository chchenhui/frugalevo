# Updated Global Insights

## Successful Algorithmic Patterns
- **The current best (Gen-45, 2.41/0.92, 2.70s) confirms the winning architecture**: sparse CSR-assembled LP radii (via `np.triu_indices` + filtered pairs) + 12 hex row seed patterns × 3 scales + 6-basin slack-directed Metropolis annealing with adaptive steps. This matches the prior round's best (Gen-33/Gen-25, 2.41) and shows the architecture is reproducible at the plateau ceiling.
- **Best-ever tracking + Metropolis acceptance is the distinguishing feature of 2.41 programs**: The best program keeps (bc/br/bt) separate from the current annealing state, so worsening moves accepted for ridge-escape never lose progress. All 2.41–2.42 scores (Gen-45, Gen-47, Gen-33) use this or Metropolis acceptance; pure greedy hill-climbs stall at 2.36–2.40 (Gen-37/38/42/46/48).
- **Greedy pre-screening before LP is a proven runtime enabler but not a score elevator**: Gen-40 (2.39, 4.74s), Gen-46 (2.40, 4.77s), Gen-44 (2.01, 2.56s) all use greedy-then-LP pre-screening — it keeps runtime bounded but every pre-screened variant lands at or below the pure-LP best, confirming prior insight that conservative pre-screen thresholds can reject beneficial moves.
- **LP-based radii remain the universal foundation**: Every correct program this round except Gen-49 uses exact `linprog` radii. Gen-49's joint center-radius L-BFGS-B penalty approach reached only 1.98 — joint continuous optimization of all 78 variables underperforms decoupled "centers free, radii LP-exact" by a wide margin (~0.43).

## Ineffective Approaches
- **Crash-on-exception constructors score 0.00 regardless of design**: Gen-43 (LP-based row-layout, coordinate descent on top-10 layouts) returned zeros on all metrics — a runtime or validation failure masked by broad exception handling, echoing Gen-39/22/31/36 failures. Time-budget and exception discipline remain hard correctness requirements.
- **Overshooting runtime through the budget cap**: Gen-40 (4.74s) and Gen-46 (4.77s) exceeded the ~2.6s target by nearly 2× yet scored no higher (2.39–2.40) than the 2.70s best — extra search time with fixed move sets buys nothing.
- **Fixed lattice templates cap the sum**: All hex-row-seeded programs cluster at 2.36–2.42 across 10+ variants (Gen-40/42/45/46/47/48), confirming the plateau is a seed-template limitation, not a search-time limitation. Gen-32 previously showed enumeration-only reaches only 2.25.
- **Joint gradient-based optimization with penalty annealing underperforms badly**: Gen-49's L-BFGS-B squared-hinge annealing (λ=100→2000) hit only 1.98, and the greedy shrink fallback caps the sum since radii shrink rather than centers densify.

## Implementation Insights
- **What makes the best program effective**: (1) Vectorized sparse LP assembly (`np.triu_indices`, d>1e-9 filter, single CSR matrix) enabling hundreds of LP solves inside 2.0s of annealing; (2) greedy `compute_max_radii` as both LP fallback and initial guess, guaranteeing validity 1.00 even if every LP call fails; (3) shrinking per-start budget `(deadline − now)/(n_starts − start)` with per-start seeded RNG for reproducible basin diversity; (4) adaptive step schedule (×1.15 on success to ceiling 0.05; stochastic 0.92-shrink or 1.4-grow on failure) with slack-weighted move selection `w = max(−scores, 0.01)`.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

# Recommendations for Future Mutations

1. **Add row-shift and cluster-shift collective moves at ~20% probability in the annealing loop.** The 2.36–2.42 plateau across all single-circle variants indicates lattice-aligned local optima per-circle moves cannot escape. With 10% probability translate an entire hex row (centers within 0.02 in y of a randomly chosen center's row) by ±0.005–0.02 horizontally, and with 10% probability shift a spatial cluster (all centers within 0.25 of a chosen center) by a common delta — both preserve local triangular geometry while repositioning rigid groups, and each evaluates through the existing sparse `lp_radii` unchanged.

2. **Jitter each of the 6 annealing basins with ±0.01 Gaussian noise on starting centers.** Currently all starts begin from the exact lattice screen winners, so starts 2–6 often retrace the same trajectory as start 1. After copying `scored[start][1]`, apply `c = c + rng_s.normal(0, 0.01, c.shape)` clipped to [0.005, 0.995] before the climb — a near-free change consistent with evidence that jittered variants of a strong base beat structurally diverse layouts.

3. **Insert a greedy pre-screen before each `lp_radii` call to fund a 7th–8th basin or temperature restarts.** Run `compute_max_radii` (already implemented, microseconds for n=26) on the trial; if its sum is below the current `tot − 0.01`, reject without solving the LP, since greedy rarely underestimates the LP by more than that margin for small perturbations. This roughly halves LP calls inside the 2.0s budget, freeing time to add basin starts from lower-ranked screen candidates or restart temperature `T` from 0.004 when a basin stalls at its best (`bc/br`).

4. **Add denser-edge and mirrored row templates to the candidate screen.** Gen-25's gain came from seed breadth, and the current 12 templates miss boundary-heavy structures closer to the AlphaEvolve 2.635 regime. Add `[6,5,5,5,6]`, `[6,5,6,5,4]`, `[5,6,4,6,5]`, and vertical mirrors of the current top-3 scoring rows — each costs only 3 LP solves (one per scale) in the screen since the sparse assembly already handles arbitrary configurations.

5. **Include 2–3 free-form (non-lattice) seeds among the multi-start basins to attack the plateau's structural origin.** Every correct program this round optimizes within hex-row templates, and the persistent ~0.22 gap to 2.635 likely requires non-lattice structures. Add boundary-clustering layouts (e.g., 26 centers placed near walls and corners at varied distances, then interior-filled), score them with the same `lp_radii` in the screen, and admit top free-form scorers into the `n_starts` basin rotation so the existing Metropolis annealing refines them identically to lattice seeds.

6. **Track best-ever per circle *and* per move type to bias future moves.** Extend the best-ever tracking (`bc/br/bt`) with a lightweight histogram of which move types (slack-directed vs. Gaussian vs. collective) produced accepted improvements in the last 50 iterations, then adjust the 0.75/0.25 split adaptively toward the historically productive type. This builds directly on the best program's distinguishing feature — best-ever tracking separated from annealing state — and costs only a few counters per iteration.
