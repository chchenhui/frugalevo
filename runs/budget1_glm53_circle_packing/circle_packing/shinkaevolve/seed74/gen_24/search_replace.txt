The hill-climb converges quickly (since_gain restart after 60), so 300 steps is more than enough per layout. We should instead screen many more distinct seed geometries cheaply using fast_radii, and only run the full LP hill-climb on the top 2-3. Since local search dominates runtime, screening 10-15 seeds with fast_radii costs microseconds and lets us pick genuinely better starting basins. Distinct row structures like [6,5,4,5,6], boundary-heavy variants, and vertical/y-scale variations (0.96, 1.02) explore different local optima — AlphaEvolve's best n=26 packings favor dense boundary rows with a hexagonal core. This increases multi-start diversity without increasing runtime much, which should push sum_radii above 2.37.
