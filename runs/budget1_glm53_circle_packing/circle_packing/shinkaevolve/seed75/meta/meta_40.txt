# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Hex-lattice seeds + Gauss-Seidel water-fill + greedy shift search remain the proven core**: Gens 35, 37, 39 all hit 2.47–2.48 / 0.94 at 0.33–0.68s, and the current best (Gen 41, `relocate_shift_refine_twice`) pushes this to 2.49 / 0.94 by adding an iterate refine–shift fixed-point loop (3 rounds of grow/relax/compact refinement followed by fine-delta shift search, always keeping the best-scoring layout).
- **Alternating global relaxation between shift-search passes breaks single-pass plateaus**: Gen 41's key addition — after the shift search plateaus, re-run `_refine` (250 iterations of penetration-proportional forces with compaction) so coordinated multi-circle moves unlock further fine shifts — produced the marginal gain from 2.48 → 2.49 over Gens 35/37. However, the gain is small (0.01) at high cost (9.07s vs 0.27–0.33s).
- **Monotone-repair radius solving (`compute_max_radii`) is the reliability backbone**: every correct program in this batch (Gens 31–33, 35, 37–39, 41) uses Gauss-Seidel water-filling plus shrink-only pairwise repair; all achieved validity 1.00. The 1e-6/1e-9 safety shrinks in Gens 31, 33, 39 consistently guarantee strict constraint satisfaction.
- **Diagonal moves in shift search add nothing measurable**: Gen 37 (`add_diagonal_moves_to_shift_search`, 2.48, 0.68s) scores identically to Gen 35 (axis-only, 2.48, 0.33s) — the lattice basin is move-set-insensitive.

## Ineffective Approaches

- **Naming/robustness bugs zero out heavy pipelines entirely**: Gen 36 (`dual_seed_best_of_two`) failed with all metrics 0.00 because `construct_packing` called `_seed_centers` while the function was named `_seed_corners` — a NameError killing the whole run. Gen 38's population + force-relaxation scored only 1.55 / 0.59, reconfirming that penetration-proportional repulsion as the primary driver (vs. a tight lattice + shift search) collapses toward sparse layouts.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Warm-start `compute_max_radii` inside the shift search to recover the ~30x runtime gap**: Pass the previous radii vector `r_prev` into the solver and use it as the Gauss-Seidel initialization (cap = min(wall, min_j(D_ij − r_prev[j]))), skipping the pairwise-repair pass when the candidate is rejected via an early-exit sum check. Gen 41's 9.07s is entirely cold-start cost (26 circles × 12 directions × 5 deltas × 3 outer rounds of full 300-sweep solves); warm-starting should bring the refine–shift fixed-point loop under ~1s while preserving the 2.49 score, and the freed budget can fund more outer rounds (cap 6–8 instead of 3).

2. **Activate the dormant `_make_seeds()` multi-start with best-of-K selection**: The function is already defined (7 lattice patterns, corner seed, Halton seed) but never called. Run the cheap pipeline (solve → one `_refine` → one fine-delta shift pass) on each of the ~25 seeds, keep the top 2 by solved sum, then run the full Gen 41 refine–shift fixed point on only those. Gen 33 showed corner-anchoring hurts as the *only* seed, but as one candidate among many under strict best-of selection it costs nothing and may break the 2.48–2.49 lattice-basin plateau that six different pipelines have failed to escape.

3. **Sweep the stagger offset per adjacent row pair**: The seed hard-codes horizontal spacing s = 0.2 for all rows; instead parameterize per-row offsets dx ∈ {0.09, 0.10, 0.11} (allowing alternating tight/loose staggering) and triage each combination with one cheap solve + single shift sweep, fully refining only the best 2. This generalizes the confirmed staggered-row family within the warm-start budget and targets wall/corner slack that axis shifts alone cannot reach.

4. **Add a best-improvement (rather than first-improvement) acceptance rule to `_local_shift_search`**: Currently the first improving move in the 12-direction list wins; instead evaluate all 12 candidates per circle per delta and apply the single best one (or the best 2–3 jointly). First-improvement greediness can take a sideways move that blocks a better diagonal one; best-improvement costs the same number of solve calls with warm-starting and historically helped Gen 41 escape single-pass plateaus via better move selection.

5. **Wrap the entire `construct_packing` in a try/except fallback to the proven Gen 35 pipeline**: Both 0.00 failures (Gens 34, 36) came from unsandboxed complexity (NameError, invalid radii) with no fallback. Before adding the multi-seed machinery above, guard it: `try: <new multi-start path> except Exception: <single-seed Gen 35-style path>`, and validate the final radii vector (all r ≥ 0, r_i + r_j ≤ d_ij, r_i ≤ wall) with a shrink-only repair before returning. This guarantees new mutations can score no worse than the 2.48–2.49 baseline regardless of internal bugs.
