# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Gauss-Seidel maximal radius growth** (Generation 8, "staggered_rows_gauss_seidel", sum=2.47, score=0.94): the current best replaces lossy proportional pairwise shrinking with a per-circle maximization loop — each radius takes the maximum value allowed by current neighbor radii and walls. This was the key upgrade over identical-layout predecessors (Generation 4's proportional shrinking scored only 1.59/0.60 on the same 4-5-4-5-4-4 lattice).
- **Fixed-point lattice sizing**: solving `r = sqrt(dy² + dx²)/2` together with the wall constraint `2r + 5·dy = 1` lets the lattice exactly fit the square (Generation 8, Generation 1's "hex_lattice_layout_26" at 2.44). Exact-fit spacing consistently beats arbitrary spacing (Generation 3's s=0.225 uniform spacing collapsed to 1.24).
- **Water-filling / LP-style exact radius solvers**: Generation 7's Gauss-Seidel water-filling (2.45) and Generation 9's scipy `linprog` radius solve (2.21) confirm the radius solver itself is near-optimal for given centers — feedback repeatedly notes the solver is not the bottleneck.
- **Pressure-based relaxation of positions** (Generation 7: 2.45; Generation 6: 1.84) shows moderate gains over rigid seeds, especially combined with a strong final radius pass.

## Ineffective Approaches

- **Proportional pairwise shrinking of radii**: uniformly scaling both radii of a violating pair shrinks them below feasible levels. Generation 3 (1.24) and Generation 4 (1.59) both used it; Generation 0's greedy variant scored only 0.96. Gauss-Seidel/water-filling on the same layouts nearly doubled the sum.
- **Rigid symmetric ring layouts**: Generation 0's concentric rings (sum=0.96) wasted the interior; symmetric hex lattices with uniform radii also cap performance (Generation 2: 2.17 by dropping 2 of 28 lattice circles without re-optimizing).
- **Truncating an over-provisioned lattice**: Generation 2 built 28 positions at r=1/12, dropped 2, leaving unexploited slack (2.17 vs 2.47).
- **Syntax errors from careless merging**: Generation 11's multi-start LP pipeline scored 0.00 solely due to a stray `=======` merge-conflict marker — an otherwise promising best-of-7 approach never ran.
- **Weak relaxation parameters**: Generation 6's 1.03 inflation factor and learning-rate floor of 0.02 limited growth (1.84 despite 400 iterations).

## Implementation Insights

- The current best program's structure is instructive: **separate the layout constructor (`build_hex_rows`) from the radius solver (`solve_radii`)**, with a precomputed pairwise distance matrix and early-stopping (`<1e-14` change) on the Gauss-Seidel loop — yielding fast 0.13s evaluation and validity 1.00.
- Wall-distance initialization (`r_i ≤ min(x, y, 1-x, 1-y)`) as an upper bound before pairwise refinement guarantees feasibility by construction across all top performers (Generations 1, 7, 8, 9).
- Convergence speed matters: Generation 8 runs in 0.13s vs Generation 7's 0.45s and Generation 6's 1.43s — the fixed-point lattice avoids expensive iteration loops while matching near-best quality.
- Multi-start diversity (Generation 11, Generation 9) is architecturally sound — but only if the code actually parses; the multi-start + exact LP combination remains untested.

## Performance Analysis

- Score trajectory across generations with hex lattices: 2.17 → 2.44/2.47 as spacing changed from uniform r=1/12 truncation to fixed-point exact-fit sizing, confirming that exact-fit lattice geometry adds ~0.3 to the sum.
- The dominant score differentiator is the **radius solver**, not the layout: identical 4-5-4-5-4-4 lattices scored 1.59 (proportional shrinking, Gen 4) vs 2.47 (Gauss-Seidel, Gen 8) — a +55% gain from the solver alone.
- Best results cluster at 2.44–2.47 (Generations 1, 7, 8, all score ~0.93–0.94), with the AlphaEvolve reference of 2.635 ~7% above. All feedback consistently identifies **center placement** (irregular, non-symmetric, mixed-size-aware, e.g., larger circles in corners) as the remaining headroom, not the radius computation.
- Validity was 1.00 for every program that ran, so correctness is not a differentiator except for the syntactically broken Generation 11 (0.00) — merge hygiene is a cheap failure to avoid.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Add position perturbation (perturb-and-resolve) on top of the Gauss-Seidel solver.** Keep `build_hex_rows` and `solve_radii` exactly as-is, but after solving, iteratively move each center away from its tightest neighbor or nearest wall by a small step proportional to its "pressure" (r_i - available slack), then re-run `solve_radii`. Evidence: Generation 7's pressure relaxation combined with a strong radius pass scored 2.45, and feedback consistently identifies center placement — not the radius solver — as the remaining headroom toward the 2.635 reference.

2. **Try a corner-aware mixed-size layout variant.** Modify `build_hex_rows` to place larger circles near the four corners (where wall constraints allow three-sided slack) and smaller circles in the interior, e.g., by shifting the first/last row's end circles toward corners (x near r) and letting the Gauss-Seidel solver naturally give them larger radii. All current top programs use symmetric layouts that waste corner space; the fixed-point exact-fit trick showed that geometry changes of ~0.1 in spacing yield +0.3 in sum.

3. **Implement multi-start layout search with the current solver, but with strict merge hygiene.** Generate 5–10 layout variants (different row counts like 5-5-5-5-4-2, different staggers, jittered seeds), run the fast 0.13s Gauss-Seidel `solve_radii` on each, and return the best. Evidence: Generation 11's multi-start approach was architecturally sound but scored 0.00 from a stray merge-conflict marker — re-implement it cleanly; with the current solver's speed, 10 starts cost ~1.3s total.

4. **Generalize the fixed-point lattice sizing to arbitrary row patterns.** Parameterize the constructor with row sizes (n_1, ..., n_k) and horizontal spacing s, then solve the joint fixed point `r = sqrt(dy² + (s/2)²)/2`, `2r + (k-1)dy = 1`, `n_j·s + gap-to-walls = 1` per row. Sweep over candidate patterns (e.g., 5-4-5-4-5-3, 6-4-6-4-6, 7-row lattices) to find the best exact-fit geometry, since exact-fit spacing consistently beat uniform spacing by ~+0.3.

5. **Add a final greedy "growth pass" after Gauss-Seidel convergence.** After the solver converges, attempt small center shifts for each circle (e.g., ±0.005 in x/y, one circle at a time), keep any shift that increases the total sum after re-solving, and repeat until no gain. This is a cheap local-search extension of the proven solver-only-optimization pattern (solver upgrade alone gave +55%), directly targeting the identified headroom in irregular center placement while preserving guaranteed feasibility via the wall-bounded initialization.
