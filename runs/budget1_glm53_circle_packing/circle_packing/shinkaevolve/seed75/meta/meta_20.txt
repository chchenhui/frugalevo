# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Single well-tuned staggered-lattice seed + greedy local shift search is the current best recipe** (Generation 17, "single_hex_seed_plus_local_shift_search", sum=2.48, score=0.94, 2.94s). Its rows-of-5,4,5,4,5,3 layout with wider-than-optimal spacing (s=0.2, last row 0.3) outperformed all hill-climbing/LP variants in this batch.
- **Gauss-Seidel water-filling radius solver remains the strongest radius engine**: the best program uses `compute_max_radii` with a monotone shrinking repair pass plus a final `_greedy_enlarge` pass — matching the prior best pattern (Gen 8, 2.47). Gen 13's same seed family with this solver reached 2.28; adding the greedy shift search raised it to 2.48.
- **Corner-aware and growth-hole lattice tricks help modestly**: Gen 18's corner-aware 5,4,5,4,5,3 layout with LP radii hit 2.32; Gen 10's exact-fit spacing plus 400 hill-climb iterations hit 2.44. But these all plateau below 2.48 — the grow/relax + local-shift pipeline is more effective per effort.
- **Exact LP radius solving is reliable but not a differentiator**: LP-based radius solving appears in Gens 5, 10, 14, 15, 16, 18 with scores 0.76–0.93, confirming the solver is never the bottleneck.

## Ineffective Approaches

- **Local hill-climbing around symmetric lattice seeds stalls**: Gen 14 (corner pushes + jitter, 2.13), Gen 16 (wall-escape moves, 2.25), Gen 18 (4-restart, 300 iterations, 2.32) — all plateau below the 2.44–2.48 achieved by gentler methods, and Gen 18 cost 6.49s in per-iteration LP solves.
- **Rigid lattice without center optimization caps hard**: Gen 5 (LP radii on fixed lattice) and Gen 12 (fixed-point relaxation, no position moves) both scored 2.00/0.76 — radius-only optimization on a fixed symmetric lattice cannot exceed ~2.0–2.1.
- **Pure pressure-perturbation without a strong solver collapses**: Gen 19's pressure-directed relief with proportional pair-shrinking scored 1.59/0.60 despite 0.14s runtime — the lossy proportional shrinking (known from Gen 4) is again the failure point.
- **Defined-but-unused multi-start code wastes potential**: Gen 17 defines `_make_seeds` (7 lattice patterns, corner-anchored, Halton) but never calls it — the score is capped by the single seed family; feedback suggests actual multi-start diversification could push past 0.94. Also recall Gen 11's 0.00 from a merge-conflict syntax error: dead/divergent code is a persistent hazard.

## Implementation Insights

- **The best program's three-stage pipeline works because each stage has a clear role**: `_refine` (250-iteration force-based grow/relax/compact with decaying steps) handles position quality; `_local_shift_search` (4 delta scales 0.01→0.001, greedy axis shifts) extracts remaining slack; `compute_max_radii` + `_greedy_enlarge` maximizes radii. Runtime stays at 2.94s with validity 1.00.
- **Monotone repair guarantees feasibility**: capping by wall distance (`min(x, y, 1-x, 1-y)`), then only shrinking radii in the repair pass, gives validity 1.00 by construction — a pattern shared by every top performer.
- **Incremental greedy shifting beats per-iteration LP re-solves**: Gen 17's delta-tuning approach (2.94s) vs Gen 18's LP-per-iteration (6.49s) shows water-filling + light local search is far cheaper per improvement, though the tiny deltas are flagged as the main runtime cost with diminishing returns.
- **Wider-than-optimal seed spacing pays off**: Gen 17 deliberately uses s=0.2 (looser than the fixed-point optimum) so sparse rows can grow larger radii — an alternative to exact-fit sizing (Gen 8's fixed-point `2r + 5·dy = 1`).

## Performance Analysis

- **Score trajectory across the batch**: 1.59 (Gen 19, proportional shrinking) → 2.00 (Gens 5, 12, rigid lattice) → 2.13–2.25 (Gens 14, 15, 16, LP + hill-climb) → 2.28 (Gen 13, multi-start grow-relax) → 2.32–2.44 (Gens 18, 10) → **2.48 (Gen 17, current best)**. The best is only ~6% below AlphaEvolve's 2.635.
- **Position optimization adds ~0.2–0.3 over radius-only**: rigid-lattice radius optimization caps at ~2.0; adding any center movement (refine, shift search, hill-climb) lifts to 2.3–2.5. Beyond that, local moves plateau — all feedback points to globally asymmetric layouts (large corner circles, mixed sizes) as the remaining ~0.15 headroom.
- **Runtime vs score trade-off**: Gen 19 (0.14s, 1.59) and Gen 5 (0.51s, 2.00) show speed without search quality is worthless; Gen 18 (6.49s, 2.32) shows expensive search without good structure is also inefficient. Gen 17 (2.94s, 2.48) and Gen 8 (0.13s, 2.47) balance both.
- **Consistent ceiling at ~2.45–2.48 for lattice-family seeds**: four programs cluster there (Gens 8, 10, 13→17), strongly indicating the lattice basin — not the solver or search intensity — is the binding constraint toward 2.635.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Activate the dormant `_make_seeds` multi-start by wiring it into `construct_packing`**: run the current pipeline (`_refine` → `_local_shift_search` → `compute_max_radii` → `_greedy_enlarge`) on each of the ~10 seeds (use fewer `_local_shift_search` delta scales, e.g. only 0.005 and 0.001, to stay within budget), keep the best. The current program defines but never calls `_make_seeds`; with the solver at 0.13s, 5–8 full starts fit in ~4s and could break the 2.48 lattice-basin ceiling that feedback explicitly attributes to the single-seed design.

2. **Add a corner-anchored seed with deliberately asymmetric large-corner circles**: build a variant where 4 circles start near corners (e.g., at (0.09, 0.09) etc.) and let the grow/relax loop pull interior circles away, so the water-filling solver assigns large radii to corner circles (three-sided wall slack). Gen 18's corner-aware variant hit 2.32 with weaker search; combined with Gen 17's refine+shift pipeline, asymmetric corner growth is the identified path to the remaining ~0.15 headroom toward 2.635.

3. **Insert an asymmetric one-shot "spreading" pass before `_local_shift_search`**: after `_refine`, push each circle along the direction that maximizes its distance to its nearest neighbor and nearest wall simultaneously (weight walls by corner proximity), then re-run the shift search. This escapes the symmetric local optimum that greedy ±0.01 axis shifts alone cannot, addressing the plateau at 2.45–2.48 shared by Gens 8, 10, 13, 17.

4. **Sweep the seed parameters (s, row_counts, last-row spacing) around the current optimum**: the current best uses s=0.2 with rows 5,4,5,4,5,3 and last-row spacing 0.3; since wider-than-optimal spacing was key, test s ∈ {0.18, 0.19, 0.21, 0.22} × patterns like [5,4,5,4,5,3], [4,5,4,5,4,4], [3,4,5,5,4,3,2] using only the fast solver (no refinement) for triage, then fully refine the top 2. This is a cheap, guaranteed-not-worse generalization of the successful exact-fit/wide-spacing insight.

5. **Speed up `_local_shift_search` via incremental evaluation to enable more search**: currently each candidate shift re-solves all 26 radii from scratch (300 Gauss-Seidel iterations × 4 deltas × 2 signs × 26 circles × sweeps). Instead, cache the radius vector and warm-start the solver from the previous solution (radii converge in a few passes after a 0.001 shift), then spend the saved ~1–2s on a fifth finer delta scale (0.0005) or a second shift-search round after `_greedy_enlarge`, extracting the slack the feedback says remains in tiny-delta moves.
