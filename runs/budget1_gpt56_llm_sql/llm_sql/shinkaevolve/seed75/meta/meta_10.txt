# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Non-mutating serialization plus positional reconstruction is the dominant correctness pattern.** The current best, **Constraint-Aware Prefix Cache Reorderer** (Generation 1), achieved the top combined score of **0.72**, full validation success, and only **2.53 s** runtime by converting values to strings solely for scoring while retaining original values for output. This same safety principle appears in Generations 3–8, all of which passed validation, unlike Generation 0’s dtype-corrupting reconstruction.

- **Frequency-weighted global column ordering is consistently effective.** The best program computes both repeated-value rank  
  `sum(len(value) * count * (count - 1))`  
  and an alternate `sum(len(value) * count * count)` rank, then evaluates both legal constrained orders by exact trie/LCP score. This produced hit rates of **0.794, 0.624, 0.826, 0.444, 0.834**. The related Generation 3 and Generation 6 variants reached **0.71**, confirming that repetition-aware global ordering is a strong baseline.

- **Constraint-aware unit construction preserves validity without materially sacrificing score.** The current best uses union-find merge groups, keeps merged columns contiguous, and applies deterministic topological ordering for one-way dependencies. Its **0.72** score is slightly above the **0.69–0.71** range of other correct constrained implementations, showing that handling constraints as units before ranking is effective.

- **Exact candidate selection by serialized trie/LCP score works better than relying on one heuristic.** The current best explicitly scores frequency, alternate-frequency, and—only when unconstrained—conditional candidates. This safeguards against a ranking heuristic being favorable in one distribution but poor in another, and likely contributes to its edge over the otherwise similar **0.71** programs.

## Ineffective Approaches

- **Rebuilding DataFrames from generic Python row lists without dtype preservation is invalid.** Generation 0, **Recursive Value-Grouping DataFrame Reorderer**, scored **0.00** and failed every successful-run measure because `.values.tolist()` reconstruction and asynchronous writes allowed timestamp-like strings/integers to be assigned into inferred incompatible columns. The evaluator specifically identified an `int64` assignment `TypeError`.

- **Using unsupported pandas factorization inputs prevented evaluation entirely.** Generation 2, **Prefix-Cache Dataframe Reordering**, also scored **0.00** because it passed a Python `list` to `pd.factorize(values, sort=False)`. On the evaluator’s pandas version, factorization required an `np.ndarray`, `pd.Index`, or `pd.Series`. Its algorithm could not be assessed because the candidate-construction path crashed before validation.

- **More expensive bounded conditional-search variants did not improve aggregate performance.** Generation 5 achieved only **0.69** while taking **34.73 s**, substantially slower than the current best’s **2.53 s** at **0.72**. Generation 7 likewise reached **0.71** but took **17.79 s**, and Generation 4 reached **0.71** in **11.42 s**. The evaluated data does not show that more elaborate conditional logic translated into a better combined score.

- **Conservative or limited conditional strategies leave hard workloads unresolved.** Correct programs repeatedly retained a weak fourth hit-rate case: **0.4444** for the current best and approximately **0.444–0.4444** for Generations 3–8. Generation 9’s more conservative adaptive approach did worse overall (**0.56**) and fell as low as **0.118** in some scenarios, indicating that merely limiting search or retaining mostly global orders can sharply reduce effectiveness on certain data distributions.

## Implementation Insights

- **The current best separates optimization representation from output representation.** `strings_by_column` is used for counting, serialization, and LCP scoring, whereas `source_values = df.astype(object).values.tolist()` is used only at final materialization. Constructing the result with `dtype=object`, original labels, and `df.index.take(row_order)` avoids the type-inference failure seen in Generation 0 while preserving values, shape, and index metadata.

- **The best program uses cheap, bounded primitives that fit its runtime result.** It scans each column once to build string values and frequency counts, computes only two global constrained orderings, and caps conditional partitioning to **48 candidate columns**, **12 depth**, and **256 nodes**. This bounded design achieved the best reported runtime, **2.53 s**, versus **8.68–34.73 s** for comparable correct approaches.

- **Constraint handling is embedded in order generation rather than retrofitted afterward.** `_constraint_units` first unions merged positions, orders positions within each block by rank, maps dependencies onto units, then topologically emits units. This avoids breaking merge adjacency or one-way dependency requirements when optimizing columns, matching the evaluator’s full validation result.

- **The exact objective is evaluated on the same serialization later used for row sorting.** For each candidate, the program concatenates values in that row’s proposed order, computes `_trie_score` as adjacent-LCP reuse after lexical sorting, then uses that same serialization to produce a deterministic stable row order. This direct alignment between candidate scoring and final ordering is a likely reason the simpler Generation 1 implementation slightly exceeds the other valid variants.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Add a small constrained-order candidate set beyond the two current frequency ranks.** Keep the existing `count*(count-1)` and `count*count` unit ranks, but also generate constrained orders using metrics such as repeated-byte mass `sum(len(v) * count)` for duplicated values and a normalized repetition score such as `sum(len(v) * count*(count-1) / max(1, distinct_count))`. Materialize each through `_constraint_units` and select by the existing exact `_trie_score`; this extends the best program’s successful “cheap heuristics plus exact selection” pattern without introducing expensive search.

2. **Make conditional prefix ordering constraint-safe instead of disabling it whenever constraints exist.** Run `_conditional_orders` over merge units rather than individual columns: choose and append whole units, preserve each unit’s internal ordering, and only allow a unit when all predecessor units have already been emitted for that row’s prefix. This directly targets the persistent weak fourth workload while retaining merge adjacency and one-way dependency validity, potentially recovering conditional-order benefits on constrained inputs.

3. **Improve serialization to avoid ambiguous concatenation boundaries.** Replace raw `"".join(...)` serialization with an injective, length-delimited encoding such as `f"{len(value)}:{value}"` per value, preferably cached once per column. The current approach aligns scoring and sorting successfully, but unseparated values can collide—for example `["ab", "c"]` versus `["a", "bc"]`—so boundary-safe strings should make trie/LCP candidate selection better reflect the actual ordered-cell sequence.

4. **Add a bounded local-improvement pass over global constrained units.** After constructing each topological unit order, test a limited number of legal adjacent swaps or legal insertion moves among incomparable units, accepting only moves that improve the exact serialized trie score. Cap the search tightly—for example, evaluate at most 16–32 neighboring legal moves—so it remains close to the current 2.53-second runtime while addressing cases where independent high-frequency units interact poorly in simple rank order.

5. **Make conditional candidate generation adaptive to estimated upside rather than always using fixed limits.** Before invoking `_conditional_orders`, estimate whether row subsets are likely to benefit by measuring how much repeated-value mass remains after the first global unit/column; skip it for low-repetition data, but permit somewhat deeper partitioning or more than 48 candidates for high-repetition inputs. This preserves the successful bounded-runtime design while allocating additional search only to distributions where global ordering is least likely to resolve the shared low-hit-rate case.
