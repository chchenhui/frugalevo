# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **The current best combines a small, diverse candidate set with exact final scoring.** The current best program, **Prefix-Cache Dataframe Reordering (Generation 2)**, achieved the top validated combined score of **0.73** at **7.36s**. It constructs exactly three complete layouts—pair-frequency global, squared-length alternate global, and bounded conditional—and evaluates each using `_score_strings` on the fully serialized rows. This evaluator-aligned final selection is the clearest advantage over most later constraint-aware variants, which reached only **0.67–0.72** despite similar broad strategies.

- **Repeated-value ranking plus a bounded conditional partition remains the most effective search structure.** Generation 2 ranks merge-aware units using  
  `Σ len(value) * count * (count - 1)`  
  and uses a squared-length version as a materially different alternate candidate. Its conditional tree chooses locally repeated units, partitions rows by unit value, and then completes each row’s ordering with a ranked dependency-safe tail. This yielded strong hit rates of **0.7941**, **0.8255**, and **0.8428** on workloads 1, 3, and 5.

- **A tightly bounded conditional search can retain quality while avoiding the cost of heavier variants.** The best program limits conditional selection to the top **24** units and depth **12**. This is substantially more efficient than broader or more expensive related implementations: Generation 12 took **31.71s** for **0.70**, Generation 13 took **38.33s** for **0.69**, and Generation 15 took **84.58s** for **0.67**. The evidence supports the current best’s bounded hybrid rather than deeper or more elaborate conditional exploration.

- **Constraint-safe ordering can coexist with strong performance when constraints are handled at the unit level.** The current best uses contiguous merge units and a score-prioritized stable topological ordering for one-way dependencies. Later programs confirm that this basic safety mechanism is robust: Generation 10 and Generation 17 both achieved **0.72** with full correctness, and Generation 17 did so in only **2.87s**. The successful common pattern is treating merges/dependencies as ordering restrictions, not altering cell values.

## Ineffective Approaches

- **More expensive conditional machinery did not improve the score over the current best.** Generation 15’s factorized-value recursive partition approach with a **128-node** budget was correct but scored only **0.67** and required **84.58s**. Generation 13 similarly used conditional/global comparison but reached only **0.69** in **38.33s**. These results indicate that expanding conditional search budgets or infrastructure did not produce better evaluator-selected serializations.

- **Constraint-aware variants generally matched but did not exceed the best three-candidate design.** Generations 10, 14, 17, and 18 each achieved **0.72**, narrowly below Generation 2’s **0.73**. Their implementations included union-find merge grouping, topological repair, trie/LCP candidate evaluation, and row-specific conditional layouts, but none showed a benchmark-level breakthrough. The extra constraint-oriented logic is valuable for correctness, but it did not by itself yield a higher cache-hit outcome.

- **The shared conditional-frequency heuristic consistently fails on one benchmark.** Generation 2 has a workload-4 hit rate of **0.444443**. Every later validated program remains at approximately the same level: Generation 10 reaches **0.444**, Generation 11 reaches **0.444**, Generation 17 reaches **0.4444**, and Generation 18 reaches **0.4444**. Because this floor persists across different implementations, it is a limitation of the common repeated-value/prefix-partition approach on that distribution rather than a defect in one program.

- **Runtime growth has not correlated with score improvement.** The slowest successful variants—Generation 15 (**84.58s**, **0.67**), Generation 13 (**38.33s**, **0.69**), and Generation 12 (**31.71s**, **0.70**)—all underperformed the current best at **7.36s**. Even the fast Generation 17 (**2.87s**) and Generation 18 (**3.40s**) reached **0.72**, showing that efficiency is possible, but added compute alone has not translated into better candidate quality.

## Implementation Insights

- **Generation 2’s separation of source values, scoring strings, and order metadata is central to both correctness and optimization.** It snapshots original values through `df.to_numpy(dtype=object, copy=True)`, generates temporary normalized strings with `fillna("").astype(str)`, and separately maintains `best_orderings`. This safely handles mixed types and missing values while allowing evaluator-compatible serialization scoring. All successful later programs preserve this principle; it directly avoids the inherited-dtype reconstruction failure documented for Generation 0.

- **The exact final objective is implemented efficiently enough to be practical.** `_score_strings` lexicographically sorts candidate serialized rows and sums adjacent LCP lengths, using binary search and C-level slice comparisons rather than Python character loops. This makes it feasible to score all three complete constructions exactly under the proxy objective. The later programs also frequently use trie/LCP evaluation, but the current best demonstrates that a small number of strongly differentiated candidates is enough to outperform larger heuristic portfolios.

- **The current best uses unit-level serialization, so merge constraints affect both ranking and conditional splitting correctly.** For each merged unit, it concatenates member-column scoring strings before calculating repeated-value rank. Consequently, pair scores, alternate scores, and conditional partitioning all operate on the actual indivisible output unit. This is more coherent than scoring columns independently and repairing the final order afterward, because merge-contiguous output affects the serialized prefixes being optimized.

- **The conditional routine is a controlled prefix-construction algorithm rather than a general permutation search.** `split_group` chooses only currently dependency-eligible units, scores repeated values within the current row group, partitions rows by the selected unit’s serialized value, and fills the remainder with `tail_order`. This explains why Generation 2 captures meaningful row-specific gains without the large runtimes seen in deeper recursive alternatives. It also preserves deterministic behavior through unit-index tie-breaking and ranked topological tail completion.

Improvements therefore come from modest gains on the other four workloads, especially repeated-value-friendly cases, rather than from solving the hardest distribution.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Add 2–4 cheap global rank families and retain exact `_score_strings` selection across the expanded portfolio.** Keep the current pair-rank and squared-length rank, then add variants such as `len(v) * count(v)^2`, `len(v)^2 * count(v) * (count(v)-1)`, and a short-prefix-biased score like `min(len(v), k) * count(v) * (count(v)-1)`. Each produces one dependency-safe topological layout, and the evaluator-aligned exact final scoring should decide among all candidates; this directly extends the best program’s strongest three-layout design without expensive recursive search.

2. **Replace greedy conditional-unit choice with a bounded one-step lookahead over only the strongest eligible units.** For each candidate split unit, compute its immediate repeated-value score plus the sum of the best next-unit repeated-value scores within its partitions, considering perhaps the top 6–10 currently eligible units. Use this two-level estimate only for choosing the next conditional prefix unit, while preserving the existing depth-12 and top-24 bounds; this targets cases where the current locally optimal split blocks a stronger downstream shared prefix.

3. **Generate a hybrid conditional candidate that stops splitting when its local gain is weaker than a global-tail alternative.** At each row group, compare the estimated prefix reuse from selecting the best conditional unit against retaining the next unit from `global_units` or `alternate_units`; if the conditional split has little or no advantage, assign the group the better compatible global tail. This preserves the current method’s ability to exploit repeated-value partitions while reducing harmful row-specific layout divergence, then lets `_score_strings` validate whether the hybrid improves whole-table serialization.

4. **Add a small dependency-safe local-mutation neighborhood around the best global layouts.** Starting from `global_units` and `alternate_units`, create a bounded number of complete variants by swapping adjacent independent units, moving one high-ranked unit one or two positions earlier, or reversing a short block of mutually dependency-free units. Restrict mutations to, for example, the first 8–12 units and score every resulting serialization exactly; this explores partial-prefix interactions that aggregate frequency ranks miss while remaining far cheaper than broader permutation search.

5. **Introduce one prefix-similarity-aware global ranking for high-cardinality units.** For each unit, supplement exact repeated-value counts with a sampled estimate of shared textual-prefix length among distinct values—for example, sort unit strings and sum adjacent LCPs, optionally weighting only the first 4–16 characters. Build a topological layout from this rank and include it as another exact-scored candidate, since the persistent approximately `0.444` workload suggests that exact-value repetition alone cannot exploit datasets whose strings share prefixes but are rarely identical.
