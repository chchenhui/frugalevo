# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Structured icosahedron-plus-poles initialization is the key success factor**: The current best program (Gen 6, `scipy_optimized_14_points`, score 1.00, ratio 0.24) and Gen 11 (`softmin_softmax_gradient_ascent`, score 0.99, ratio 0.24) both use icosahedron vertices plus two pole points as structured starts. Gen 11's feedback explicitly credits these structured starts for its strong result, and it achieved the same score in 0.42s vs. the best program's 8.81s.
- **Soft-min/soft-max (log-sum-exp) surrogates on the true ratio objective, refined with L-BFGS-B**: Both top-scoring programs (Gen 6, Gen 11) use this approach. Gen 11's temperature annealing schedule (0.3→0.04) with analytic gradients achieved ratio 0.24 vs. Gen 2's softmax-only multi-start achieving only 0.14 — annealing the sharpness matters more than 400 restarts.
- **Two-stage pipeline: smooth surrogate optimization followed by direct polish on the true ratio**: The best program polishes with Nelder-Mead (4000 iters) on the actual min/max ratio after L-BFGS-B; Gen 5 similarly used a 4000-iteration polish. This refinement lifted the ratio from ~0.15-0.18 (hill climbing / annealing alone) to 0.24.
- **Multi-seed hill climbing with plateau acceptance (`>=`)** provided decent but suboptimal results (Gen 3, score 0.74, ratio 0.18, 0.55s) — useful as a cheap baseline but trapped in local optima.

## Ineffective Approaches

- **SLSQP constraint formulation (Gen 7, score 0.16, ratio 0.04)**: Squared-distance ≥ slack constraints with 91 inequality constraints failed badly — the optimizer got stuck near degenerate clustered configurations instead of escaping poor basins.
- **Pure random initialization (Gen 0, score 0.02)**: Random Gaussian placement puts points nearly coincident; structured geometry is essential for this problem.
- **Bug-prone silent truncation of structured seeds (Gen 9, score 0.00)**: `ico[:14]` on a 12-vertex icosahedron silently produced a (12,3) array, failing validation — structured seeds must be shape-checked/padded to n=14.
- **Naive multi-start without annealing or structured starts (Gen 2, score 0.57)**: 400 restarts of smooth surrogate gradient ascent still landed at only ratio 0.14, showing brute-force restarts cannot compensate for poor surrogate scheduling.

## Implementation Insights

- **Icosahedron construction**: Building the 12 icosahedron vertices from the golden ratio and appending `[0,0,±2.0]` poles gives a strong 14-point start; the best program then perturbs by 0.1σ noise to break symmetry. This exact pattern appears in both score-1.00 and score-0.99 programs.
- **Dead/incorrect gradient code is harmless when the optimizer uses numerical gradients**: The current best program's custom `grad` is never passed to L-BFGS-B, so its flawed derivation doesn't affect correctness — Gen 11 similarly contains dead gradient code from an earlier derivation. However, Gen 11's working analytic gradient made it ~20x faster (0.42s vs. 8.81s) at equal score.
- **Simple syntax bugs destroy otherwise good designs**: Gen 4 (mismatched `))` vs `])`) and Gen 10 (1D `dist` array indexed as 2D) both scored 0.00 despite sound algorithmic approaches — shape validation and careful indexing of pairwise-distance arrays are critical.
- **Post-processing normalization** (center + scale so max distance = 1) appears in all successful programs and standardizes output without changing the ratio.

## Performance Analysis

- **Score progression correlated with initialization quality + surrogate sophistication**: random (0.02) → multi-start softmax without annealing (0.57) → simulated annealing with structured seeds (0.63) → hill climbing multi-seed (0.74) → icosahedron start + annealed softmin/softmax + polish (0.99-1.00).
- **Current best (ratio 0.24, 8.81s) vs. Gen 11 (ratio 0.24, 0.42s)**: identical achieved ratio, ~21x speed difference — analytic gradients plus temperature annealing (Gen 11) dominates numerical-gradient L-BFGS-B (Gen 6). Gen 11 is arguably the more efficient implementation at equivalent quality.
- **Evaluation time is not a reliable proxy for quality**: the fastest correct programs ranged from 0.02 (random) to 0.99 (Gen 11); the best program's 8.81s is second-slowest, driven by numerical gradients over 7 starts plus Nelder-Mead polish.
- **Ratio plateau around 0.24**: multiple distinct methods (Gen 6, Gen 11) converge to min_max_ratio ≈ 0.24, suggesting a common local optimum basin from icosahedron+poles starts; feedback from Gen 5 notes the known optimum is ~0.62, indicating all current search strategies remain far from the global optimum.

2. **Escape the 0.24 basin by diversifying structured starts beyond icosahedron+poles.** Both top programs converge to ratio ≈0.24 from icosahedron+poles starts while the known optimum is ~0.62, indicating all current starts land in one basin. Add structured candidates such as: a slightly-rotated/perturbed cuboctahedron + poles, points sampled on a unit sphere via Fibonacci spirals (14 points), or the icosahedron with poles placed on a different axis and at varying radii (try pole heights 0.5–3.0 rather than fixed ±2.0).

3. **Add a repulsion-based preprocessing stage (e.g., projected gradient descent on a Coulomb/-inverse-distance energy) before surrogate optimization.** Pure random starts failed (Gen 0, score 0.02) because points cluster, but running ~200 iterations of repulsion (minimize Σ 1/‖pi−pj‖², or simply −Σ log(dd)) with centering/scaling between steps transforms random starts into well-spread quasi-uniform configurations. This gives many diverse high-quality basins cheaply, complementing the single structured icosahedron basin.

4. **Insert a symmetry-breaking rotation/reflection diversification between polish attempts.** The single 0.1σ perturbation of the icosahedron start leaves much of the basin unexplored; run the polish stage (Nelder-Mead on the true ratio, which lifted 0.15–0.18 to 0.24) from the top 3–5 surrogate solutions rather than only the best one, with larger perturbations (0.05–0.3σ) applied to each. Keep the same 4000-iteration polish budget per start now affordable via recommendation 1's speedup.

5. **Remove or repair the dead gradient code to eliminate confusion and enable gradient-based polishing.** The current `grad` function contains placeholder terms (`* 0`) and an incorrect final chain-rule combination, and is never passed to the optimizer — sound design but wasted. Either delete it or implement the correct gradient: for f = −smin/smax, df/dp_a = −(dsmin/dp_a · smax − smin · dsmax/dp_a)/smax², where dsmin/dp_a = Σ_b (w_ab/W)·u_ab and dsmax/dp_a = Σ_b (w'_ab/W')·u_ab for softmin/softmax weights. This enables a fast final L-BFGS-B polish directly on the true ratio (maximizing dd.min()/dd.max() via the k→∞ surrogate limit) instead of the slower Nelder-Mead.
