## Implementation Insights

- **The current best program's exact-constraint SLSQP formulation with feasibility-safe returns is the core quality guarantee**: `_slsqp_stage` rescales the input to dmax ≤ 1 before optimizing, uses `objective = -dmin` with inequality constraint `1 - dmax ≥ 0`, and returns the (rescaled) input unchanged if the output is non-finite — the fallback check credited since Gen 23 prevents failed SLSQP runs from destroying good repulsion candidates.
- **Per-iteration diameter normalization in repulsion (dividing by dmax each of 500 iterations with 0.997 step decay)** keeps configurations in the feasible region, aligning repulsion output with the constrained SLSQP objective — validated across Gens 23, 29, 37, and the current best.
- **Strict-improvement acceptance (`r > cur_r + 1e-14`) in the multi-pass polish and bottleneck stage** ensures monotone quality: only accepted if the true ratio strictly improves and output is finite, mirroring the greedy-perturbation polish discipline in Gens 30, 35, 36.
- **1e-4 displacement along the closest-pair separation axis followed by a tight SLSQP pass (ftol 1e-14, maxiter 200)** is the current best's bottleneck implementation — a minimal, cheap nudge that the feedback credits with "small but real gains" only after convergence is already near-optimal.
