# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Repulsion → SLSQP (dmin max s.t. dmax ≤ 1) → bottleneck polish remains the only 1.00 architecture, with now 15+ confirmations**: The current best (Gen 49 lineage, 0.24/1.00, 48.89s) and Gens 54, 56, 59 in this batch all hit 1.00 (or 0.99) using exactly this pipeline. Gen 56's variant — 20 seeded inits, 1/d¹² repulsion, then SLSQP softmin polish with alpha 20→1000 on the top 8 candidates — achieved 0.24/1.00 in 35.94s, the fastest 1.00-tier result in this batch.
- **Screening before polishing is the proven runtime lever**: Gen 56's "polish only top 8 of 20 candidates" and Gen 59's "beam search over ranked candidate starts with staged early-exit (skip redundant SLSQP once target met)" both hit 1.00 at 35.94s and 44.98s respectively, vs. the current best's 48.89s — confirming prior insight that cheap ranking before expensive SLSQP is the best runtime/quality tradeoff.
- **Icosahedron+poles structured seeds remain the basin entry point**: Gen 56's feedback explicitly credits "structured icosahedron-based inits" for reliable convergence to the best-known geometry; the current best's lazy ico+poles-first seed ordering with early-exit at an achievable threshold kept runtime moderate.
- **Analytic jacobians deliver near-optimal results at dramatically lower runtime**: Gen 51 (0.23/0.97 at 2.98s) with hand-coded jacobians for the objective and 91 constraints plus diverse seed zoo matched the Gen 44/46 soft-surrogate runtime frontier while pushing closer to the optimal ratio — the best sub-1.00 runtime point seen yet.

## Ineffective Approaches

- **Antipodal reparameterization is now conclusively a red herring (fourth and fifth confirmations)**: Gen 49 (0.24/0.99 at 54.74s with 7-antipodal-pair reduction), Gen 54 (1.00 but 47.18s), and Gen 55 (0.99 at 40.46s with differential evolution over 7 generators) all spent substantial complexity on symmetry machinery without runtime or quality advantage over the plain repulsion+SLSQP pipeline (Gen 56: 1.00 in 35.94s). Worse, the antipodal approach produced two outright crashes: Gen 57 (ambiguous truth-value bug in pair extraction, score 0.00) and Gen 61 (reshape 42→(7,3) crash from mixing 21-value generator and 42-value point parameterizations, score 0.00). The symmetry adds a whole class of dimensional-consistency failure modes for zero measured benefit.
- **Pure soft-surrogate/multi-stage softmax machinery still plateaus below the optimum**: Gen 50's heavy four-stage softmax pipeline (28 seeds × 3 betas + SLSQP polish) reached only 0.22/0.94 — worse than simpler programs — with feedback noting "the SLSQP stage gets stuck in poor local optima or the true optimum is higher than achieved." Progressive beta escalation without exact constrained optimization consistently undershoots.
- **Trivial variable-name bugs are fatal and recurring**: Gen 53's `PJ_` vs `PJ` NameError destroyed an otherwise sound annealing strategy (score 0.00), and Gen 57's ambiguous-truth-value crash shows the same pattern — sophisticated geometry strategy is worthless if a single coding slip prevents any output. Two of nine programs in this batch failed on such bugs.
- **Uncalibrated internal targets waste compute silently**: Gen 55's TARGET_RATIO of 0.4899 "never triggers" against its measured 0.24 convention, mirroring Gen 45's dead-code threshold — reconfirming that threshold values must match the program's own ratio normalization.

## Implementation Insights

- **The current best's safety guards are the quality guarantee**: `_slsqp_stage` rescales input to dmax ≤ 1 before optimizing and returns the *rescaled input unchanged* on non-finite or non-improving output — this pattern (now visible across Gens 48–59) prevents failed SLSQP runs from destroying good repulsion candidates, and the `for cand in (pre, init)` dual-candidate structure per seed ensures the raw seed always gets its own chance even if repulsion degrades it.
- **Strict-improvement acceptance plus lazy seed generation controls runtime**: the current best's `r > best_r + 1e-12` acceptance and lazy ico+poles-first seed ordering mean early-exit fires after the first successful seed, avoiding construction of unneeded random seeds. Gen 59's skip-redundant-polish-when-target-met extends the same principle into the polish stage itself.
- **Softmin surrogate + differential evolution works but is unnecessary**: Gen 55's softmin (beta=60) global search followed by exact SLSQP polish is a viable alternative architecture (0.99 in 40.46s), but the simpler repulsion pre-optimizer achieves the same result faster — repulsion is effectively a free global explorer.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Reorder `_seed_generator` to yield a single ico+poles seed first, with all other seeds demoted to lazy fallbacks after the early-exit check**: Multiple generations (23/25/28/37/40, and Gen 56's feedback crediting ico+poles for reliable convergence) confirm the first ico+poles seed reaches ratio ~0.4899 and triggers the TARGET_RATIO exit — so the 2 remaining ico+poles repeats, 3 Fibonacci variants, and 10 random seeds are dead cost. Keep exactly 1–2 ico+poles seeds up front and move everything else behind the exit check to cut the 48.89s runtime toward Gen 35's ~20s floor with zero quality risk.

2. **Add fused early-exit inside `_process_seed`: check `_ratio` after repulsion and after the first SLSQP pass**: Currently the bottleneck polish runs even when the `pre`-candidate SLSQP already hit TARGET_RATIO. Check after `_repulsion_stage` and after the first `polished` candidate; if `r >= TARGET_RATIO`, return immediately, skipping the `init` candidate, second SLSQP, and bottleneck polish. Gen 59's skip-redundant-polish-when-target-met demonstrated this principle inside the polish stage — extending it into the candidate loop compounds the savings.

3. **Add pre-validation guards in `_slsqp_stage` to harden against crash-class bugs**: The batch's 33% crash rate (Gens 53, 57, 61 — NameError, ambiguous truth value, reshape mismatch) shows single slips are fatal. Add at the top of `_slsqp_stage`: `if pts.shape != (N, D) or not np.all(np.isfinite(pts)): return pts` — complementing the existing post-check that returns the rescaled input on non-finite/non-improving output. This is zero-cost insurance for the exact proven safety pattern (Gens 48–59).

4. **Parallelize the seed loop with per-seed deterministic RNGs**: Replace the shared `rng` with `np.random.default_rng(1000 + idx)` per seed (pre-drawn indices make results deterministic and reproducible) and dispatch seeds via `joblib.Parallel(n_jobs=4)`. Gens 39–48 show identical quality across 2.7× runtime spread, so the restarts are redundant work that parallelism converts purely into wall-time savings — potentially cutting 48.89s to ~15s while preserving 1.00. Keep the early-exit as a post-collection check over returned (pts, ratio) pairs.

5. **Screen candidates cheaply before the expensive SLSQP stage, Gen 56-style**: Run a fast ranking pass — e.g., 20 seeds through only `_repulsion_stage` plus `_ratio` evaluation (~milliseconds each), then polish only the top 8 with the full SLSQP + bottleneck pipeline. Gen 56's top-8-of-20 screening achieved 1.00 in 35.94s (the fastest 1.00-tier result), confirming that cheap repulsion-based ranking before expensive SLSQP is the best runtime/quality tradeoff and that repulsion alone identifies which basins will polish to the optimum.
