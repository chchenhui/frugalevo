# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Exact subset-DP directed Steiner optimization is the strongest validated cost pattern.** The current **Hybrid Directed Steiner Broadcast Planner (Gen. 20, `dominator_component_exact`)** achieved **5/5 successful configurations**, **618.10 total cost**, and **123.62 average cost**. This exactly matches the best prior exact-DP family results from Generations 3, 4, 8–10, and 13–19. Its `dp[mask][node]` formulation allows terminal subsets to merge at the same relay before reverse-edge propagation, explicitly charging a shared upstream edge once.

- **Reverse Dijkstra relaxation after subset merging is the effective implementation mechanism.** In `_exact_directed_steiner`, each terminal singleton begins at zero cost, composite masks evaluate same-node merges, and `h.predecessors(node)` propagates solutions backward. This supports shared source-side trunks, unlike Generation 0’s independent shortest-path behavior, which reached **1035.14 total cost**, **417.04 higher** than the current result.

- **The current program preserves the successful exact regime while safely handling broader cases.** It applies full exact DP for up to **13 reachable unique non-source terminals**, then considers dominator decomposition, corridor-overlap clusters, and greedy trees only for larger cases. This maintained the exact-DP family’s **100% success rate** rather than introducing the reliability failure seen in the seeded greedy approach of Generation 12.

- **Defensive graph preprocessing remains consistently successful.** Gen. 20’s `_valid_broadcast_graph` filters missing/non-numeric, non-finite, negative-cost, self-loop, and source-entering edges. Together with reachability filtering before solving, this matches the robust Gen. 10–19 pattern: all completed validation successfully despite varied exact thresholds and fallback structures.

## Ineffective Approaches

- **Advanced large-fan-out heuristics did not improve the 618.10 plateau.** Gen. 20 adds source-side dominator decomposition, 35%-slack shortest-path corridors, overlap-based terminal clustering, exact local cluster solves, pruning, and a greedy candidate comparison. Nevertheless, it remained at **618.10 total cost / 0.00 cost score**, identical to simpler exact-DP variants. The measured data provides no evidence that these additions selected a cheaper topology on the five evaluated configurations.

- **Greedy shared-tree construction is substantially weaker when it drives topology selection.** The current `_greedy_shared_tree` iteratively attaches the cheapest destination reachable from any current tree node. Earlier basic greedy shared-tree programs cost **795.08–805.27**, roughly **177–187** above Gen. 20’s 618.10. Such local attachment can miss a more expensive immediate branch that enables better multi-terminal sharing later.

- **Independent per-destination shortest paths remain poorly aligned with shared-edge cost.** The **1035.14** result from Generation 0 shows that optimizing destination paths independently fails to select common trunks deliberately. Even if an individual path is cheapest, its union can be much more expensive than a jointly optimized Steiner network.

- **Extra heuristic complexity has not overcome the evaluator’s hidden cost bar.** Gen. 20 is correct and robust, as were most Gen. 10–19 programs, but all received **combined_score = 0.00** and **cost_score = 0.00** at the same **618.10** cost. Thus, correctness-preserving heuristic refinements have not produced measurable movement toward the evaluator’s cost threshold.

## Implementation Insights

- **Gen. 20’s exact solver is functionally complete, not merely a lower-bound calculator.** `choices[mask][node]` stores `"terminal"`, `"merge"`, and `"edge"` decisions. `expand(full_mask, root)` reconstructs an actual directed edge union from the DP decisions. This reconstruction is essential to the program’s validated **5/5** correctness result and to realizing the shared-cost solution in returned paths.

- **Candidate validation and edge-union comparison make the hybrid strategy safe.** After each candidate is produced, `_prune_to_destinations` removes irrelevant branches, then the code verifies every reachable requested terminal has a source path before considering it. `min(valid_candidates, key=_edge_union_cost)` selects by the actual union objective rather than by an indirect path metric. This prevents heuristic candidates from replacing a valid topology with a disconnected or unnecessarily branched one.

- **The dominator decomposition is a conservative structural optimization.** `_dominator_component_tree` only decomposes when there are at least two source-side dominator groups and every group is within the exact terminal limit. This avoids claiming independence where cross-group sharing may still be possible. However, because Gen. 20 still tied the ordinary exact-DP result, this safe decomposition was either not exercised materially or did not expose lower-cost structure in the evaluated inputs.

- **Route materialization remains compatible with the validator.** After selecting a shared tree, Gen. 20 extracts one source-to-destination path per terminal and assigns the same path to every partition. This partition-agnostic representation was also used by successful Gen. 10–19 variants and is therefore not responsible for their zero cost scores.

## Performance Analysis

- **Gen. 20 is tied for the best observed cost but not uniquely better.** Its **618.10 total / 123.62 average / 5 successful configurations** matches the earlier exact directed-Steiner family precisely. Increasing exact coverage to 13 terminals and adding dominator and clustering logic did not improve over programs using lower thresholds or simpler exact-only paths.

- **The cost hierarchy is consistent and large.** Exact DP at **618.10** is approximately **22.3% lower** than the best basic greedy result of **795.08**, approximately **6.7% lower** than the seeded shared-tree result of **662.49**, and approximately **40.3% lower** than independent shortest paths at **1035.14**. This strongly correlates global subset-sharing optimization with lower union cost.

- **Reliability is strongest in the exact-DP family.** Gen. 20 and the Gen. 10–19 variants achieved **runs_successfully = 1.00**, **success_rate = 1.00**, and no failed configurations. In contrast, Generation 12’s seeded greedy approach had **runs_successfully = 0.00**, so even its potentially useful reuse heuristic did not establish a reliable evaluated result.

- **The unchanged zero score reveals a benchmark-threshold issue rather than a correctness issue.** Despite Gen. 20’s valid output and its large improvement over greedy and independent routing, **cost_score and combined_score remained 0.00**. The repeated exact **618.10** across many materially different implementations indicates that the shared subset-DP core consistently reaches the same benchmark-local solution, while added pruning, clustering, and fallback mechanisms have not changed the evaluated objective outcome.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Implement bounded equal-cost alternative retention inside `_exact_directed_steiner` and compare reconstructed unions.** For each `dp[mask][node]` state, retain a small beam (for example, 2–4) of decisions whose values are equal within tolerance or within a tiny relative slack, rather than overwriting all ties with the first encountered merge/edge choice. Reconstruct several full-mask root candidates, prune and validate each, then select by `_edge_union_cost`; this preserves the proven exact subset-DP objective while addressing the possibility that numerically equivalent DP derivations produce different edge unions after reconstruction.

2. **Add an exact-preserving terminal and relay reduction stage to raise the practical DP limit beyond 13 terminals.** Before allocating `2^k` DP masks, remove nodes unreachable from `src` or unable to reach any requested terminal, then retain only edges satisfying an adaptive source-to-node plus node-to-terminal lower-bound budget. Run exact DP on several reduction slack levels—such as shortest-path-only, 5%, 15%, and unrestricted when feasible—and keep the cheapest validated tree, enabling 14–18 terminal exact solves without abandoning the highly successful global-sharing formulation.

3. **Add a directed local-search improvement pass over the reconstructed exact/clustered edge union.** For each selected non-source edge or rooted subtree, temporarily remove it, identify the terminals disconnected by that removal, and search for a lower-cost replacement attachment from the retained source-reachable portion of the tree to the removed subtree root or directly to its affected terminals. Accept only replacements that preserve reachability and strictly reduce unique edge-union cost; unlike the current DP reconstruction, this explicitly optimizes the final selected union and can improve large-fan-out heuristic candidates as well.

4. **Replace or supplement corridor-overlap clustering with estimated Steiner merge-benefit clustering.** For terminal clusters `A` and `B`, estimate `benefit(A,B) = cost(tree(A)) + cost(tree(B)) - cost(tree(A ∪ B))` using exact DP for small candidate unions or a bounded terminal sample when necessary, then merge the pair with the greatest positive benefit. This is more aligned with the validated shared-trunk objective than Jaccard overlap of shortest-path corridors, since profitable Steiner sharing can occur on paths that are not individually near-shortest.

5. **Use a second-stage global optimization of cluster attachment points for terminal sets above the exact limit.** After solving local exact cluster trees, collect several plausible entry/branch nodes from each tree—such as the first common relay, immediate successors of `src`, and low-cost ancestor relays—and treat these as alternatives in a smaller subset DP or beam search for the common upstream backbone. Attach the local cluster subtrees only after the backbone is selected, reducing duplicated source-side trunks that the current independently solved `_clustered_steiner_tree` can retain.
