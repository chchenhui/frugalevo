# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Exact directed-Steiner subset DP remains the strongest measured approach.** The current best program uses `costs[mask][node]` states, subset merges at the same relay, and reverse-edge Dijkstra relaxation. It achieved **618.10 total cost / 123.62 average cost** with **5/5 successful configurations**. This matches the prior best results from Generations 3, 4, 8, and 9 and remains far better than independent shortest paths (**1035.14**) or basic greedy shared trees (**795.08–805.27**).

- **Charging shared edges through merge states is the important optimization.** In the current program, a state for terminal set `mask` can be formed by merging `submask` and `other` at the same node before propagating backward through incoming edges. This permits one source-side trunk edge to serve multiple destination subsets. The repeated **618.10** result across Exact Directed Steiner Broadcast DP (Gen. 10), Directed Steiner Multicast Tree Builder (Gen. 13), Directed Steiner Broadcast Topology (Gen. 14), and the current clustered planner confirms that this core DP formulation is consistently valid and cost-effective relative to greedy alternatives.

- **Robust graph sanitation preserved complete evaluation success.** The current program filters invalid, negative, nonnumeric, and NaN costs; excludes self-loops; and removes edges entering the source. The same defensive patterns appear throughout the successful Gen. 10–19 family, all of which reached **runs_successfully = 1.00**, **success_rate = 1.00**, and no failed configurations.

- **Using one reconstructed multicast tree for all partitions was consistently compatible with validation.** The current program reconstructs a selected directed edge union, extracts a source-to-destination path from that tree, and assigns that path to every partition. Every correct Gen. 10–19 program used this partition-agnostic route replication and passed all validation, so this representation is not a source of execution failures.

## Ineffective Approaches

- **The newer pruning, clustering, and threshold variations did not improve the 618.10 plateau.** Gen. 10’s irrelevant-relay pruning, Gen. 14 and 17’s corridor reduction, Gen. 15’s cluster-plus-greedy hybrid, Gen. 16’s terminal corridor narrowing, Gen. 18’s prune-and-extend variant, and Gen. 19/current program’s overlap-clustered exact fallback all produced exactly **618.10 total cost**. These changes retained correctness but showed no measured cost improvement over the existing exact-DP baseline.

- **Greedy fallback logic is repeatedly associated with weaker cost behavior when it is exercised.** Earlier greedy attachment programs reached **795.08–805.27**, and the seeded shared-tree heuristic reached **662.49**, still **44.39** above the exact-DP result. The Gen. 10–19 feedback likewise repeatedly identifies greedy attachment, shared-prefix fallback, or clustering for larger fan-outs as likely sources of missed sharing opportunities, even though their aggregate tested total remained tied at 618.10.

- **Independent per-destination routing is materially worse under the shared-edge objective.** Generation 0’s independent Dijkstra routing cost **1035.14 total**, which is **417.04 higher** than the current program’s 618.10. It minimizes each route separately and therefore cannot intentionally choose a slightly longer individual route that creates a lower-cost shared trunk.

- **The seeded greedy implementation introduced a reliability regression.** Greedy Shared-Edge Multicast Routing (Gen. 12) attempted zero-marginal-cost reuse and several initial seeds, but had **runs_successfully = 0.00** because one or more configurations failed before usable results were produced. Unlike the DP family’s consistent 5/5 completion record, this variant did not establish a valid cost result.

## Implementation Insights

- **The current best program’s reconstruction is a key functional detail.** It does not merely calculate a DP value: `choices[mask][node]` records `"terminal"`, `"merge"`, or `"edge"` decisions, and `reconstruct()` materializes the selected directed edge union. This is the implementation mechanism that turns the shared-cost optimization into a valid broadcast topology and supports the program’s **100% validation success**.

- **Reverse relaxation correctly models rooted directed multicast structure.** For each DP state, the current code initializes terminal states at cost zero, then traverses `h.predecessors(current)` and adds the cost of `predecessor -> current`. This lets a common upstream path be paid once for a combined terminal mask, whereas independent forward shortest-path calls would duplicate the optimization decision per terminal.

- **The current program’s exact regime is broader than several related variants but did not change measured cost.** It runs full DP for up to **14 unique non-source terminals**, compared with limits of 10 in Gen. 13, 12 in Gen. 18, 13 in Gen. 15, and 16 in Gen. 17. Despite these different limits, all successful variants returned **618.10**, indicating that the evaluated instances either fell within the exact-solver range already or converged to the same selected topology.

- **The large-fan-out clustering fallback is structurally more sophisticated than plain greedy attachment, but its measured benefit is unproven here.** The current program computes each destination’s source shortest-path corridor, merges clusters sharing baseline edges up to 12 terminals, and applies local exact DP per cluster. This is more globally informed than simple marginal branch attachment, but its overall result remained identical to the simpler exact-DP programs and still had **cost_score = 0.00**.

## Performance Analysis

- **The dominant measured trend remains: stronger global sharing optimization lowers total cost.** Independent shortest paths were **1035.14**, constrained greedy sharing was **1095.14**, simple greedy shared trees were **795.08–805.27**, seeded/frontier sharing reached **662.49**, and exact directed-Steiner DP reached **618.10**. The current program is therefore **22.4% lower-cost than the 795.08 greedy baseline** and **6.7% lower-cost than the 662.49 seeded shared-tree result**.

- **The current program is tied, not uniquely ahead, within the exact-DP family.** Its **618.10 total / 123.62 average** exactly matches Gen. 10 through Gen. 19’s successful directed-Steiner variants, as well as the earlier best programs cited in the global insights. The code-level additions—pruning, increased terminal thresholds, local exact clusters, and fallback refinements—did not produce observable cost separation in the five evaluated configurations.

- **Correctness and cost scoring are disconnected in the observed evaluation.** The current program and nearly all Gen. 10–19 variants achieved **runs_successfully = 1.00**, **success_rate = 1.00**, and **5 successful configurations**, yet every one received **cost_score = 0.00** and **combined_score = 0.00**. Thus, the 618.10 topology is substantially better than earlier alternatives but still fails the evaluator’s undisclosed cost-scoring threshold.

- **The repeated 618.10 value suggests a common benchmark or objective ceiling rather than random implementation variation.** Multiple independently modified exact-DP implementations reconstruct valid shared multicast trees and converge to the same aggregate cost. This consistency supports the conclusion that the subset-DP/reverse-Dijkstra method is the effective common mechanism, while the evaluator’s cost objective or benchmark-specific expected topology is not improved by the newer pruning and fallback modifications.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Add bounded multi-choice tie retention to the exact subset DP and select by reconstructed union cost.** Instead of storing only one `choices[mask][node]` entry, retain several equal-cost or very-near-cost merge/edge alternatives for each state, particularly when `candidate == costs[mask][index]` within a small tolerance. Reconstruct a bounded number of full-mask candidates, remove redundant edges, verify source reachability to all terminals, and choose the candidate with minimum unique selected-edge cost; this targets the repeated 618.10 plateau without replacing the proven reverse-Dijkstra DP.

2. **Apply a post-reconstruction directed-tree improvement pass to the DP edge union.** For every nonterminal branch or subtree in the reconstructed topology, temporarily remove its incoming branch and search for a cheaper path from any retained source-reachable tree node to the branch root or affected terminal set. Accept a replacement only if all destinations remain reachable and the cost of the unique edge union decreases, directly optimizing the evaluator-relevant shared-edge objective rather than just DP-state cost.

3. **Increase the practical exact-DP terminal limit through terminal-aware graph reduction before allocating DP states.** Compute source-to-node distances plus node-to-terminal reverse distances, retain nodes and edges within an adaptive low-slack corridor for at least one destination, and run the existing exact solver on that reduced graph. This preserves the strongest measured algorithmic mechanism while potentially allowing exact optimization for 15+ terminals that currently trigger clustered local solves.

4. **Replace shortest-path-overlap clustering with merge-benefit clustering for large fan-outs.** For candidate terminal groups, estimate the benefit of joining them using a small exact DP solve or a pairwise/group Steiner estimate, comparing `cost(A) + cost(B)` against `cost(A ∪ B)` rather than merely counting shared edges on independently shortest paths. Repeatedly merge clusters with the largest positive estimated savings, then solve final clusters exactly; this better reflects the insight that optimal multicast trunks may not lie on any individual shortest-path corridor.

5. **Add a second-stage exact DP over contracted cluster entry points or selected branch roots.** After solving local clusters, identify each cluster’s first shared node after the source or its reconstructed attachment/root candidates, contract each local subtree into a terminal-demand object, and run a smaller directed-Steiner DP to optimize common upstream infrastructure across clusters. This extends the current cluster-exact strategy while addressing its main limitation: independently solved clusters can duplicate expensive source-side trunk edges that a global DP would charge once.
