# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns
- **Exact shared directed-Steiner optimization produced the best measured cost.** The current best, **Directed Steiner Broadcast Planner** (Generation 9), achieved **total cost 618.10 / average 123.62**, tied with Generations 3, 4, and 8. This is a substantial improvement over independent per-destination shortest paths in Generation 0 (**1035.14 / 207.03**) and demonstrates that optimizing a shared edge union is materially beneficial.
- The best-performing family uses **subset DP over destination masks plus reverse-Dijkstra closure**. In the current program, `dp[mask][node]` represents the minimum shared-edge cost of reaching a terminal subset from `node`; split states allow terminal groups to merge at relay nodes, while backward propagation prices the trunk from predecessors. This avoids the local branch-order mistakes of greedy tree growth.
- **Routing all partitions through the same selected multicast route** was consistent across the best DP programs. Generations 3, 4, 8, and 9 all duplicate the selected source-to-destination route for every partition and all reached the same leading 618.10 result, indicating that this representation is valid and that shared-route construction is preferable to independently selecting paths per partition.
- The current best also combines exact optimization with a **scalable fallback**: it uses exact DP for at most 11 reachable destinations and switches to a shared-frontier heuristic for larger receiver sets. Although the evaluated configurations evidently benefited from the exact regime, this preserves full correctness and 100% successful execution across all five configurations.

## Ineffective Approaches
- **Independent cost-shortest paths performed worst** for aggregate cost. Generation 0’s per-destination Dijkstra implementation cost **1035.14 total**, which is **417.04 higher** than the 618.10 exact-Steiner result. Selecting each destination’s cheapest route independently fails to account for the fact that common transit edges can be reused.
- **Conservative shared-tree selection with route-stretch constraints did not help.** Generation 1 required every destination to remain within 2% of its independent shortest-path cost, but reached **1095.14 total / 219.03 average**, even worse than the independent baseline. The stretch restriction limited the ability to choose longer individual routes that could create lower-cost shared trunks under the tree objective.
- **Greedy marginal-attachment trees consistently underperformed exact DP.** Generations 2 and 6 reached **795.08**, while Generation 7 reached **805.27**. Their strategy—attach the cheapest currently reachable destination from an existing tree node—can commit early to branches that are cheap in isolation but prevent better future multi-terminal merging.
- **Seeded/frontier greedy reuse was better than simple greedy attachment but still inferior to exact optimization.** Generation 5’s seeded multi-source Dijkstra tree obtained **662.49**, an improvement of roughly 133 over the 795–805 greedy group, but remained **44.39 above** the exact-Steiner result. Edge sharing alone was insufficient when the tree construction remained locally driven.

## Implementation Insights
- The current best program’s key effective mechanism is its **directed-Steiner DP reconstruction**. It stores whether each state was created by a terminal, a subset split, or an incoming edge relaxation; `collect()` then reconstructs a selected edge set rather than merely returning independent shortest paths. This is the implementation detail that distinguishes its 618.10 performance from the 795–805 greedy tree planners.
- **Reverse-edge relaxation is important for rooted multicast structure.** `_close_over_incoming_links()` propagates a state’s cost backward through each predecessor, adding the directed edge cost exactly once for that state. Combined with subset merging at the same node, this naturally models a shared upstream trunk followed by divergence toward terminal subsets.
- The current best includes robust graph sanitation without harming feasibility: `_clean_transfer_graph()` removes source-incoming links, self-loops, and invalid, nonfinite, or negative-cost edges. This pattern is shared by the high-performing DP variants and supported their **100% success rate across all five configurations**.
- The code materializes routes by finding source-to-destination paths in the reconstructed selected-edge graph and then writes `list(records)` for every partition. This preserves the required topology interface and validation success, but the identical 618.10 plateau across all exact-DP variants suggests that interface-level partition duplication and/or evaluator accounting may be a limiting factor beyond the shared-tree solver itself.

## Performance Analysis
- The measured progression strongly favors stronger global sharing optimization: independent shortest paths were **1035.14**, constrained greedy sharing was **1095.14**, ordinary greedy shared trees were **795.08–805.27**, frontier-based sharing improved to **662.49**, and exact directed-Steiner DP reached the best **618.10**.
- The current best is tied with three independently named implementations—**Shared Directed-Steiner Broadcast Planner** (Gen. 3), **Directed Steiner Broadcast Routing** (Gen. 4), and **Exact Directed Steiner Broadcast DP** (Gen. 8)—all at **618.10 total / 123.62 average**. This repeatability indicates that the DP/reverse-Dijkstra shared-arborescence formulation, rather than incidental coding differences, drove the best observed cost.
- Exact DP improved total cost by **177.98** relative to the best simple greedy shared-tree result (795.08), about a **22.4% reduction**, and by **44.39** relative to the more sophisticated frontier-grown heuristic (662.49), about a **6.7% reduction**.
- Despite large relative cost reductions, **every program received `cost_score: 0.00` and `combined_score: 0.00`**. Therefore, the evaluation distinguishes functional correctness from a stricter cost threshold: all programs were fully valid (`runs_successfully = 1.00`, `success_rate = 1.00`), but even the best exact shared-tree objective did not align closely enough with the evaluator’s scored transfer-cost objective.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Extend the exact directed-Steiner regime beyond the fixed 11-terminal cutoff using component reduction.** Before invoking subset DP, remove unreachable destinations, contract zero-cost strongly connected components, and decompose terminals by source-reachable articulation/branch regions where possible; then run exact DP independently on smaller terminal groups and merge their selected edge sets. This preserves the proven reverse-Dijkstra/subset-merge formulation while allowing more cases to benefit from exact optimization rather than falling back to the weaker frontier heuristic.

2. **Replace the large-terminal `SharedFrontierPlanner` fallback with a DP-guided clustering strategy.** Cluster reachable destinations by overlap of their reverse shortest-path corridors, solve each cluster exactly with `DirectedSteinerPlanner`, and then optimize the union of cluster roots or iteratively merge clusters when joining them lowers union cost. The current frontier method was empirically better than simple greedy attachment but still substantially behind exact DP, so using exact optimization locally should be a stronger scalable approximation.

3. **Add a post-solve edge-union improvement pass to the reconstructed Steiner tree.** Starting from `selected_edges`, repeatedly test whether a subtree or branch can be replaced by an alternate directed path from any already-selected tree node, accepting replacements only when all affected terminals remain reachable and the total unique-edge cost decreases. This directly targets the evaluator-relevant union cost and can improve tied DP solutions when multiple equal-cost DP choices produce a valid but noncanonical tree.

4. **Preserve multiple near-optimal DP decisions and evaluate reconstructed union costs before selecting a solution.** The current DP stores only one predecessor/split choice per `(mask, node)` and resolves ties implicitly by iteration order; instead, retain a bounded set of equal or near-equal choices, reconstruct several candidate arborescences, prune redundant edges, and choose the lowest actual unique-edge-cost candidate. This builds on the successful exact DP core while addressing the observed 618.10 plateau, where tie-breaking may hide better equivalent-cost state decompositions.

5. **Introduce a terminal-aware reduction graph before DP by retaining only promising relay nodes and edges.** Compute forward shortest-path distances from the source and reverse distances from each terminal, then retain edges/nodes lying on low-slack source-to-terminal corridors; run the exact Steiner DP on this reduced graph, optionally expanding the slack if no route is found. This can make higher terminal limits computationally practical while still retaining the shared trunks and relay opportunities that made reverse-edge directed-Steiner optimization outperform greedy routing.
