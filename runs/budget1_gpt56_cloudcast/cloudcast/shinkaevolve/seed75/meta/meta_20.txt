# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **The current best program, Shared-Tree Directed Steiner Broadcast (Generation 14), achieved the lowest reported total cost: 618.09 total / 123.62 average, with 5/5 successful configurations.** Its strongest pattern is the combination of a shared-edge greedy construction with an exact directed-Steiner subset DP refinement for `2–9` reachable non-source destinations. This slightly edges the otherwise tied exact/hybrid results at **618.10** from Generations 7, 8, 11, and 15–19.

- **Explicitly optimizing a union of installed directed edges was the major successful cost improvement.** Generation 14 charges each selected edge once through `installed_edges`, then derives individual destination paths from that union. This shared-topology design reduced cost from the independent-shortest-path baseline of **1035.14 total** to **618.09**, a roughly **40.3% reduction**.

- **Exact subset-DP Steiner refinement consistently matched or improved on greedy shared-tree construction.** The current program’s DP merges terminal subsets at a relay (`dp[submask][node] + dp[other][node]`) and propagates the resulting subtree backward over incoming edges. Its result matches the strongest observed class of exact/hybrid solvers: Generation 11 (**618.10**), Generation 15 (**618.10**), Generation 16 (**618.10**), and Generation 17 (**618.10**).

- **Robust graph filtering remained a universally successful implementation pattern.** Generation 14 removes incoming edges to the source and self-loops, while `_edge_cost` excludes missing, non-finite, and negative costs by treating them as infinite. This is consistent with the perfect reliability of the successful exact/hybrid programs: **runs_successfully = 1.00**, **success_rate = 1.00**, and all five configurations validated.

## Ineffective Approaches

- **Greedy attachment without exact global refinement was measurably more expensive.** Generation 10’s Greedy Shared Multicast Steiner Routing used zero-cost installed edges and tried destination seeds, but reached **627.12 total / 125.42 average**. The current Generation 14 improves this by approximately **9.03 total cost**, showing that greedy marginal attachment can still lock into a locally attractive but globally inferior trunk structure.

- **Some purported exact-Steiner implementations did not translate their optimization into competitive evaluated topology cost.** Generation 12 used exact Dreyfus-Wagner-style DP through 12 terminals but produced **795.08 total / 159.02 average**, much worse than Generation 14. The evaluation feedback specifically points to a mismatch between the shared-union objective or path extraction and the benchmark metric; exact DP alone was not sufficient unless the reconstructed installed-edge union was aligned with the evaluated cost model.

- **Increasing exact-solver coverage did not produce a measurable gain on these five configurations.** Generations 11, 15, 16, 17, 18, and 19 used exact thresholds ranging from 9 to 16 destinations and all reported **618.10 total cost**, essentially tied with Generation 14’s **618.09**. The observed benchmark instances therefore did not reward higher exact-terminal limits beyond the current program’s range.

- **Correctness failures eliminate any potential optimization value.** Generation 13 attempted a similar shared directed-Steiner strategy but had **runs_successfully = 0.00** and a zero combined score because one or more configurations failed. In contrast, Generation 14’s conservative path materialization and handling of unreachable destinations preserved full validation success.

## Implementation Insights

- **Generation 14’s DP implementation captures directed multicast sharing correctly at the edge-union level.** For each terminal mask, it first combines disjoint terminal subtrees at a common node, then performs reverse relaxation through `h.predecessors(node)`. This allows a single upstream edge to serve multiple terminal subsets, which is the essential advantage over separately computing source-to-destination shortest paths.

- **The current best program uses the greedy tree as a safe baseline rather than its final mandatory answer.** `build_shared_tree()` gives already installed edges zero incremental weight, performs multi-source Dijkstra from current tree nodes, and evaluates multiple initial seeds. The exact solution replaces that tree only when `exact_cost < greedy_cost`. This preserves a feasible shared tree even if the exact DP is infeasible or not beneficial.

- **Separating topology selection from path output supports both cost sharing and API correctness.** Generation 14 first collects `installed_edges`, creates `broadcast_graph` solely from those edges, and then finds each source-to-destination path within that restricted graph. It can therefore output required per-destination, per-partition path lists while the optimization remains based on the cost of the shared physical edge union.

- **Path replication across partitions is reliable but not a source of measured optimization variation.** Like Generations 10–19, the current program assigns the same `edge_path` to every partition. This clearly supports its **100% success rate**, but the reported cost differences arise from multicast-tree construction, not partition-specific routing decisions.

## Performance Analysis

- **Generation 14 is the reported best result, but only by a negligible numerical margin.** Its **618.09 total cost** is effectively tied with the **618.10** results of the other successful exact/hybrid directed-Steiner programs. Given the displayed two-decimal precision, these programs form one top-performing performance tier rather than demonstrating a meaningful cost separation.

- **There is a clear hierarchy among successful topology strategies.** Independent routing was worst at **1035.14**; weaker greedy shared-growth variants ranged from **759.09** to **795.08**; seed/multistart greedy sharing reached **627.12**; and exact/hybrid directed-Steiner methods reached approximately **618.09–618.10**. The largest gain came from sharing links at all, while exact global optimization supplied the final roughly **9.02–9.03** reduction over the strongest pure greedy approach.

- **Reliability is no longer the discriminating metric among the correct programs.** Generation 14 and nearly all listed alternatives completed all five configurations successfully, with validation passing. The difference between Generation 14’s **618.09** and Generation 10’s **627.12**, or Generation 12’s **795.08**, is therefore attributable to the selected shared topology rather than malformed-cost handling, output construction, or reachability processing.

- **Despite being the strongest observed cost result, Generation 14 still received `combined_score = 0.00` and `cost_score = 0.00`.** This means the evaluator’s cost threshold or scoring baseline was below even the best observed **618.09** result. The evaluation evidence supports that the current best implementation is comparatively effective within the tested set, while also showing that the score function did not award partial credit for this measured improvement.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Extend the exact DP only where it can affect the greedy fallback: use an exact-core-plus-attachment hybrid for destination sets above nine terminals.** Select a small core of 7–9 destinations based on shortest-path-prefix overlap or common low-cost relay ancestors, solve that core with the existing directed-Steiner subset DP, then attach all remaining destinations using the current zero-incremental-cost multi-source Dijkstra. This directly preserves Generation 14’s successful union-cost objective and exact reconstruction while targeting the only meaningful scalability gap in the present `<= 9` exact refinement.

2. **Add a post-construction prune-and-reroute local search over `installed_edges`.** First remove edges in descending-cost order whenever every destination remains reachable from `src`; then, for expensive branch edges, test replacing the downstream branch with a shortest path from any node already reachable in the retained topology, accepting a move only if the deduplicated edge-union cost decreases. The current solver already obtains strong feasible shared trees, so a cost-monotone cleanup phase is low risk and can recover sharing opportunities missed by greedy attachment order or by hybrid merging.

3. **Make the greedy fallback more diverse through deterministic destination-order and seed policies, then score the final deduplicated union.** In addition to the existing “one destination as initial trunk” seeds, construct trees using farthest-first, lowest source-distance-first, highest estimated prefix-overlap-first, and a small fixed set of seeded randomized orders; prune each result before comparing union costs. Generation 10 showed that shared greedy growth is already close to the exact tier, while Generation 14 showed that global refinement matters, so broader candidate generation is a practical way to improve large-fanout cases without sacrificing reliability.

4. **Use relay-aware terminal clustering before exact optimization rather than choosing the exact core solely by terminal count.** Compute candidate common relays from reverse shortest-path trees or predecessor overlap, cluster destinations that can share inexpensive source-to-relay trunks, solve each cluster exactly, and connect cluster trees using the existing installed-edge-aware attachment routine. This generalizes the successful DP merge-at-relay mechanism to larger multicast groups without incurring a full \(2^k\) state space over all destinations.

5. **Add a bounded exact neighborhood search around the selected topology.** After greedy or hybrid construction, identify a small set of costly or high-fanout branch terminals—such as 6–9 terminals below expensive trunk edges—and rerun the existing subset DP for that local terminal set while treating already retained upstream topology edges as zero incremental cost; replace the local subgraph only if total unique-edge cost falls. This reuses the proven directed-Steiner recurrence and shared-edge accounting, but applies exact optimization to the portions of large trees where it is most likely to improve on greedy decisions.
