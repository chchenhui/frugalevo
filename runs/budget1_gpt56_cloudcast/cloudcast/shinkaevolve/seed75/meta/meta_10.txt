# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Shared multicast edge reuse substantially reduced evaluated cost versus independent routing.** The initial independent shortest-path implementation (Generation 0) cost **1035.14 total / 207.03 average**, while all shared-tree approaches improved on it. The current best, **Exact-and-Greedy Shared Broadcast Steiner Routing** (Generation 8), achieved **618.10 total / 123.62 average**, a **40.3% reduction in total cost** from independent per-destination shortest paths.

- **The current best program’s directed-Steiner subset DP is the strongest evaluated topology-construction pattern.** For up to 14 unique non-source destinations, it uses `dp[mask][v]` to combine terminal subsets at common relay nodes and then applies reverse Dijkstra relaxation. This explicitly prices a shared edge once in the selected topology, rather than paying for separate source-to-destination paths.

- **Graph sanitization and source-root constraints are consistently successful correctness patterns.** The current best removes source-incoming edges and self-loops and excludes missing, non-finite, or negative costs. These measures, also used by Generations 4–7 and 9, correlated with **5/5 successful configurations and 100% validation success**.

- **Exact optimization matched the best measured cost obtained by any evaluated program.** Generation 7’s exact-DP-through-11-terminals implementation and Generation 8’s expanded 14-terminal version both reached **618.10 total cost**, outperforming the best purely greedy shared-tree runs: Generations 6 and 9 at **627.12**.

## Ineffective Approaches

- **Duplicating independent shortest paths across every partition was by far the most expensive routing approach.** Generation 0 used individual Dijkstra paths for every destination and copied them into every partition, resulting in **1035.14 total cost**, the worst result among successful programs. It did not exploit common multicast trunks.

- **Single-pass greedy incremental tree growth remained materially weaker than the best exact/hybrid method.** Generation 2’s detour-guarded growth tree cost **999.13**, Generation 3’s multi-source branch attachment cost **795.08**, and Generation 4’s zero-cost-installed-edge heuristic cost **759.09**. Although these implementations reused installed edges, local attachment choices did not consistently produce low-global-cost trees.

- **A conservative direct-path detour guard did not improve cost.** Generation 2 added a `1.12` direct-path detour policy and fallback paths, yet its **999.13** total cost was only modestly better than independent Dijkstra and substantially worse than unconstrained shared-tree methods. The additional suitability check apparently restricted useful shared-route selections.

- **Increasing only the exact-terminal threshold did not yield a measured gain.** Generation 7 used exact optimization through 11 terminals and Generation 8 expanded this to 14, but both had identical **618.10 total / 123.62 average** results. On the evaluated configurations, the higher cutoff did not change the selected cost outcome, likely because evaluated fanout patterns either remained within both limits or continued to invoke the same greedy behavior.

## Implementation Insights

- **The current best program represents shared topology explicitly as an edge union, then derives destination paths from that union.** `_exact_shared_edges` reconstructs selected directed edges from DP decisions, while `_paths_from_shared_edges` finds a source-to-destination path inside that shared edge set. This separation is important: optimization is performed over physical shared links, while the output still satisfies the required per-destination path interface.

- **Its exact DP correctly captures the core multicast benefit through merge states.** In `_exact_shared_edges`, a state can be formed by `dp[submask][v] + dp[other][v]`, meaning multiple destination groups meet at relay `v`; reverse Dijkstra then finds the least-cost upstream way to reach that relay. This is more globally informed than the greedy methods in Generations 3–6 and 9, which choose only the next cheapest destination attachment.

- **The greedy fallback preserves correctness and scalability but limits the current best’s optimization scope.** For fanout above `EXACT_TERMINAL_LIMIT`, `_greedy_shared_edges` repeatedly runs `nx.multi_source_dijkstra` from the installed tree and adds the cheapest reachable destination branch. This is robust—consistent with the program’s **1.00 run and success rates**—but evaluator feedback specifically identifies this large-fanout fallback as a likely reason cost remains uncompetitive.

- **All partitions receive identical copies of each destination path.** The current best calls `set_dst_partition_paths(dst, partition, list(paths[dst]))` for every partition. This preserves valid output formatting and likely contributes to the perfect validation rate, but it means the routing search itself does not create partition-distinct topologies. This limitation is shared by all evaluated implementations, including Generations 0–7 and 9.

## Performance Analysis

- **The current best is tied for the lowest evaluated cost, but its score remains zero because it did not meet the evaluator’s cost threshold.** Generation 8 achieved **618.10 total / 123.62 average**, tied with Generation 7, versus **627.12 / 125.42** for the closest greedy multi-start methods (Generations 6 and 9). Despite being the best observed cost, both `combined_score` and `cost_score` remained **0.00**.

- **Shared routing delivered a clear cost hierarchy.** From worst to best among correct programs: independent shortest paths (**1035.14**), detour-guarded tree (**999.13**), shared-branch greedy (**795.08**), incremental shared tree (**759.09**), multi-start greedy tree (**627.12**), and exact/hybrid Steiner methods (**618.10**). The data shows that shared-edge reuse matters most, with exact/global subset optimization providing a smaller additional improvement over strong greedy sharing.

- **Multi-start greedy initialization was a meaningful improvement over ordinary greedy growth, but not enough to match exact DP.** Generations 6 and 9 reduced cost to **627.12**, improving by **167.96** relative to Generation 4’s **795.08** and by **131.97** relative to Generation 5’s **759.09**. However, the exact/hybrid designs still saved an additional **9.02 total cost**.

- **Reliability does not distinguish the programs; cost optimization does.** Every listed program completed all five configurations successfully with **runs_successfully = 1.00** and **success_rate = 1.00**. Therefore, the decisive observed difference is topology cost, not handling of invalid inputs, unreachable nodes, duplicate destinations, or interface construction.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Replace the large-fanout greedy fallback with a hybrid exact-core strategy.** For terminal sets above `EXACT_TERMINAL_LIMIT`, first identify a small core subset of destinations with high potential for shared prefixes (for example, nearest terminals or terminals clustered by overlapping shortest-path ancestors), solve that subset with `_exact_shared_edges`, then attach remaining terminals using the existing installed-tree multi-source Dijkstra. This preserves the current program’s robust scalability while extending the exact shared-edge optimization beyond the current 14-terminal cutoff, directly targeting the identified weakness of the pure greedy fallback.

2. **Add local-search improvement moves after constructing either an exact or greedy edge union.** Starting from `selected_edges`, repeatedly test replacing a branch or relay-to-terminal suffix with a cheaper path from any already reachable topology node, accepting only changes that reduce the union cost while preserving reachability of every terminal. The current DP already produces high-quality shared topologies and the greedy tree is valid but locally constrained; a prune-and-reroute phase can exploit additional sharing not captured by incremental attachment order.

3. **Use multiple greedy construction orders and retain the lowest-cost pruned topology for large terminal sets.** Keep the present multi-source attachment rule, but run it under several deterministic destination-selection policies: nearest-first, farthest-first, lowest standalone source-distance first, highest shared-prefix-overlap first, and several seeded randomized tie-break orders. Generation 6/9-style multi-start behavior materially improved greedy shared trees, and evaluating the actual deduplicated union cost after pruning provides a low-risk way to improve the fallback without weakening validation reliability.

4. **Decompose large destination sets into candidate clusters, solve clusters exactly, and merge their trees with shared-aware attachment.** Build clusters using shortest-path overlap, common predecessor/relay candidates, or terminal-to-terminal distance, run the directed-Steiner DP separately within each cluster, and then connect cluster topologies to the existing union using cheapest shared attachment paths. This extends the successful subset-DP merge principle while avoiding a full \(2^k\) state space, and it is more globally informed than treating every post-limit destination as an independent greedy attachment.

5. **Add a cost-preserving topology cleanup pass that removes redundant edges and re-optimizes extracted paths.** After `selected_edges` is built, iterate through edges in descending cost order, temporarily remove each edge, and keep it removed if all terminals remain reachable from `src`; then derive destination paths from the reduced union. Because the evaluator prices shared physical links and the best program already explicitly optimizes an edge union, this directly eliminates reconstruction or hybrid-merge redundancy while retaining the current source-root, sanitization, and path-validity guarantees.
