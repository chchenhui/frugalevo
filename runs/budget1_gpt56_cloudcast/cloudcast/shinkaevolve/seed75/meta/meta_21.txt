# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Shared directed edge-union optimization is the dominant successful pattern.** The current best, **Generation 14 – Shared-Tree Directed Steiner Broadcast**, reached **618.09 total cost / 123.62 average** with **5/5 successful configurations**. Rather than charging separately for each destination path, it maintains `installed_edges` and evaluates the union cost once. This is the major improvement over the independent-shortest-path baseline (**1035.14 total**), a reduction of roughly **40.3%**.

- **Greedy shared-tree construction plus exact small-terminal refinement is the strongest observed combination.** Generation 14 first builds a feasible shared tree using zero incremental weight for already-installed edges, then runs subset-DP exact directed Steiner refinement for **2–9 terminals** and replaces the greedy result only if `exact_cost < greedy_cost`. This matched or slightly exceeded the near-identical **618.10** results reported by Generations **7, 8, 11, and 15–19**, including the evaluated **Generation 20 hybrid_steiner_broadcast** at **618.10**.

- **Multi-start trunk selection improves the greedy baseline before exact refinement.** In the current best program, `build_shared_tree(seed)` is run once without a seed and once for every possible initial destination seed. The algorithm retains the minimum union-cost tree across these candidates. This avoids relying on one arbitrary first attachment and is stronger than single-growth greedy strategies such as **Generation 10**, which stopped at **627.12 total / 125.42 average**.

- **Reliability-preserving graph filtering and path materialization remained effective across top performers.** Generation 14’s removal of source-incoming edges and self-loops, safe handling of invalid costs through `_edge_cost`, and reconstruction of each destination’s path only from the final installed-edge graph produced **runs_successfully = 1.00**, **success_rate = 1.00**, and no failed configurations. Generation 20 used the same broad hybrid pattern and was likewise fully correct, confirming this is a stable implementation class.

## Ineffective Approaches

- **Greedy sharing without exact global refinement leaves measurable cost on the table.** **Generation 10 – Greedy Shared Multicast Steiner Routing** achieved **627.12 total cost**, about **9.03 higher** than Generation 14’s **618.09**. Its installed-edge zero-cost logic successfully finds sharing, but greedy attachment order can commit to an inferior trunk and branch structure that exact subset-DP later avoids.

- **Exact DP alone is not sufficient when reconstructed topology or objective alignment is weak.** **Generation 12** used an exact Dreyfus-Wagner-style approach through up to 12 terminals yet reported **795.08 total / 159.02 average**, much worse than the current best. The prior evaluation feedback indicates that its resulting union or path extraction was not aligned effectively with the evaluator’s shared-cost metric. The contrast with Generation 14 shows that exact DP must produce and preserve an economical installed-edge union, not merely calculate a nominal DP value.

- **Broader exact-solver thresholds did not improve the measured five-instance benchmark.** Generation 20’s exact threshold reaches **13 destinations**, while several related programs used thresholds from **9 through 16**, but these variants all clustered at approximately **618.10**. Generation 14’s narrower **2–9** DP range still achieved **618.09**, so there is no evaluation evidence that solving larger fanouts exactly improved the selected topology on these configurations.

- **Correctness problems erase any possible optimization benefit.** **Generation 13** had a similar shared directed-Steiner intent but recorded **runs_successfully = 0.00** and a zero combined score due to failures. In contrast, both Generation 14 and Generation 20 retained full validation success. The evaluated results show that conservative handling of unreachable destinations and valid per-partition path construction is essential.

## Implementation Insights

- **Generation 14’s directed-Steiner DP correctly models shared upstream infrastructure.** For each terminal bitmask, it combines disjoint submasks at the same node:
  `dp[submask][node] + dp[other][node]`,
  then propagates that combined subtree backward across predecessor edges. This means an upstream edge entering a relay is paid once before the subtree fans out, directly matching a directed shared-edge-union broadcast objective.

- **The best program uses exact DP as a guarded improvement, not as the only route-construction mechanism.** It always has a feasible greedy `installed_edges` candidate, computes `exact_edges` when applicable, and adopts them only if the physical union cost is lower. That safeguard helps explain its full **5/5** success rate while preserving the cost benefit of exact optimization. Generation 20 follows the same high-level hybrid model but was fractionally higher at **618.10**.

- **Greedy growth is implemented as marginal installation cost rather than conventional path cost.** In `incremental_weight`, an edge already in `edges` costs `0.0`; otherwise it costs `_edge_cost(data)`. Multi-source Dijkstra starts at all existing tree nodes, so candidate paths may reuse any previously installed branch at no additional union cost. This is the operational detail that turns shortest-path search into a shared-topology heuristic.

- **Topology optimization and API path output are properly separated.** The program first selects `installed_edges`, creates a restricted `broadcast_graph`, then runs source-to-destination Dijkstra within that graph for every destination. The same resulting edge path is copied to all partitions. This produces evaluator-valid path objects while ensuring measured differences come from the chosen physical union, not duplicated per-partition routing.

## Performance Analysis

- **Generation 14 is the best reported result, although only by a negligible displayed margin.** Its **618.09 total cost** is **0.01 lower** than Generation 20’s **618.10** and the same-cost tier represented by Generations 7, 8, 11, and 15–19. At two decimal places these should be treated as effectively tied in topology quality, but Generation 14 remains the recorded best.

- **There is a clear performance hierarchy across evaluated routing strategies.** Independent per-destination routing was about **1035.14 total**; weaker shared or mismatched exact approaches were around **759.09–795.08**; strong pure greedy sharing reached **627.12**; and hybrid greedy-plus-directed-Steiner approaches reached roughly **618.09–618.10**. Most of the improvement comes from edge sharing, while exact refinement provides the final roughly **9.03** reduction beyond the strongest listed greedy-only implementation.

- **Expansion of exact-terminal coverage has no observed cost correlation in this benchmark.** Generation 20’s up-to-13-terminal exact phase did not beat Generation 14’s up-to-9-terminal phase; both were fully successful, yet the former produced **618.10** versus **618.09**. Likewise, previous threshold variants through 16 terminals stayed at **618.10**. The reported configurations therefore appear to be dominated by small-fanout cases, cases already solved optimally within the lower DP threshold, or larger cases where the greedy fallback determines the result.

- **All leading correct implementations still receive no evaluator reward despite strong relative cost performance.** Generation 14 has **combined_score = 0.00** and **cost_score = 0.00** despite the best observed **618.09** total cost, and Generation 20 has the same zero scores at **618.10**. Since both had perfect execution and validation, the zero score reflects an evaluator threshold or baseline below this entire leading performance tier, rather than any reliability or output-format deficiency.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Add a cost-monotone pruning pass after selecting `installed_edges`.** Iteratively test installed edges in descending `_edge_cost` order, temporarily remove each edge, and retain the removal whenever every reachable destination can still be reached from `src` in the remaining directed subgraph. This is low risk because the current algorithm already materializes paths only after topology selection, and it can eliminate redundant cycle/alternate-route edges introduced by greedy growth or DP reconstruction without changing valid destination reachability.

2. **Use deterministic multi-order greedy construction in addition to the current initial-seed enumeration.** Extend `build_shared_tree` to support destination attachment policies such as farthest source-distance first, nearest first, descending direct-path cost, and a relay-overlap ordering based on shared prefixes of source shortest paths; retain the lowest deduplicated union after pruning. Generation 14 already proves that candidate diversity matters through seed selection, while Generation 10 shows greedy shared routing is close enough to optimal that better construction order can plausibly improve larger groups beyond the `<= 9` DP limit.

3. **Implement exact-core-plus-greedy attachment for destination sets larger than nine.** Select a core of 7–9 terminals with the largest estimated shared-trunk opportunity—for example, terminals whose reverse shortest-path trees meet at common relays—solve that core with the existing directed Steiner DP, then attach remaining destinations through the zero-incremental-cost multi-source Dijkstra routine. This preserves the current program’s reliable feasible-tree fallback and proven DP recurrence, while targeting the cases currently handled only by greedy search.

4. **Add bounded local directed-Steiner reoptimization around expensive branching points.** After building the final tree, identify high-cost edges or relay nodes that dominate paths to several destinations, choose up to 9 downstream terminals affected by that branch, and rerun the existing subset DP while treating retained upstream/tree edges outside the local region as zero incremental cost. Accept the replacement only when recomputing the full unique installed-edge union produces a strictly lower cost, extending the successful exact-refinement idea to useful neighborhoods of larger multicast trees.

5. **Introduce relay-aware alternative trunk candidates before exact refinement.** Build candidate trees by selecting promising relay nodes—such as nodes appearing frequently in direct source-to-destination shortest paths—and force an initial source-to-relay trunk before attaching destinations with the current marginal-cost search. Compare these relay-seeded trees with the existing destination-seeded candidates using total unique edge cost, then retain the best as the greedy baseline for DP comparison; this directly exploits the DP’s demonstrated merge-at-relay advantage while remaining scalable and reliability-preserving.
