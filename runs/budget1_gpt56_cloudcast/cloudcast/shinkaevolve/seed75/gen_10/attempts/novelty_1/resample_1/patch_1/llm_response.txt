<DESCRIPTION>
The greedy multicast-tree construction currently evaluates each new destination path using the full link cost, including edges that are already part of the multicast tree. This incorrectly penalizes paths that reuse an existing shared trunk, even though a broadcast only pays for that trunk once.

Evaluate attachments on a marginal-cost graph instead: selected tree edges receive zero cost while all unselected links retain their transfer cost. The shortest attachment then represents only the additional network transfer needed to extend the current broadcast topology. This better favors fan-out from already replicated data, reduces redundant cross-cloud transfers, and can discover lower-cost shared routes across multiple networks.
</DESCRIPTION>
