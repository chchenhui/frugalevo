# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Exact directed Steiner subset DP remains the strongest observed routing pattern.** The current best program, **Hybrid Directed Steiner Broadcast Routing** (Generation 18, `incumbent_pruned_steiner`), achieved **618.10 total cost / 123.62 average cost** with **5/5 successful configurations**. Its DP state, `dp[mask][node]`, models the minimum-cost directed subtree rooted at `node` that reaches a terminal subset. This explicitly captures the value of shared downstream relay branches, unlike terminal-by-terminal attachment.

- **Reverse-graph Dijkstra relaxation is a consistently successful implementation technique for directed Steiner construction.** Generation 18 initializes singleton terminal states at zero cost and relaxes through `h.predecessors(node)`, adding the original forward edge cost. This finds the cheapest upstream source/relay node that can feed a solved subtree. The same general exact-DP-plus-reverse-relaxation design also produced **618.10** in Generations 12, 13, 15, 16, 17, and 19, confirming that this is the dominant successful pattern rather than an isolated result.

- **Shared-edge tree materialization substantially outperformed independent routing.** The current program reconstructs one selected edge union, normalizes it into source-to-terminal routes, and gives every partition the same route over this common tree. This aligns with the prior observed improvement from **1035.14** for independent per-destination shortest paths to **618.10** for exact shared-Steiner designs, a **40.3% raw-cost reduction**.

- **Defensive graph sanitization was compatible with perfect reliability.** Generation 18 removes source-incoming edges, self-loops, negative/non-finite/malformed costs, and gracefully returns empty routes for unreachable nodes. All newer exact and hybrid variants retained **success_rate = 1.00**, so filtering invalid routing options did not create validation regressions.

## Ineffective Approaches

- **Pure greedy shared-tree growth remained materially worse than exact shared-subset optimization.** **Greedy Shared Multicast Tree** (Generation 10) used repeated multi-source Dijkstra and marginal transfer-cost attachment, but cost **795.06 total / 159.01 average**, which is **176.96 cost units (28.6%) higher** than Generation 18’s 618.10. Its local “best next connector” selection cannot account for relay nodes whose value appears only when several future terminals are jointly considered.

- **A fixed exact terminal core with greedy attachments performed especially poorly on the tested inputs.** **Hybrid Directed Steiner Broadcast Planner** (Generation 11) used exact DP for up to 11 terminals and a distant-terminal exact core plus greedy attachments above that point, yet produced the worst listed result at **1065.12 total / 213.02 average**. This is even worse than Generation 10’s basic greedy construction, indicating that the chosen core/attachment decomposition failed to preserve the shared structure favored by the evaluator.

- **Restricting exact optimization too aggressively left substantial cost on the table.** Generation 14 considered exact Steiner candidates only through **eight terminals**, alongside shared-attachment, marginal-union, and independent shortest-path candidates. It reached **741.08 total / 148.22 average**, nearly identical to the older greedy family and **122.98 above** the 618.10 exact-Steiner result. Its small exact-solver range did not cover enough of the multicast decision space.

- **More elaborate hybrid names or pruning stages did not improve on the 618.10 plateau.** Generations 12, 13, 15, 16, 17, and 19 all matched Generation 18 at **618.10**, despite differences such as 9-, 12-, 13-, or 15-terminal exact cutoffs, relay-aware greedy fallback, pruning, and core-tree logic. These variants were correct but showed no measurable raw-cost gain beyond the established exact-DP topology.

## Implementation Insights

- **Generation 18’s exact DP is effective because it supports both branching and directed path extension.** For every non-singleton terminal mask, `_exact_steiner_tree` first evaluates partitions of the mask at a common node with `left[node] + right[node]`, then propagates the merged subtree backward across incoming directed edges. The `"merge"` decisions represent multicast branching; the `"edge"` decisions represent directed relay extension. This directly models the shared broadcast objective reflected in the best observed **618.10** cost.

- **The program builds a feasible greedy incumbent before exact search.** `_greedy_shared_tree` provides an immediately deployable shared-edge topology and `_normalize_tree` removes unused cycles/redundant links by retaining source-reachable shortest routes within the selected union. The incumbent’s summed edge cost is passed as `upper_bound` into the exact DP, so states costing at least the known feasible tree are not expanded. This preserved full correctness while keeping exact search practical through **12 unique terminals**.

- **Tree reconstruction preserves edge sharing until the final path materialization stage.** `_exact_steiner_tree` accumulates `selected_edges` from DP decisions in a single `nx.DiGraph`, then `_normalize_tree` derives source-rooted paths from that selected union. Only afterward does `search_algorithm` translate each destination’s node route into edge records and replicate that route across partitions. This is materially different from computing independent paths first, which prior results show incurred **1035.14** cost.

- **There is evidence that implementation refinements after the core DP had limited cost impact.** Generation 18’s incumbent pruning, Generation 17’s “cost-aware tree materialization,” Generation 12’s larger exact limit, and Generation 19’s greedy-incumbent/exact-relaxation design all converged to **618.10**. The shared exact DP formulation—not the surrounding naming, pruning, or normalization variation—appears to be the main driver of the observed best result.

## Performance Analysis

- **The raw-cost ranking strongly favors globally shared exact trees.** Across the available evaluations: independent shortest paths were **1035.14**, Generation 11’s hybrid core planner was **1065.12**, Generation 10’s greedy multicast tree was **795.06**, Generation 14’s limited exact/candidate hybrid was **741.08**, prior marginal-cost search was **627.13**, and the exact-Steiner family led by Generation 18 achieved **618.10**. This shows a clear progression as the algorithm gains the ability to optimize branching decisions jointly.

- **Generation 18 decisively outperformed greedy designs while matching every other strongest exact variant.** Its **618.10** total is **176.96 lower than Generation 10** and **122.98 lower than Generation 14**. However, it is tied with Generations 12, 13, 15, 16, 17, and 19. The repeated tie indicates that the evaluated configurations either fit within all relevant exact-search limits or lead these variants to the same selected topology.

- **The prior marginal-cost approach came close but did not equal exact DP.** Previous results place the more sophisticated marginal-union search at **627.13**, only **9.03 cost units (1.46%)** above the Generation 18 exact result. This confirms that accounting for already-selected edges captures much of multicast sharing, but the remaining gap corresponds to globally beneficial terminal-subset and branch-point choices captured by the exact state space.

- **Reliability does not distinguish the candidates; raw cost does.** Every listed Generation 10–19 program had **5 successful configurations, zero failures, and success_rate 1.00**. Nevertheless, every program—including current-best Generation 18—received **combined_score = 0.00** and **cost_score = 0.00**. The benchmark’s threshold therefore was not reached by any evaluated implementation, but the actual total-cost data consistently identifies the exact directed-Steiner family at **618.10** as the best observed approach.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Raise the exact-DP coverage using adaptive terminal reduction rather than a fixed 12-terminal cutoff.** Before falling back to greedy routing, contract or group terminals that lie on the same cheap source-to-terminal corridor, then run the proven reverse-relaxed subset DP over cluster representatives plus structurally distinct terminals. After solving the representative tree, expand each cluster with marginal-cost attachments; this extends exact shared-branch optimization to larger destination sets while preserving the successful `dp[mask][node]` formulation.

2. **Replace the strict incumbent cutoff with admissible branch-and-bound lower bounds for DP states.** The current condition `candidate < upper_bound` prunes only by accumulated subtree cost, which can reject equal-cost exact solutions and cannot distinguish states that are cheap so far but expensive to connect to `src`. Add a lower bound such as `dp_cost + reverse_distance_to_src[node]` (and optionally a terminal-connectivity bound for unresolved masks), and prune only when that bound cannot beat the greedy incumbent; this should permit more useful exact-state exploration without sacrificing the incumbent-guided runtime benefit.

3. **Seed the exact solver with multiple feasible shared-tree incumbents, not only the one-order greedy tree.** Generate several marginal multicast trees using different attachment priorities—for example nearest marginal terminal, farthest source-distance terminal, largest overlap with existing tree, and randomized deterministic tie orders—and use the cheapest normalized tree as the DP upper bound. The marginal-union family was already close to exact performance (627.13 versus 618.10), so stronger incumbents may unlock exact search on more terminals and improve fallback quality when exact search is limited.

4. **Add a directed local-improvement phase to the reconstructed shared tree.** For each non-source relay/branch node, identify the descendant terminals it serves, temporarily remove its incoming edge or a redundant subtree, and test alternate predecessor-to-branch paths whose incremental union cost is lower while retaining reachability for all affected destinations. Although the subset DP is exact under its selected state model, reconstruction and normalization can leave equal-cost decision artifacts; safe exchange moves over the final unique-edge union could uncover a lower evaluator-cost topology.

5. **Implement sharing-aware deterministic tie-breaking in both DP decisions and tree normalization.** When merge or reverse-edge relaxations have equal numerical cost, prefer candidates that use nodes or edges present in already selected lower-mask solutions, favor lower out-degree relay chains only when they do not reduce reuse, and prioritize paths with greater terminal-subtree overlap. The current implementation accepts only strict improvements and therefore lets insertion/order effects choose among equivalent DP solutions; explicit tie resolution is low risk and may change the materialized edge union even where reported DP costs are tied.
