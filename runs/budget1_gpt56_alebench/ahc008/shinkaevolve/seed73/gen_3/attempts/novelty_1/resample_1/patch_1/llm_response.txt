reachable_wall_targeting

<DESCRIPTION>
The wall-selection heuristic currently ranks candidate standing squares by Manhattan distance. After several walls have been built, a geometrically close candidate can be unreachable. In that case `get_bfs_move_char` returns `.`, but the code considers the target successfully selected and resets the stuck counter, potentially causing a human to repeatedly target the same unreachable wall forever.

Add a lightweight BFS distance routine using the current passability map and tentative walls, then use that true path distance when evaluating wall targets. Unreachable candidates are ignored. This preserves the existing strategy while substantially improving its ability to finish partially constructed enclosures.
</DESCRIPTION>

            dist[r][c] = -1;
        }
    }

    std::queue<Point> q;
    q.push(start_pos);
    dist[start_pos.r][start_pos.c] = 0;

    while (!q.empty()) {
        Point cur = q.front();
        q.pop();
        for (int d = 0; d < 4; ++d) {
            Point nxt = {cur.r + DIRS[d].r, cur.c + DIRS[d].c};
            if (!is_valid_point(nxt) || is_impassable_grid_static[nxt.r][nxt.c] ||

                continue;

            dist[nxt.r][nxt.c] = dist[cur.r][cur.c] + 1;
            q.push(nxt);
        }
    }
    return INF;
}
