<DESCRIPTION>
The incremental scoring currently counts both the old and new edge lines when an edge moves or a bulge is inserted. This is incorrect for fish exactly on a boundary: for an expansion, fish on the old edge were already inside and must not be added again; for a contraction, fish on the new edge remain inside and must not be removed.

This matters especially because the search deliberately snaps edge coordinates to fish coordinates. Correcting the swept-strip query prevents score drift, improving SA acceptance decisions and ensuring that the retained best polygon corresponds much more closely to its actual judged score.
</DESCRIPTION>

// Count precisely the part of the rectangle whose membership changes when an
// axis-parallel boundary moves from old_coord to new_coord.  When expanding,
// the old boundary was already inside; when contracting, the new boundary is
// still inside.  This distinction is essential because fish on polygon edges
// are considered caught.
void calculate_score_delta_for_swept_edge(int old_coord, int new_coord,
                                          int span_min, int span_max,
                                          bool is_vertical, bool expanding,
                                          int& delta_m, int& delta_s) {
    int lo = std::min(old_coord, new_coord);
    int hi = std::max(old_coord, new_coord);

    if (expanding) {
        if (new_coord > old_coord) ++lo;
        else --hi;
    } else {
        if (new_coord > old_coord) --hi;
        else ++lo;
    }

    if (is_vertical) {
        calculate_score_delta_for_rectangle(lo, hi, span_min, span_max, delta_m, delta_s);
    } else {
        calculate_score_delta_for_rectangle(span_min, span_max, lo, hi, delta_m, delta_s);
    }
}
