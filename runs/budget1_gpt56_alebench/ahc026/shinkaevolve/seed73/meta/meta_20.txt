# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Shortest non-source destination selection is the proven score-driving heuristic.** The current best program selects, immediately before every suffix relocation, the currently shortest stack excluding the source. It achieved **8785.74**, with **50/50 ACCEPTED**. This exactly matches Generations **9, 11–18, and 20**, whose implementations differ in lookup details but all use the same shortest-stack placement rule and also score **8785.74**. The repeated identical result strongly confirms that dynamic load balancing—not incidental coding variation—is the key successful policy.

- **Ascending target extraction plus one whole-suffix transfer is consistently legal and effective.** The best program processes `target = 1..n`, relocates exactly the boxes above the target as a single contiguous block, then removes the now-exposed target. Programs such as **Greedy Stack Uncovering** (Generation 9), **Sequential Target Stack Extraction** (Generation 13), and **Greedy Stack Unblocking Simulation** (Generation 20) all use this pattern and pass all 50 cases at the top score. It avoids moving blockers individually and preserves their stack order.

- **Current best combines direct target lookup with exact metadata maintenance.** Its `pos[box] = {stack, height}` table makes target lookup constant time, while only the transferred suffix has its metadata updated. This matches the successful metadata-based designs in Generations 9, 11, 12, 15, 16, and 20. The result is a direct simulation that is both robust and efficient enough for all tested instances.

- **Empty-stack preference is compatible with, but does not improve beyond, shortest-stack placement.** Generation 17 explicitly selects an empty destination when available, otherwise the shortest stack, yet still scores **8785.74**. Since an empty stack is necessarily a shortest stack, this supports the conclusion that the effective decision rule is minimum destination height; special-case empty handling does not yield a measured gain.

## Ineffective Approaches

- **Fixed cyclic or “next stack” relocation is substantially worse despite full correctness.** Prior cyclic-destination programs—Generations **1, 3, 6, 7, 8, and 10**—were accepted on all cases but scored only **8064.82**. Compared with the current best’s **8785.74**, this is a loss of **720.92 points**. These solvers still process boxes in order and move whole suffixes, so the observed degradation is specifically associated with ignoring current stack heights when selecting the buffer.

- **Linear target searching does not harm the judged score here, but offers no demonstrated score advantage.** Generation 14 and Generation 18 use linear location/search variants and still obtain **8785.74**, because they retain shortest-stack placement. This means lookup structure is not responsible for the objective improvement. Generation 18’s feedback notes that repeated searches and vector operations may scale less well on large instances, but no score penalty appeared on the evaluated 50-case suite.

- **Advanced planning had no measured value when it failed portability requirements.** The previous beam-search/simulated-annealing implementation (Generation 0) received **0.00**, passed **0/50**, and had validity **0.00** because `<span>` was unsupported. Consequently, the evaluation provides no evidence that its more elaborate planning would beat the simple greedy solver; compilation compatibility dominated all potential algorithmic sophistication.

## Implementation Insights

- **The current best’s state representation directly supports its successful policy.** Stacks are bottom-to-top `std::vector<int>` objects, and `pos` gives each live box’s stack and zero-based height. For each target, the code computes:
  - source stack: `pos[target].first`,
  - target height: `pos[target].second`,
  - moved suffix start: `target_height + 1`.
  
  This makes the intended block relocation explicit and avoids rescanning all stacks to find the required target.

- **Metadata is updated only where mutations occur.** On a block move, the best program appends each suffix element to `stacks[dst]` and updates that box’s `pos` entry using `old_dst_size + offset`; after transfer, `stacks[src].resize(first_moved_height)` removes the suffix. The target’s own `pos` entry need not be updated because it is immediately removed. This is a compact and correct bookkeeping pattern validated by all **50/50** accepted cases.

- **Operation encoding aligns exactly with block semantics.** The current best records `(first_moved_box, dst + 1)` before moving the suffix, where `first_moved_box` is the bottommost element of the relocated block. It then records `(target, 0)` for removal. Generations 13, 16, and 18 use the same conceptual encoding. This is important because the judge interprets a relocation by its bottom moved box, not by every individual blocker.

- **Preallocation and buffered output are sensible supporting optimizations.** The best program reserves `n` capacity for every stack and reserves `2*n` operations. Generation 13 similarly highlights reservation and bulk-oriented vector handling as practical efficiency choices. Although the exact number of operations can be below `2n`, the bound is safe because each target produces one removal and at most one relocation.

## Performance Analysis

- **The evaluated programs form a clear two-tier score pattern.**
  - **8785.74:** current best and shortest-different-stack implementations, including Generations **9 and 11–18, 20**.
  - **8064.82:** fixed cyclic/next-stack implementations from the prior results.
  
  All direct simulators were generally correct, so the **720.92-point** gap isolates destination selection as the measured quality difference.

- **The current best is tied with many independently implemented variants, establishing a robust plateau rather than a one-off result.** Programs using position tables, such as Generations 9, 11, 12, 15, 16, and 20, and programs using more direct or linear scanning approaches, such as Generations 14 and 18, all reach exactly **8785.74**. Therefore, the tested objective appears insensitive to these representation-level differences once minimum-height relocation is used.

- **Correctness is saturated among the simple greedy family; solution quality differentiates them.** Every listed shortest-stack variant achieved **ACCEPTED on 50/50 cases**, as did the lower-scoring cyclic variants. Thus, the performance signal is not legality or output validity: it is the effect of balanced relocation on the judge’s optimization criterion.

- **The current best’s implementation is especially well aligned with the dominant successful mechanism.** Unlike cyclic solvers, it recomputes the shortest legal destination using current mutable stack sizes for every relocation. Unlike search-based code that did not compile, it uses portable standard C++ vector operations and straightforward bookkeeping. This combination produced the top observed score, **8785.74**, with complete validation coverage.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Retain the exact ascending-target, whole-suffix relocation framework as the non-negotiable baseline.** Continue processing `target = 1..n`, moving the complete suffix above the target in one operation, and then emitting the target-removal operation immediately. This is the common structure of all 50/50 accepted high-scoring programs, so experimental mutations should modify only destination choice or tie-breaking—not extraction order or block semantics.

2. **Add a deterministic tie-breaker when multiple non-source stacks share the minimum height.** Keep minimum current height as the primary destination criterion, but among tied shortest stacks prefer one whose top box has a larger label, or whose contents contain fewer low-numbered boxes likely to be needed soon. The current program selects the first minimum-height stack by index, and all observed best-score variants effectively leave this tie space unexplored; tie-breaking is therefore a low-risk source of score improvement.

3. **Implement bounded candidate look-ahead only for equally short or near-shortest destination stacks.** For a relocation, form candidates consisting of stacks at minimum height, optionally plus stacks within one box of that height; simulate the next 5–20 target extractions for each candidate and choose the one with the fewest predicted moved boxes or relocations. This preserves the proven load-balancing behavior while allowing the solver to distinguish choices that are identical under the current greedy rule but may create different future blocking patterns.

4. **Use a future-blocking-aware secondary score without abandoning shortest-stack placement.** For each destination candidate, compute a lightweight score such as `large_weight * destination_height + moved_suffix_count_of_boxes_with_label <= target + horizon`, or penalize suffix boxes whose labels are among the next `H` targets. The dominant height term preserves the empirically superior 8785.74 minimum-load policy, while the future-label term can avoid burying boxes that will soon need to be extracted.

5. **Preserve and extend the current exact `pos` metadata to support fast speculative simulation.** Keep `pos[box] = {stack, height}` and suffix-only metadata updates in the primary state, but implement candidate evaluation using reversible move logs or copied state for only the affected stacks and moved suffixes. Direct lookup did not independently raise the measured score, but it is the implementation feature that makes bounded look-ahead feasible without replacing the portable, validated vector-based simulation.
