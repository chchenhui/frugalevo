# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Bounded destination lookahead produced the highest observed score.** The current best program, **Lookahead-Guided Stack Sorting**, achieved **8868.08** with **50/50 ACCEPTED**. It retains the proven ascending extraction model—remove targets `1..n`, relocate the complete suffix above a buried target, then remove the exposed target—but improves the relocation destination decision through a 12-target forward simulation.

- **The current best improves on shortest-stack greedy without abandoning its balancing principle.** Rather than considering every stack indiscriminately, it first finds the minimum non-source height and considers only destinations whose height is at most `min_height + 1`. This preserves the core load-balancing behavior responsible for the earlier **8785.74** plateau while allowing lookahead to choose among similarly short buffers.

- **Future-aware placement measurably improves over purely local placement.** Generation 29, **Greedy Stack Unblocking and Removal**, used shortest-stack selection with an earliest-label-aware tie-break and scored **8834.58**. The current best’s explicit simulation of the next 12 extractions scores another **33.50 points** higher, showing that directly estimating near-future forced relocations is more effective than a static label-based tie-break.

- **Whole-suffix relocation remains the common correctness foundation.** The current best and all high-performing variants move blockers as a single contiguous suffix identified by the first moved box, then output `(target, 0)` for removal. This pattern was accepted across all 50 validation cases in the current solver, Generation 29, and the shortest-stack solvers from Generations 19–23.

## Ineffective Approaches

- **Fixed next-stack/cyclic relocation remains substantially weaker than state-aware destination selection.** Generations 24–27, including **Sequential Stack Unloading** and **Sequential Stack Clearing with Temporary Transfers**, all passed **50/50** but scored only **8064.82**. Their cyclic destination policy is **803.26 points below** the current best’s **8868.08**, confirming that choosing a buffer without regard to present stack loads or future interference is the principal quality loss.

- **Pure shortest-stack selection is strong but leaves measurable optimization value unused.** Generations 19–23 scored **8785.74** with the same sequential suffix-transfer strategy and shortest non-source destination rule. They are correct and robust, but are **82.34 points below** the current best. The new result shows that balancing stack heights alone does not fully minimize future blocking.

- **Static future-awareness is weaker than simulated future behavior.** Generation 29’s tie-break prefers stacks whose smallest box label is later, attempting to avoid burying soon-needed boxes. This raised its score to **8834.58**, but still trailed the current best by **33.50 points**. The result indicates that one summary statistic—the smallest label in a stack—does not capture the full cost of upcoming suffix relocations.

- **Implementation complexity without portability does not provide usable value.** As noted in the previous evaluation history, the earlier unsupported beam-search/simulated-annealing implementation failed compilation due to `<span>`, receiving **0.00** and **0/50** acceptance. In contrast, the current best uses portable `std::vector` operations and standard headers while still obtaining the top score.

## Implementation Insights

- **The current best evaluates relocation choices on an accurate trial state.** For each candidate destination, it copies `stacks`, appends the suffix above the current target to that candidate, erases the suffix from the source, and removes the current target before simulating targets `target + 1` through `min(n, target + 12)`. This is important: the lookahead starts from the state that would actually exist after the currently planned relocation and removal.

- **Its evaluation metric is tied to future blocking work.** During each trial extraction, the program adds `moved + 1` whenever a future target is buried, where `moved` is the number of boxes above that target. It then applies a shortest-destination move within the trial. Thus, candidate placement is judged by the amount of immediate future unblocking work it induces, while preserving the already validated shortest-stack behavior as the rollout policy.

- **Candidate pruning keeps the stronger policy bounded.** The program does not simulate all placements equally: it admits only non-source stacks with size `<= min_height + 1`. Since the basic shortest-stack policy already scored **8785.74**, this pruning focuses computation on placements that remain near-balanced and avoids considering obviously overloaded buffers. The accepted **8868.08** result demonstrates that this restricted candidate set was sufficient on all 50 cases.

- **The code keeps legal operation encoding and stack mutation simple.** As in the successful greedy programs, stacks are bottom-to-top vectors; `stacks[source][position + 1]` identifies the bottommost moved box, which is emitted as `(first_moved_box, destination + 1)`. The suffix is transferred with `insert`, removed with `erase`, and the target is subsequently removed with `pop_back`. This is consistent with the legal block-move semantics validated by every accepted solver.

## Performance Analysis

- **The results now form a clear three-level optimization progression.**
  - Fixed cyclic/next-stack relocation: **8064.82** — Generations 24–27.
  - Shortest-stack greedy relocation: **8785.74** — Generations 19–23.
  - Future-aware policies: **8834.58** for Generation 29 and **8868.08** for the current best.
  
  All these approaches passed all 50 cases, so the score differences reflect solution quality rather than correctness.

- **Dynamic balancing delivers the largest measured improvement.** Moving from the fixed next-stack strategy (**8064.82**) to current shortest-stack placement (**8785.74**) gained **720.92 points**. This remains the dominant gain in the evaluated results and confirms the earlier insight that buffer-stack load balancing is the essential baseline policy.

- **Lookahead adds a smaller but real second-stage gain.** The current best improves by **82.34 points** over the shortest-stack plateau and by **33.50 points** over Generation 29’s future-aware tie-break. Because all three use the same target order and whole-suffix transfers, the measured difference is attributable specifically to destination selection quality.

- **Search cost was acceptable under the evaluated constraints.** Earlier shortest-stack implementations used direct searches or position tables and all reached the same **8785.74** score, indicating that lookup representation was not responsible for objective quality. The current best deliberately accepts extra work—copying trial vectors and repeatedly locating future boxes during a 12-step rollout—and nevertheless remained fully accepted on **50/50** cases while producing the top score of **8868.08**.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Tune the lookahead horizon and make it adaptive to the amount of blocking.** Test fixed horizons such as 8, 16, 20, and 24, but also try `H = min(24, 6 + 2 * moved_suffix_size)` so expensive relocations receive more future evaluation than one-box moves. The current 12-step rollout is the strongest observed policy, so extending the same exact trial-state simulation is lower risk than replacing it with a fundamentally different extraction strategy.

2. **Use a richer lexicographic rollout objective rather than only `moved + 1`.** Keep predicted relocation work as the primary score, but break equal scores using secondary measures such as total number of boxes moved, maximum trial-stack height, and the number of next-`H` targets buried after the rollout. This preserves the demonstrated value of near-balanced placement while distinguishing candidates that have equal immediate cost but leave different future stack structures.

3. **Expand destination candidates selectively beyond `min_height + 1` when future benefit is compelling.** Evaluate the current near-shortest set first, then optionally include stacks of height `min_height + 2` only when their top suffix contains fewer labels from the next lookahead window or when simulation predicts strictly lower blocking cost. The existing pruning is clearly effective, but a controlled extra candidate tier could capture rare cases where accepting one additional unit of imbalance prevents repeatedly burying imminent targets.

4. **Improve rollout fidelity by applying the same lookahead-aware destination rule recursively for the first few simulated extractions.** In the current trial, future targets use plain shortest-stack relocation, so candidate evaluation may underestimate interactions caused by future tie choices. For example, use the existing candidate rule plus a smaller secondary horizon of 3–5 steps during simulation, or use a deterministic future-aware tie-break among equal-height destinations; this extends the proven policy while keeping the speculative search bounded.

5. **Add a deterministic imminent-target placement penalty before or alongside rollout scoring.** For each candidate destination, inspect the moved suffix and penalize placing boxes labeled in `[target + 1, target + H]` onto a stack that already contains especially near-future targets, particularly if those targets would become deeply buried. Generation 29 already showed that static label awareness improves over pure shortest-stack selection, and combining such a penalty with the current exact simulation may resolve rollout-score ties more intelligently without abandoning the successful whole-suffix, ascending-target framework.
