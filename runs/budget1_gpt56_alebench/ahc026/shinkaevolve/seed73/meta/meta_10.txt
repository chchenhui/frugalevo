# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Minimum-height buffer selection is the clear scoring improvement.** The current best program, **Greedy Stack Clearance by Target Order**, scored **8785.74** on all **50/50** cases by moving the suffix above each target to the *shortest different stack*. The equivalent strategies in **Greedy Stack Unblocking Sort** (Generation 4) and **Greedy Stack Unloading with Minimum-Height Buffer** (Generation 5) achieved the identical **8785.74**, confirming this is a robust improvement rather than an implementation accident.

- **Process required boxes in ascending target order and unblock with one suffix move.** The current best program locates `target`, transfers the entire contiguous block above it in one operation, then removes the newly exposed target. This maintains legality and keeps each target to at most one relocation plus one removal operation. All accepted variants use this fundamental pattern.

- **Bulk suffix transfers preserve ordering and reduce operations.** Rather than moving blockers individually, the current best uses:
  `insert(destination.end(), source.begin() + position + 1, source.end())`
  followed by erasing the source suffix. This matches the strong accepted behavior of the other block-relocation solvers and avoids unnecessary move operations.

- **Balancing live stack heights beats a fixed relocation destination.** Programs using the cyclic “next stack” destination—such as **Sequential Block Relocation Solver** (Generation 1), **Sequential Block Relocation Sort** (Generation 3), and **Sequential Stack Block Relocation** (Generation 6)—all passed every case but scored only **8064.82**. Dynamic minimum-height placement produced a gain of **720.92 points** over these fixed-destination variants.

## Ineffective Approaches

- **Using a fixed cyclic destination degraded the score despite full correctness.** Generations 1, 3, 6, 7, 8, and 10 achieved **8064.82**, versus **8785.74** for the shortest-stack policies. Their common limitation was moving each obstructing suffix to the next cyclic stack rather than accounting for current stack heights. This apparently creates less favorable future configurations and more expensive subsequent clearances.

- **The C++20 `std::span` dependency prevented any evaluation.** **Beam Search and Simulated Annealing Stacker** (Generation 0) scored **0.00**, passed **0/50** cases, and had validity **0.00** because the environment lacked `<span>`. Its potentially more sophisticated beam-search/annealing logic was never evaluated, so no algorithmic benefit can be inferred from it.

- **More sophisticated search did not translate into measured performance because portability failed first.** The beam-search program included destination planning, partial suffix simulation, and simulated annealing, but its non-compilation means it underperformed every simple C++17-compatible direct simulator in actual judge results.

## Implementation Insights

- **The current best program’s representation is simple but sufficient for the tested constraints.** It stores each stack as a bottom-to-top `std::vector<int>`, scans stacks linearly to find each target, and directly simulates legal moves. Generation 5 explicitly confirms that linear searches and vector insert/erase operations were sufficient for the official input sizes; the current best’s **50/50 accepted** result supports that conclusion.

- **Choosing the destination immediately before each relocation is important.** In the current best, `best_height` is recomputed from the current mutable stack sizes while excluding the source stack. This ensures the transferred suffix goes to the least-loaded legal buffer at that exact state, which is the key implementation distinction from the **8064.82** cyclic variants.

- **Operation encoding is compact and correctly aligned with block semantics.** For a suffix relocation, the current best records `{first_moved_box, destination + 1}`, where `first_moved_box` is the bottommost box in the transferred suffix. It then records `{target, 0}` for extraction. The order-preserving `insert`/`erase` logic guarantees that this recorded move corresponds to a valid contiguous block transfer.

- **Metadata tables are not required for score quality under these constraints.** Programs such as **Sequential Block Relocation Solver** and **Sequential Box Extraction with Block Moves** maintained per-box position metadata, yet remained at **8064.82** because they retained cyclic placement. Thus, direct lookup can reduce simulation overhead, but the observed score difference is driven by relocation policy, not target-location data structures.

## Performance Analysis

- **The evaluation separates correctness from solution quality.** Every direct block-relocation simulator except the non-compiling C++20 program passed all **50** cases. However, accepted scores formed two distinct tiers:
  - **8785.74:** shortest-different-stack greedy placement (current best; Generations 2, 4, and 5).
  - **8064.82:** fixed cyclic/next-stack placement (Generations 1, 3, 6, 7, 8, and 10).

- **The current best outperformed the cyclic family by approximately 8.94%.** The absolute increase is **720.92** points (`8785.74 - 8064.82`), demonstrating that stack-height balancing materially improves the judged objective even though both families use the same ascending-target and whole-suffix relocation structure.

- **Equivalent results across multiple independent greedy implementations strengthen the causal conclusion.** Generations 2, 4, and 5 all obtained precisely **8785.74** with shortest-stack destination selection, despite differing in whether they maintained box-location metadata or used linear scans. This indicates the destination heuristic is the dominant contributor to the higher score.

- **Compilation compatibility is a hard performance prerequisite.** Generation 0’s **0.00** versus the current best’s **8785.74** shows that unsupported language/library features eliminate all potential gains from advanced optimization logic.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Keep ascending-target extraction and whole-suffix moves as the immutable baseline.** Any mutation should continue locating targets `1..n` in order, moving all boxes above the target as one contiguous suffix, then immediately extracting the target. This structure is shared by every accepted solver and prevents regressions from per-box relocation or out-of-order extraction.

2. **Extend the minimum-height destination rule with a small tie-breaker heuristic.** Preserve “choose the shortest different stack” as the primary criterion, but when several destinations have equal minimum height, evaluate deterministic tie-breakers such as preferring the stack whose top box has the largest label, or the destination that minimizes the next target’s estimated blocking depth. Since minimum-height selection is responsible for the observed 8785.74 tier, tie-breaking is a low-risk way to improve future configurations without abandoning the proven policy.

3. **Test a bounded look-ahead among only near-minimum-height buffers.** For each suffix relocation, collect stacks within a small height window of the minimum, simulate each candidate destination for the next few targets, and choose the candidate with the lowest estimated future relocation cost. Restricting the candidate set and horizon—for example, the 2–3 shortest stacks and 5–20 next targets—retains the best program’s efficient greedy behavior while allowing it to avoid locally tied placements that create expensive future blockages.

4. **Introduce an explicit relocation-cost objective for destination selection.** Instead of scoring candidates only by current stack height, score them with a lightweight formula such as `current_height + alpha * number_of_near-future-targets-in-moved-suffix + beta * predicted_depth_of_next_targets`. The proven shortest-stack heuristic should remain the dominant term, but this mutation can distinguish equally balanced placements by preferring destinations that keep low-numbered, soon-needed boxes closer to the top.

5. **Improve simulation efficiency without changing relocation semantics, enabling stronger search variants safely.** Maintain `stack_of[box]` and `position_in_stack[box]`, updating metadata after suffix transfers and removals, so target lookup does not require scanning all stacks. Direct lookup did not improve the measured score by itself, but it can make bounded look-ahead or candidate simulation practical while preserving the C++17-compatible vector-based block-transfer implementation that already passes all cases.
