<DESCRIPTION>
Replace the purely shortest-stack destination rule with a priority based on the smallest remaining label in each candidate stack. A stack containing a smaller label will need to be accessed sooner, so placing a blocking suffix onto it is likely to create additional future moves. Prefer the stack whose minimum label is largest, meaning its next required box is furthest in the future. Use stack height only as a tie-breaker to retain the useful balancing behavior of the original strategy. This directly improves the expected amount of repeatedly moved boxes while preserving the same always-valid ascending-target construction.
</DESCRIPTION>
