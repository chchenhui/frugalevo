# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Hybrid empty-tile positioning followed by graph-aware beam search is consistently strong.** Every top result uses the same high-level structure: first move the empty tile to `(N-1, N-1)`, then optimize with beam search using DSU-derived pipe connectivity. The current best, **Generation 11 — “Hybrid A* Empty Placement Beam Search”**, scored **428171.84**, ahead of Generation 7 (**427363.72**) and Generation 0 (**427205.36**).

- **The current best’s largest successful distinction is avoiding expensive path work on ties.** Generation 11’s patch is named `remove_expensive_tie_paths`, and the code only reconstructs/stores `overall_best_path_str` when `current_actual_score_val > overall_best_actual_score`, not on equal scores. This supports more search throughput within the approximately 2.55-second effective search window and coincides with the highest observed mean score, **428171.84**.

- **Elite retention plus randomized near-elite sampling performs better than purely narrow deterministic search.** The current best retains the top **20%** of sorted candidates and fills the remaining beam from a shuffled pool extending to **3 × beam width** beyond the elite set. This same diversification pattern appears in other high-scoring programs: Generation 7 (**427363.72**), Generation 0 (**427205.36**), and Generation 6 (**426323.18**).

- **Prioritizing the largest acyclic component dominates score behavior.** The beam heuristic gives each additional tree node a weight of `1e9`, while fragmented-component penalties are also extremely large (`0.8e9` per extra component). This aligns search with the actual objective and is consistently present in the strongest programs, including Generation 11, Generation 7, and Generation 0.

## Ineffective Approaches

- **Tournament-selection variation underperformed the stronger elite-plus-randomized-pool approach.** Generation 3, `tournament_beam_selection`, scored **412173.44**, substantially below the current best’s **428171.84**—a deficit of about **15,998 points**. Although it retained correctness across all 50 cases, its tournament-based diversification appears less effective than selecting broadly from the top-ranked candidate pool.

- **Some path/history-focused variants did not translate into improved optimization quality.** Generation 2, `avoid_redundant_path_reconstruction`, scored **420157.02**, and Generation 6, `avoid_repeated_path_reconstruction`, reached **426323.18**. Both were valid optimizations, but neither exceeded Generation 11. The result suggests that reducing path-reconstruction overhead alone is insufficient unless it preserves the current best’s broader search balance and candidate-selection behavior.

- **Beam-width-oriented changes showed mixed value rather than a monotonic benefit.** Generation 5, `stack_dsu_wider_beam`, scored **425194.08**, below Generation 11 by roughly **2,978 points**. Wider beams can improve coverage, but their extra candidate generation, full sorting, DSU scoring, and history allocation can reduce effective search depth or iteration count within the fixed runtime budget.

- **Earlier scoring/search variants were correct but materially weaker.** Generation 1 scored **424536.80**, Generation 4 scored **424454.30**, and Generation 8 scored **425832.00**. All passed 50/50 cases, so their lower scores reflect optimization quality rather than correctness failures; their changes did not outperform the current best’s combination of low-overhead best-path handling and diversified beam selection.

## Implementation Insights

- **Generation 11 minimizes expensive reconstruction in the hot search loop.** Each child still receives a compact history entry—just `{parent_history_idx, move_char_taken}`—but full path reconstruction occurs only when a strictly improved actual score is found. This is important because the beam may create many candidates per iteration, while reconstructing paths repeatedly would require walking parent links and allocating/reversing strings.

- **Incremental board mutation and Zobrist hashing avoid repeated full-state work.** For each successor, the current best swaps the moved tile and empty cell in place, updates the 64-bit hash incrementally, scores the board, and then restores the original board/hash. Combined with `unordered_map<uint64_t, ScoreComponents>` score caching and minimum-move transposition pruning, this avoids recomputing DSU results for many revisited states.

- **The DSU scorer is compact and objective-aligned.** It initializes fixed-size stack arrays for up to `10 × 10` cells, adds only compatible horizontal and vertical pipe edges, counts connected components, and identifies whether a component is a tree via `edges == nodes - 1`. The resulting `(max_tree_size, num_components)` state is exactly the information used by the beam score, limiting evaluation to relevant graph properties.

- **Resource limits are explicitly incorporated into the design.** The current best reserves capacity for up to **3,000,000** history entries and **2,000,000** entries in each score/transposition cache, applies size guards before insertion, and uses board-size-adaptive beam widths: **1200** for `N <= 6`, declining to **250** for `N = 10`. These details match the evaluator feedback emphasizing reliable completion under the time limit across all 50 cases.

## Performance Analysis

- **Generation 11 is the clear best among the evaluated programs.** Its **428171.84** mean exceeds the next-best Generation 7 result of **427363.72** by **808.12 points**, exceeds Generation 0 by **966.48**, and exceeds Generation 6 by **1,848.66**. Since all programs passed all 50 cases, these differences represent solution-quality gains rather than reliability differences.

- **The top cluster shares almost all core algorithmic components.** Generations 11 (**428171.84**), 7 (**427363.72**), 0 (**427205.36**), and 6 (**426323.18**) all combine empty-corner initialization, DSU tree scoring, incremental Zobrist hashing, score caching, reverse-move pruning, visited-cost pruning, adaptive beam widths, and stochastic diversification. The close grouping indicates that this architecture is robust and that improvements come from small throughput/search-quality tradeoffs.

- **Avoiding unnecessary overhead is correlated with the highest scores.** Generation 11’s `remove_expensive_tie_paths` result is higher than both path-reconstruction-related predecessors: Generation 2 at **420157.02** and Generation 6 at **426323.18**. This is consistent with the current implementation’s choice to reconstruct only strict improvements and to represent all other paths as parent indices plus one move character.

- **Selection strategy has the largest observed spread among otherwise similar solvers.** The tournament-selection Generation 3 result (**412173.44**) is far below the elite-plus-shuffled-near-elite designs, while the current best uses the latter strategy. This suggests the effective beam behavior is not merely “add randomness,” but specifically preserve strong elites while sampling diverse candidates from a bounded high-quality ranking range.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Keep strict-improvement-only path reconstruction, and remove history allocation for children that cannot improve the incumbent.** Preserve Generation 11’s key optimization of reconstructing the string only for `current_actual_score_val > overall_best_actual_score`; additionally, compute the score before `beam_history_storage.push_back` and only allocate a history node for candidates that survive a lightweight admission threshold. This extends the demonstrated throughput win while retaining parent-link reconstruction for genuinely competitive states.

2. **Replace the full `std::sort` of every candidate pool with partial ranking plus the existing elite/random selection policy.** Use `std::nth_element` to isolate approximately `num_elites + 3 * beam_width` best candidates, then sort only that bounded prefix before retaining the top 20% and shuffling the following near-elite pool. This preserves the successful elite-plus-randomized-near-elite behavior while reducing a repeated hot-loop cost, especially when wide beams generate several thousand successors.

3. **Make beam width dynamically responsive to measured iteration cost rather than only board size.** Retain the proven board-size base widths, but after several iterations measure elapsed time, candidates generated, and remaining move budget; shrink the beam if projected runtime threatens the slack budget and enlarge it modestly when scoring/cache-hit throughput is high. The goal is to maximize useful search depth under the fixed ~2.55-second search window without relying on a universally wider beam, which prior results showed is not reliably beneficial.

4. **Introduce a controlled multi-bucket diversification step within the same bounded top-ranked pool.** Keep the best 20% exactly as elites, but fill the random 80% from separate score bands—for example, 50% from ranks immediately after elites, 30% from the middle of the `3 × beam_width` pool, and 20% from candidates with a distinct empty position or different last-move direction. This is a conservative extension of the successful shuffled-near-elite pattern that may prevent the beam from collapsing into near-identical trajectories without reverting to the poorly performing tournament selection.

5. **Add a cheap secondary tie-break heuristic for candidates with equal dominant DSU values.** Continue making `max_tree_size` and component count overwhelmingly dominant, but when those match, prioritize states that maximize compatible open pipe endpoints adjacent to the largest tree and/or minimize dangling connections pointing outside the board or into incompatible neighbors. This adds guidance in the large plateaus where the current heuristic mostly differs only by move count and empty distance, potentially improving which diverse near-elite states are retained while preserving objective-aligned DSU scoring.
