<DESCRIPTION>
The beam evaluates a very large number of candidates with identical actual scores, especially before a full tree is found because the actual score depends only on `max_tree_size`. The existing tie-handling reconstructs the complete history path one to three times for every such tie, despite only needing to know whether the candidate path is shorter.

Every candidate’s total path length is exactly `next_K_total`, while the current best path length is already available as `overall_best_path_str.length()`. Therefore, reconstruct the history only if the score strictly improves, or if an equal-score candidate is provably shorter. This preserves the existing selection semantics while substantially reducing string allocations, reverse operations, and history traversal, allowing more beam search work within the time limit.
</DESCRIPTION>
