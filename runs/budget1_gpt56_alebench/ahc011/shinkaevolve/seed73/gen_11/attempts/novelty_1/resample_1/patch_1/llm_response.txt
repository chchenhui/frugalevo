remove_expensive_tie_paths
</NAME>

<DESCRIPTION>
The beam evaluates many candidates with the same official score, especially while the largest tree size is unchanged. The current tie-handling reconstructs full move histories (often twice) merely to compare path lengths. Within one beam layer all newly generated candidates have the same length, and any candidate from a prior layer is strictly shorter, so an equal official score never requires replacing the saved path. Removing this work substantially increases the number of beam expansions possible within the time limit.
</DESCRIPTION>

<NAME>
stack_dsu
</NAME>

<DESCRIPTION>
Score evaluation is the hottest part of the beam search. The board has at most 100 cells, but the DSU currently performs three dynamic vector allocations for every uncached evaluation. Replacing these vectors with fixed-size arrays eliminates repeated heap allocation and improves cache locality. This is safe because N is always at most 10 and preserves all DSU behavior.
</DESCRIPTION>
