<DESCRIPTION>
The beam search reconstructs complete move strings for every candidate tied with the current best score. Ties are extremely common because incomplete-tree scores depend only on tree size. Since path length is exactly `next_K_total`, the existing “prefer shorter path” condition can be checked without reconstruction. This substantially reduces allocation and reverse-traversal overhead, allowing more beam iterations.

Additionally, the current fixed 400 ms safety slack stops around 2.55 seconds despite a 3 second limit. Reducing it moderately to 250 ms gives the search more useful iterations while retaining a conservative margin for system-test timing variation.
</DESCRIPTION>
