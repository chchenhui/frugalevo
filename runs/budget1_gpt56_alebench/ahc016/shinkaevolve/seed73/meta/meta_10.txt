# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **The current best, “Adaptive Graph Codebook Decoder” (Generation 12), achieved the top score of 13,895,152.26** by retaining the core hybrid split: exhaustive permutation-invariant GED only for small graphs (\(N \le 6\)), and edge-count coding for larger/noisier cases. It passed all 50/50 cases, confirming this division is both safe and score-effective.

- **Score-objective-driven edge-count sizing was especially successful.** Generation 12’s `correct_score_objective` selection evaluates candidate \(N=4\ldots100\) using the expected contest score:
  \[
  100\log(1-0.1p_{\mathrm{error}})-\log N.
  \]
  This correctly models the stated nonlinear score behavior through \((1-0.1p)^{100}\), instead of approximating it as \(0.9^{100p}\). This outperformed prior edge-count sizing variants:
  - Generation 7: 13,838,834.84
  - Generation 0: 13,791,484.44
  - Generation 6: 13,602,492.10
  - Generation 1: 13,514,732.24.

- **Small-graph GED codebook construction remains a high-value low-noise mechanism.** The best program uses precomputed canonical masks for all 156 non-isomorphic 6-vertex graphs, computes pairwise permutation-minimized edit distances once, then applies greedy maximin selection. This preserves robust structural discrimination without expanding factorial matching beyond six vertices.

- **For large-\(N\) mode, evenly spaced edge counts with random edge placement worked consistently.** The best program assigns template edge counts approximately as `round(k * L / (M-1))`, then decodes against the noise-adjusted expectation
  \[
  E[|H| \mid |G|=e]=(1-2\epsilon)e+L\epsilon.
  \]
  This was the common successful fallback in the high-scoring edge-count generations.

## Ineffective Approaches

- **Adding degree-profile information reduced score materially.** Generation 4 (“Adaptive GED and Edge-Count Graph Decoder”) used a decoder combining edge count and sorted centered degree-sequence deviations and scored 12,354,500.80. Generation 8 used the same broad edge/degree approach and scored 12,306,930.96. Both remained fully correct, but were about 1.54–1.59 million below Generation 12. The evaluation evidence indicates that the extra degree statistic did not improve the score/runtime tradeoff enough to justify its added complexity or altered decision behavior.

- **Earlier edge-spacing or edge-size heuristics were inferior to directly optimizing the actual score objective.** Generation 2’s `score_tuned_edge_spacing` scored 12,662,602.40, over 1.23 million below the current best. Although it correctly used hybrid GED/edge-count coding, its separation tuning did not match the final program’s objective-aware \(N\)-selection.

- **Cost-aware or generic heuristic sizing was adequate but not optimal.** Generation 6’s `cost_aware_n_selection` reached 13,602,492.10 and Generation 1’s `optimize_edgecount_size` reached 13,514,732.24. Both passed 50/50, but neither matched Generation 12. The score differences suggest that the exact expected-score model matters more than broad runtime/cost or separation heuristics once correctness is already saturated.

## Implementation Insights

- **Generation 12 limits exact isomorphism work to a deliberately bounded state space.** For GED mode, it uses canonical unlabeled masks and precomputes pairwise GED distances among the candidate unlabeled graphs. The 6-vertex precomputed mask table avoids repeated canonicalization over all \(2^{15}\) labeled masks, while the pairwise cache avoids recomputing permutation searches during greedy codebook selection.

- **The greedy maximin selection is aligned with the GED decoder.** Starting from empty and complete graphs, the program repeatedly selects the graph whose minimum cached GED distance to the existing codebook is maximal. This is an implementation-level match between codebook construction and decoding metric, unlike ad hoc structural features that may not correspond directly to decision boundaries.

- **The edge-count branch uses the correct flipped-edge observation model.** For a source graph with \(e\) edges among \(L\) possible edges, the expected received count is computed as:
  ```cpp
  e * (1.0 - 2.0 * epsilon_noise_rate) + L_ACTUAL * epsilon_noise_rate
  ```
  The classifier selects the nearest expected total. This is statistically coherent with independent bit-flip noise and was part of every stronger edge-count result.

- **The best program’s candidate-\(N\) loop makes the accuracy/graph-size tradeoff explicit.** It accounts for count variance \(\sqrt{L\epsilon(1-\epsilon)}\), adjacent codeword spacing \(L/(M-1)\), two-sided interior decoding errors, and the score cost of larger \(N\). This is more targeted than simply maximizing edge-count separation, because higher \(N\) improves statistical spacing but reduces score through the \(-\log N\) term.

## Performance Analysis

- **Generation 12 is the strongest measured configuration at 13,895,152.26**, with acceptance and 50/50 validation success. Its closest predecessor was Generation 7 at 13,838,834.84, a gain of 56,317.42. The smaller gain over Generation 7 suggests both had a strong hybrid foundation, while the final score-objective correction provided a meaningful final refinement.

- **The conventional GED-plus-edge-count family dominates the leaderboard.** Results for this family range from 13,514,732.24 (Generation 1) through 13,895,152.26 (Generation 12), with Generation 0 at 13,791,484.44, Generation 5 at 13,557,666.30, and Generation 3 at 13,536,805.32. Every one passed all 50 cases, so score differences reflect efficiency and quality of \(N\)/codebook choices rather than correctness failures.

- **Degree-profile variants form a clearly lower-performing cluster.** Generations 4 and 8 scored 12.35M and 12.31M respectively, versus 13.90M for the current best. Their shared use of edge/degree statistical decoding correlates with roughly an 11–12% score deficit relative to Generation 12, despite identical full validation success.

- **Correctness was not the differentiator: all listed programs passed 50/50.** The performance trend instead favors minimizing graph size subject to adequate noise separation, using exact GED where it is computationally contained, and optimizing the edge-count branch against the evaluation score rather than only against an estimated classification-error proxy.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Refine the edge-count \(N\)-selection using the exact discrete codebook spacing rather than continuous \(L/(M-1)\).** For each candidate \(N\), construct the actual rounded counts `round(k*L/(M-1))`, derive every adjacent midpoint, and estimate each class’s probability of crossing its true left/right boundary under the binomial flip model. Use these per-index error probabilities in the existing score objective \(100\log(1-0.1\bar p)-\log N\); this preserves Generation 12’s successful objective alignment while removing rounding and endpoint approximations.

2. **Replace the normal-tail approximation in candidate-\(N\) scoring with exact or high-accuracy binomial tails.** Given source count \(e\), the received count is the sum of `Binomial(e, 1-eps)` and `Binomial(L-e, eps)`, so class error probabilities can be computed by convolution/DP or stable recurrence for each candidate \(N\le100\). This is a targeted improvement to the best program’s strongest component, especially near small optimal \(L\) values where Gaussian approximations and continuity assumptions can shift the chosen \(N\).

3. **Optimize edge-count codeword locations jointly with \(N\), instead of forcing uniformly spaced source edge counts.** Keep the monotone one-dimensional count decoder, but use dynamic programming or local coordinate search to choose integer edge counts \(0=e_0<\dots<e_{M-1}=L\) that maximize the same expected-score surrogate under the noise-adjusted means. Uniform spacing is robust and successful, but integer-aware nonuniform placement can compensate for endpoint classes having only one decision boundary and may permit a slightly smaller, higher-scoring \(N\).

4. **Evaluate GED-versus-edge-count strategy selection with a common expected-score comparison rather than the fixed `epsilon < 0.01` gate.** Precompute, for each feasible GED size \(N=4,5,6\), the selected codebook’s minimum-distance or pairwise-distance-based estimated error and compare its expected score against the optimized edge-count candidate. The current hybrid split is clearly valuable, but the hard threshold can be replaced with a data-driven decision that retains GED exactly where its small-codebook robustness is predicted to beat count coding.

5. **Improve the small-\(N\) GED codebook search beyond purely greedy maximin while retaining its cached permutation-invariant metric.** Start from the current empty/complete-seeded greedy solution, then run inexpensive swap-based local search: replace one selected unlabeled graph with one unselected graph whenever it improves a lexicographic distance profile or an estimated noisy nearest-neighbor error. This builds directly on the proven canonical-mask and cached-GED infrastructure, avoids factorial work beyond \(N=6\), and may improve codebook packing where greedy tie choices are suboptimal.
