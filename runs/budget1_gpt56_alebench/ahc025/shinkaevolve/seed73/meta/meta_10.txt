# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Best-performing pattern: pivot-based ordinal estimation plus best-state simulated annealing.** The current best program, **Generation 6 “Pivot-Based Weight Estimation with Annealed Partitioning,”** achieved the highest combined score, **309.88** (raw mean **3,227,051.56**), while passing all 50 cases. Its core successful structure is: cached 1v1 pivot sorting, selective 1v2 sum comparisons to establish pivot gaps, binary-search placement of non-pivots, greedy descending-estimate assignment, and annealing while preserving the best partition encountered.

- **Retaining the best annealing state is consistently beneficial.** Programs explicitly built around best-state preservation were strong: Generation 6 scored **309.88**, Generation 3 scored **292.18**, Generation 0 scored **290.45**, and Generation 5 scored **283.38**. The current program’s `best_assignment_array` is updated only when a lower estimated variance is found, preventing accepted uphill SA moves from degrading the final emitted partition.

- **Using remaining interactive-query budget reliably supports competitive results.** The current best program exhausts unused queries after informative estimation queries, matching the robust budget behavior noted for Generation 6. Other full-budget/cached-query variants were also comparatively strong, including Generation 3 (**292.18**) and Generation 0 (**290.45**). This does not prove dummy queries directly improve partition quality, but it is a recurring feature of valid high-scoring implementations and avoids leaving permitted interaction unused.

- **Estimate-aware LPT-style initialization is a strong base for local search.** The current program sorts items by descending estimated weight and places each into the currently lightest estimated group. This same greedy structure appears in the stronger cluster of programs: Generation 6 (**309.88**), Generation 3 (**292.18**), and Generation 0 (**290.45**). It provides SA with an already balanced starting state rather than relying on stochastic search to repair a poor initial assignment.

## Ineffective Approaches

- **Rank/quantile reconstruction performed substantially worse than the strongest direct pivot-gap heuristics.** Generation 1, **“Pivot-Based Weight Estimation and Annealed Balancing,”** used exponential-quantile rank estimates and scored only **179.73** with raw mean **5,563,949.20**, despite passing all 50 cases. This is far below the current best’s **309.88** / **3,227,051.56**, indicating that ordinal rank placement alone was materially less effective than the current program’s 1v2-informed incremental pivot magnitude construction plus interpolation.

- **Adding deterministic local improvement before annealing was not associated with a gain.** Generation 7 combined greedy assignment, deterministic relocate/swap local search, and SA, but scored **263.47** (raw mean **3,795,499.18**). That is below the simpler current best SA pipeline by **46.41 combined-score points**. Given the shared pivot-query framework, the extra deterministic phase likely did not compensate for estimation error and may have consumed useful runtime or moved the search into less useful local regions.

- **Returning the final annealed state instead of the tracked best state weakened results.** Generation 12 intentionally outputs the final annealed assignment and scored **269.31** (raw mean **3,713,247.34**), versus **309.88** for the current best, which restores the best estimated-variance state. Since SA deliberately accepts uphill moves, final-state output can discard earlier high-quality partitions; the score gap is consistent with this risk.

- **Moderate variants of the same basic method did not match the strongest estimator/search combination.** Generations 2 (**250.34**), 4 (**257.69**), 8 (**248.02**), and 9/12-style variants (**269.31**) all passed validation but remained below the leading result. Their shared pivot-plus-SA design was sound, but the evaluated scores show that implementation details of weight reconstruction, initialization, and best-state handling matter substantially even when correctness is identical.

## Implementation Insights

- **The current best program tightly couples query caching with a query-budget-aware pivot count.** It computes a pivot count from an estimated cost model, uses cached pairwise comparisons during merge sort and binary searches, and caches 1v2 queries by left item and unordered right pair. This minimizes accidental repeated interactive queries and allows the pivot ordering and non-pivot placement stages to operate reliably within the budget. Full 50/50 acceptance confirms this machinery is robust.

- **Its estimation logic is richer than pure rank estimation.** The best program first establishes monotonic pivot estimates, then for later pivots queries whether the current pivot exceeds `previous_pivot + earlier_pivot`. It uses these results to bracket an incremental gap and adds that estimate to the previous pivot weight. Non-pivots are then estimated by geometric-mean interpolation between bracketing pivots, with guarded extrapolation outside the pivot range. This retains ordinal consistency while introducing approximate magnitude information, unlike the weaker rank-quantile approach in Generation 1.

- **Incremental objective maintenance makes the 1.85-second SA budget practical.** Rather than recomputing all group totals or variances, the current program updates only the two affected group sums for a relocate or swap and adjusts `current_sum_sq_group_totals` in constant time. Group membership uses vectors plus per-item positions, permitting O(1)-style removal by replacing an item with the group’s final vector entry. This permits many more candidate moves under the fixed time limit.

- **The implementation protects against stochastic regression.** The code separately tracks current SA state and the best surrogate state. On an accepted move, it updates `best_assignment_array` before mutating the active assignment, including the exact altered item or item pair. This detail is especially important because the temperature schedule permits uphill moves and occasional reheating; it explains why the best-state pattern outperformed Generation 12’s final-state output.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Preserve the pivot-gap estimator and test a small set of calibrated gap rules rather than replacing it with rank-only reconstruction.** Keep the cached 1v1 pivot ordering and 1v2 binary search, but mutate only the conversion from bracketing pivots to `estimated_X_j`: compare the current arithmetic mean with a geometric mean, a weighted mean biased toward the lower bound, or a mild median-of-rules estimate. Generation 6’s advantage strongly suggests that extracting approximate additive gap information is valuable, while Generation 1 shows that pure ordinal/quantile estimates are not competitive.

2. **Use adaptive pivot selection that deliberately includes extreme and well-spaced pivots after an initial random sample.** Instead of choosing every pivot uniformly at random, initially sample a modest random subset, sort it, then spend remaining pivot slots by selecting items likely to fill sparse ordinal intervals through comparisons against existing pivots. This should improve interpolation and extrapolation accuracy, especially for heavy items that dominate group imbalance, while retaining the current budget-aware cached-query architecture.

3. **Improve non-pivot weight reconstruction with interval-sensitive interpolation.** Keep binary-search placement, but choose the interpolation rule based on pivot-gap shape: use geometric interpolation when adjacent pivot estimates have a large ratio, arithmetic interpolation when their difference is locally stable, and clamp extrapolated extreme items with a less aggressive ratio cap. The best program already benefits from geometric means and guarded extrapolation; making that choice conditional may reduce systematic over- or under-estimation without discarding its successful estimator.

4. **Retain best-state SA, but bias proposals toward estimated overloaded and underloaded groups instead of selecting all groups uniformly.** For relocate proposals, sample an item from one of the heaviest estimated groups and move it toward one of the lightest groups; for swaps, preferentially select one item from each side whose estimated weights are close to the amount needed to equalize the two sums. Continue allowing random proposals and uphill acceptance for diversification, but make perhaps 60–80% of moves imbalance-directed; this extends the proven greedy-plus-SA approach without adding the deterministic pre-search phase that underperformed in Generation 7.

5. **Add a final short best-state-preserving intensification phase using only estimated objective deltas.** After the annealing temperature becomes low or the time budget is nearly exhausted, repeatedly evaluate targeted single relocations and pair swaps between the currently heaviest/lightest groups, accepting only improving moves and updating the best assignment. This differs from Generation 7’s broad deterministic local search by using it only as a final polish after SA exploration, while preserving the current program’s most important protection: always emit the globally best surrogate partition encountered.
