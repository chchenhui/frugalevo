# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **The current best, Generation 0 “Simulated Annealing Grid Path Planner,” achieved 1447.78**, the highest score among all evaluated programs. Its strongest combination is a compact **170-strategy segment model**: direct BFS, target unblocking, slide-based arrivals with optional obstacle placement, and post-arrival grid edits. This provides enough local flexibility without the larger strategy-space overhead seen in some variants.

- **Incremental suffix reevaluation is consistently associated with the top scores.** Generation 0 reuses cached per-segment player/grid states and reevaluates only from the earliest changed segment. Generation 3, with the same general 170-strategy and cached-prefix design, reached **1447.64**, only **0.14** below the best. Generations 2, 4, 5, 6, and 8 all retained this cached partial-evaluation structure and clustered at **1446.26–1447.48**.

- **BFS that treats both normal moves and slides as unit-cost graph actions is a successful base routing primitive.** The best program explicitly searches move and slide transitions, allowing strategies to exploit walls, borders, and created blockers. The strong results of Generation 0 (**1447.78**), Generation 3 (**1447.64**), and Generation 2 (**1447.48**) indicate that this routing model is robust across all 50 cases.

- **A heterogeneous simulated-annealing neighborhood performs well.** The current best mixes random multi-segment mutations, single-segment base/post-action tweaks, and sampled local greedy reoptimization. This pattern also appears in the other high-scoring planners and supports exploration while preserving the ability to cheaply exploit promising segment decisions.

## Ineffective Approaches

- **The compact-mask/checkpoint implementation in Generation 9 performed substantially worse despite full correctness.** “Simulated Annealing Segment Route Planner” scored **1357.82**, roughly **89.96 points below** the current best. It used a 210-code strategy representation and checkpointed partial reevaluation, so caching alone was not sufficient; its different action-code formulation and/or search behavior produced much weaker optimization quality.

- **Expanding the strategy space from 170 to 210 did not improve results.** Generation 4’s “Simulated Annealing Grid Slide Planner” used **210 composable strategies**, including additional post-target block alterations, but scored **1447.38**, below Generation 0’s **1447.78** and Generation 3’s **1447.64**. The larger action space appears to add search choices without yielding a measurable quality gain under the fixed ~1.95 s budget.

- **Specific behavioral patches did not consistently outperform the baseline strategy model.** Generation 1’s `slide_post_actions` scored **1445.04**, Generation 7’s `slideaware_sa` scored **1444.94**, and Generation 8’s `target_block_postmove` scored **1446.26**. All were accepted, but none exceeded the current best. This suggests that merely broadening slide/post-action semantics is less valuable than maintaining a well-balanced, efficiently searchable strategy set.

- **Specialized alterations such as `reverse_post_alter` and `allow_target_pass_through` did not produce a net gain.** Generations 5 and 6 scored **1447.04** and **1447.18**, respectively—good results, but below the baseline best. Their added flexibility likely changes the search landscape more than it improves the best reachable plans within the time budget.

## Implementation Insights

- **The current best avoids expensive repeated BFS initialization through generation stamping.** `g_bfs_cell_last_visited_generation` and `g_bfs_cell_dist` allow each BFS to mark only visited cells rather than clearing full visitation arrays. Since greedy initialization evaluates up to 170 strategies per segment and annealing performs many suffix evaluations, this directly supports the substantial search completed within the **1950 ms** limit noted in the feedback.

- **Its cache granularity is aligned with the mutation structure.** `PathCacheEntry` stores the player position, entire grid state, and accumulated turns *before each segment*. When a strategy code changes, `evaluate_choices` starts at the earliest changed segment and copies the valid unchanged prefix. This is especially effective because the search often mutates only one or a few of the 39 transitions.

- **The strategy encoding efficiently composes a base arrival action with local post-arrival modifications.** The code uses 10 base strategies × 17 post-action choices = **170 combined strategies**. The base options cover direct routing, unblocking a target, existing-wall slides, and blocker-creating slide setups; post actions can toggle an adjacent cell or move once and toggle a nearby cell. This gives future segments controllable obstacle-state variation while keeping the code representation simple.

- **The annealing implementation combines global disruption with local refinement.** Random mutations can alter one, two, three, or occasionally more segments; fine tweaks preserve either the base strategy or post-action component; greedy reoptimization samples 40 alternatives for one segment from its cached predecessor state. This mixed operator design is consistent with the strong score of Generation 0 and the near-best results of related cached-SA implementations.

## Performance Analysis

- **Generation 0 is the clear leader at 1447.78**, followed closely by Generation 3 at **1447.64** and Generation 2 at **1447.48**. The leading three differ by only **0.30 total points**, and all use BFS move/slide routing, compact per-segment strategy choices, greedy initialization, cached partial reevaluation, and simulated annealing. This is the dominant high-performance design family.

- **The 170-strategy formulation compares favorably to the 210-strategy variants.** Generation 0’s 170 choices scored **1447.78**, while Generation 4’s 210 choices scored **1447.38** and Generation 9’s 210-style base/post codes scored **1357.82**. The evidence indicates that a moderately sized compositional strategy set is easier to optimize effectively in the fixed runtime.

- **All programs except Generation 9 lie in a narrow high-performing band of 1444.94–1447.78.** This confirms that the core BFS-plus-SA architecture is robust: every listed implementation passed **50/50** validation cases. However, the approximately **2.84-point** spread within that band shows that implementation/search details—especially strategy semantics, initialization, and neighborhood composition—still matter for score quality.

- **The current best’s advantage is incremental rather than a radical algorithmic departure.** It exceeds Generation 3 by **0.14**, Generation 2 by **0.30**, Generation 4 by **0.40**, and Generation 1 by **2.74**. The evaluation feedback specifically attributes the best program’s throughput to generation-stamped BFS and path-state caching, supporting the conclusion that efficient repeated evaluation enabled better use of the same ~1.95-second optimization budget.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Keep the 170-code base/post-action representation, but bias mutation sampling toward historically feasible codes.** Preserve the successful 10 base strategies × 17 post-actions structure rather than expanding to 210 codes, since broader action spaces did not improve the fixed-budget search. During greedy initialization and SA mutations, maintain lightweight per-segment feasibility or success counts and sample more often from codes that are valid from the cached predecessor state, while retaining a smaller uniform-random exploration probability.

2. **Make greedy single-segment reoptimization exhaustive or adaptively larger for early segments.** The current operator samples only 40 of 170 strategies, even though its cached state already makes evaluating one segment relatively cheap; testing all 170 codes for selected segments—especially early segments whose grid edits affect many later targets—could find stronger local pivots. Use an adaptive policy: evaluate all codes for early or frequently changed segments, and keep the 40-code sample for late segments or when remaining time is low.

3. **Add a suffix-aware candidate ranking step to the greedy reoptimization operator.** Instead of selecting a replacement solely by minimum immediate segment turns, retain the best several feasible local candidates (for example 3–8) and run cached suffix evaluation for each candidate before choosing the neighbor. This directly targets the important effect of a segment’s post-arrival grid edit on later routing, while still exploiting the existing earliest-changed-segment cache.

4. **Introduce periodic targeted large-neighborhood mutations around bottleneck segments.** Track which segment index most often starts failed evaluations, causes high local turn cost, or lies before large suffix-cost changes; occasionally mutate a contiguous block centered on that segment rather than choosing all random mutation indices uniformly. The current mixed neighborhood is strong, but this focused destroy-and-repair operator can coordinate adjacent grid-edit decisions that single-segment tweaks cannot escape.

5. **Use a multi-phase annealing schedule with restart-from-best perturbations near the time limit.** Retain the current exponential cooling, but reserve the last portion of the 1950 ms budget for several short intensification cycles: start from `best_sa_choices`, perturb 2–5 related segments, then cool quickly with a lower initial temperature. This builds on the best program’s efficient cached suffix reevaluation and heterogeneous mutations, while reducing the chance that the final SA state drifts away from a high-quality basin found earlier.
