# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Generation 11 “Simulated Annealing Grid Skater Planner” is the new best evaluated program at 1447.90**, improving on the previously reported Generation 0 leader at **1447.78** by **0.12**. It retains the proven 170-strategy formulation—10 base arrival methods × 17 post-arrival alteration choices—while combining greedy construction, prefix-cache reuse, and simulated annealing. Its `greedy_lookahead_tiebreak` behavior is a plausible source of the small but measurable improvement: when several strategies have equal immediate cost, it selects the one with the cheapest achievable next segment.

- **Move-and-slide BFS remains the dominant routing primitive.** Generation 11’s BFS gives equal unit cost to normal moves and maximal directional slides, which lets the optimizer use existing borders/walls and deliberately constructed blockers. This same core model appears in Generation 12 (**1447.80**), Generation 13 (**1441.60**), and the previously strong Generation 0/3 family (**1447.78/1447.64**), confirming that it is robust across all 50 validated cases.

- **A compact, compositional local strategy space performs better than broader alternatives under the fixed time budget.** Generation 11’s 170 codes cover direct traversal, target unblocking, four existing-stopper slide arrivals, four newly-built-stopper slide arrivals, and 17 post-arrival grid/player-state modifications. This is sufficiently expressive to manage future wall layouts without incurring the search dilution seen with the 210-code designs.

- **Heterogeneous annealing mutations are consistently effective.** The best program mixes random one-to-multi-segment changes (50% probability), isolated base/post-action fine tweaks (35%), and sampled greedy single-segment reoptimization (15%). This preserves both broad exploration and targeted exploitation. The near-identical Generation 12 implementation, using cached partial evaluation and randomized local neighborhoods, reached **1447.80**, only **0.10** behind Generation 11.

## Ineffective Approaches

- **Increasing the strategy space from 170 to 210 did not provide a scoring gain.** Previous Generation 4, using 210 composable strategies, scored **1447.38**, below Generation 11’s **1447.90** by **0.52**. More decisively, Generation 9’s 210-style checkpoint/mask implementation scored only **1357.82**, about **90.08** below the current best. The results indicate that extra action encodings can consume search budget and complicate optimization without proportionate plan-quality gains.

- **Specialized slide/post-action semantic changes generally underperformed the balanced baseline.** Generation 1 (`slide_post_actions`) reached **1445.04**, Generation 7 (`slideaware_sa`) reached **1444.94**, and Generation 8 (`target_block_postmove`) reached **1446.26**. These were all correct, but their modifications did not beat the compact 170-choice formulation and mixed annealing neighborhoods used by Generation 11.

- **The beam-search-only approach was substantially weaker in score despite correctness.** Generation 10 “Beam Search Sliding Grid Router” passed all 50 cases but scored **1418.24**, which is **29.66** below Generation 11. Its beam of 34 reusable stopper configurations captures useful diversity, but it lacks the extensive iterative refinement of segment-level simulated annealing and cached suffix reevaluation.

- **More aggressive hybrid slide-oriented strategy modeling did not necessarily improve quality.** Generation 13’s hybrid slide SA passed every case but scored **1441.60**, **6.30** below the current best. Its reported design still had BFS, caching, and annealing, so the gap emphasizes that strategy semantics and neighborhood behavior matter beyond simply supporting slides and incremental evaluation.

## Implementation Insights

- **Generation 11’s greedy tie-break is a concrete differentiator at the top of the score range.** During initialization, it evaluates all 170 strategies for the current segment, collects equal-minimum-cost candidates, then—when another target exists—tests each tied candidate’s cheapest next-segment continuation. This preserves immediate greedy cost while selecting among neutral choices according to their short-horizon effect on player location and stopper layout. The resulting **1447.90** exceeds Generation 12’s neutral equal-cost diversification result of **1447.80**.

- **Prefix cache entries are aligned precisely with the mutation model.** Each `PathCacheEntry` stores the player position, full 20×20 wall grid, and cumulative turns immediately before a segment. When a proposal changes segment `k`, `evaluate_choices` starts from cached state `k` and reevaluates only the affected suffix. Since many mutations alter just one segment, this avoids recomputing the unchanged prefix across 39 transitions and enables much more annealing within the approximately **1.95-second** budget.

- **Generation-stamped BFS avoids repeated full-array clearing.** The program increments `g_bfs_generation_id` and checks per-cell visitation stamps rather than resetting visited/dist arrays before each search. This is particularly relevant because initialization can test 170 strategies per segment, lookahead can test many tied candidates and next-step strategies, and SA repeatedly evaluates changed suffixes. The implementation converts routing throughput directly into more explored candidate plans.

- **The 170-strategy encoding is both expressive and operationally efficient.** Base codes represent direct pathing, blocked-target unblocking, and two slide classes; post codes represent no edit, adjacent toggles, or move-then-toggle actions. The state transition is evaluated through one `apply_combined_strategy` function, so the optimizer mutates compact integers while the executor consistently updates both the player state and mutable wall grid. This compact representation is shared by the highest-scoring SA family and compares favorably with the weaker larger-code variants.

## Performance Analysis

- **Generation 11 is the strongest measured result: 1447.90, accepted on 50/50 cases.** It edges Generation 12 at **1447.80** by **0.10**, the prior Generation 0 best at **1447.78** by **0.12**, Generation 3 at **1447.64** by **0.26**, and Generation 2 at **1447.48** by **0.42**. These small margins show that the leading solutions share the same overall architecture, with incremental search-design choices determining the remaining gain.

- **The best-performing cluster is tightly concentrated around the 170-strategy cached-SA architecture.** Generation 11 (**1447.90**), Generation 12 (**1447.80**), Generation 0 (**1447.78**), Generation 3 (**1447.64**), and Generation 2 (**1447.48**) all use move/slide BFS, mutable-grid local strategies, cached partial reevaluation, greedy initialization, and time-limited annealing. The evidence strongly supports this as the dominant design family.

- **The current best’s advantage appears incremental and specifically consistent with initialization quality rather than a wholesale search redesign.** Generation 11 and Generation 12 are nearly identical in score and both use 170 strategy combinations plus cache-assisted SA; Generation 11’s explicit next-segment tie-break corresponds to its **0.10** lead. This is also consistent with the code: the tie-break only influences equal-cost greedy decisions, preserving the established search behavior while improving starting-state quality.

- **Correctness is universal among the listed recent planners, but optimization quality varies materially.** All of Generations 10–13 passed **50/50** cases, yet scores range from Generation 10’s **1418.24** to Generation 11’s **1447.90**, a **29.66-point** spread. Thus, feasibility is not the differentiator: the measured score depends on efficiently finding useful reusable blocker configurations, preserving favorable player positions, and spending the fixed runtime on high-value local plan refinement.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Strengthen the greedy initialization tie-break from one-step to selective two-step rollout.** Keep the current “minimum immediate segment cost first” rule, but for tied codes evaluate the cheapest continuation over the next two segments (or only for the top 4–8 tied candidates to control cost). Generation 11’s one-segment lookahead likely explains its narrow lead over Generation 12, so a bounded deeper rollout is a direct extension that may improve the starting basin without changing the proven 170-code space.

2. **Replace the sampled 40-code greedy-reoptimization operator with an adaptive exhaustive scan for high-impact segments.** For early segments, or segments whose cached suffix is long, test all 170 codes from the cached predecessor state; retain the 40-code random sample for late segments and low remaining time. Early grid edits influence many later routes, and prefix caching makes their full local enumeration comparatively affordable, while the current random sample can miss rare but valuable slide/stopper configurations.

3. **Make greedy reoptimization suffix-aware rather than choosing solely by immediate segment cost.** During a reoptimization move, retain several locally good feasible alternatives—for example the best 4 codes by segment cost plus ties—and evaluate each candidate’s cached suffix before constructing the final neighbor. This directly optimizes the blocker-layout and player-position effects that the current initialization tie-break already exploits, while avoiding the search-budget dilution associated with expanding beyond 170 strategies.

4. **Add bottleneck-directed contiguous-block destroy-and-repair mutations.** Track segment indices that frequently cause infeasible suffixes, high segment turn counts, or large score changes after accepted moves; periodically mutate a block of 2–5 choices centered near one of those indices. Rebuild that block greedily from the cached prefix, optionally with one-step tie-breaking, then evaluate the remaining suffix; this gives SA a coordinated escape move beyond independent random code replacements.

5. **Use late-stage intensification restarts from the global best solution.** Reserve roughly the last 15–25% of the time budget for several short annealing cycles initialized from `best_sa_choices`, each perturbed in a small related region and cooled rapidly at lower temperature. The current algorithm correctly preserves the best solution but spends all time on one cooling trajectory; restart-based local refinement can repeatedly exploit the strongest discovered stopper layout without abandoning the successful cached-SA architecture.
