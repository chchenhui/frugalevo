<DESCRIPTION>
The key flaw in the current optimizer is that the annealing/polish objectives use the **raw** minimum triangle area, not the normalized one (min_area / hull_area). During search, points can drift outward and grow the convex hull, inflating the raw minimum area while the actual metric (normalized by hull area) stays flat or worsens — the optimizer climbs the wrong hill. Fix: make every accept/reject decision inside `_anneal` and `_polish` use the hull-normalized score. Additionally, add a repulsion-relaxed random initialization (points as mutually repelling particles) which is a classic good starting basin for Heilbronn-type problems, and slightly increase polish iterations for refinement. These changes are deterministic (fixed seed) and cost little extra time.

def _score(pts: np.ndarray) -> float:
    """Hull-normalized objective: min triangle area / hull area."""
    h = _hull_area(pts)
    if h < 1e-12:
        return 0.0
    return float(_areas(pts).min()) / h


def _init_repulsion(rng) -> np.ndarray:
    """Force-relaxed random configuration: mutually repelling particles."""
    pts = rng.uniform(-1.0, 1.0, (N, 2))
    for _ in range(400):
        diff = pts[:, None, :] - pts[None, :, :]
        d2 = (diff ** 2).sum(-1) + np.eye(N)
        inv = 1.0 / d2
        np.fill_diagonal(inv, 0.0)
        force = (inv[:, :, None] * diff).sum(axis=1)
        nrm = np.linalg.norm(force, axis=1, keepdims=True)
        nrm[nrm < 1e-12] = 1.0
        pts += 0.05 * force / nrm
        # keep points in a bounded disk
        r = np.hypot(pts[:, 0], pts[:, 1])
        far = r > 1.0
        if far.any():
            pts[far] *= (1.0 / r[far])[:, None]
    return pts
