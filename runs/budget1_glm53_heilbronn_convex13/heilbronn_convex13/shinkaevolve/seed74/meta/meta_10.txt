# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Deterministic multi-restart hill climbing with symmetric seeds** (Generation 12, score 0.64): The current best combines concentric-ring structured seeds (varying inner/outer radii and ring sizes) with 8 random seeds, runs 1200 iterations per seed of single-point Gaussian perturbation with geometric step decay (0.75), then a 2000-iteration deterministic polish with 0.6 decay. This is the only optimized program to both pass validation and produce a nonzero score.
- **Vectorized scoring over all 286 triples**: Precomputing all C(13,3) index combinations and using stable Heron's formula via `np.linalg.norm` allows each hill-climb step to rescore all triangles cheaply enough to complete in 3.56 seconds — unlike Python-loop gradient assembly (Generation 8) or 14k full rescoring with naive structures (Generation 3), which were too slow or failed.
- **Hull-area normalization via monotone chain** (0.5·|shoelace|): Used consistently in the best program and several others; it survived validation, whereas programs normalizing to other targets or with points escaping the domain (Generation 6 simulated annealing, Generation 4) failed validation entirely.
- **Accepting non-worsening moves (`s >= best`)** allowed the climber to traverse flat plateaus and converge quickly, contributing to the 3.56s runtime within deadline.

## Ineffective Approaches

- **Trivial API/signature mismatches are the leading cause of zero scores**: Generation 1 (tuple unpacking `'tuple' object has no attribute 'min'`, score 0.00), Generation 5 (`np.triu_indices(n,3)` returns 2 arrays not 3, crash), Generation 9 (undefined `seed` variable). Sound algorithms were completely wasted by single-line bugs.
- **Softmax/softmin sign errors**: Generation 8's softmin implementation used `signed.max()` without negation, so the gradient ascended toward the *largest* triangle — optimizing the wrong objective and scoring 0.0.
- **Heavy stochastic local search with noisy restarts**: Generation 3's 14k full rescoring iterations and Generation 2's ~120 rounds × 13 points × 8 candidates were extremely slow, nondeterministic, and converged to invalid or poor configurations — all scored 0.0.
- **Broad try/except fallbacks masking failures**: Generations 8 and 9 silently returned raw lattice/fallback configurations, producing invalid outputs instead of surfacing errors for debugging.
- **Naive random placement** (Generation 0) yields near-zero minimum triangle area (0.01 combined), confirming structure/optimization is essential.

## Implementation Insights

- **The best program's success hinges on simplicity and correctness**: pure numpy, a fixed rng seed 42 (deterministic across platforms), a small function set (`_hull_area`, `_min_tri_area`, `_score`, `_optimize`), and careful seeded candidate generation. Compared to Generation 4's flawed loop (repeating identical candidates, unbounded points), Generation 12's clean accept/reject single-point move loop is robust.
- **Stable Heron's formula with `np.maximum(..., 0)` clamp** prevents NaN from floating-point degeneracy — a correctness detail the validation-passing program got right.
- **Symmetric seeds + random seeds together** give both good basin starts (rings approximate known Heilbronn structures) and diversity; feedback notes the low 0.02 min_area_normalized suggests the greedy-only climber gets trapped, so the seeding carries much of the quality.
- **Deadline-aware iteration budgets** (1200 iters × ~18 seeds + 2000 polish fitting in 3.56s) contrast with Generation 9's 4.5s deadline approach that still crashed on an undefined variable.

## Performance Analysis

- **Score trajectory**: Generation 0 random = 0.01 (correct but trivial); Generations 1–9 all = 0.0 due to crashes, validation failures, or wrong objectives; Generation 12 = 0.64 (min_area_normalized 0.02, 3.56s) — the only successful optimizer, a massive jump from all failed attempts.
- **Correctness dominates algorithmic sophistication**: Several failed programs (softmin gradient ascent Gen 1, staged softmin pipeline Gen 8) had potentially stronger algorithms than hill climbing, but crashes or sign errors left them at 0.0. Merely making Generation 1 runnable (fixing tuple unpacking) was identified as a minimal high-value fix.
- **Correlation between runtime and validity**: The best program's 3.56s fits comfortably within evaluation constraints; programs with 14k–60k iteration loops (Gen 3, Gen 6) either timed out or failed validation, suggesting a ~2–4s budget with vectorized scoring is the practical sweet spot.
- **Headroom remains**: The best program's 0.02 normalized minimum area is very low relative to the 0.64 combined score, indicating the validation-passing framework captures most of the score while the geometric quality still has substantial room for improvement via better search (e.g., annealing or population methods on top of the working hill-climb skeleton).

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Add a coordinate-wise directional search to the hill-climb inner loop.** Since the climber only gets 0.02 normalized minimum area, augment the accept/reject loop in `_optimize` so that when a Gaussian move fails, try the move along each axis separately (4 candidate perturbations per iteration instead of 1) before rejecting. This exploits the cheap vectorized rescoring already in place and only multiplies cost by ~4×, which fits the 2–4s budget sweet spot identified in the performance analysis.

2. **Track and optimize the argmin triangle directly instead of the global score.** The min-area score is a max-min objective and hill climbing on the flat minimum plateaus easily. Modify the loop to accept moves that increase the area of the currently-smallest triangle (or the k smallest triangles) rather than only the overall min — periodically re-check the global min to keep it as the gate. This targeted pressure should escape the local traps that leave min_area_normalized at 0.02.

3. **Add structured Heilbronn-style seeds beyond concentric rings.** Keep the existing symmetric + random seed mix, but add candidates known to work well for the Heilbronn problem: points on a parabolic arc `(t, t²)` for evenly spaced t, points on a 13-point "no-three-in-line" lattice perturbation, and points on an ellipse with golden-angle spacing. Seeding carries much of the current quality per the insights, so better basins directly raise the final score at nearly zero runtime cost.

4. **Replace the single final polish with an adaptive restart that re-anneals the best solution.** After the 2000-iteration polish, run a short (500-iteration) reheat phase with step reset to 0.05 followed by decay, keeping the best-ever configuration as a fallback (as the return statement already does). Simulated annealing with restarts addresses the greedy-climber trap noted in the feedback while retaining the deterministic rng(seed=42) pattern that made Generation 12 robust and reproducible.

5. **Add cheap exit-early and per-move pruning to spend the iteration budget where it pays.** Skip seeds whose score after 200 iterations is far below the current best (e.g., < 50%), reallocating those iterations to the top 3 seeds with extended budgets (2400 iterations each). Also precompute `tri_idx` once (already done) and clamp candidate points to the hull's bounding box after perturbation to avoid wasted rejected moves that push points outside the domain — a failure mode that killed Generation 4's validation.
