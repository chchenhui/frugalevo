<DESCRIPTION>
All prior programs plateau at min_area_normalized = 0.02. Two problems in the current code: (1) `_point_outside_hull` always returns True ("conservative"), and it's actually called incorrectly (indexes `cand` with an interior index but never receives the moved vertex index), so accepted moves get exact recomputes via a wrong path while rejected moves use approximate hull areas that may never update — the cached `hull_a` can go stale and corrupt the score silently. (2) The annealer only ever moves a single vertex at a time with adaptive sigma, which collapses to tiny local steps and cannot escape the incumbent basin — this is exactly why every program is stuck at 0.02.

Fix: (a) replace the acceptance block with an exact score recomputation on every accepted move (full 286-triangle numpy evaluation + monotone-chain hull is only microseconds, so correctness costs nothing while the incremental min-over-rest still screens candidates cheaply); (b) replace `_point_outside_hull` with a proper point-in-convex-polygon test; (c) add a basin-hopping mechanism: when no improvement for several rounds, kick 3-4 randomly chosen vertices simultaneously at sigma ~0.14 from the best-known configuration, then resume local annealing — coordinated multi-vertex kicks are far more likely to jump between basins than isotropic single-vertex noise, and the strict best-seen bookkeeping guarantees the returned result never regresses.</DESCRIPTION>

def _point_outside_hull(pt, hull_pts):
    """True if 2D point pt lies strictly outside convex polygon hull_pts.

    hull_pts must be ordered (we sort by angle around the centroid first).
    Uses the sign of the cross product against each hull edge.
    """
    if len(hull_pts) < 3:
        return True
    c = hull_pts.mean(axis=0)
    ang = np.arctan2(hull_pts[:, 1] - c[1], hull_pts[:, 0] - c[0])
    H = hull_pts[np.argsort(ang)]
    x, y = H[:, 0], H[:, 1]
    x2, y2 = np.roll(x, -1), np.roll(y, -1)
    cr = (x2 - x) * (pt[1] - y) - (y2 - y) * (pt[0] - x)
    # outside if the point is on the "wrong" side of ANY edge
    return bool(np.any(cr > 1e-12) and np.any(cr < -1e-12))
