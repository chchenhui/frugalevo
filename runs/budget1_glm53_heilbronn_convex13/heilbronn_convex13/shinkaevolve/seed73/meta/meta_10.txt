# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Deterministic coordinate-descent with multi-direction, dual-step trials is the current best approach**: The Gen 6 program "deterministic_local_refinement" (score 0.72, min_area_normalized 0.02, 6.20s) starts from 12 points on a unit circle plus center, then performs coordinate-descent over 8 normalized directions with dual step sizes (step, 0.5×step) and step-halving down to 1e-5. This directly optimizes the *hard* minimum-triangle-area/hull-area ratio rather than a smooth surrogate — a key differentiator from all soft-min gradient methods (scores 0.18–0.21).
- **Direct optimization of the true objective (hard min over all 286 triples) beats smooth approximations**: The current best program evaluates the exact minimum via vectorized cross products (row-vectorized over `points[j+1:, :]`), and it scores 0.72 versus 0.18–0.21 for softmin/LogSumExp/subgradient approaches (Gens 3, 7, 9, 10, 11). Soft-min gradients consistently converge to degenerate or near-degenerate configurations (min_area_normalized ≈ 0.01).
- **Circle+center initialization with no jitter avoids degenerate triples**: Both the best program (0.72) and Gen 4's design (crashed, but same seed) use a symmetric 12-ring + center start, which structurally guarantees a nonzero minimum triangle area, unlike random uniform placement (Gen 0, score 0.01, essentially degenerate).
- **Step-size annealing/halving schedules**: The best program's halving schedule (0.25 → 1e-5, only halving when no improvement found) provides both coarse exploration and fine refinement; similar annealed schedules (×0.6–0.7 every 500 iterations) appear in the crashed Gen 4/5 designs and are a sound design choice.

## Ineffective Approaches

- **Soft-min / LogSumExp smooth surrogate gradients repeatedly fail to escape poor local optima**: Gen 3 (softmin gradient, 0.20), Gen 7 (C3-symmetric softmin with box barriers, 0.18), Gen 9 (16-init softmin + polish, 0.19), Gen 10 (soft-min subgradient in hexagon, 0.21), and Gen 11 (hard-min repulsion on 8 smallest triangles, 0.18) all plateaued at min_area_normalized ≈ 0.01. Feedback consistently notes the gradient oversmooths the true minimum or gets trapped near symmetric/degenerate configurations — even 16 diverse initializations (Gen 9) could not rescue it.
- **Constrained/symmetric search spaces restrict achievable scores**: Gen 10/11 restrict points to hexagon rings with symmetric jitter; Gen 7 enforces 3-fold symmetry; Gen 5 restricts to circle boundary (angular-only). All scored ≤ 0.21 or crashed. Known optimal Heilbronn-13 placements are irregular, so over-symmetry is a liability — though note the best program still uses a *symmetric seed*, its unconstrained coordinate-descent can break symmetry during refinement.
- **Naive random placement is the worst baseline**: Gen 0 (uniform random, score 0.01) produces near-collinear triples, confirming substantial optimization is mandatory.
- **A single recurring unpacking bug crashed three programs (Gens 2, 4, 5)**: `np.triu_indices(n, k)` returns only 2 index arrays; unpacking into `i, j, k` raises "not enough values to unpack (expected 3, got 2)". All three crashed with score 0.00 before any optimization was evaluated, wasting otherwise sound algorithms (e.g., Gen 5's exact on-circle formula `0.5·|sin(b−a)+sin(c−b)+sin(a−c)|`).

## Implementation Insights

- **Vectorized hard-min evaluation with row-broadcasting is efficient enough for O(n³) trials**: The best program's `_min_triple_area` computes, for each (i, j) pair, all k > j areas in one vectorized cross-product operation (`areas = 0.5 * np.abs(v1x*dy - v1y*dx)`), enabling thousands of exact evaluations in 6.20s — no smooth surrogate is needed for speed at n=13 (only 286 triples).
- **Deterministic seeding (or fully deterministic descent) makes results reproducible**: The best program is fully deterministic (no RNG), eliminating seed variance; crashed designs used seed=42 for reproducibility, a good practice.
- **Score = min triple area / convex hull area, with shoelace hull via monotone chain**: The best program computes hull area via Andrew's monotone chain + shoelace (np.roll dot products), matching the scoring metric exactly — optimizing the ratio directly is what lifted it to 0.72.
- **Correct triple-index generation must use 3-index construction**: Working programs avoid `np.triu_indices`-style 2-index unpacking by iterating explicit i < j < k loops or broadcasting, per the crash feedback for Gens 2, 4, 5.

## Performance Analysis

- **Score hierarchy**: Best (Gen 6, hard-min coordinate descent): **0.72**. Soft-min gradient family (Gens 3, 7, 9, 10, 11): 0.18–0.21, clustered tightly at min_area ≈ 0.01. Random baseline (Gen 0): 0.01. Crashed (Gens 2, 4, 5): 0.00. The 3.5× gap between the best and the entire gradient-based cluster shows optimizer *type* matters far more than initialization diversity or iteration count.
- **Hard vs. soft minimum is the decisive factor**: Every program that optimized a smooth soft-min surrogate landed at min_area_normalized ≈ 0.01 regardless of multistart count (Gen 9's 16 inits × 4 seeds, 18.65s vs. Gen 10's 0.13s — same result). Only the exact hard-min coordinate descent (Gen 6) reached 0.02 normalized area and 0.72 combined score.
- **Runtime does not correlate with score**: Gen 11 ran 0.07s for 0.18; Gen 9 ran 18.65s for 0.19; the best ran 6.20s for 0.72. Extra compute spent on smooth gradients bought nothing; compute spent on exact hard-min line searches did.
- **Known ceiling remains far away**: Feedback on the best program notes that known optimal Heilbronn-13 solutions are irregular; the symmetric circle+center start with local descent likely still limits the achievable ratio, and the current 0.72 leaves substantial headroom despite being the clear best so far.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Multi-start hard-min coordinate descent with diverse deterministic seeds.** Keep the exact hard-min coordinate-descent optimizer (which beat all soft-min methods 3.5×), but run it from 5–8 structurally distinct initializations beyond circle+center: e.g., two concentric rings (7+5+center), a hexagonal lattice perturbation, and slightly irregular circle placements (angles perturbed by fixed golden-ratio offsets). Keep each configuration only if its final `_score` exceeds the running best. Evidence: the single symmetric seed is suspected to limit the score since known Heilbronn-13 optima are irregular, but initialization diversity only failed when paired with soft-min gradients (Gen 9); paired with hard-min descent it is untested.

2. **Add perturbation-and-restart (basin hopping) around the converged solution.** After the coordinate descent converges (step < 1e-5), apply a deterministic perturbation (e.g., displace each point by ±0.05·(i mod 3 directions), or rotate ring angles by fixed nonuniform offsets), then re-run descent from the perturbed configuration. Accept only if the final score improves. This directly attacks the local-optimum limitation of pure coordinate descent while preserving its proven exact-objective refinement.

3. **Extend the direction set with randomized/rotated search directions.** The current 8 axis/diagonal directions can only move along 4 orientation axes; add 8 more directions at 22.5° increments (e.g., using cos/sin of k·π/16) to allow the descent to break the ring symmetry and reach irregular configurations known to characterize optimal Heilbronn placements. This is a cheap change to the `dirs` array with no new machinery.

4. **Adaptive per-point step sizes instead of a single global step.** Maintain a separate step size per point, halving only that point's step when none of its trials improve, and occasionally re-growing (e.g., ×1.5 capped at 0.25) when a point was skipped for many sweeps. This lets highly constrained points (like the center) refine finely while hull points explore more, and prevents one "stuck" point from forcing premature global step reduction.

5. **Optimize the hull-area term jointly via mild outward expansion moves.** Since score = min-area / hull-area, small increases in hull area also raise the score — but only if min triple area doesn't drop proportionally. Add an occasional trial that radially expands all outer points by a small factor (e.g., 1.01×) evaluated with the same exact `_score`, accepted only on improvement. Also cache hull-area recomputation: the current `_hull_area` uses a Python-loop monotone chain on 13 points, so replacing it with `scipy.spatial.ConvexHull` or a vectorized version will cut runtime substantially, enabling more descent iterations within the same 6.2s budget.
