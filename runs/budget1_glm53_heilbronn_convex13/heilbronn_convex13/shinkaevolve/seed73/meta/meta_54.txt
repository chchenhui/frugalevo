# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

# Updated Global Insights

## Successful Algorithmic Patterns

- **The 3-fold expand-then-break-symmetry funnel with multi-elite kicks is confirmed as the top architecture**: This generation's Gen 44 (`multi_elite_basin_hopping`, **0.89**, 30.37s) — the current best — and Gen 42 (0.89, 8.67s) both use 4 base points expanded via 120° rotations + center, coarse-to-fine 8-coordinate pattern search, then a 26-coordinate symmetry-breaking polish. Gen 44 adds deterministic multi-amplitude kicks (0.01–0.08, golden-angle per-point directions, ± sign) around the **top-3** elites with re-polish.
- **Seed diversity + exact objective + funnel remains the winning recipe**: Gen 44 uses ~46 seeds (structured radii/angular offsets + 24 random); Gen 52's `fast_hull_incremental_solver` (0.88) similarly uses ~50 diverse seeds (rings, lattices, random) with softmin-gradient ascent, incremental hill-climbing, and multi-elite basin hopping with an amplitude ladder — a fully unseeded-symmetry variant of the same funnel that nearly matched the best.
- **Incremental triangle recomputation is validated at scale again**: Gen 52 caches all 286 triangle areas and updates only rows touched by a moved point via precomputed per-point row maps, making 9000+ move iterations cheap — reaching 0.88 in ~43s.

## Ineffective Approaches

- **Hand-designed deterministic configurations fail outright**: The two zero-scorers this generation (`hardcoded_13pt_3fold_symmetric_config`, `heilbronn13_hull_expand_hybrid`) both scored **0.00 and failed validation**. The hardcoded concentric rings with shared angles produce near-collinear/degenerate minimum triangles; the hill-climb variant's strict 4-base-DOF symmetry plus `except Exception: continue` silently swallowing all seed runs left only the fallback configuration.
- **Fixed kick directions in basin hopping plateau**: Gen 44's own feedback notes the 0.03 min-area plateau is "likely limited by the fixed kick directions in basin hopping rather than a lack of search effort" — the amplitude ladder bought nothing measurable over Gen 42's simpler scheme.
- **Redundant hull recomputation undermines caching**: Gen 52's dirty-check condition `(_hull_area(self.P) != self.ha and True)` is always true, recomputing the hull on essentially every move and negating the denominator-side caching benefit — flagged as a notable speed fix that did not prevent its 0.88 score but wasted budget.

## Implementation Insights

- **What makes Gen 44 (current best) effective**: exact min/hull ratio scoring throughout (no surrogate), scipy ConvexHull with monotone-chain fallback for robustness, per-point batched 16-direction candidate evaluation in `_polish_full` (recomputing only triangles containing the moved point), duplicate-point nudging and regular-polygon fallback for defensive hygiene, and try/except around per-seed and per-kick stages so no single failure zeros the run.
- **Incremental row-cache area updating is the highest-leverage speed technique**: Gen 52's Solver class (~66 triangles per moved point) and Gen 49's earlier incremental climb (0.85, 17.07s) confirm this; Gen 44's `_polish_full` partially adopts it but still calls the hull routine per direction — the main reason it costs 30s vs Gen 42's 8.67s.
- **Exact-objective refinement consistently beats surrogate-guided refinement**: exact-score programs (Gens 42, 44, 52, 45, 49) score ~0.85–0.89, while surrogate-blend programs (Gens 43/46/47) cluster at 0.67–0.76.
- **Objective/scoring misalignment can zero an otherwise-valid program**: Gen 51's unit-hull rescale + ratio-only objective scored 0.00 despite passing validation; the hardcoded and exception-swallowing programs also scored 0.00 — defensive hygiene and objective fidelity are both decisive.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

# Recommendations

1. **Add a hull-shrink / radial-hull-vertex move set to `_polish_full` to attack the 0.03 plateau.** After each full per-point sweep, try (a) scaling all points about the centroid by factors {0.995, 1.005, 0.99, 1.01} and (b) moving only hull-vertex points radially inward/outward by step, accepting only if `_true_score` improves. Since score = min_area/hull_area, the denominator is the only underexploited lever — seven programs stall at 0.03 min-area and all top scorers never shrink the hull alone.

2. **Vectorize `_polish_full`'s 16-direction loop with full incremental triangle recomputation.** Precompute the full 286-entry `_tri_areas(P)` array once per point sweep; for each of the 16 candidate moves of point `i`, update only the ~66 rows containing `i` (precompute per-point row masks once at module load, as Gen 52 did). Skip the `_hull_area(base)` call per direction — the hull changes only when point `i` is a hull vertex; otherwise reuse the cached hull area. This removes the main 30s-vs-8.67s bottleneck and frees ~20s of budget for more seeds/deeper polish.

3. **Replace fixed golden-angle kick directions with per-trial randomized orthogonalized direction sets.** Gen 44's own feedback attributes the plateau to fixed `kick_dirs`; instead, for each (elite, amp, sgn) trial, generate 4–8 rng-seeded random direction sets (rng fixed at seed=42 for determinism) or apply a random per-point rotation to the kick pattern, then re-polish. Keep the polish-after-kick loop — it's the credited element; only the direction diversity changes.

4. **Adopt Gen 42's lean budget allocation: drop the top-3 amplitude ladder, add exact-score two-pass screening.** Rank all ~46 polished candidates by exact `_true_score`, run a cheap 3-sweep mini re-polish on the top 10–20 to re-rank, then deep-polish (min_step=1e-5, wider step ladder 0.02→0.05→0.01) only the re-ranked top 3. Gen 42 matched 0.89 in 8.67s without elite kicks, so this saves ~20s that can fund recommendation 1's hull moves and recommendation 2's deeper sweeps.

5. **Add 4-fold and 6-fold seed symmetry families plus fully-random 13-point seeds fed straight to `_polish_full`.** Keep the proven 3-fold `_expand`, but add: 3 base points × 4-fold rotation + center, 2 base points × 6-fold rotation + center, and ~8 fully random 13-point configurations that skip `_refine_base` entirely and go directly to `_polish_full` + basin hopping. Gen 32 credited its 0.87 to geometric seed diversity; new symmetry families may land in basins structurally unavailable to 3-fold expansions, which is the most plausible escape from the 0.03 plateau.
