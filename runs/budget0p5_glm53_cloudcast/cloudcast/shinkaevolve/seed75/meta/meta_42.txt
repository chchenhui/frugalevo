# Optimization Insights Analysis

## Successful Algorithmic Patterns
- **Dual-strategy per-config comparison remains the decisive structure**: The current best program (Gen 36, steiner_discount_sweep) computes both a swept Steiner tree AND independent per-destination shortest paths, then emits whichever is cheaper per config. This produced the record **726.07 total / 145.21 avg** — beating Gen 40 (sorted_dst_steiner_tree, 756.08) and Gen 41 (single_partition_edge_append, 756.69) by ~30 points (~4%), and duplicated-path routing (1035.14) by ~30%.
- **Discount sweeping with multiple orderings beats fixed-discount and randomized approaches**: Gen 36 sweeps 7 discounts (0.0–1.0) × 3 orderings (default, closest-first, farthest-first), vs Gen 41's fixed 0.01 discount plus 5 randomized perturbation attempts (756.69) and Gen 40's cost-sorted Dijkstra ordering (756.08). Randomized perturbation added zero value — systematic sweeping and ordering did.
- **Sanitization + 1e6/1e9 backfill + reachability guards is the universal correctness contract**: Both Gen 40 and Gen 41 (and the best Gen 36) remove `in_edges(src)` and self-loops, backfill missing costs, filter `reachable_dsts` via `nx.has_path`, and use plain-Dijkstra fallback on the original G for unreachable destinations. - **Whole-edge appends replicated to all partitions via `append_dst_partition_path(d, j, [s, t, G[s][t]])` keep validation passing**: Both Gen 40 and Gen 41 confirmed this; emitting the same edge set across all (dst, partition) pairs preserves validity regardless of which strategy wins.

## Implementation Insights
- **Gen 36's key mechanism — never commit to the Steiner tree unconditionally**: `use_tree = best_edges is not None and best_cost < base_total` compares `_tree_cost(best_edges)` against the union cost of cached `single_source_dijkstra` paths, choosing the cheaper per config. Since discount=0.0 Steiner ≈ independent shortest paths, this guarantees cost ≤ baseline while capturing sharing wins — the single feature separating 726.07 from the 756+ cluster.
- **Discount applied only during attachment, true costs restored after**: Gen 36 modifies weights as `cost * (1 - discount)` on tree edges during attachment, then restores original weights and evaluates with `_tree_cost` on real costs. This avoids Gen 41's pitfall where penalty/fallback costs inflate the final score.
- **Path trimming to the first tree node**: Gen 36 walks `best_path` from each terminal and only appends edges from the first node already in the tree (`idx` scan), avoiding redundant edge additions that Gen 41's greedy appends suffered from.
- **Cheapest terminal attachment**: Gen 36 runs `single_source_dijkstra` from *each* terminal in the growing tree and picks the cheapest hookup, rather than Gen 40's single multi-source attach or Gen 41's src-rooted approach — this is where the modest sweep gains come from.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

# Recommendations

1. **Replace the per-terminal Dijkstra loop with a single multi-source Dijkstra per destination.** The current `_steiner_tree` runs `single_source_dijkstra` from every terminal for every destination (O(|terminals|×) per attach) and contains dead code (`nx.dijkstra_path(...) if False else None`). Use `nx.multi_source_dijkstra(wg, terminals, dst)` — this computes exactly the cheapest terminal-to-dst path in one run, producing identical trees while freeing runtime budget for a wider discount/order sweep (e.g., extend to 12 discounts × 5 orders).

2. **Add per-destination hybrid routing: mix tree and independent paths destination-by-destination.** Gen 36's win came from a whole-strategy comparison, but a destination whose tree branch is expensive and exclusive should be routed independently. Concretely: start from `best_edges`, then for each destination compute (tree-exclusive branch cost) vs (independent `sp_paths[d]` marginal cost); switch if independent is cheaper and prune orphaned edges. All evaluation via `_tree_cost` on true costs, then emit each destination's chosen path via the existing `append_dst_partition_path` loop.

3. **Add a post-hoc leaf-rewiring pass after the sweep selects `best_edges`.** For each leaf branch of the selected tree, try reconnecting its subtree via plain Dijkstra (on true costs) to the nearest surviving tree node; accept if `_tree_cost` decreases. This mitigates the greedy backbone over-commitment during discount-swept attachment and operates purely on real edge costs, avoiding Gen 38's inflated-fallback pitfall.

4. **Sweep structural destination orderings, not just distance-based ones.** The current 3 orders are distance-keyed; add (a) betweenness-centrality-ascending order (lock in backbone hubs first), (b) an overlap-greedy order — iteratively pick the next destination whose independent shortest path shares the most edges with already-attached tree edges, and (c) an adaptive cheapest-attachment order (next dst = min attach cost to current partial tree). Each candidate is judged by `_tree_cost` so there is no validity risk; this widens the sweep that produced the 726.07 record.

5. **Eliminate the per-call graph copy and test per-partition edge deduplication for cost_score leverage.** `wg = h.copy()` inside `_steiner_tree` runs 21+ times per invocation; instead maintain a dict overlay of discounted tree-edge weights restored after each attachment. Separately, since cost_score is 0.00 even at 726.07 and insights point to partition-level edge pricing, run one controlled variant that emits each distinct tree edge once per partition (deduplicated edge list per (dst, partition) while still forming a continuous src→dst chain), explicitly avoiding Gen 35's within-partition re-emission failure mode.
