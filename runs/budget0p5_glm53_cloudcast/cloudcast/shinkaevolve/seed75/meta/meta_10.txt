# Optimization Insights Analysis

## Successful Algorithmic Patterns
- **Correctness first**: The only successful program (Gen 0, Dijkstra Per-Destination, score 0.00 but success_rate 1.00, 5/5 configs, total cost 1035.14) is the only one that passes all validation tests. Every subsequent "improvement" attempt (Gens 1–12) scored 0.0 with 0/5 configs — the baseline pattern of removing src in-edges and self-loops, then running `nx.dijkstra_path(h, src, dst, weight="cost")` and appending paths via `append_dst_partition_path` is the only validated approach.
- **Simplicity of path storage works**: The best program stores paths as `[s, t, G[s][t]]` per edge per partition, exactly matching the `SingleDstPath`/`BroadCastTopology` schema. All failures (Gens 2, 5, 7) were at least partly attributed to path-format mismatches.
- **The cost-optimization opportunity exists but is unexploited**: cost_score is 0.00 despite success, indicating shortest-path-per-destination without shared edges across destinations/partitions leaves large cost savings on the table (feedback to Gen 0).

## Ineffective Approaches
- **k-shortest-path / Yen variants all fail**: Gens 1, 2, 3, 8, 12 all used `nx.shortest_simple_paths` and all scored 0.0. Common failure causes per feedback: `cost=None` edges crashing weight-based pathfinding, unbounded/exponential path enumeration (no cutoff), generator exhaustion, and unreachable-node exceptions in Dijkstra fallbacks.
- **Steiner-tree approaches fail validation**: Gen 4 (metric closure MST) broke by treating a directed graph as undirected — unioned paths not traversable from src; Gen 6 (Takahashi-Matsuyama) failed from blind per-partition duplication ignoring throughput constraints and graph mutation bugs during iteration.
- **Per-edge fragment appending**: Gens 5 and 7 were flagged for appending individual edges rather than coherent per-partition paths, breaking the expected `SingleDstPath` structure.
- **Complexity without correctness**: Gens 2 and 6 layered congestion penalties, reuse discounts, and zeroed-edge multi-source Dijkstra on top of fragile foundations — none passed a single config.

## Implementation Insights
- **Sanitize the graph exactly as the baseline does**: remove `in_edges(src)` and self-loops before pathfinding (present in best program and Gens 3, 8, 12). Gen 4's failure reading costs from the unsanitized original graph `G` (KeyErrors/None) shows the danger of diverging from this.
- **Edge cost handling is a landmine**: `make_nx_graph` produces edges with `cost=None` (unpriced pairs). Gen 0's Dijkstra with `weight="cost"` succeeded because Dijkstra tolerates the graph as constructed in its runs, but Gens 1/2/7's scoring logic on `cost=None` crashed. Any heuristic must explicitly handle None costs (Gen 3's 1e6 penalty backfill was the right idea, but embedded in an otherwise broken implementation).
- **Respect the output schema**: success hinges on using `BroadCastTopology.append_dst_partition_path(dst, partition, path)` with whole paths per partition; string-keyed partition dicts and custom storage (Gen 7) break validation.
- **Dijkstra fallbacks must handle unreachable nodes**: Gen 3's fallback raised on unreachable nodes; the baseline never needed a fallback because Dijkstra was the primary method.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Add a Steiner-tree edge-sharing layer on top of the exact Gen 0 skeleton.** Keep the sanitized copy `h`, per-destination `nx.dijkstra_path(h, src, dst, weight="cost")`, and whole-edge appends via `append_dst_partition_path` identical to Gen 0, but first compute a directed Steiner-ish tree (e.g., iteratively run Dijkstra from src and merge shortest paths to all dsts, only keeping each tree edge once). Then per destination, append the tree's src→dst path. This shares edges across destinations to reduce total cost while preserving the validated I/O contract. Crucially, work only on the directed graph `h` and read edge data from `h`, never the unsanitized `G`.

2. **Backfill `cost=None` edges with a large-but-finite penalty before any heuristic scoring.** Gen 3's 1e6 backfill was the right idea inside a broken program. Before pathfinding, set `h[u][v]["cost"] = 1e6` when None (or simply delete those edges if unreachable nodes are handled). This unlocks use of `nx.shortest_simple_paths`, `nx.multi_source_dijkstra`, and custom scoring without the `None`-cost crashes that killed Gens 1, 2, and 7 — while plain Dijkstra behavior on priced edges stays unchanged, keeping Gen 0's correctness.

3. **Try partition-level path differentiation instead of duplicating every edge across all partitions.** Gen 0 appends each path edge to all `num_partitions`, which likely inflates cost. Instead, for each (dst, partition), compute a distinct path — e.g., cycle through the k-cheapest simple paths (with `cutoff` on path length to avoid enumeration blowup) or alternate between shortest path and second-shortest edge-disjoint path per partition index. Each partition still gets a complete, valid src→dst path, satisfying throughput by spreading load.

4. **Implement a directed, non-mutating Takahashi-Matsuyama-style Steiner heuristic as a pure cost-reduction experiment.** Gen 6 failed on graph mutation during iteration and throughput-blind duplication, not on the core idea. Reimplement it: copy `h` per candidate merge, add terminal dsts one at a time by Dijkstra from the growing tree's nodes (directed, so paths must be traversable *toward* dsts), and track per-edge aggregate partition flow against `throughput` — drop candidates that violate capacity. Only commit the final tree after full computation, then emit whole per-partition paths.

5. **Add an unreachable-node guard around Dijkstra with a pre-check, enabling safe experimentation.** Wrap `nx.dijkstra_path` in a try/except `nx.NetworkXNoPath` and pre-verify `dst in nx.descendants(h, src)` (or `nx.has_path(h, src, dst)`). This small defensive addition costs nothing on passing configs but prevents the fallback crashes (Gen 3) that turn any exploration mutation into a 0/5 result, making future heuristic variants far more likely to survive validation.

**Overall priority**: recommendation 2 + 5 first (safe enablers), then 3 (simplest cost lever within Gen 0's structure), then 1/4 (bigger Steiner-style wins). Baseline total cost to beat: 1035.14.
