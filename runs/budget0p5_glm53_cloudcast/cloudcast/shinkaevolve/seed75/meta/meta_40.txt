# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

# Optimization Insights Analysis

## Successful Algorithmic Patterns
- **Graph sanitization + cost backfill remains the universal correctness contract**: All correct programs in this generation (Gens 31–33, 35, 36, 38, 39) remove `in_edges(src)` and self-loops and backfill missing edge costs (1e6–1e9). The two programs that skipped robust handling (Gen 30's raw `cost=None` Dijkstra crash, Gen 37's broken parent-chain attachment) failed all configs, confirming this is a non-negotiable prerequisite.
- **Baseline comparison is the new best-known cost mechanism**: Gen 36 (steiner_discount_sweep) achieved **726.07 total / 145.21 avg — the lowest cost of any correct program on record**, beating Gen 27's previous best (756.69/151.34) by ~4% and per-destination Dijkstra (1035.14) by ~30%. Its key addition was computing *both* a swept Steiner tree and independent per-destination shortest paths, then choosing whichever is cheaper per config. Since discount=0.0 Steiner tree ≈ independent shortest paths, this effectively guarantees cost ≤ baseline while occasionally capturing sharing wins.
- **Discount sweeping works but only marginally**: sweeping 7 discounts × 3 orderings (Gen 36) matched or beat fixed-discount approaches (Gen 38's 0.01 discount: 756.09; Gen 39's sweep 0.0–0.5: 759.09) — but all remain in a narrow ~726–759 band, confirming tree-construction refinements are nearly exhausted as a lever.
- **Whole-edge appends matching the `SingleDstPath` schema keep validation passing**: every correct program uses `append_dst_partition_path(d, j, [s, t, G[s][t]])` replicated across all partitions. Gen 34 proved edges written to only partition 0 fail validation ("Empty partitions" for all dst×partition pairs 1–9).

## Ineffective Approaches
- **Identical paths across all partitions with no sharing logic**: Gen 31 (single-source Dijkstra duplicated everywhere, 1035.14) and Gen 33/35 (identical tree per partition, 759.09) all scored cost_score 0.00. Diversifying paths for load balancing is also cost-adverse (historical Gens 28/29: ≥1026), so neither pure duplication nor partition-spreading works.
- **Edge re-emission per destination negates deduplication**: Gen 35's feedback explicitly notes that re-emitting each edge per destination within a partition wipes out the intended sharing benefit — the same trap Gen 24 fell into. Sharing must happen at the tree-edge level, charged once.
- **Expensive per-terminal Dijkstra sweeps with no payoff**: Gen 36's feedback notes repeated per-terminal Dijkstra from every tree node adds heavy compute; Gen 39's per-iteration multi-source Dijkstra likewise. Gen 38's `hash((src,dst))` RNG makes perturbation non-reproducible — randomization remains valueless (Gen 38's perturbation trials: 756.09, no gain).
- **Structural shortcuts violate the validator**: Gen 34 (edges only in partition 0) and Gen 30/37 (crash on missing costs / broken parent walks) confirm that any deviation from "every (dst, partition) gets a valid continuous path" yields 0.00 regardless of cost quality.

## Implementation Insights
- **Gen 36's dual-strategy comparison is the decisive new structure**: compute `base_edges` from cached `single_source_dijkstra` paths, then compare `_tree_cost` of the best swept Steiner tree against the baseline union cost, emitting whichever is cheaper. This per-config strategy selection is what produced the 726.07 record — the first program to systematically *not commit* to a Steiner tree when independent routing is cheaper.
- **Cheap 1e6/1e9 backfill + reachability guards** (Gen 36: `reachable_dsts` filter with `nx.has_path`, unreachable-dst fallback on the original graph G) keeps runs_successfully at 1.00 while avoiding the crash modes that killed Gens 30 and 37.
- **Discount sweep details**: Gen 36 applies discounts only *during attachment* (`cost * (1 - discount)` on tree edges) and restores original weights afterward, evaluating each candidate tree with `_tree_cost` on true costs — this avoids Gen 38's pitfall where penalty/fallback costs inflate the final score.
- **Unreachable-dst fallback via plain Dijkstra on original G** (all three non-crashing Gen 36–39 variants) preserved validity where earlier generations silently dropped destinations.

## Performance Analysis
- **Gen 36 (726.07/145.21) is the new best program**, improving on the prior best Gen 27 (756.69/151.34) by ~30.6 total cost points, and beating every other correct program in this batch: Gen 32/33/35/39 (all 759.09/151.82), Gen 38 (756.09/151.22), Gen 31 (1035.14/207.03).

Further Steiner/discount refinements within the 726–759 band appear to have diminishing returns.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

# Recommendations

1. **Replace the per-terminal multi-source Dijkstra inside `_steiner_tree` with a single reverse multi-source Dijkstra per destination.** The current code runs `single_source_dijkstra` from every terminal for every destination (the exact "expensive per-terminal sweep" flagged in Gen 36's feedback), and also contains dead code (`nx.dijkstra_path(... ) if False else None`). Add a virtual super-node connected with zero-cost edges to all current terminals, run one Dijkstra from it (or use `nx.multi_source_dijkstra(wg, terminals, dst)`), and reconstruct the path — output trees should be identical while runtime drops by roughly |terminals|×.

2. **Add a per-destination hybrid strategy: mix tree paths and independent shortest paths destination-by-destination.** Gen 36's win came from comparing whole strategies (all-tree vs all-independent). Extend this granularity: start from the cheaper global structure, then for each destination test whether routing it independently (removing its tree-exclusive branch edges) lowers total true edge cost; if so, switch that destination and prune any now-orphaned tree edges. Since the current program already computes both `sp_paths` and tree paths, this is a cheap incremental refinement that can shave cost when a far destination drags in an expensive branch that only serves it.

3. **Add a post-hoc tree-pruning/rewiring pass after the best tree is selected.** After `_steiner_tree` picks `best_edges`, for each leaf branch test whether reconnecting its subtree via a cheaper path (plain Dijkstra from the nearest surviving tree node) reduces `_tree_cost`; re-run the tree-path emission only on the pruned graph. This directly addresses the greedy over-commitment to the early backbone and operates purely on true costs, avoiding Gen 38's pitfall of inflated fallback costs.

4. **Sweep additional destination orderings to widen the tree-search space.** The current program sweeps 7 discounts × 3 orders; insights confirm ordering matters (the first destination forms the backbone). Add orderings keyed to graph structure rather than just distance: (a) ascending/betweenness-centrality ordering, (b) descending number of shortest-path-overlap neighbors (destinations whose paths share many edges first, to lock in sharing early), and (c) a couple of greedy adaptive orders — pick the next destination as the one cheapest to attach to the current partial tree. Each candidate is still evaluated with `_tree_cost` on true costs, so there's no scoring risk.

5. **Prune unreachable/dead graph structure before the sweep to cut wasted compute, then exploit cost_score structure by testing cheaper edge-charging variants.** First, drop `wg = h.copy()` inside `_steiner_tree` (copy per call × 21 sweep combinations) by maintaining a discount overlay dict of tree-edge weights instead. Second, since cost_score is still 0.00 even at the 726.07 record and insights point to *partition-level edge pricing* as the remaining lever, run one controlled variant: for each (dst, partition), emit the path edges in topological order but test whether appending each distinct tree edge only once per partition (rather than once per destination per partition) still validates — Gen 35's failure was re-emission *within* a partition, which this explicitly avoids by deduplicating the appended edge list per partition while preserving a continuous src→dst chain per destination.
