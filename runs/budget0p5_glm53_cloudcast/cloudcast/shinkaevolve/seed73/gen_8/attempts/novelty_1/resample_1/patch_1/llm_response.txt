steiner_tree_broadcast_and_partition_disjoint_paths</NAME>
<DESCRIPTION>
The current algorithm independently computes a shortest path from src to each destination and then, wastefully, replicates that same path for every partition (num_partitions times). Two improvements:

1. **Reduce redundant transfers with a shortest-path Steiner tree.** Instead of computing each (src→dst) path independently, compute the Steiner tree approximation (networkx's `steiner_tree` on the undirected view, or fall back to a shortest-path DAG). All destinations whose paths share edges get the data forwarded once over shared links instead of once per destination, dramatically reducing total cost on multi-cloud topologies where many regions share transit hubs.

2. **Balance load across networks with diverse paths per partition.** Instead of using the *same* path for all partitions of a destination, compute k-shortest (simple, edge-disjoint when possible) paths per destination and round-robin partitions across them. This spreads traffic over multiple networks (e.g., different cloud interconnects), avoiding bottlenecking a single low-cost-but-low-throughput link, which reduces effective completion time and cost when flows are capacity-limited.

We keep per-partition path storage via `append_dst_partition_path`, so downstream consumers of `BroadCastTopology` still see one edge list per partition — no interface change needed. If fewer than num_partitions diverse paths exist, we cycle among available paths so behavior remains valid.
