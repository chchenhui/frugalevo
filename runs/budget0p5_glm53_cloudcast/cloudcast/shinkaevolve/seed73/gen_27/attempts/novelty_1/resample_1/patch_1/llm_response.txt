<DESCRIPTION>
Process destinations in descending order of their baseline Dijkstra path cost. The most expensive destinations build the expensive trunk edges first; subsequent (shorter/cheaper) destinations can then route through those already-paid-for edges at zero marginal cost via the existing reuse-aware scoring. This maximizes the shared-trunk discount effect without any structural changes — only the iteration order of the destination loop changes. We precompute each destination's baseline Dijkstra cost (with the same edge_cost function so missing costs are penalized) and iterate sorted descending, falling back to original order for unreachable destinations.
