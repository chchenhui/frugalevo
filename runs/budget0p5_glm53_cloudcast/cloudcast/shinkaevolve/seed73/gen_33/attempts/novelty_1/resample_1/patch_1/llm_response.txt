<DESCRIPTION>
Process destinations in descending order of baseline Dijkstra path cost when applying reuse discounts. Long, expensive routes have the most shared-trunk potential; routing them first builds up the set of used edges so that later, shorter destinations can latch onto already-built trunks at a discount. This is a low-risk mutation of the loop iteration order: we pre-compute baseline paths/costs, sort destinations by descending baseline cost, and then run the existing reuse-aware candidate selection in that order.
</DESCRIPTION>
