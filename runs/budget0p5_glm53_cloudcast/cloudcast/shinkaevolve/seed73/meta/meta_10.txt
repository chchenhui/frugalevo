# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns
- **Only two programs passed all 5 configs (100% success)**: the current best "Dijkstra Shortest-Path Broadcast Topology Search" (total cost 1035.14, avg 207.03, but cost_score 0.00) and Generation 9's "Congestion-Aware Multi-Path Broadcast Routing" (total cost 1206.45, avg 241.29). Both build a valid `BroadCastTopology` and append edges via the standard `[s, t, G[s][t]]` format per partition.
- The current best program's simplicity is its key success factor: copy graph, remove src in-edges and self-loops, run plain `nx.dijkstra_path(h, src, dst, weight="cost")` per destination, then append the same path to all partitions. No unbounded path enumeration, no cost-mutation bugs, no undefined methods.
- Generation 9's greedy per-partition re-scoring (base cost + 0.5 × congestion load, 4–8 candidate paths) also preserved 100% success while attempting cost optimization — the only other validated approach, though ~17% more expensive than the best program.

## Ineffective Approaches
- **Unbounded `nx.shortest_simple_paths` enumeration** repeatedly caused total failure (combined score 0.0): Gen 3 wrapped it in `list(...)` and hung/exhausted memory; Gens 1, 2, 5, 6, 7, 8 all used it without strict bounds, leading to crashes or malformed output.
- **Undefined `set_graph()` method** called from `__init__` when `paths` is passed crashed Gens 5 and 8 outright — the evolved block omitted methods referenced by the constructor, showing that any structural change to `BroadCastTopology` risks breaking instantiation.
- **Cost mutation/restore heuristics are fragile**: Gen 4's zero-then-restore shared-trunk cost logic left edges incorrectly priced and failed all tests. Gen 2 had dead code in the partition assignment loop; Gen 7's undirected Steiner tree traversal emitted edges not present in the directed graph.
- Complex structural innovations (Steiner trees Gen 7, weighted exponential partition splits Gen 6, reuse-aware re-ranking Gen 8) all scored 0.0 despite conceptually sound ideas — correctness, not sophistication, is the binding constraint.

## Implementation Insights
- The working pattern is minimal mutation of the base class: the best program uses only `append_dst_partition_path(dst, j, [s, t, G[s][t]])` and never modifies `BroadCastTopology.__init__`. Every program that touched the constructor (Gens 5, 8) or emitted edges not sourced from `G[s][t]` (Gen 3's single-edge segments, Gen 7's undirected tree edges) failed validation.
- Preprocessing before path search is safe and consistent across the two passing programs: remove `in_edges(src)` and self-loops, and use the `"cost"` edge attribute as Dijkstra weight. Gen 9 additionally filtered missing costs; Gen 2's LARGE_COST=1e6 penalty approach did not survive validation.
- Edge attribute handling matters: `make_nx_graph` leaves `cost=None` for pairs not in the cost CSV; Gen 8 defaulted these to 0, skewing weights, whereas the best program simply routes by available costs and succeeds.
- Bounded candidate generation is essential when exploring alternatives: Gen 9 bounded `shortest_simple_paths` to 4–8 paths and passed; Gen 3's unbounded `list(...)` never terminated.

## Performance Analysis
- Score distribution is starkly binary: 8 of 10 programs scored 0.00 (total failure), while only the two 100%-success programs produced any cost data at all (1035.14 vs 1206.45). No program achieved a nonzero cost_score, meaning the cost frontier is untouched.
- The current best program is ~171 total cost (~17%) cheaper than Gen 9's congestion-aware variant, indicating the naive single-shortest-path duplication is currently cost-competitive with load-balanced multi-path routing — likely because partition flows are small enough that a single cheapest path per destination suffices.
- Trend across generations: complexity monotonically increased (diverse paths → Steiner trees → reuse-aware ranking) while success collapsed to zero; the two survivors both kept Dijkstra-based core routing with only bounded, incremental additions.
- The clearest opportunity signal from the data: preserving the best program's validated structure (100% success) while adding *only* shared-trunk or capacity-aware edge reuse in a bounded, non-mutating way — since cost_score 0.00 means even small total-cost reductions below 1035.14 would yield the first nonzero combined score.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Preserve the exact best-program skeleton, mutate only inside `search_algorithm`.** Keep `BroadCastTopology.__init__`, `append_dst_partition_path`, and the preprocessing (copy graph, remove `in_edges(src)` and self-loops) byte-identical — Gens 5 and 8 crashed from constructor changes. Any mutation should be confined to the loop body after `path = nx.dijkstra_path(...)`.

2. **Try a bounded k-shortest-path candidate selection with the Gen 9 safety bound.** Replace the single Dijkstra call with `islice(nx.shortest_simple_paths(h, src, dst, weight="cost"), 4)` and pick the cheapest path per destination — never wrap in `list(...)`. Gen 9 proved 4–8 bounded candidates preserves 100% success; the win would come from occasionally finding cheaper paths than single-source Dijkstra (e.g., when the cheapest dst path is suboptimal for another dst's shared trunk).

3. **Add edge-reuse-aware path weighting without mutating edge costs.** For each destination, compute path cost as `sum(G[s][t]["cost"] for edges) - alpha * reuse_discount(edges already used by prior dsts)`, selecting among 2–4 bounded candidates. Gen 4's zero-then-restore cost mutation failed, but a read-only scoring function (like Gen 9's congestion re-scoring) avoids that fragility and could reduce total cost below 1035.14 by consolidating shared trunks.

4. **Exploit the free cost_score frontier with a minimal-risk perturbation.** Since cost_score is 0.00, even a tiny validated reduction yields the first nonzero combined score. Safest mutation: only change routing when a candidate path is strictly cheaper than the Dijkstra path for that destination (greedy one-sided improvement), keeping Dijkstra output as fallback for all others.

5. **Handle `cost=None` edges explicitly rather than by penalty.** Gen 2's LARGE_COST=1e6 approach failed validation; instead, build the Dijkstra weight via a `weight=lambda u,v,d: d.get("cost") if d.get("cost") is not None else default_fallback` or simply skip None-cost edges when building `h`. This can unlock slightly cheaper paths on edges Gen 8 mis-weighted as 0, but must be tested carefully since the best program succeeds precisely by routing only on available costs.
