# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns
- **The current best program (Gen 17, "Dijkstra Baseline with Candidate Path Planner") matches the minimum observed cost frontier**: 100% success (5/5 configs), total cost 1035.14 (avg 207.03). It shares this cost with Gens 14, 16, and 18 — all of which replicate a single Dijkstra shortest path per destination across all partitions. This is the validated cost floor so far.
- **The winning structural pattern remains**: copy graph, remove `in_edges(src)` and self-loops, run `nx.dijkstra_path(h, src, dst, weight="cost")` per destination, append edges as `[s, t, G[s][t]]` to all partitions. The current best's `PathPlanner` adds candidate machinery but the "never worse than baseline" fallback (`if planner.path_cost(best) > planner.path_cost(dij): best = dij`) guarantees at least baseline cost — a safe design that preserved 100% success.
- **Bounded candidate generation is proven safe**: the current best caps `shortest_simple_paths` at 6 candidates with an early `break`; Gen 20's `islice` bound (4 candidates) also passed 5/5, though at slightly higher cost (1065.13). Unbounded enumeration (prior Gen 3) hung and failed.
- **Preprocessing with `cost=None` edge filtering** (current best's `_build_valid_graph`) plus a fallback to the full graph when no path is found, safely handled incomplete cost data without crashing.

## Ineffective Approaches
- **Candidate-path enumeration adds no cost benefit**: Gen 17 (current best, 6 candidates), Gen 16 (4 candidates + strict-improvement adoption), Gen 20 (bounded 4 candidates, cost 1065.13), and Gen 14 (plain Dijkstra, cost 1035.14) all hit cost_score 0.00. Three of them produced *identical* total cost (1035.14), meaning K-path alternatives were never cheaper than the Dijkstra baseline — the elaborate machinery is pure overhead.
- **Capacity/throughput-aware path spreading inflates cost**: Gen 10's load-aware k-shortest-path partitioning (total 1162.40) and Gen 13's shared-edge round-robin over k=3+ candidates (1095.02) both succeeded but cost 12% and 6% more than the plain Dijkstra baseline. Pushing partitions onto alternate paths for load balance is counterproductive.
- **Large penalties for missing-cost edges distort routing**: Gen 13's 1e6 penalty and Gen 10's fixed 10.0 default likely forced traffic onto expensive priced links; the current best instead *filters* None-cost edges (with a full-graph fallback), achieving the lowest cost.
- **Steiner-tree variants remain broken**: Gen 11 (path-assembly incompatibility), Gen 12 (bidirectional bookkeeping, dead code `if False else`), and Gen 15 (`self.src = str` typo — a one-character bug that fails validation before routing logic ever runs) all scored 0.0 with 0% success. Structural changes to `BroadCastTopology` and non-`G[s][t]` edge emission continue to be fatal.

## Implementation Insights
- **Never modify `BroadCastTopology.__init__`**: Gen 15's `str` vs `str(src)` typo is direct evidence — the routing logic was never even evaluated. Every 100%-success program (Gens 10, 13, 14, 16, 17, 18, 20) used the constructor untouched and appended via `append_dst_partition_path(dst, j, [s, t, G[s][t]])`.
- **The current best's safety-net design is its key contribution**: the fallback chain (`planner.select` → Dijkstra baseline → `nx.shortest_path` on full graph) ensures no destination is ever dropped, explaining runs_successfully 1.00 while still attempting (failed) optimization.
- **Per-partition path diversity has been tried three ways and never helped**: round-robin (Gen 13), residual-capacity assignment (Gen 10), and full replication (Gens 14/16/17/18) — full replication is cheapest, suggesting per-partition flows don't benefit from splitting on these configs.
- **Shared-edge reuse ideas were never validly tested**: Gen 15's reuse-discount heuristic (0.15 discount on tree edges) and Gen 13's free shared edges both aimed at multicast-style cost sharing; Gen 13 ran but cost more, Gen 15 crashed. The shared-trunk concept remains untested in a working program.

## Performance Analysis
- **Cost clustering at 1035.14**: four programs (Gens 14, 16, 17, 18) — including the current best — achieve exactly 1035.14, confirming the plain Dijkstra-per-destination baseline is what the candidate machinery converges to. Gen 20's 1065.13 shows even bounded k-path selection can be slightly worse.
- **Success is now common but cost_score is universally 0.00**: seven of ten evaluated programs in this generation batch achieved 100% success (vs. 2 of 10 previously), yet none earned any cost score. The correctness problem is largely solved; cost optimization below the 1035.14 reference is the untouched frontier.
- **Monotone relationship between path diversity and cost**: full replication (1035.14) < shared-edge k-paths (1095.02) < bounded k-path pick (1065.13 is an outlier) < load-aware spreading (1162.14 range). More partition spreading has consistently *increased* total cost by 6–12%.
- **The most promising unexplored direction evidenced by the data**: a valid shared-trunk/multicast tree that reuses edges across *destinations* (not partitions) — Gen 15's reuse-discount logic — since it was never evaluated due to a trivial constructor typo, while all tested per-partition diversification has only raised cost.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

# Recommendations for Future Program Mutations

1. **Implement a shared-trunk multicast tree with per-destination edge-reuse discounts (the untested Gen 15 idea, done correctly).** Keep the entire current skeleton byte-identical, but inside the destination loop, maintain a `used_edges` set and score each bounded candidate (≤6) as `path_cost(p) - alpha * sum(cost of edges in p already in used_edges)`, with alpha ≈ 0.15–0.5. Select the candidate minimizing this discounted score, but only adopt it if its *true* cost is ≤ the Dijkstra baseline cost (keeping the proven "never worse than baseline" fallback). This is the only direction that ever plausibly reduces cost below 1035.14, since per-destination diversification has consistently failed while cross-destination trunk consolidation has never been validly evaluated (Gen 15 crashed on a constructor typo before its logic ran).

2. **Process destinations in descending order of Dijkstra path cost when applying reuse discounts.** Long routes contribute more shared-trunk potential, so routing the most expensive destinations first (greedy by baseline cost) maximizes the chance that later, shorter destinations can latch onto already-built trunks at a discount. This is a pure mutation of the loop iteration order (`for dst in sorted(dsts, key=lambda d: planner.path_cost(nx.dijkstra_path(h, src, d, weight="cost")), reverse=True)`) plus the reuse-aware scoring from Recommendation 1 — zero structural risk since only the loop body ordering changes.

3. **Build an explicit directed Steiner tree over destinations using the valid-graph copy, then extract per-destination paths from it.** The current best already isolates `h` with `in_edges(src)` and self-loops removed; extend this by computing an approximate Steiner tree (e.g., shortest-path-union heuristic: for each dst, union its Dijkstra path edges into a growing subgraph) and then emit each destination's path as the shortest path *within that union subgraph* rather than the full graph. Critically, emit edges exactly as `[s, t, G[s][t]]` via `append_dst_partition_path` — never attempt custom edge objects or modified `BroadCastTopology` methods, per Gens 11/12/15's fatal failures.

4. **Sweep the candidate bound and reuse-discount parameters as isolated single-variable mutations.** Since Gens 14/16/17/18 all landed at exactly 1035.14, any parameter change that keeps 100% success while moving total cost at all is informative. Run variants with `k_candidates ∈ {2, 4, 8}` and `alpha ∈ {0.0, 0.25, 1.0}` under the reuse-discount scoring from Recommendation 1 — alpha=0.0 replicates the current baseline as a correctness check, while alpha=1.0 makes shared edges effectively free (Gen 13's free-shared-edge idea, but applied across destinations instead of partitions, which is the untested variant). Never enumerate unbounded candidates (Gen 3 hung); always `break` on the cap.

5. **Safely exploit `cost=None` edges only via a bounded fallback, never as primary routing.** The current best filters None-cost edges and succeeds at 1035.14; Gen 2's 1e6 penalty failed and Gen 10's fixed 10.0 default inflated cost. A safe variation: compute the baseline path on the cost-valid graph, then compute an alternative on the full graph using a small uniform default weight (e.g., median observed cost) for None edges, adopting the alternative only if its valid-graph cost is strictly lower. This preserves the "never worse than baseline" invariant while potentially finding shortcuts through edges the current program ignores — the only remaining topological slack in the current best.
