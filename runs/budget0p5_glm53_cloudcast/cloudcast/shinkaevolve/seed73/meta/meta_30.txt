# Analysis of Program Evaluation Results

## Successful Algorithmic Patterns
- **The new cost frontier is 1021.03 (avg 204.21)**, achieved by two programs in this batch: Gen 21 ("Shared-Edge Reuse k-Shortest-Paths Broadcast Search") and Gen 27 ("Shared-Edge Reuse Greedy Broadcast Path Search" — the current best). This **beats the previous 1035.14 Dijkstra-replication floor by ~1.4%**, breaking the assumption that plain per-destination Dijkstra replication was optimal. Both programs use: sanitized graph (in-edges of src + self-loops removed), bounded k=4 candidate simple paths, a `shared_edges` set treating already-paid edges as free, and appending edges as `[s, t, G[s][t]]`.
- **Expensive-destinations-first processing (Gen 27) is a validated refinement**: precomputing per-destination Dijkstra baselines and routing costly destinations first lets later, cheaper destinations reuse committed trunks at zero marginal cost. This ordering contributed to reaching 1021.03.
- **Zero-marginal-cost reuse accounting is the only mechanism that has ever beaten 1035.14**: rather than discounts (Gen 23's 0.5×, Gen 24's 0.3×, Gen 28's 0.3×), Gen 21 and Gen 27 treat shared edges as *completely free* in candidate scoring — and they are the only two programs below the Dijkstra floor.
- **100% success remains fully solved**: all 10 programs in this batch achieved 5/5 configs with the untouched `BroadCastTopology` constructor and `append_dst_partition_path(dst, j, [s, t, G[s][t]])` emission pattern.

## Ineffective Approaches
- **Partial reuse discounts don't work**: Gen 23 (0.5× discount + 0.1 congestion penalty, cost 1125.18), Gen 24 (0.3× discount, 1035.14), and Gen 28 (0.3× discount with "never worse than baseline" rule, 1035.14) all matched or exceeded the Dijkstra floor. Gen 28's feedback is decisive: the strict-improvement adoption rule makes the heuristic *inert* — no candidate can beat minimal Dijkstra true cost, so it degenerates to plain Dijkstra. Gen 23's 1125.18 was the *worst* cost in the batch.
- **Reuse-epsilon Dijkstra (Gen 25) catastrophically inflates cost**: reducing reused edges to ~1e-9 with a congestion penalty yielded total cost 1618.37 (avg 323.67) — 58% above the current best. Making edges nearly free during pathfinding (rather than during candidate *scoring*) distorts route selection badly.
- **Full-graph fallbacks with unvalidated paths are risky**: Gen 26's median-default-weight fallback and unweighted last-resort paths landed at 1035.14 with no cost benefit, and duplicating every path into all partitions offered no savings.
- **Congestion/load-spreading across partitions consistently adds cost**: Gen 30's k=8 candidates with partition cycling cost 1054.05, and Gen 22's epsilon-reduced Dijkstra cost 1065.13 — both above the 1021.03 frontier, confirming the previous insight that partition diversity inflates cost 2–6%.

## Implementation Insights
- **The current best (Gen 27)'s key mechanism is read-only shared-edge bookkeeping**: `shared_edges` is a plain set consulted only during candidate scoring — the routing graph `h` is never mutated. This contrasts directly with Gen 25's mutated cost copy (1618.37) and validates scoring-time reuse accounting over graph-time cost rewriting.
- **Bounded candidate enumeration (k=4) is confirmed safe and sufficient**: every successful program in this batch used `nx.shortest_simple_paths` with an early `break` at 4–8 candidates. Gen 21 and 27 (k=4) achieved the best costs; increasing to k=6 (Gen 24: 1035.14) or k=8 (Gen 30: 1054.05) did not help — pool size is not the bottleneck; the *selection criterion* is.
- **Expensive-first ordering is cheap to add and validated**: Gen 27's `sorted(dsts, key=baseline_cost, reverse=True)` requires one extra Dijkstra pass per destination and was paired with the cost win; Gen 21 achieved 1021.03 *without* it, so the shared-free scoring is the primary driver and the ordering is a compatible enhancement.
- **Never mutate `BroadCastTopology.__init__` remains ironclad**: all 10 programs (100% success each) kept the constructor untouched; the one prior failure (Gen 15) was a constructor typo. The 1e6 penalty for None-cost edges (Gens 21, 27) was used safely here but the previous insight that None-cost *filtering* is cheaper still stands — 1e6 penalties only work when no alternative path exists.

## Performance Analysis
- **Cost distribution across the batch**: 1021.03 (Gens 21, 27 — best) < 1035.14 (Gens 24, 26, 28 — Dijkstra floor) < 1054.05 (Gen 30) < 1065.13 (Gen 22) < 1125.18 (Gen 23) < 1618.37 (Gen 25). Six programs matched or beat the old 1035.14 floor, and two broke through to 1021.03.
- **Zero-marginal-cost reuse > discounted reuse > epsilon-rewriting**: free-shared-edges scoring (1021.03) beat percentage discounts (1035.14–1125.18), which beat near-zero-cost graph mutation (1618.37). This is a clean monotone relationship — the stronger and *cleaner* the reuse incentive applied at scoring time, the lower the cost.
- **cost_score remains 0.00 for every program, including the new 1021.03 frontier**: the scoring baseline is evidently well below 1021.03, so even the best result so far earns no cost points. The gap from 1035.14 → 1021.03 (~1.4%) demonstrates cost reduction is *possible* but far too small to register; the scoring threshold demands a fundamentally different cost structure (likely a genuine shared-trunk/multicast tree across destinations), not greedy per-destination improvements.
- **Partition round-robin over candidates did not sink Gen 27**: despite cycling partitions through the k=4 candidate paths (a pattern that previously inflated cost in Gens 10 and 13), the shared-free scoring kept it at 1021.03 — indicating reuse savings can offset mild partition spreading. Still, Gen 21's simpler shared-edge design matched the same cost, so spreading machinery adds risk without measurable benefit.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

# Recommendations for Future Program Mutations

1. **Replace partition round-robin with per-partition independent shared-edge tracking.** Gen 27 currently adds every emitted edge to a single global `shared_edges` set and cycles partitions through candidates, which Gen 21 showed is unnecessary overhead at the same 1021.03 cost. Instead, run the ordered-destination loop *per partition* (num_partitions iterations), maintaining a fresh `shared_edges` set per partition — within one partition, all destinations are served by the same logical trunk, so reuse consolidation is maximal and each partition converges toward a genuine Steiner-tree-like structure rather than k=4 diversified paths. Keep scoring identical (shared edges fully free); this is the most direct bridge from "greedy reuse" to "multicast tree."

2. **Apply the expensive-first ordering *before* the shared set is populated, but re-score candidates against a hypothetical future trunk.** The validated insight is that free-shared-edge scoring is the primary driver (Gen 21 hit 1021.03 without ordering). A refinement: for each destination, compute candidate scores twice — once against the current `shared_edges`, and once against the union of `shared_edges` plus edges used by *other already-scored but not-yet-emitted* candidates for expensive destinations. Bias selection toward edges that will be shared by multiple destinations (a one-step lookahead trunk detector), while keeping the final score exactly as validated (fully free reuse, never discounted).

3. **Emit identical shared trunks across partitions instead of round-robining candidates.** Currently partition j gets `chosen[j % len(chosen)]`, spreading partitions over up to 4 different paths. Since shared-free scoring already offsets spreading, try the opposite extreme: emit the *same* cheapest-reuse path to all partitions (dropping `j % len(chosen)`). If the evaluator's cost model counts an edge once globally or per partition, this either wins big (edge paid once, replicated free) or matches 1021.03 — a cheap, low-risk single-line mutation that tests the cost model's structure directly.

4. **Build an explicit directed Steiner tree via shortest-path-heuristic (SPH) over `h`, then extract per-destination paths from the tree.** All greedy incremental approaches plateau near 1021.03 with cost_score still 0.00, indicating the scoring baseline requires a fundamentally different cost structure. Implement: start with terminal set = ordered dsts (expensive first); for each terminal, find the shortest path from the *current tree* (not just src) to that terminal using a graph where tree edges cost 0; merge path edges into the tree. Then for each dst, emit the unique tree path from src. Emit edges exactly as `[s, t, G[s][t]]` via `append_dst_partition_path` — never custom edge objects or constructor changes.

5. **Sweep k and a "shared-edge length preference" tiebreaker as isolated single-variable mutations.** Gen 21 vs Gen 27 proves k=4 with correct scoring suffices, but candidate *selection* among ties is untested: add a secondary sort key preferring paths with more edges already in `shared_edges` (breaking cost-score ties toward maximal reuse) or shorter hop-count paths (fewer paid edges). Run k ∈ {1, 2, 4} variants — k=1 collapses to ordered Dijkstra-reuse as a correctness baseline, while the tiebreaker variants may unlock reuse opportunities invisible to pure cost ranking. Keep the `break` cap always; never enumerate unbounded candidates.
