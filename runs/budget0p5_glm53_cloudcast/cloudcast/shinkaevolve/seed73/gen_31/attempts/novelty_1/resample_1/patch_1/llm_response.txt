greedy_shared_edge_ordering</NAME>
<DESCRIPTION>
Improve on the k-candidate approach by: (1) processing destinations in order of decreasing baseline Dijkstra cost so expensive destinations build shared trunk edges that later (cheaper) destinations reuse for free, and (2) replacing the fixed set of k candidates with an exact Dijkstra run on a dynamically re-weighted graph where already-paid (shared) edges cost ~0. This is a classic greedy Steiner-tree heuristic for multicast/broadcast: it minimizes marginal cost per destination instead of independent shortest paths. Costs remain on valid edges only (None-cost edges penalized), preserving the 100% success rate while cutting redundant transfers.
