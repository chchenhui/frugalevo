## Successful Algorithmic Patterns

- **The current best remains Gen 31's multi-order discounted-refinement recipe (744.69 total, 148.94 avg)**, implemented in this batch's "Iterative Discounted-Refinement Multi-Destination Broadcast Routing" (Gen 32, identical score of 744.69). # META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

# Recommendations for Future Mutations

1. **Eliminate per-partition edge duplication — the single highest-leverage fix.** The current best loops `for j in range(num_partitions): bc_topology.append_dst_partition_path(d, j, [s, t, G[s][t]])`, so every trunk edge is emitted into all 4 partitions and counted at full cost 4×, which is the confirmed structural blocker behind cost_score=0.00 despite a 28% cost reduction. Assign each shared edge `(s, t)` to exactly one partition — e.g., the partition of the first destination that used it — while still emitting a valid `src→dst` path per partition (rebuild each partition's path from its assigned edge subset, filling gaps with cheapest non-shared edges if needed for connectivity).

2. **Add a swap-based local-search post-pass over the winning tree.** After `simulate()` commits the best ordering, iterate: for each destination `d`, remove `d`'s edges from `final_used`, recompute `shortest_with_discount(final_used, d)`, and accept the new path if the true undiscounted sum over the resulting edge set decreases. Repeat until no improvement or a fixed iteration cap (e.g., 5 rounds). This directly attacks greedy lock-in inside the proven discounting framework and is nearly free given the small destination count.

3. **Replace src-rooted Dijkstra with Steiner-style grafting onto the accumulated tree.** Instead of always routing from `src`, run discounted Dijkstra from each destination to the *nearest already-connected node* in the tree and graft only the new branch. With discount=0.0 the current program approximates this implicitly, but explicit grafting lets you compare the true incremental cost of each candidate graft point and pick the minimum — a structurally different accounting that avoids long free-edge detours that inflate the evaluator's undiscounted bill.

4. **Expand the ordering search with dynamic orderings while keeping true-cost selection.** Currently only 3 static orderings are simulated. Add: (a) a dynamic ordering that at each step picks the destination with the largest discounted-cost reduction versus `orig_cost[d]`, (b) a hop-count ordering, and (c) a random-restart set (fixed-seed, ~5 permutations). Keep the exact `simulate()` selection mechanism (minimum total over unique undiscounted edges) that proved decisive in Gen 24/31/32 — compute is negligible at this scale, so even 10 candidate orderings is trivial.

5. **Add a throughput feasibility filter on heavily-shared trunk edges.** The current program ignores `throughput` entirely; if multiple destinations funnel over one shared edge, aggregate demand may violate capacity and gate cost_score even after the duplication fix. Track per-edge destination counts during `simulate()`; when `count × per-dst flow > throughput`, restore the edge's original cost (remove it from `sim_used`) so later destinations route around it. Per the Gen 27/30 evidence, apply this strictly as a hard capacity filter — never as load-spreading, which costs 5–10%.
