# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns
- **Shared-edge discounting is the biggest cost breakthrough yet**: Gen 10 ("shared_edge_discount_dijkstra") achieves total cost 756.09 (avg 151.22) — a ~25% reduction vs the previous best (Gen 5, 1002.43) and ~27% vs the Dijkstra baseline (Gen 0, 1035.14). The technique (discounting already-used edges to 0.001 and re-running Dijkstra per destination in ascending original-cost order) exploits cross-destination edge sharing, which the previous per-destination k-shortest-path paradigm (all clustered at 1002–1095) never touched.
- **Proven structural invariants hold**: strip source in-edges and self-loops, append per-edge `[s, t, G[s][t]]` tuples per partition via `append_dst_partition_path`, handle None costs (Gen 10 sets them to 1e9 rather than infinity — valid routes preserved). All 5/5-successful programs in this batch share these patterns.
- **Ordering matters for sequential sharing**: Gen 10 processes destinations sorted by original shortest-path cost, letting cheap destinations free-ride on edges locked in by expensive ones first — the opposite of Gen 18 (decreasing cost order, 948.05) which performed worse despite similar reuse intent.

## Ineffective Approaches
- **Load balancing / congestion spreading remains cost-hostile**: Gen 12 (Monte Carlo congestion-aware, 1086.34), Gen 13 (round-robin over load-inflated candidates, 1088.83), Gen 15 (marginal cost with λ=0.05 penalty, 1095.31) all scored worse than the plain Dijkstra baseline (1035.14). The exponential/weak congestion penalties push partitions onto expensive alternates with no scoring reward.
- **Concentrating all partitions on one cheapest path is not the answer either**: Gen 17 and Gen 22 (both 1065.13) show single-path assignment exceeds baseline cost — likely throughput/capacity effects or pure path-quality loss.
- **Steiner-tree trunk building without deduplication wastes the sharing**: Gen 11 (1033.77), Gen 19 (988.27), and Gen 16 (1044.15) build shared trunks but append the full edge list to every partition, so sharing never reduces summed cost. Only Gen 10's discounting actually changes *which* edges get used downstream.

## Implementation Insights
- **Gen 10's winning mechanism**: after routing each destination, its path edges are added to `used_edges`; subsequent Dijkstra runs on a copy with those edges' cost set to 0.001, so later destinations are strongly pulled onto already-paid-for links. This is the first program to materially change the cost structure rather than just reshuffle candidates.
- **Sequential per-destination Dijkstra with state (used_edges set) is cheap and robust** — no exception-prone tree grafting (which broke Gen 4, Gen 7) or randomized search (Gen 12) required.
- **Reuse scoring within partitions (Gen 18's REUSE_BONUS=0.9, 948.05) beats load spreading but loses to sequential global discounting** — reuse must be across destinations, not within a partition's own paths.
- Even Gen 10's 756.09 still yields cost_score 0.00, indicating the scoring baseline requires an even more radical cost reduction than 27% — possibly true edge deduplication across partitions rather than just shared path selection.

## Performance Analysis
- **New cost ranking of correct programs**: Gen 10 (756.09) ≪ Gen 18 (948.05) < Gen 19 (988.27) < Gen 5 (1002.43) < Gen 0 (1035.14) < Gen 16/11 < Gen 17/22 (1065.13) < Gen 12/13/15 (1086–1095).
- **Correlation confirmed**: the closer the algorithm stays to cheapest-path selection while adding cross-destination sharing, the lower the cost. Spreading heuristics (1086–1095) consistently cost ~10% more than the baseline; sharing heuristics break below it.
- **Correctness remains bimodal and gated on output format** — every program in this batch passed 5/5, validating that the per-edge append pattern is now a solved, reliable template.
- Despite a 27% cost improvement, cost_score is still 0.00 across all 11 evaluated programs, suggesting the threshold for nonzero cost_score is far below 756 total — future gains must come from eliminating per-partition edge duplication (e.g., partition-specific path truncation or shared-prefix accounting), which Gen 11/19 feedback explicitly points toward.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

# Recommendations for Future Mutations

1. **Tune the discount magnitude and make reuse costs fully free within a refinement loop.** Gen 10 uses 0.001; try a small sweep of the discount value (e.g., 0.0, 0.01, 0.1) — a zero discount makes later destinations maximally greedy for reuse, which may pull them onto slightly longer but already-paid routes and further cut total cost. Also try an outer refinement loop: after all destinations are routed, re-run the entire routing pass with used_edges initialized from the previous pass (iterated discounting often converges to better shared trunks in 2–3 passes at trivial compute cost).

2. **Iterate over destination ordering strategies within the proven sequential-discount framework.** Gen 10's ascending-cost order beat Gen 18's descending order (756 vs 948), but other orderings are unexplored: (a) descending number of shared edges with the src's immediate neighborhood, (b) greedy dynamic ordering — at each step pick the destination whose discounted shortest path drops the most relative to its original cost, or (c) ordering by path length (hop count). Keep the discount mechanism and per-edge `[s, t, G[s][t]]` append format exactly as in Gen 10.

3. **Add a swap/local-search post-pass on the routed solution.** After Gen 10's sequential pass, run a local improvement phase: for each destination (in random or cost order), recompute its shortest path on a graph where edges used by *other* destinations are discounted; if the new path yields lower total unique-edge cost when substituted, keep it. This fixes the greedy lock-in weakness of sequential processing without the exception-prone tree grafting that broke Gen 4/7.

4. **Use true Steiner-tree construction with correct per-partition deduplication.** The insights note Gen 11/16/19 built shared trunks but appended full edge lists to every partition, wasting the sharing. Combine Gen 10's discounting with an explicit Steiner approximation (e.g., repeated shortest-path-to-nearest-terminal, Kou–Markowsky style) over the destination set, then assign each destination its root-to-terminal path *including only edges on its own branch* — while still emitting each partition's edges as `[s, t, G[s][t]]` tuples. This directly targets the deduplication the cost_score gap implies.

5. **Apply capacity/throughput as a hard feasibility filter on shared trunk edges.** Gen 10 ignores throughput; if many destinations concentrate on discounted shared edges, per-edge aggregate flow may exceed `h[s][t]['throughput']`. Add a check: when adding a path edge to used_edges, track per-edge destination count; if `count * flow > throughput`, exclude that edge from future discounting (restore its original cost) so later destinations route around it. This guards against hidden feasibility gates that may be capping cost_score at 0.00, without re-introducing load-spreading penalties (which the data shows cost ~5–10%).
