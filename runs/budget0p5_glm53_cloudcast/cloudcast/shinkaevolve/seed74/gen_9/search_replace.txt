<DESCRIPTION>
The key inefficiency is that each partition independently traverses the same edges from src, paying the same cost num_partitions times. Instead, assign each partition its own shortest path (shortest paths differ per partition by removing used edges), and for partitions that share a common prefix with the cheapest path, only re-send on diverging suffixes. The current code already scores candidates but the round-robin assignment ignores cost and still duplicates. Improve by: (1) computing per-partition distinct paths via iterative edge-removal Dijkstra (k-shortest-path style), (2) preferring the absolute cheapest path for most partitions while spreading the remainder across parallel low-cost alternatives, and (3) keeping the load-balancing scoring. Also handle None costs gracefully (treat as excluded edges when possible paths exist).
