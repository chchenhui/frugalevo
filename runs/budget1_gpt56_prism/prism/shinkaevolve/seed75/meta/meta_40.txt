# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Expand threshold-packing order diversification with residual-capacity-aware item orders.** Add deterministic orders such as descending `(size / max(80 - size, EPS), demand, size)`, descending `(size > 40, size, demand)`, and descending `demand / max(80 - size, EPS)` to prioritize models that are difficult to place without eliminating KV-cache headroom. Keep the existing transformed-size, memory-first, and demand-first orders, since multi-order construction is a demonstrated source of robustness and quality.

2. **Use a stronger candidate-GPU tie-break during threshold construction based on the projected full pressure profile.** After enforcing transformed and physical capacities, compare candidate GPUs first by projected maximum pressure and then by a compact lexicographic profile such as `(projected_max_pressure, projected_second_max_pressure, transformed_fill, -new_remaining)`. This preserves the successful threshold-feasibility formulation while avoiding greedy placements that create multiple nearly saturated pressure bottlenecks.

3. **Add the symmetric two-for-one exchange neighborhood to the existing one-for-two local polish.** The current code can move one model from `left` in exchange for two models from `right`; also enumerate replacing two models on a bottleneck GPU with one model from another GPU, checking only the final memory-safe state and accepting strictly improved pressure profiles. Previous high-performing local-search families showed that variable-cardinality exchanges help resolve fragmentation patterns that moves and ordinary swaps cannot repair.

4. **Focus local-search enumeration on bottleneck and near-bottleneck GPUs before scanning all GPU pairs.** Build a deterministic active set containing GPUs within a small tolerance of `current_profile[0]`—for example, the top two or all pressures at least `0.95 * max_pressure`—and prioritize moves, swaps, and exchanges involving those GPUs. This can permit richer neighborhoods or more polish iterations without sacrificing the current program’s key runtime advantage, because only changes affecting the maximum-pressure region are likely to improve the minimax objective.

5. **Add a bounded deterministic perturb-and-repolish phase after strict local descent stalls.** From the polished threshold solution, try a few capacity-safe neutral-profile swaps or very small worsening relocations involving bottleneck models, then rerun the existing strict move/swap/exchange descent and retain only states that beat the original solution. This extends the successful multi-start/local-search pattern without weakening correctness or accepting inferior final placements, and may escape local minima created by the greedy threshold packing order.
