# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Multi-start greedy construction plus bounded bottleneck refinement is the strongest evaluated pattern.** The current best, **Generation 8: Multi-Start KV Cache Pressure Placement**, reached **25.87 combined / 24.87 max_kvpr**, improving over single-start local-search variants such as Generation 6 (**25.85**) and Generation 3 (**25.63**). Its four deterministic orderings address different failure modes: high request pressure, large-model packing, pressure density, and size-weighted pressure.

- **Lexicographic minimization of the complete sorted GPU-pressure vector consistently performs well.** Generation 2 and Generation 5, both lexicographic greedy-plus-local-search approaches, reached **25.80 / 24.80**. The current best retains that objective both during construction and refinement, rather than optimizing only the currently worst GPU. This preserves improvements to the bottleneck while also favoring more balanced second- and later-ranked GPU pressures.

- **Strictly improving local exchanges substantially outperform pure greedy placement.** The initial greedy baseline (Generation 0) scored only **21.89**, while adding relocation in Generation 1 reached **22.78**. More complete move/swap search raised results to **25.63–25.85**, and the current best’s inclusion of **one-for-two exchanges** reached **25.87**. The evaluation therefore supports local-search neighborhoods that can resolve both pressure imbalance and memory fragmentation.

- **Capacity-aware pressure modeling is essential and remained successful across all correct programs.** The best implementation evaluates each GPU as `load / remaining_memory`, checks every move/exchange against the 80-GB constraint, and raises an explicit error when greedy construction cannot place a model. All evaluated programs with these feasibility safeguards maintained **100% success rates**.

## Ineffective Approaches

- **A single simple greedy ordering leaves substantial placement quality on the table.** Generation 0’s descending request-rate/SLO greedy assignment scored **21.89**, nearly **3.98 points below** the current best’s **25.87**. Although fast and correct, it lacked alternate orderings and post-placement refinement, making it more exposed to early memory-fragmentation decisions.

- **Adding only limited relocation gives a modest but insufficient gain.** Generation 1 added targeted bottleneck relocation and improved to **22.78**, but remained **3.09 points below** the best result. Its “up to one relocation pass per model” could improve some bottlenecks, but did not provide the richer swap/exchange mechanisms needed when a useful move requires coordinated reassignment.

- **Single-start minimax construction can underperform lexicographic multi-start search.** Generation 4’s prospective minimax greedy placement with relocation scored **23.05**. Even though it explicitly minimized resulting maximum KVPR, it lagged Generation 2/5’s lexicographic approaches (**25.80**) and the current best (**25.87**), indicating that minimizing only the immediate maximum is less robust than comparing the full pressure profile across multiple starts.

- **Additional search complexity showed diminishing measured returns after the strong lexicographic baseline.** Generation 2/5 scored **25.80**, Generation 6 scored **25.85**, and Generations 7/8 scored **25.87**. Thus, swaps and one-for-two exchanges helped, but the gain from the current best over the already strong pairwise-swap variant was only **0.02**, rather than a large step change.

## Implementation Insights

- **The current best uses a precise state comparison rather than a scalar-only heuristic.** `state_objective()` sorts all GPU pressures in descending order and compares tuples lexicographically. In greedy construction, each feasible GPU is evaluated by its *post-assignment global state*, not merely its own local pressure. This matches the high **24.87 max_kvpr** result and the similarly strong Generation 2/5 lexicographic implementations.

- **Its construction phase explicitly diversifies ordering without randomized runtime cost.** Four deterministic orders are used: descending pressure/size, descending size/pressure, pressure-per-GB density, and pressure scaled by model size. Candidate placements are then ranked by the same lexicographic objective. This is a concrete robustness mechanism for memory fragmentation and likely explains why the multi-start generations (**25.87**) slightly exceeded the three-order lexicographic variants (**25.80**).

- **Refinement is best-improvement and bottleneck-focused.** The current best considers moves, one-for-one swaps, and one-for-two exchanges only from GPUs whose pressure equals the current maximum within `EPS`. Each candidate is accepted only when it strictly improves the full objective. This avoids cycling, bounds work through `max_iterations`, and preserves the negligible reported execution time (**0.00**) while improving placement quality.

- **Feasibility and numerical edge handling are implemented defensively.** The program handles zero/negative GPU counts, records per-GPU remaining memory, rejects infeasible placements, and defines pressure safely for exhausted memory (`inf` only when positive load remains). These choices align with the evaluator’s **1.00 success rate** and with feedback emphasizing reliable feasibility handling in Generations 2, 5, 7, and 8.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Refine all four greedy starts instead of only the best two, while retaining the same bounded best-improvement loop.** The current code already pays the construction cost for four diverse orderings but discards local-search opportunities for the third- and fourth-ranked starts; a slightly weaker greedy state can lie in a better local-search basin. Since evaluated execution time is effectively negligible and multi-start search is the strongest demonstrated pattern, test refining all candidates or at least candidates within a small lexicographic tolerance of the second-best start.

2. **Add reverse two-for-one exchanges in addition to the existing one-for-two neighborhood.** The current refinement can replace one bottleneck model with two models from a target GPU, but cannot replace two bottleneck-GPU models with one larger model elsewhere; this asymmetric omission can leave packing and pressure improvements unreachable. Implement a `pair_for_one` candidate that chooses pairs on current bottleneck GPUs, checks both post-exchange capacities, and accepts only strict improvements to the complete sorted pressure vector.

3. **Use an adaptive bottleneck candidate set rather than restricting every exchange source to exactly the current maximum-pressure GPU.** Preserve the lexicographic objective and strict-improvement rule, but also inspect the second- or third-highest pressure GPUs when their pressure is within a small relative/absolute threshold of the maximum. This can enable coordinated balancing where moving work from a near-bottleneck GPU prevents it from becoming the new maximum after relieving the current bottleneck, while remaining consistent with the proven full-vector lexicographic criterion.

4. **Add a deterministic repair-oriented construction ordering focused on large-model feasibility.** In addition to the four current pressure/size orderings, try a “hard-to-place first” ordering such as descending `(model_size / 80, pressure_density, model_size)` or prioritize models with sizes above half a GPU before normal pressure ordering. The current multi-start diversity is a proven advantage, and this extra ordering directly targets the remaining failure mode of fragmented free memory that can limit the quality of otherwise pressure-balanced starts.

5. **Introduce limited multi-step local-search escape moves with an intermediate non-worsening constraint.** When no single move, swap, or one-for-two exchange strictly improves the lexicographic state, search a small deterministic set of two-step sequences—such as moving a low-pressure model to free capacity, followed by moving a bottleneck model—where the first step does not worsen the maximum pressure beyond a tiny EPS tolerance and the final state strictly improves. This extends the demonstrated value of coordinated exchanges without abandoning feasibility checks, bounded runtime, or the successful strict final lexicographic improvement policy.
