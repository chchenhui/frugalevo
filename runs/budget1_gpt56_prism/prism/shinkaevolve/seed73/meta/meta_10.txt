# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Multi-start greedy construction combined with both relocation and swap refinement produced the best results.** The current best, **Multi-Start GPU KV Pressure Placement** (Generation 9), scored **26.21** with **max_kvpr 25.21**, **0.02 s** runtime, and **100% success**. It evaluates five ordering heuristics under two tie-breaking policies, then uses best-improving feasible relocations and swaps. This outperformed otherwise similar local-search variants: Generation 5 scored **25.83**, Generation 7 **25.67**, and Generation 8 **25.55**.

- **Using projected global maximum KVPR as the greedy assignment objective is consistently effective.** Rather than assigning according to only local load or a fixed ratio, the successful programs evaluate the post-placement maximum pressure. Generation 1’s projected-KVPR greedy plus local search reached **25.85**, and Generation 5’s memory-aware projected-max-KVPR strategy reached **25.83**. This is materially stronger than the initial Generation 0 greedy ratio heuristic at **21.89**.

- **Diversified model ordering reduces sensitivity to memory fragmentation.** The current best tries weight-first, size-first, weight×size, weight/size, and a size-first alternative ordering. Earlier multi-order greedy-only programs validate this benefit over a single ordering: Generation 6 reached **23.31**, Generation 3 reached **23.41**, and Generation 2 reached **24.57**. The best score occurs when that diverse initialization is followed by local search.

- **Strictly improving, memory-feasible local actions are a strong refinement pattern.** Generation 9 only accepts moves or swaps whose score improves by more than a small epsilon and verifies target capacity before moving or exchanging models. The same approach was successful in Generations 5, 7, and 8, all above **25.5**, indicating that feasibility-preserving bottleneck reduction is a reliable source of quality gains.

## Ineffective Approaches

- **Control-flow defects can eliminate all algorithmic value regardless of the intended heuristic.** Generation 4, **Greedy GPU KV Cache Placement**, scored **0.00** because its swap logic and candidate-selection code were unreachable after early returns, while reachable code used undefined `model_pressure`. Although it intended multi-start greedy placement and local improvement, validation failed before a placement could be produced.

- **A simple one-pass greedy rule is substantially weaker than projected minimax construction plus refinement.** Generation 0 was correct and extremely fast, but its descending request-rate/SLO ordering and lowest weighted-load-to-remaining-memory selection scored only **21.89**. Compared with Generation 9’s **26.21**, the gap is **4.32 combined-score points**, showing that feasibility alone is not enough to achieve high KVPR quality.

- **Multiple orderings without swaps/local search leave quality on the table.** Generations 2, 3, and 6 use multi-order greedy construction, with at most relocation refinement, and scored **24.57**, **23.41**, and **23.31**, respectively. All are correct, but remain below the **25.55–26.21** range reached by variants that add both relocations and feasible pairwise exchanges.

- **Implementation sophistication must remain executable and scoped correctly.** Generation 4 demonstrates that adding swap logic is not beneficial if it is incorrectly indented or placed after `return`; correctness and reachability are prerequisites for the optimization strategy to affect evaluation metrics.

## Implementation Insights

- **The current best isolates placement mechanics in a mutable state object.** `PlacementState` keeps `groups`, cumulative request/SLO `loads`, and `remaining` memory synchronized, with dedicated `add`, `move`, and `swap` methods. Its `projected_add_score`, `move_score`, and `swap_score` methods compute candidate quality before mutation. This structure supports safe local search and likely contributes to Generation 9’s perfect success rate.

- **The objective correctly models the evaluated pressure metric as load divided by remaining memory.** The best program’s `ratio(load, remaining)` returns `load / remaining` for positive remaining memory and treats positive load at zero memory as infinite. Greedy selection minimizes the resulting global maximum, directly aligning each construction and refinement decision with the reported `max_kvpr` objective.

- **Capacity checks are explicit at every stage.** Generation 9 rejects individual models larger than 80 GB, accepts greedy candidates only when `model_size <= remaining[gpu]`, checks move feasibility against target remaining memory, and checks both post-swap memory balances. The evaluation feedback specifically confirms correct validation and **100% success**, unlike the failed Generation 4 implementation.

- **The tie policy is deliberately diversified rather than incidental.** For equivalent projected scores, `pack_ties=True` prefers lower post-placement remaining memory, preserving empty GPUs for potentially large later models; `pack_ties=False` prefers more remaining memory, spreading work. Running both policies for every ordering gives ten construction paths with minimal measured runtime cost. This is a concrete extension beyond earlier two-, three-, or four-order variants.

## Performance Analysis

- **Generation 9 is the strongest evaluated correct program at 26.21.** It exceeds Generation 1 (**25.85**) by **0.36**, Generation 5 (**25.83**) by **0.38**, Generation 7 (**25.67**) by **0.54**, and Generation 8 (**25.55**) by **0.66**. The improvement is modest over other local-search designs, but consistent with the added breadth of five orderings and two tie policies.

- **The main performance jump comes from moving beyond plain greedy placement.** Generation 0’s **21.89** rose to **23.31–24.57** for multi-order greedy methods (Generations 6, 3, and 2), then to **25.55–26.21** when multi-start construction was paired with relocations and swaps (Generations 8 and 9). The results show a clear progression: projected minimax placement improves initial quality, while local search closes remaining imbalance and fragmentation gaps.

- **Swap-enabled refinement correlates with the top score band.** Generation 5’s relocation-and-swap approach scored **25.83**, Generation 7 scored **25.67**, Generation 8 scored **25.55**, and the current best Generation 9 reached **26.21**. By contrast, relocation-only multi-order methods remained at **23.41–24.57**, suggesting that exchanges are particularly useful when capacity constraints prevent a beneficial one-way move.

- **Runtime did not meaningfully penalize the stronger search strategies in this evaluation.** Generations 1, 5, 7, and 8 all reported **0.00** execution time, while the broader Generation 9 procedure reported only **0.02 seconds**. Its additional ordering diversity, dual tie-breaking, bounded iteration limit, and exhaustive best-improvement checks therefore delivered the best quality with still negligible execution cost.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Add bounded two-step neighborhoods after the existing move/swap local search.** Preserve strictly improving feasibility checks, but evaluate small compound actions such as moving one model to a temporary feasible GPU followed by a second move, or a 2-for-1 exchange between two GPUs. This directly extends the proven swap-enabled refinement pattern and may escape local optima where neither a single relocation nor a one-for-one swap improves the maximum KVPR.

2. **Use a bottleneck-focused candidate reduction strategy for richer local search.** Identify GPUs currently at, or within a small tolerance of, the maximum KVPR, then prioritize moves/swaps involving models on those GPUs and destinations with low pressure or useful free-memory profiles. This keeps the current objective-aligned best-improvement approach while allowing more iterations, additional neighborhoods, or more starts without materially increasing the already-low runtime.

3. **Expand initialization with pressure-aware hybrid ordering heuristics.** In addition to the five existing static orderings, add orderings such as descending `(weight / max(GPU_MEM_SIZE - model_size, tiny))`, descending `(weight, -model_size)`, and descending weight with large-model-first buckets. The current best already shows that diverse orderings and both packing/spreading tie policies improve robustness, so a few targeted orderings may expose initial layouts that existing local search can refine into better basins.

4. **Introduce controlled non-worsening plateau moves followed by strict improvement.** When ordinary best-improvement search stalls, permit one or two memory-feasible actions that preserve the current score within epsilon but substantially change remaining-memory distribution, then resume strictly improving relocation/swap search. This is a conservative way to overcome fragmentation barriers while retaining the successful minimax objective and avoiding unrestricted random perturbation.

5. **Add a focused large-model repair phase before general refinement.** After greedy construction, inspect GPUs with little remaining capacity and test exchanges involving the largest assigned models, especially swaps that increase free memory on high-pressure GPUs while maintaining capacity on both sides. Memory fragmentation is the main reason multi-order construction helps, and targeted large-model exchanges build directly on the demonstrated value of feasible pairwise swaps.
