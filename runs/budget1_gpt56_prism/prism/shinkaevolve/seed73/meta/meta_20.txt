# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **The current best program, Generation 19 “lexicographic_bottleneck_search,” combines broad initialization with compound local search and achieved the top evaluated score of 26.23** (`max_kvpr` 25.23, 0.01 s, 100% success). It runs five model orders and both packing/spreading tie policies, producing ten feasible greedy seeds. This retains the successful diversification pattern from the earlier Generation 9 result (26.21) while slightly improving it.

- **Projected global KVPR minimization remains the key greedy-construction choice.** In the current program, every feasible GPU candidate is evaluated by its projected maximum `load / remaining_memory` ratio rather than by load, size, or a purely local score. This directly aligns construction with the evaluator’s pressure objective. Earlier evidence supports this: simple greedy placement in Generation 0 reached only 21.89, while projected-minimax multi-order approaches reached the mid-20s.

- **Best-improvement relocations and swaps are consistently associated with the high-score band.** Generation 19 searches feasible relocations from bottleneck GPUs and memory-safe pair swaps, accepting an action only when it improves the lexicographically sorted pressure vector. This expands on the prior strongest pattern—multi-start greedy plus relocation/swap refinement—which produced 26.21 in Generation 9 and 26.19–26.20 in Generations 11, 13, and 14.

- **One-for-two exchanges help address memory fragmentation without harming runtime.** Generation 19 includes a one-model-for-two-model compound exchange only after ordinary moves and swaps find no improvement. This mechanism was also present in Generation 17, which reached 26.21, compared with 25.54–25.66 for several otherwise similar move/swap-only variants (Generations 10, 12, 16, and 18). The current result suggests that compound exchanges contribute a small but measurable gain when simple neighborhoods are blocked by capacity constraints.

## Ineffective Approaches

- **Single-pass or weakly refined greedy placement leaves substantial quality unrealized.** Previous results show Generation 0’s simple greedy rule at 21.89, while multi-order greedy-only or relocation-limited methods reached roughly 23.31–24.57. In contrast, the current best’s diversified greedy construction followed by local search reached 26.23. Feasible placement alone is therefore insufficient for strong KVPR balance.

- **Additional local-search complexity does not automatically yield a better score.** Generation 13 used six sort orders, two memory tie-breaks, lexicographic improvement, and bounded search, but scored 26.20 at 0.04 s—slightly below Generation 19’s 26.23 at 0.01 s. Likewise, Generation 17’s one-for-two exchange approach scored 26.21. The current program’s advantage is marginal, showing that most of the value came from the established multi-start-plus-local-search structure rather than any one sophisticated extension.

- **Plateau-escape variants did not clearly outperform strict lexicographic improvement.** Generation 11’s limited non-worsening plateau moves and Generation 14’s plateau moves with squared-pressure balancing both scored 26.19. Generation 15’s bottleneck move/swap search with up to two plateau escapes scored only 25.85. Generation 19 instead accepts strictly better lexicographic pressure vectors, avoiding arbitrary neutral transitions while still permitting improvements that reduce secondary bottlenecks.

- **Correctness and reachability remain mandatory.** The earlier Generation 4 implementation scored 0.00 because swap/candidate logic was unreachable and referenced undefined state. Every high-scoring program, including Generation 19, explicitly maintains capacity feasibility for construction, moves, swaps, and exchanges and passed validation with a 1.00 success rate.

## Implementation Insights

- **Generation 19’s mutable `PlacementState` cleanly synchronizes placement, pressure load, and remaining memory.** The program keeps `groups`, `loads`, and `remaining` together and updates all three in dedicated `add`, `move`, `swap`, and `exchange` methods. This mirrors the effective state-management approach identified in the prior Generation 9 best program and supports the current program’s perfect validation rate.

- **The current program evaluates local changes against a full sorted pressure vector, not only the maximum pressure.** `key_after(...)` computes post-action GPU pressures and compares `tuple(sorted(values, reverse=True))`. Consequently, an action can be selected when it preserves the leading bottleneck but reduces the next-largest pressure, creating a more stable basis for later bottleneck reduction. This is the defining distinction of Generation 19’s lexicographic bottleneck search and corresponds to its slight lead over Generation 17’s 26.21.

- **Bottleneck-focused neighborhood pruning preserves very low runtime.** Relocation candidates are generated only from GPUs whose pressure equals the current maximum within `1e-12`; swaps and exchanges are considered only when at least one involved GPU is a bottleneck. This targets the objective-relevant parts of the placement while keeping the expanded search at 0.01 s despite ten construction seeds and compound exchanges.

- **Capacity protection is applied before every mutation.** Construction requires `model.model_size <= remaining[gpu]`; swaps verify both post-swap remaining-memory values; one-for-two exchanges verify both resulting capacities. The program also rejects nonpositive GPU counts, zero SLOs, individual oversized models, and globally unconstructable placements. The evaluation feedback explicitly confirms that these checks produce correct placement output across all validation cases.

## Performance Analysis

- **Generation 19 is the strongest reported correct program, but its lead is narrow.** Its combined score of **26.23** exceeds Generation 17’s **26.21** by 0.02, Generation 13’s **26.20** by 0.03, and Generations 11 and 14’s **26.19** by 0.04. Relative to the previously identified Generation 9 best at 26.21, it improves by 0.02. The result confirms a refinement of an already strong algorithmic family rather than a large step change.

- **The largest historical gain comes from local search after diversified greedy seeds.** Multi-order greedy methods without the full move/swap refinement were in the 23.31–24.57 range, whereas the move-and-swap family reached 25.54–26.23. The current program strengthens that relationship: ten greedy construction paths identify good feasible starting points, then local search resolves pressure imbalance and memory fragmentation.

- **Compound exchanges correlate with the top end of the observed range, though only modestly.** Generation 17’s one-for-two exchange design scored 26.21, and Generation 19’s lexicographic version scored 26.23. By comparison, several strict move/swap variants scored 25.54 (Generations 10 and 18), 25.55 (Generation 12), and 25.66 (Generation 16). This suggests that compound exchanges are useful specifically for hard capacity configurations that ordinary relocation and pair swaps cannot traverse.

- **Runtime is not a meaningful penalty among the successful variants.** Generation 19 achieved the best score at 0.01 s, equal to Generation 11 and Generation 14, faster than Generation 13’s 0.04 s, and only marginally above several 0.00 s variants. The evaluation therefore shows that the added lexicographic comparison and bounded one-for-two exchange search improved reported quality while maintaining negligible execution cost.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Add a bounded two-for-one exchange neighborhood complementary to the existing one-for-two exchange.** When move and swap searches stall, test replacing two models on a bottleneck GPU with one model from another GPU, with exact post-exchange capacity checks and the same strict lexicographic-pressure acceptance rule. The current one-for-two operator is correlated with the top score band because it resolves fragmentation; its reverse can unlock cases where the bottleneck GPU needs to shed load while consolidating memory elsewhere.

2. **Expand the ten greedy seeds with a small set of targeted pressure-and-capacity orderings.** Add model orderings such as descending `weight / max(80 - model_size, tiny)`, descending `(weight, -model_size)`, descending `weight` within large/medium/small size buckets, and descending size with a weight-based secondary key. Multi-order initialization is already a defining strength of Generation 19, so a few objective-aware orderings may reach basins that the current five static orders miss without altering the successful local-search core.

3. **Use lexicographic best-improvement consistently when selecting the final seed, not only maximum score.** Store each refined candidate’s full sorted pressure vector and choose the candidate with the smallest vector lexicographically; use scalar maximum pressure only as the first component implicitly. Generation 19’s edge over close predecessors comes from reducing secondary bottlenecks, so preserving that criterion across multi-start selection can retain layouts that have equal maximum pressure but better overall balancing and more useful memory slack.

4. **Add a bounded ejection-chain repair operator for blocked relocations.** For a model on a bottleneck GPU that cannot be directly moved to a promising destination due to capacity, try moving one small destination model to a third GPU and then moving the bottleneck model into the freed space; evaluate the complete two-move action atomically with `key_after`. This extends the proven fragmentation-aware compound exchange idea while being more flexible than a strict one-for-two exchange, and candidate enumeration can remain small by restricting source GPUs to bottlenecks and third GPUs to the lowest-pressure feasible targets.

5. **Introduce a targeted large-model refinement pass before exhaustive compound exchanges.** After moves and swaps fail, rank models on bottleneck GPUs by a combination of high weight and large size, then evaluate exchanges involving only the top few ranked models and counterpart models/pairs that improve free-memory distribution. This preserves Generation 19’s bottleneck-focused pruning and low runtime while directing expensive compound search toward the models most likely to create capacity barriers and dominate pressure imbalance.
