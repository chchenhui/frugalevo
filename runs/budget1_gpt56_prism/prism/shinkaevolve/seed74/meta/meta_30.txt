# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **The current best program, Binary-Search KV Pressure Bin Packing (Generation 29), is the strongest evaluated design.** It achieved **26.23 combined score**, **25.23 max_kvpr**, **0.01 execution time**, and **1.00 success rate**. Its core advantage is objective alignment: for a threshold `T`, it packs each model with effective size `size + weight / T`, directly encoding  
  \[
  \frac{\sum weight}{80-\sum size}\le T.
  \]
  This produced a materially better KVPR result than all correct greedy-local-search programs.

- **Threshold-guided construction plus local refinement outperformed direct projected-ratio greedy placement.** Generation 29’s transformed packing followed by relocation/swap search scored **26.23**, versus **25.49** for Generation 22’s multi-seed KV-cache local search, **25.57** for Generation 20’s greedy placement with local refinement, and **25.66** for Generation 24’s multi-start local search. The threshold search supplies a stronger global initial structure than choosing the GPU with the best immediate projected pressure.

- **Multiple deterministic packing orders remain a successful anti-fragmentation pattern.** Generation 29 tests three orderings: effective-size/size/weight, effective-size/weight/size, and effective-size/weight-density/size. This is consistent with the successful multi-start family: Generation 22 uses several seed orderings and achieved **25.49**, Generation 24 used five greedy orderings and reached **25.66**, and Generation 27 used seven deterministic orderings for **26.18**.

- **Move-and-swap refinement is consistently useful after greedy construction.** The current best uses strictly improving relocations and pairwise exchanges, while Generation 20’s relocation/swap repair reached **25.57** and Generation 24’s move/swap/two-model repair reached **25.66**. These neighborhoods improve placements that cannot be repaired by a direct single-model move because memory fragmentation blocks otherwise beneficial balancing changes.

## Ineffective Approaches

- **Threshold packing alone is not sufficient when feasibility is represented only by unreliable greedy decisions.** Generation 21’s Binary-Search Transformed Best-Fit Placement, Generation 23’s Threshold-Guided GPU Model Placement, and Generation 28’s Threshold-Guided GPU Model Packing all scored **0.0** due to validation failure. Their feedback explicitly identifies that heuristic bin-packing checks can incorrectly reject feasible configurations or otherwise return results inconsistent with evaluator requirements.

- **Local-search complexity did not guarantee correctness.** Generation 25 added two-for-one exchanges to greedy placement but still received **0.0**. The evaluator feedback suggests that broader search neighborhoods do not compensate for fragile construction logic or incorrect handling around fully utilized GPUs and pressure ratios.

- **More elaborate threshold logic did not automatically improve over the current best implementation.** Generations 21, 23, and 28 all used binary search, transformed constraints, multiple orderings, and some local search, yet failed validation. In contrast, Generation 29 retained only assignments that were concretely constructed by `pack_for_threshold`, starts its search from a verified feasible upper bound, and returns a locally refined feasible assignment.

- **Direct greedy pressure balancing remained below threshold-based packing even when correct.** Generation 20 scored **25.57**, Generation 22 scored **25.49**, Generation 24 scored **25.66**, Generation 26 scored **25.70**, and Generation 27 scored **26.18**. These are strong results, but none exceeded Generation 29’s **26.23**, indicating that the minimax-threshold formulation—not merely a larger local-search neighborhood—was the main quality improvement.

## Implementation Insights

- **Generation 29’s effective-size formulation is the key implementation detail.** It computes:
  ```python
  effective[i] = sizes[i] + weights[i] / target
  ```
  and tests whether the effective sizes fit in 80-GB bins. This is algebraically equivalent to requiring each GPU’s aggregate load and remaining memory to satisfy the selected KVPR threshold. Unlike projected-ratio greedy methods, the construction phase is directly optimizing the same bottleneck metric measured by evaluation.

- **The current best keeps a verified feasible candidate throughout binary search.** It initializes `high` only after `pack_for_threshold(high)` succeeds, then updates:
  ```python
  if candidate is not None:
      high = middle
      best_solution = candidate
  ```
  Therefore, it never returns an analytical lower bound or a failed packing attempt; it returns an assignment generated by an actual successful packing pass. This behavior is especially important given the validation failures of Generations 21, 23, and 28.

- **The best program combines effective-capacity best fit with actual-objective selection.** For each threshold it tries multiple orders, assigns using either first-fit or best-fit residual effective capacity, then evaluates the resulting assignment using actual GPU KVPR:
  ```python
  key = score_key(loads, remaining)
  ```
  It chooses the lexicographically best pressure vector among successful heuristic packings. This prevents the transformed packing surrogate from being the sole ranking signal.

- **Strict local-search acceptance preserves feasibility and avoids cycling.** Generation 29 simulates moves and swaps, checks physical remaining-memory feasibility before accepting them, and only commits when `better(candidate_key, best_key)` shows a strict maximum-pressure improvement or a lexicographic pressure-vector improvement. This mirrors the successful design principle from Generations 20, 22, and 24: pressure balancing must be paired with explicit memory accounting.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Add a bounded exact/repair search inside `pack_for_threshold` when all greedy orders fail near the binary-search boundary.** Preserve the current verified-construction rule, but for a failed placement try reassigning the last 4–8 ordered models with depth-limited backtracking, or evict one model from a candidate bin and reinsert it into another feasible bin. This directly targets the false-infeasibility weakness identified in failed threshold-packing variants while retaining Generation 29’s robust “only return concretely packed assignments” behavior.

2. **Expand the transformed-packing portfolio with a small number of deterministic anti-fragmentation orders and placement rules.** In addition to the current three rankings, test descending raw size, descending weight density `weight / size`, descending `weight / (80 - size)`, and tie-break rotations; for each ordering, evaluate both first-fit and best-fit rather than coupling first-fit to only one order. The multi-start local-search programs and Generation 29’s existing order diversity show that deterministic construction diversity improves packing quality without meaningful runtime cost.

3. **Tighten binary-search upper bounds using the actual pressure of every successful constructed assignment.** When `pack_for_threshold(middle)` succeeds, compute `candidate_key[0]` and attempt packing again at `min(middle, candidate_key[0])`, retaining the best verified result if it succeeds. The effective-size threshold is objective-aligned but can contain slack because greedy transformed packing need not exactly saturate the pressure bound; feeding actual KVPR back into the search may expose a better feasible threshold and starting assignment.

4. **Run local refinement from several elite feasible threshold packings rather than only the final binary-search candidate.** Retain a bounded archive of the best assignments encountered during successful threshold checks—e.g., the best 3–5 distinct assignments by actual `score_key`—then apply the existing strict move/swap search to each and return the best refined result. This combines Generation 29’s objective-oriented threshold construction with the demonstrated benefit of multi-start search in Generations 22, 24, and 27, while preserving feasibility because every seed was explicitly packed.

5. **Add a carefully bounded two-model-to-one-model exchange neighborhood after single moves and swaps.** For overloaded GPUs, test moving two relatively small models from that GPU to another GPU while moving one compatible model back, checking physical memory exactly and accepting only strict `score_key` improvements. Simple relocation and swap neighborhoods are already validated as beneficial; a targeted 2-for-1 exchange can escape fragmentation patterns that pairwise swaps cannot solve, but should be restricted to models on the current highest-pressure GPUs to maintain near-zero runtime.
