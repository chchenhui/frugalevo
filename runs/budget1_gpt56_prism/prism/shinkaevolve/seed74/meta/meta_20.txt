# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Direct minimax threshold formulation remains the strongest pattern.** The current best, **Generation 5: Binary-Search KV Cache Bin Packing**, achieved **26.23 combined score** with **25.23 max_kvpr**, perfect validation, and effectively zero runtime. Its key advantage over greedy-local-search methods is that it tests the actual pressure bound \(T\):  
  \[
  \frac{L}{80-M}\le T \iff L+T M\le 80T.
  \]
  Using transformed item costs `weight + T * size` and bin capacity `80 * T` makes each binary-search feasibility test directly aligned with the minimax KVPR objective.

- **Multi-order best-fit construction improves both objective quality and robustness.** Generation 5 tries four descending orders based on transformed cost, model size, and load weight, then uses best-fit placement into the tightest feasible transformed-capacity bin. This diversification is consistent with the successful multi-start local-search family: Generation 12 reached **25.66**, Generation 14 and Generation 17 reached **25.63**, and Generation 16 reached **25.56**, all with 100% success. Multiple deterministic orderings reduce failure from memory fragmentation and ordering-sensitive greedy choices.

- **Local-search refinement is valuable, but it does not surpass threshold packing.** Greedy projected-KVPR placement plus moves/swaps was consistently correct and strong: Generation 10, 11, and 19 all scored **25.57**; Generation 16’s multi-seed plus swaps and pair relocations scored **25.56**. These results confirm that feasible swaps and pair moves escape move-only local minima. However, they remain **0.57–0.67 combined-score points below Generation 5**, showing that direct threshold feasibility is more effective than indirect greedy balancing.

- **Feasibility-first handling of edge cases correlates with perfect validation.** The successful methods explicitly preserve the 80-GB memory constraint throughout construction and refinement. Generation 5 additionally handles empty inputs, invalid GPU counts, oversized models, infeasible ordinary-memory packing, and the full-GPU positive-load case. This layered handling contributed to its **1.00 success rate**, as did explicit capacity checks in Generations 10–12, 14, 16, 17, and 19.

## Ineffective Approaches

- **Sophisticated heuristics still failed when evaluator-facing correctness was not robust.** Generation 13’s multi-start search with single moves, swaps, and same-source pair moves scored **0.0** despite a design similar to successful Generation 12 and Generation 17 variants. Generation 15’s lexicographic multi-start greedy plus move/swap refinement and Generation 18’s five-order/two-tie-break steepest-descent search also scored **0.0**. Their feedback indicates that explicit memory checks and local-search sophistication alone did not guarantee valid expected behavior across all validation cases.

- **A transformed-packing design can fail if its feasibility search is unreliable.** Previous Generation 9 scored **0.0** despite binary search, transformed costs, fallbacks, and local post-processing. This sharply contrasts with Generation 5’s **26.23**. The distinction is not merely using the algebraic transformation: Generation 5 retains only assignments returned by successful `try_pack` calls, tries several concrete packing orderings, and has a separate ordinary-memory fallback for degenerate cases.

- **Single-model relocation is structurally weaker than neighborhoods containing swaps.** Earlier move-only programs such as Generation 2 (**23.05**) and Generation 7 (**23.13**) were correct but substantially behind the successful swap-capable methods, which clustered around **25.56–25.66**. A model may not fit on a target GPU individually, while a cross-GPU swap can simultaneously improve pressure balance and resolve memory fragmentation.

- **Purely heuristic seed quality remains sensitive to hard packing arrangements.** The failed lexicographic/tie-breaking variants in Generations 15 and 18 demonstrate that more seed orders or alternative comparison rules do not automatically improve robustness. In contrast, Generation 5’s search evaluates a scalar feasibility condition tied exactly to the objective, rather than assuming a lexicographically attractive greedy partial placement will lead to an evaluator-valid global result.

## Implementation Insights

- **Generation 5’s transformed constraint correctly combines load and memory.** It computes `weights[i] = req_rate / slo` and, for candidate pressure `T`, uses:
  ```python
  costs[i] = weights[i] + T * sizes[i]
  capacity = T * GPU_MEM_SIZE
  ```
  A bin is feasible exactly when the transformed sum does not exceed `capacity`, corresponding to `load / remaining_memory <= T`. This is more objective-specific than the successful Generation 10/11/19 strategy of selecting the GPU with the lowest projected current maximum ratio.

- **The best implementation separates ordinary memory feasibility from finite-pressure optimization.** `memory_packing()` performs size-first, weight-second best-fit packing under physical 80-GB constraints. It is used if a positive-load model consumes an entire GPU, where remaining memory is zero and finite KVPR optimization is not meaningful, and as a safeguard if pressure expansion exceeds `1e15`. This concrete degenerate-case handling is absent from the summaries of the failed heuristic variants and is consistent with Generation 5’s full validation success.

- **Retaining the latest feasible assignment is a critical correctness detail.** In binary search, Generation 5 updates `best_assignment` only when `try_pack(middle)` succeeds:
  ```python
  if candidate is not None:
      right = middle
      best_assignment = candidate
  ```
  Since best-fit decreasing is a heuristic feasibility procedure rather than an exact bin-packing solver, this guarantees that the returned placement corresponds to an actually packed tested bound rather than an infeasible analytical lower bound or failed midpoint.

- **Anti-fragmentation choices are consistent across successful programs.** Generation 5 chooses the feasible GPU with minimum residual transformed capacity, while its fallback uses minimum residual physical memory. Similarly, Generations 10, 11, 14, 16, 17, and 19 combine pressure-aware greedy construction with relocation and swap repairs. The common implementation theme is not simply balancing load; it is preserving enough residual capacity to place difficult large models later.

This contrasts with the successful algorithms’ **1.00 success rate** and shows that even high-quality heuristic logic has no measured value unless it consistently satisfies all output and feasibility requirements.

The progression supports the conclusion that swaps and diversified seeds address local packing traps, while the current best’s direct search over the maximum allowable KVPR addresses the global minimax objective itself.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Evaluate every successful transformed-packing ordering and retain the best actual-KVPR assignment, rather than returning the first feasible one.** In `try_pack(pressure)`, construct assignments for all four orders that fit, compute each GPU’s true `load / (80 - used_memory)`, and select lexicographically by minimum maximum pressure, then second-highest pressure, then maximum residual memory. This preserves Generation 5’s threshold-feasibility guarantee while exploiting the fact that different feasible transformed packings can have noticeably different real pressure profiles.

2. **Add bounded repair when a promising transformed greedy packing fails.** When best-fit cannot place an item at pressure `T`, attempt a small repair neighborhood: swap the failed item with one item in each candidate GPU, evict one item from a candidate GPU and reinsert it elsewhere, or re-pack only the last 4–8 placed items with limited backtracking. This directly addresses best-fit’s false-infeasibility weakness without replacing the robust binary-search framework that made Generation 5 successful.

3. **Apply a strictly improving move/swap local search to the final feasible binary-search assignment.** After binary search, evaluate memory-feasible single-model moves and pairwise swaps, accepting only changes that lower actual maximum KVPR, with a secondary tie-break on the sorted pressure vector. Successful local-search generations consistently showed that swaps overcome fragmentation that moves alone cannot, and this refinement can improve the concrete assignment returned at an already feasible threshold without risking invalid placement.

4. **Expand transformed packing orders with a small number of pressure-aware anti-fragmentation rankings.** Keep the four existing deterministic orders, then add orders such as descending `weight / max(80 - size, EPS)`, descending size, then descending weight density, plus a few deterministic rotated tie-break variants for nearly equal transformed costs. Generation 5 already benefits from diversified orders, while the successful multi-start local-search programs support the idea that order diversity improves robustness against difficult memory layouts; keep the set bounded to retain near-zero runtime.

5. **Use the actual maximum KVPR of each feasible packing as an immediate upper-bound tightening step before continuing binary search.** Whenever `try_pack(middle)` succeeds, compute the assignment’s true max KVPR and set `right = min(middle, actual_max_kvpr)` when it remains finite, then attempt reconstruction at that tighter bound. The transformed threshold is objective-aligned, but a feasible greedy packing may have slack; feeding its measured pressure back into the search can expose lower feasible thresholds and improve beyond the current 25.23 max-KVPR result.
