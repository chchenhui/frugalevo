# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Pressure-threshold bin packing produced the best measured result.** The current best, **Binary-Search KV Cache Bin Packing** (Generation 5), reached **26.23 combined / 25.23 max_kvpr**, exceeding all greedy-local-search variants. Its key improvement is converting the KVPR condition into a transformed capacity constraint: for pressure bound `T`, each model has cost `weight + T * size` and each GPU has capacity `T * 80`. Binary-searching `T` directly targets the minimax objective rather than indirectly improving an initial placement.

- **Multiple construction orderings consistently improve robustness.** Generation 5 tries four descending orderings based on transformed cost, size, and weight before declaring a pressure bound infeasible. This matches the strong results of multi-start greedy methods: **Generation 1** reached **25.81**, **Generation 6** reached **25.66**, and **Generation 3** reached **25.65**. Across these programs, varying ordering reduces sensitivity to model-size/load ordering and memory fragmentation.

- **Memory-feasible balancing with moves and swaps is substantially better than one-pass greedy placement.** The baseline **Generation 0** greedy method scored only **21.89**, while greedy methods that optimize projected global KVPR and then repair placements reached roughly **25.57–25.65**: Generation 8 (**25.57**), Generation 4 (**25.62**), and Generation 3 (**25.65**). Pairwise swaps are particularly useful because they can improve balance where no individual relocation is memory-feasible.

- **Explicit handling of degenerate capacity cases supports correctness.** The current best detects a positive-load model occupying an entire 80 GB GPU and uses ordinary memory packing instead of attempting to binary-search an effectively infinite pressure. Together with oversized-model validation and fallback packing, this contributed to its **1.00 success rate**.

## Ineffective Approaches

- **A superficially similar transformed-packing approach failed completely when its feasibility logic was not reliable.** **Generation 9, Binary-Search KV Pressure Bin Packing**, scored **0.0** and failed validation, despite using transformed costs, binary search, fallback placement, and post-processing moves/swaps. The evaluator specifically reported that its packing/search heuristic did not reliably produce valid or expected placements. This contrasts with Generation 5’s successful design, where feasibility is checked through several concrete best-fit orderings and the latest feasible assignment is retained during search.

- **Single-start or lightly repaired greedy placement leaves significant objective quality on the table.** Generation 2’s projected-minimax greedy with relocation scored **23.05**, and Generation 7’s bottleneck-focused move-only search scored **23.13**. Both are correct and fast, but are about **3.1–3.2 combined-score points below** the current best. The common limitation is reduced diversification: fewer initial placements and no robust threshold-level packing search.

- **Move-only local improvement is weaker than move-plus-swap refinement.** Generation 7 uses strictly improving single-model relocations and achieved **23.13**. Programs explicitly adding feasible pairwise swaps—Generation 4 (**25.62**) and Generation 8 (**25.57**)—performed materially better. The reported reason is structural: swaps can escape memory-fragmentation and move-only local minima.

## Implementation Insights

- **The current best encodes the minimax KVPR objective in the packing test itself.** For a GPU with load `L` and used memory `M`, KVPR obeys `L / (80 - M) <= T`, rearranged as `L + T*M <= 80*T`. Generation 5 uses `req_rate / slo` as model load and `weight + T * model_size` as transformed item cost. This lets every binary-search iteration ask the relevant question: whether the target global pressure bound can be packed.

- **Feasibility safeguards are concrete and layered.** The implementation checks `gpu_num > 0`, rejects any model larger than 80 GB, returns empty assignments cleanly, and checks transformed single-item feasibility before packing. Its `memory_packing()` fallback uses size-first best fit and returns an explicit error if total placement is impossible. These details are consistent with its perfect validation outcome, unlike Generation 9’s incorrect result.

- **Keeping the latest feasible assignment during binary search is an important correctness pattern.** In Generation 5, `best_assignment` is updated only after a successful `try_pack(middle)`. Thus, even though best-fit decreasing is heuristic rather than an exact bin-packing oracle, the returned placement corresponds to an actually feasible tested pressure bound. The code does not return an assignment from a failed midpoint or from only an analytical lower bound.

- **Best-fit placement supports both transformed and ordinary memory constraints.** For each ordering, the algorithm places an item on the feasible GPU with the least slack after insertion. This is a practical anti-fragmentation choice. Comparable best-fit and multi-order construction patterns were also successful in Generation 1, Generation 3, and Generation 6, all of which exceeded **25.6 combined score**.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Add a bounded move-and-swap refinement phase to each feasible binary-search assignment.** After `try_pack(T)` returns an assignment, compute actual KVPR per GPU and apply only memory-feasible moves and pairwise swaps that strictly reduce the current maximum KVPR (with secondary reduction in the second-highest pressure). Generations 3, 4, and 8 show that swaps address fragmentation and local minima that single-item moves cannot; retain the refined assignment only if it remains valid and improves the actual objective.

2. **Expand transformed-packing diversification with additional deterministic and seeded tie-break orderings.** Keep the four successful current orderings, but add variants such as descending `weight / max(GPU_MEM_SIZE - size, eps)`, descending size-to-weight tradeoff, and a small fixed set of deterministic hash/rotation tie-breaks for near-equal costs. Multi-start/order diversification was consistently valuable in Generations 1, 3, 5, and 6, and this is a low-risk way to find feasible lower-pressure packings that best-fit decreasing misses.

3. **Use a stronger candidate-selection rule when multiple packings succeed at the same pressure.** Instead of returning the first feasible ordering in `try_pack`, evaluate all successful orderings and choose the assignment with the best lexicographic actual-pressure profile: lowest maximum KVPR, then lowest second-highest KVPR, then greatest minimum remaining memory. The transformed capacity condition establishes feasibility, but multiple feasible transformed packings can have materially different real KVPR distributions due to the interaction between load and memory.

4. **Introduce a small exact or bounded-search repair around the bottleneck GPUs during threshold feasibility checks.** When greedy best-fit fails at a promising midpoint, attempt limited reassignment search involving the failed item and models on one or two candidate GPUs—for example, one-for-one swaps, ejecting one item and relocating it elsewhere, or trying the last 3–6 items in alternate bins. This preserves Generation 5’s robust binary-search framework while addressing the main weakness of heuristic bin-packing feasibility: false infeasibility at a pressure bound that is actually packable.

5. **Warm-start lower binary-search candidates from the best known feasible placement and use pressure-aware reconstruction.** After finding an initial feasible assignment, derive its actual maximum KVPR as an improved upper bound, then attempt targeted reconstruction near that bound using the assignment’s bottleneck GPU composition as a guide—for example, place high `weight/(80-size)` items first and reserve low-memory bins for large models. This builds on the current program’s direct minimax formulation while borrowing the bottleneck-focused intuition of local-search methods, without sacrificing the current fallback and correctness safeguards.
