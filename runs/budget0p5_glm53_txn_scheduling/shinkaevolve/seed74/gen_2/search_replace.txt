<DESCRIPTION>
The current code runs a single greedy pass with random sampling, so the result varies a lot and often gets stuck in a bad local ordering. Two improvements: (1) run many greedy restarts with different random starting transactions and keep the best schedule found, and (2) add a cheap local search (adjacent-swap improvement) on the best schedule to squeeze out further makespan reductions. Since greedy construction is fast (only ~num_samples cost evaluations per step), doing many restarts is affordable and directly improves expected makespan. The swap-based local search exploits the fact that swapping two adjacent transactions in the sequence only changes conflict-induced delays locally, so small perturbations can yield meaningful makespan reductions. We keep the original greedy as a fallback structure but wrap it in a restart loop and polish with local search.

    def local_search(schedule, max_rounds=30):
        # Adjacent-swap local search: try swapping neighbors and keep improvements.
        best_cost = workload.get_opt_seq_cost(schedule)
        best_sched = list(schedule)
        improved = True
        rounds = 0
        while improved and rounds < max_rounds:
            improved = False
            rounds += 1
            i = 1
            while i < len(best_sched) - 1:
                cand = best_sched[:]
                cand[i], cand[i + 1] = cand[i + 1], cand[i]
                c = workload.get_opt_seq_cost(cand)
                if c < best_cost:
                    best_cost = c
                    best_sched = cand
                    improved = True
                else:
                    i += 1
        return best_cost, best_sched
