<DESCRIPTION>
The current version performs a single greedy pass with a fixed sample rate. The prior best-performing program showed that running many randomized greedy restarts (best-of-N) and keeping the schedule with the lowest makespan substantially improves the combined score (2631 vs 2732 scale — more restarts = better schedules). Randomized restarts diversify the search: each restart uses a random starting transaction and random sampling when picking the next transaction, so different restarts explore different orderings. Returning the minimum-cost schedule across all restarts monotonically improves the expected makespan. I restore the multi-restart wrapper and tune the parameters (more restarts, smaller candidate sample with high greedy rate) to bias toward strongly greedy but still diverse trajectories.
