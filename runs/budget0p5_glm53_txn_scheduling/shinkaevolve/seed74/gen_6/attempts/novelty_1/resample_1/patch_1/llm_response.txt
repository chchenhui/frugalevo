<DESCRIPTION>
The current code runs a single greedy pass with random sampling. A simple, high-impact improvement is to run many randomized greedy restarts and keep the best schedule found. Greedy orderings are highly sensitive to the starting transaction and tie-breaking, so multiple restarts with varying sample rates explore different orderings cheaply. We also add a local-improvement step: try swapping adjacent transaction pairs in the best schedule and keep improvements. This multi-start + perturbation strategy reliably reduces makespan versus a single greedy run.
