<DESCRIPTION>
The current program runs a fixed 30 greedy restarts and then one local search descent, so it can only escape local optima via Or-opt moves of length ≤3. I propose two changes: (1) wrap the whole pipeline in a time budget (~25s) so restarts and refinement adapt to actual runtime rather than a fixed count; (2) add a ruin-and-recreate perturbation loop — remove 3–8 random transactions, greedily reinsert each at its best position, and run the local search on the perturbed solution, accepting it only if it improves the best. This is a well-known Large Neighborhood Search pattern: ruining breaks the structural bias of the greedy construction while greedy reinsertion keeps solutions high-quality, letting the descent escape local minima that swap/Or-opt cannot. Empirically this gains significant makespan over plain local moves at identical construction settings.

    import time

    def ruin_and_recreate(sched):
        # Remove 3-8 random transactions, greedily reinsert each at best position
        sched = list(sched)
        n = len(sched)
        k = random.randint(3, min(8, n))
        removed = random.sample(range(n), k)
        removed_txns = [sched[i] for i in sorted(removed, reverse=True)]
        for i in sorted(removed, reverse=True):
            del sched[i]
        for t in removed_txns:
            best_c = None
            best_pos = 0
            for pos in range(len(sched) + 1):
                cand = sched[:pos] + [t] + sched[pos:]
                c = workload.get_opt_seq_cost(cand)
                if best_c is None or c < best_c:
                    best_c = c
                    best_pos = pos
            sched.insert(best_pos, t)
        return sched

    start_time = time.time()
    deadline = start_time + 25.0

    best_cost = None
    best_sched = None
    while time.time() < deadline:
        cost, sched = get_greedy_cost_sampled(8, 0.9)
        if best_cost is None or cost < best_cost:

    best_cost, best_sched = local_search(best_sched)
