<DESCRIPTION>
The current implementation runs a single greedy pass with a fixed sample of 10 candidates per step and no restarts, so a single bad early pick can lock in a poor schedule. Since get_greedy_cost_sampled is randomized, we can run many independent greedy restarts with slightly varied sampling rates and keep the best schedule found. This is essentially a "GRASP"-style (Greedy Randomized Adaptive Search Procedure) approach: each restart explores a different region of the ordering space, and taking the best-of-N dramatically lowers the expected makespan without changing per-run cost structure. We also lower the per-step sample count to 5 so we can afford more restarts within a similar compute budget, since the best-of-many effect dominates the per-step sample quality. To stay within reasonable time, we cap the number of restarts (e.g., 150) and track the best makespan/schedule across restarts, returning the overall best. This directly reduces the makespan metric while keeping schedules valid (each greedy pass already asserts a complete permutation).
