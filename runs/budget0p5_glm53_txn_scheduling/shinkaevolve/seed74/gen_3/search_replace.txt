<DESCRIPTION>
The current code runs a single greedy pass with full sampling (sample_rate=1.0), so the result depends heavily on one random starting transaction. Since greedy is cheap per restart, running many randomized restarts (with partial sampling to add diversity) and keeping the best schedule found dramatically reduces makespan. Additionally, after picking each transaction we keep the best-so-far across all restarts. This "best-of-N randomized greedy" is a standard and very effective metaheuristic for sequencing problems like this, and directly optimizes the actual makespan via `get_opt_seq_cost` rather than heuristics like transaction length.

Key changes:
1. Reduce `num_samples` per step slightly (10 -> 6) to allow more restarts within the same budget.
2. Use a sample_rate < 1 (0.85) so occasionally a random transaction is appended, adding diversity between restarts.
3. Run N restarts (e.g., 40) and return the schedule with the lowest overall makespan.
