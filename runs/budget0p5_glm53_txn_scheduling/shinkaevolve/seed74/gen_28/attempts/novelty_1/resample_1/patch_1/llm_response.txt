<DESCRIPTION>
Reasoning:
1. The current algorithm uses a single greedy construction + local search + ruin-and-recreate. A known weakness of single-seed iterated local search is premature convergence to one basin. Keeping a small pool of diverse seeds (from multiple randomized greedy constructions) and running ruin-and-recreate + local search on each spreads the search across basins, which is standard practice in ILS/beam-style scheduling optimizers.
2. The local search only uses single-txn relocation and swaps. Adding Or-opt moves (relocating short contiguous segments of 2–3 transactions) is a classic improvement for sequencing problems because good schedules often require moving small blocks of dependent transactions together.
3. The ruin operator currently only removes one contiguous segment. Removing multiple random scattered transactions ("random ruin") diversifies differently than contiguous "radial ruin" and is known (Schneider et al., ruin-and-recreate literature) to escape different local optima.

Changes:
- Build a pool of 3 seeds via greedy+local-search, each with a time slice, then continue ILS from the best, periodically re-seeding perturbations from the second-best to explore a different basin.
- Add Or-opt segment relocation moves to the local search.
- Perturbation randomly chooses between contiguous ruin and scattered random ruin.

This should lower makespan by exploring more of the search space within the same time budget.

        # mutually-dependent transactions together.

                if i != j:
                    moves.append((i, j))

                if time.time() >= deadline:

                    # relocation: move txn at i to position j
                    t = cand.pop(i)
                    cand.insert(j, t)
