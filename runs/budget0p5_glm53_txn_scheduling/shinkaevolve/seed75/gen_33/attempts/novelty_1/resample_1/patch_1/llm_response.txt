<DESCRIPTION>
The current program's local search only uses an insertion (relocate) neighborhood. Swap moves between adjacent/nearby conflicting transactions are a different, complementary neighborhood — insertion moves can't always reach orderings that swaps reach in one step, and vice versa. A hybrid neighborhood (best-of insertion + swap + adjacent swaps) explores a much richer set of orderings per round, so the search is less likely to stall in a local optimum. Additionally, the annealing schedule currently cools too fast (temp hits 0 after ~44 rounds with 0.9 decay), freezing the search early. I slow cooling (0.95 decay, floor 0.05 so a small diversification pressure persists) and increase rounds, since the cost cache makes repeated evals cheap. This is a targeted change to `local_search_insertion` only — the greedy construction, caching, and restart loop stay intact, keeping the known-good structure (score 3412.97 baseline) while deepening the search that produced the last two improvements (3401 → 3413). Step-by-step: (1) each round, sample both insertion moves and swap moves, tracking the single best improving (or annealing-accepted) move across both neighborhoods; (2) apply the best move; (3) slower cooling keeps the search alive longer, and the global-best tracking already protects against worsening moves.
