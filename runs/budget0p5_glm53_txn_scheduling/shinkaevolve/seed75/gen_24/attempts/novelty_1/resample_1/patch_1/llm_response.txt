<DESCRIPTION>
The recommendation analysis shows the current local search uses best-improvement relocation with full double loop over all (i, j) pairs, which is expensive per round. Switching to first-improvement with a shuffled i-order lets us accept the first improving move immediately and break the inner loop, dramatically cutting per-round query count. The saved time budget lets us raise the restart cap from 20 to 45 within the same 100-second deadline. More deep restarts (random greedy + local search polish) explore more basins of attraction, which prior generations showed helps. We keep a final best-improvement polish round at the end of each restart's local search so results are fully refined before being compared to the global best.

Step-by-step: (1) In `local_search_insertion`, pre-shuffle the index order each round and iterate in that randomized order. (2) When an improving relocation is found for position i, accept it immediately and break out of the j loop (first-improvement), continuing with the next shuffled i. (3) Run this until no improvement, then do one final best-improvement pass to polish. (4) Raise restart cap to 45 since each restart is now much cheaper, giving many more independent search trajectories within the same 100-second budget, which should lower the best makespan found.
