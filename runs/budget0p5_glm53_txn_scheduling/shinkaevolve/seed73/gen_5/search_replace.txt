<DESCRIPTION>
The current code runs a single greedy pass with sampling, which is highly noisy. A much better approach is:
1. Run the greedy-with-sampling construction many times (randomized restarts), since each run is cheap and gives a diverse pool of schedules.
2. Improve the best candidates with a local search: try moving a transaction to a different position (insertion neighborhood) and swapping pairs, accepting improvements in makespan. This directly optimizes the actual objective (`get_opt_seq_cost`) rather than heuristics.
Since `get_opt_seq_cost` evaluates the true makespan, a hill-climbing refinement over insertion/swap moves — repeated over multiple restarts within a time budget — will systematically reduce makespan compared to a single noisy greedy run. Time-budgeted multistart ensures we use whatever compute is available and always return the best schedule found.
