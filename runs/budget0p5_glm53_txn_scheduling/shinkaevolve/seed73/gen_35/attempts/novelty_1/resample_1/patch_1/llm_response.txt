<DESCRIPTION>
Reasoning step-by-step:

1. **Diagnose the bottleneck.** In the beam loop, every child's cost is computed once via `get_opt_seq_cost(new_seq)` and stored in the candidate tuple — yet at the end of each restart the code calls `get_opt_seq_cost(seq)` *again* on every beam entry. This is pure wasted evaluation. Reusing the already-stored cost `c` frees budget for wider beams / more restarts.

2. **Phase 2 is the biggest lever.** The top prior program (combined score 3623.19, makespan 275) used *iterated local search* (ILS) — first-improvement insertion, swap, or-opt block moves, and segment-reversal — with perturbation restarts, and it beat every simulated-annealing variant tried (3521, 3546, 3584). SA wastes many accepted uphill moves; ILS spends nearly all evaluations on improving or perturb-then-improve moves, which empirically yields better makespans here.

3. **Diversity matters.** The winning ILS program also deduplicated candidates by sequence so the local search budget isn't spent re-optimizing identical seeds.

So I apply: (a) reuse stored beam costs, (b) replace the SA phase with the proven ILS (first-improvement local search + shuffled-segment perturbation restarts), (c) dedupe candidates. This should recover the best-known performance while keeping the beam construction phase unchanged.
