# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns
- **Beam search is the strongest construction strategy**: The current best program ("Beam Search with Randomized Restarts," Gen 7, combined score 3610.11, makespan 276) outperformed all pure greedy variants. It prunes a beam of 2–6 partial orderings by actual makespan at each step, with randomized restarts (1–8) seeded by txn 0 plus random starts, and adaptive beam/restart widths scaled inversely to workload size.
- **Hybridization of construction + local search helps**: "Time-Budgeted Greedy Sampling with Local Search" (Gen 5, 3508.77, makespan 284) and "Beam Search with Restarts plus Local Search Refinement" (Gen 10, 3448.28, makespan 289) both beat pure greedy multistart, showing insertion/swap refinement on top candidates adds real gains.
- **Exhaustive multistart from all starting transactions is a strong greedy baseline**: "Multistart Greedy with Full-Lookahead" (Gen 3, 3333.33, makespan 299) substantially improved on sampled greedy approaches by restarting from every possible starting transaction.
- **Time budgets with frequent checks** (Gen 5's 25s 50/50 phase split; Gen 10's 20s with time checks) enabled more search without hurting validity.

## Ineffective Approaches
- **High random-skip rates degrade quality**: Gen 6's 80% random-choice probability produced the worst correct score (2624.67, makespan 380) despite 100 restarts—too much randomness overwhelms the greedy cost signal.
- **Sampled greedy alone plateaus**: Gen 1 (2801.12), Gen 4 (2808.99), Gen 11 (2976.19) all clustered around makespan 335–356 regardless of restart count (30–60), indicating multistart sampling alone cannot escape its quality ceiling.
- **Excessive restart counts waste compute**: Gen 4's 60×20 samples and Gen 6's 100 restarts added runtime without beating lighter restarts with better search structure (beam search).
- **Unconditional local search**: Gen 11's 15%-of-best local search filter only reached 2976.19, suggesting local search helps most when applied to already-strong beam-search candidates (Gen 10), not weaker greedy ones.

## Implementation Insights
- The current best program's key detail: **beam candidates carry full state** (cost, seq, remaining list), sorted and pruned to `beam_width = max(2, min(6, 400 // n))` each step, keeping multiple good partial orderings alive rather than committing greedily.
- **Restart count adaptive to workload size**: `num_restarts = max(1, min(8, 200 // n))` balances search breadth against cost-evaluation overhead—this adaptive scaling was unique to the two best-performing beam programs (Gen 7 and Gen 10).
- **Seeding restarts with txn 0 plus random starts** (Gen 7, Gen 10) provided a mix of deterministic and diverse entry points.
- All top programs still evaluate full-sequence cost via `get_opt_seq_cost` per candidate; feedback repeatedly notes incremental cost tracking (e.g., commented-out `get_incremental_seq_cost`) as the main unexplored efficiency lever that would allow wider beams/more restarts within budget.

## Performance Analysis
- Score ranking: Beam search (3610.11) > greedy+local search (3508.77) > beam+local search (3448.28) > full multistart greedy (3333.33) > two-phase randomized greedy (3225.81) > greedy+2-opt (2976.19) > sampled greedy cluster (~2800) > high-randomness greedy (2624.67).
- Beam search's advantage over best greedy is ~23 makespan points (276 vs 299); adding local search to beam search (Gen 10, 289) actually scored *worse* than pure beam (276), suggesting the local search consumed budget that would have been better spent on more beam expansion/restarts.
- Within greedy approaches, makespan correlates inversely with greedy determinism: 80% random (380) < sampling ~0.85–0.95 (335–356) < full lookahead no sampling (299).
- Schedule score (3.00) and validity (1.00) were uniform across all programs, so combined score differences are driven entirely by makespan—optimization effort should focus purely on makespan reduction.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

# Recommendations for Future Mutations

1. **Implement incremental cost tracking to widen the beam and restarts.** The top unexplored lever repeatedly flagged in feedback: replace full `get_opt_seq_cost(new_seq)` calls per candidate with `get_incremental_seq_cost` (or a custom incremental delta when appending txn `t` to `seq`). This would cut per-expansion cost from O(n) to O(1), enabling beam widths of 10–20 and restart counts of 16–32 within the same time budget—directly amplifying the beam-search pattern that dominates the leaderboard.

2. **Scale beam width adaptively during the search instead of keeping it constant.** Use a wide beam early (e.g., `max(6, 400 // n)` for the first 20% of placements, where branching choices compound most) and narrow it toward the end (2–3), or vice versa. Since beam pruning error compounds over depth, this concentrates search effort where it matters most while keeping the restart budget intact.

3. **Diversify restarts with greedy-shuffled seeds rather than uniformly random starts.** Currently seeds are txn 0 plus two uniform random picks; instead, seed each restart with the top-3 transactions by a cheap single-step heuristic (e.g., each txn's cost alone) plus one randomized pick. This combines the determinism that made full-lookahead greedy strong (Gen 3, makespan 299) with the diversity that helps beam search escape local optima.

4. **Add beam diversity pruning: keep the best `k-2` candidates by cost plus 2 candidates that maximize Hamming/sequence distance from the current beam.** Pure cost-pruning makes all beam members converge to near-identical prefixes, wasting beam slots. Diversity-preserving beam search (like Diverse Beam Search) is a natural, low-cost extension of the exact current architecture.

5. **Use a time-budgeted escalation: run pure beam search first, then spend any remaining time on more restarts with larger beams—not local search.** Gen 10 showed adding local search to beam search hurt (289 vs 276) by consuming budget better spent on beam expansion. Instead, add a wall-clock check (as in Gen 5's 25s budget) and dynamically increase `num_restarts` while there is time remaining, exiting early only when the budget expires—this converts spare compute directly into the search dimension that demonstrably works.
