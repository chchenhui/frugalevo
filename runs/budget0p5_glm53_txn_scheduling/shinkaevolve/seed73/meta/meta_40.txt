# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

# Recommendations for Future Mutations

1. **Add incremental delta-based cost evaluation for the ILS move neighborhoods.** The `local_search` function calls `get_opt_seq_cost(cand)` on every candidate move (O(n) full-sequence evaluation per neighbor), making a full insertion sweep O(n³) evaluations. Cache the current cost and use a delta-evaluator (or memoize recently evaluated sequences via a `tuple(seq)` LRU dictionary) so repeated candidate sequences across perturbation restarts cost O(1) — this can double effective restart count within the same 60% ILS budget, directly amplifying the proven perturbation-restart loop that produced the +348-point jump.

2. **Bias candidate refinement toward beam solutions by raising the deduplicated top pool from 6 to 8–10 with a mixed-composition quota.** Gen 35 (3816.79) showed cost-reuse beam variants are competitive, and Gen 33's top-6 pool beat Gen 35's top-4. Split the pool quota: reserve ~4 slots for the best beam solutions, ~2 for greedy constructions, and ~2 for perturbation-restart local optima discovered mid-refinement — this feeds the ILS with distinct basins rather than six near-identical beam outputs, which currently risk converging on the same local optimum.

3. **Scale perturbation strength to stagnation count instead of fixed 2–8 element shuffles.** Gen 33's restarts always shuffle 2–8 elements; when the incumbent has stagnated through many restarts, switch to larger perturbations (segment reversal of 10–20 elements or random 3-block reassembly, i.e., an LNS-lite kick). This borrows the ruin-and-recreate idea from Gen 38/39 but applies it only as an escape mechanism inside the winning ILS framework rather than as the primary intensifier, avoiding the wasteful full-sweep behavior that dragged SA variants down.

4. **Add diversity-preserving pruning within the beam: keep top `beam_width - 2` by cost plus 2 children with distinct last-appended transactions.** Beam slots currently converge on near-identical prefixes, wasting restart capacity on duplicates that later get deduplicated anyway. Zero extra cost, and it directly generalizes the construction-diversity principle (greedy rates 0.7/0.9/1.0) that made Phase 1b valuable — it also increases the number of distinct candidates surviving into the top-6 ILS pool.

5. **Add an or-opt-extended "block-swap" neighborhood: exchange two segments of length 1–3 pairwise.** The move-set ranking (290 → 272 → 245 as neighborhoods enriched) shows neighborhood breadth is the dominant score lever, and 2-opt (segment reversal) plus or-opt (segment reinsertion) are already validated — segment-swap is the natural next move in that family, changing many pairwise orders at once like 2-opt does. Insert it into the same first-improvement loop with the existing per-loop deadline checks so it doesn't starve the time budget.
