<DESCRIPTION>
The current greedy runs once with a fixed sampling of candidates. Two improvements: (1) run the greedy many times with different random starting transactions and candidate samples, keeping the best schedule found ("best-of-N restarts"), which dramatically reduces variance and reliably finds better orderings; (2) reduce wasted work by evaluating candidates with the full-sequence cost only when needed and short-circuiting when only one transaction remains. Since conflicts are local, transaction orderings that interleave conflicting transactions with low delay vary with the start point, so restarts explore different conflict-resolution structures. This directly lowers makespan while keeping the code simple and fast.
</DESCRIPTION>
