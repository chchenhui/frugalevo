<DESCRIPTION>
Instead of a single greedy run with a random start, run many randomized greedy restarts and keep the best schedule found. Greedy construction quality varies heavily with the starting transaction and random sampling, so multiple restarts dramatically improve expected makespan at modest cost. We keep the same greedy machinery (sampled candidate evaluation with `get_opt_seq_cost`) but wrap it in a restart loop, tune sample size/rate, and return the best result across restarts.</DESCRIPTION>
