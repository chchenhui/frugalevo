<DESCRIPTION>
The `balanced_packing` function is the main performance bottleneck: it runs a nested Python loop over all layers and all groups, and for each group performs an O(num_packs) linear scan (via `min` over a generator with `pack_weights.__getitem__` as key) to find the lightest pack. This gives O(num_layers * num_groups * num_packs) pure-Python time, which dominates the algorithm runtime (times_algorithm=0.56, speed_score=0.00).

Replace this with a heap-based approach: for each layer, maintain a min-heap of (current_pack_weight, tie_breaker, pack_index, items_in_pack). Pops/pushes are O(log num_packs) instead of O(num_packs), and we remove the generator-expression overhead entirely. A tie-breaker counter also makes ordering deterministic and avoids comparing packs with equal weights repeatedly.

Additionally, a small balance improvement: when picking the lightest pack among those with capacity, packs that are already full are lazily re-pushed only after their weight increases, so the heap stays small. The greedy still assigns the heaviest items first (indices are sorted descending), preserving the existing quality heuristic while being much faster.

For the common case of few packs (num_nodes or gpus per node), the constant-factor reduction from removing the generator + `min` per item is large (often 3-5x), directly improving `times_algorithm` and `speed_score`, while producing the same (or equivalent) balanced packing, so balancedness is preserved.
</DESCRIPTION>
