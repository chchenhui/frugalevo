The main bottleneck is `balanced_packing`: it contains a pure-Python double loop over all layers × all groups, doing a linear scan of pack weights for every item (O(num_layers * num_groups * num_packs)). This makes `speed_score` 0.00. I replace it with a fully vectorized "snake" (serpentine) LPT-style assignment: sort items descending once per layer, then assign the sorted sequence round-robin with alternating direction. This guarantees each pack receives exactly n/m items, keeps sums well balanced (snake pairing strong items with weak items beats plain round-robin), and runs in O(n log n) fully on tensor ops with no Python loop. Since the hierarchical algorithm is dominated by this routine (called twice with large row counts, e.g. num_layers*num_nodes rows), this should dramatically cut execution time while preserving/improving balancedness. `replicate_experts` is already vectorized; the remaining ops are cheap tensor kernels.
