<DESCRIPTION>
The current `balanced_packing` runs a Python-level loop over all items, but each iteration performs several full-row tensor operations (`torch.where`, `argmin`, two `scatter_`, fancy indexing). That is O(n) tensor kernel launches per row — the dominant cost of the whole algorithm (it is called twice per rebalance). Replacing it with a classic heapq-based LPT packer operating on plain Python lists removes all per-item tensor kernel launches while producing an identical (or better, due to deterministic tie-breaking) assignment. Since weights are already moved to CPU as the first operation of `rebalance_experts`, pure-Python list arithmetic is very fast at these problem sizes (tens of layers, hundreds of experts). Likewise, `replicate_experts` performs `num_redundant` iterations of tensor ops (`argmax`, gather, index updates); converting it to a per-row Python greedy with lists eliminates those kernel launches too. This keeps the exact same greedy semantics (clone the expert with the highest per-replica load) but with far lower overhead, directly improving `times_algorithm` / `speed_score` without touching the resulting balancedness scores. Per the reliability recommendation, `weight = weight.float().cpu()` stays the first operation in the entry point, all intermediate tensors remain on CPU, and `torch.sort(..., descending=True)` (no newer kwargs) is used for the initial ordering.</DESCRIPTION>

    # Greedy LPT (longest processing time first) heuristic implemented with
    # a plain Python heap: items are sorted descending once, then assigned
    # one at a time to the lightest non-full pack. Operating on Python
    # lists avoids per-item tensor kernel launches, which dominate the
    # runtime of the previous vectorized-loop implementation.
    import heapq

    order = weight.float().sort(-1, descending=True).indices.tolist()
    weights = weight.float().tolist()
    X = num_layers
    pack_index = torch.empty(X, num_groups, dtype=torch.int64)
    rank_in_pack = torch.empty(X, num_groups, dtype=torch.int64)
    cap = groups_per_pack

    for r in range(X):
        row_order = order[r]
        row_w = weights[r]
        load = [0.0] * num_packs
        count = [0] * num_packs
        heap = [(0.0, p) for p in range(num_packs)]
        heapq.heapify(heap)
        pi = pack_index[r].tolist()
        ri = rank_in_pack[r].tolist()
        for item in row_order:
            w, pack = heapq.heappop(heap)
            pi[item] = pack
            ri[item] = count[pack]
            count[pack] += 1
            w += row_w[item]
            load[pack] = w
            if count[pack] < cap:
                heapq.heappush(heap, (w, pack))
        pack_index[r] = torch.tensor(pi, dtype=torch.int64)
        rank_in_pack[r] = torch.tensor(ri, dtype=torch.int64)

    return pack_index, rank_in_pack
