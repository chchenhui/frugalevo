# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Vectorized snake/serpentine packing in `balanced_packing` is the proven backbone**: the current best program (Gen 1 lineage, combined 0.13, times_algorithm 0.00, speed_score 0.01, times_inference 0.23) uses descending sort + tensor-computed `rank_sorted`/`pack_sorted` with two `scatter_` calls — zero Python loops. Gens 12, 14, 19 confirm this core works; Gen 19's snake packing achieves identical GPU balancedness (0.66) at combined 0.13.
- **The three-stage hierarchical pipeline (groups→nodes, per-node replication, physical experts→GPUs) with global fallback when `num_groups % num_nodes != 0` remains correct in every passing program** (Gens 9, 13, 18, 19, current best) — the structure is validated; only internals differentiate.
- **Best observed speed profile comes from the current best**: times_inference 0.23 and speed_score 0.01 are the strongest of all evaluations. Every competing variant that added refinement loops (Gen 12/19: 64-iteration local search; Gen 13: 8-pass; Gen 18: 4·num_packs rounds) regressed to speed 0.00 and inference 0.44–0.55, confirming vectorized no-loop packing is strictly faster with no balance loss (GPU balancedness stuck at 0.66 everywhere).

## Ineffective Approaches

- **Rewriting `replicate_experts` quotas is high-risk**: Gen 11 (`proportional_replication_with_sorted_placement`) crashed with a 66-vs-72 tensor shape mismatch because floor/remainder quota counting didn't guarantee emitted replicas equal `num_phy` — all metrics 0.00. Any replication change must preserve the exact-count invariant before scatter.
- **Vectorized local-search swap refinements repeatedly crash**: Gen 15 (`balanced_pair_packing`) hit an out-of-bounds index (629990972 vs size 72) from `rank = block*2 + side` arithmetic with odd group counts; Gen 16 failed with scatter shape mismatch (`[1,8]` src vs `[58,8]` index). Both scored 0.00. Refinements that touch `rank_in_pack`/pack indices break the `phy2log * maxlogcnt + phyrank` scatter invariants (echoing Gen 6's earlier failure).
- **Working swap refinements still don't pay off**: Gen 13 (heap LPT + 8-pass refine, 0.13), Gen 12 (snake + 64-iteration refine, 0.13), Gen 18 (LPT + swap refine, 0.13) all matched but never exceeded the no-refinement baseline — extra compute bought zero balance improvement (GPU 0.66, expert 0.25) and cost speed.
- **Pure-Python heap/list loops**: Gen 9 (0.13, speed 0.00), Gen 13 (times_algorithm 0.05 vs best's 0.00), Gen 17 (heap on CPU lists) confirm loops double inference time (0.43–0.55 vs 0.23) with no quality gain.

## Implementation Insights

- **The current best's `balanced_packing` is the model to preserve**: `sort` → `pos // num_packs` (rank) → `pos % num_packs` with `torch.where(rank_sorted % 2 == 0, offset, num_packs - 1 - offset)` for snake direction → dual `scatter_(1, indices, ...)`. It's the only correct implementation achieving times_algorithm 0.00 without crashing.
- **`replicate_experts` remains the weakest, least-vectorized part even in the best program**: a Python loop `for i in range(num_log, num_phy)` doing per-step `(weight / logcnt).max(-1)` argmax. All correct programs — best included — score expert balancedness 0.25, so this greedy argmax heuristic caps the score; Gen 11's attempt to fix it shows the fix must keep exact replica counts.
- **Scatter index invariants are the dominant crash source**: Gens 11, 15, 16 all failed in scatter ops because computed pack/rank/replica indices violated shape or bounds constraints. Any modification must validate `rank_in_pack < groups_per_pack`, pack capacity, and `phy2log * maxlogcnt + phyrank < num_logical_experts * maxlogcnt` across all shape configurations.
- **Gen 17 (correct, all 0.00 metrics) repeats the "correct-but-zero" pattern** of Gens 3/7 — treat zero-metric runs as evaluation capture issues, not algorithmic regressions.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Vectorize `replicate_experts` with proportional replica allocation, keeping the exact-count invariant**: Replace the `for i in range(num_log, num_phy)` greedy argmax loop (the only remaining Python loop and the sole source of the 0.25 expert-balance plateau) with a closed-form allocation: compute per-row target counts as `torch.round(num_phy * weight / weight.sum(-1, keepdim=True)).clamp(min=1)`, then apply a single tensorized largest-remainder correction (diff vs `num_phy`, add/subtract 1 on rows at the extreme) so each row's counts sum exactly to `num_phy`. Build `phy2log` via `torch.repeat_interleave` and `rank` via `torch.arange` within segments — all tensorized, preserving times_algorithm 0.00. Critically, before returning, assert `logcnt.sum(-1) == num_phy` and `logcnt.max() <= maxlogcnt` to avoid Gen 11's 66-vs-72 shape crash.

2. **Cap replica counts at `maxlogcnt` before scatter, with redistribution**: The greedy argmax heuristic concentrates replicas on few experts, capping expert balancedness at 0.25. After computing proportional counts (recommendation 1), clamp counts at the redundancy ceiling (`num_redundant // 2 + 1` per node-level replicate call, verified against `maxlogcnt` in `rebalance_experts`), then redistribute excess to next-highest-load experts via tensorized masked top-k. Without this clamp, `phy2log * maxlogcnt + phyrank` in the final scatter can go out of bounds — the exact invariant that killed Gens 6/11/15/16.

3. **Keep the snake `balanced_packing` byte-identical and mutate nothing downstream of it**: The packing stage is saturated (GPU balance 0.66 across every correct program) and speed-optimal (times_algorithm 0.00, speed_score 0.01). Any future mutation should leave `balanced_packing`, the dual `scatter_` construction, and the `phy2pphy`/`pphy2mlog` index arithmetic untouched. The one untapped score dimension is expert balancedness; all mutations should target replication only, since every packing/swap variant (Gens 12, 13, 15, 16, 18, 19) either crashed or bought zero balance at 2–3× inference cost.

4. **If attempting a joint replication–packing refinement, mutate counts before packing, never ranks after**: A single tensorized pass after Step 2: compute per-GPU loads from a hypothetical packing via `scatter_add` on `tokens_per_phy`, and if the max-GPU load exceeds the mean by a threshold, shift one replica count from the highest-load logical expert in the hottest pack to the lowest in the coldest pack using top-k selection. This is the safe form of Gen 8's swap idea — it changes `logcnt`/`phy2mlog` inputs to Step 3, preserving all scatter invariants, and must remain loop-free to keep speed_score > 0.

5. **Preserve evaluation-timing hygiene in every variant**: Keep `weight = weight.float().cpu()` as the first operation of `rebalance_experts`, keep the global-fallback branch for `num_groups % num_nodes != 0`, use only `torch.sort(..., descending=True)` (never `torch.argsort` kwargs — Gen 5's crash), and never create tensors on other devices mid-algorithm. Gens 3, 7, and 17 show correct programs can score all-zeros from flaky capture; when a variant scores 0.00 with no crash, re-run before treating it as an algorithmic regression.
