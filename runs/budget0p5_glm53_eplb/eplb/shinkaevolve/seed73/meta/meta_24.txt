# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

# Updated Global Insights

## Successful Algorithmic Patterns

- **The current best program's vectorized snake LPT packing remains the proven backbone**: descending sort → `rank_sorted = pos // num_packs`, snake offset via `torch.where(rank_sorted % 2 == 0, offset, num_packs - 1 - offset)`, then dual `scatter_` — zero Python loops. It achieves times_algorithm 0.00, times_inference 0.23, speed_score 0.01, the strongest speed profile of all evaluations (Gens 12, 14, 19 confirm).
- **The three-stage hierarchical pipeline (groups→nodes, per-node replication, physical→GPUs) with global fallback when `num_groups % num_nodes != 0` is validated across every passing program** — Gens 20, 21, 22 (all combined 0.13, correct) again implement this structure unchanged, confirming only internals differentiate performance.
- **Gens 20–22 independently confirm the plateau, not a regression**: all three new correct variants (replica cap, heap LPT, vectorized LPT + spread cap) scored identical combined 0.13, GPU 0.66, expert 0.25 — matching the current best. No replication modification pattern found so far moves expert balancedness.

## Ineffective Approaches

- **Replica-count caps (`redundant//2 + 1`) hurt expert balancedness with no speed payoff**: Gen 20 (`cap_replica_spread`), Gen 21 (`heap_lpt_fast_packing`), and Gen 22 (`cap_and_spread_replica_counts`) all implemented capped `replicate_experts`; all scored expert balancedness 0.25 and speed 0.00 (vs best's 0.01). The cap spreads replicas too thinly relative to weight distribution — same expert balance as uncapped, but slower.
- **Gen 23's joint refinement stage crashed entirely** (all 0.00, "tensor a (72) must match tensor b (64)"): the refinement's count-rebuild gathers per-node `mlogcnt` (rows × num_mlog) with full-width `log2mlog` indices, violating index-space invariants. Echoes the established crash pattern of Gens 11, 15, 16 — refinements touching `logcnt`/scatter assembly break `phy2log * maxlogcnt + phyrank` invariants.
- **Python heap/list loops still double inference time**: Gen 21's heap-based greedy LPT on CPU lists produced times_inference 0.45 vs best's 0.23, speed_score 0.00. Confirms Gens 9/13/17's finding — the claimed "avoid kernel-launch overhead" benefit never materializes into better speed_score.

## Implementation Insights

- **The best program's `replicate_experts` is the confirmed score bottleneck and every attempted fix has failed**: the greedy loop `for i in range(num_log, num_phy)` with `(weight / logcnt).max(-1)` caps expert balancedness at 0.25 in all correct programs. Gen 22's vectorized-batched `balanced_packing` attempt succeeded in correctness (vectorizing across all rows via scatter) but still scored expert 0.25 — the greedy argmax heuristic itself, not the loop structure, is the quality limit.
- **Any post-replication refinement must preserve the mlog→log index space**: Gen 23 shows that rebuilding counts requires `mlogcnt` to be expanded/unflattened per node (`mlogcnt.view(num_layers, -1)` must align with `log2mlog`'s per-node unflattened ordering) before gathering — the 72-vs-64 mismatch came exactly from skipping this step.
- **Scatter index invariants remain the dominant crash source**: Gens 11, 15, 16, 23 all failed in scatter/gather ops. Any replication change must guarantee emitted replicas exactly equal `num_phy` and that `phy2log * maxlogcnt + phyrank < num_logical_experts * maxlogcnt` across configurations.
- **CPU-side `weight = weight.float().cpu()` with vectorized tensor ops is the winning runtime recipe** (best: 0.00 algorithm, 0.23 inference) — pure vectorized tensors, no Python-level per-item work.

## Performance Analysis

- **Universal plateau persists across 10+ correct programs**: combined 0.13 (GPU 0.66 / expert 0.25) for the best program plus Gens 9, 12, 13, 14, 18, 19, 20, 21, 22. GPU balancedness is saturated by the packing stage; expert balancedness is fixed by the replication heuristic and has never been moved by any working variant (caps, spreads, vectorized LPT all leave it at 0.25).
- **Current best dominates all new variants on speed**: 0.00/0.23/0.01 vs Gen 20 (0.02/0.45/0.00), Gen 21 (0.03/0.45/0.00), Gen 22 (0.01/0.45/0.00). The replica caps cost ~2× inference time with zero balance gain — strictly dominated by the best program.

- **Correlation reaffirmed**: speed_score > 0 occurs only in the fully loop-free packing (best, 0.01); any Python loop or refinement iteration collapses speed_score to 0.00 regardless of balance outcome.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Replace the greedy `replicate_experts` loop with a tensorized proportional largest-remainder allocation**: Compute per-row target counts as `torch.floor(num_phy * weight / weight.sum(-1, keepdim=True)).clamp(min=1)`, then fix the remainder in one tensorized pass: `diff = num_phy - counts.sum(-1)`, and for rows with `diff != 0`, use `topk` on the fractional residuals to increment/decrement the correct entries so each row sums exactly to `num_phy`. Build `phy2log` via `torch.repeat_interleave` on a sorted expert-id tensor and `rank` via `cumsum` within segments — fully loop-free, preserving times_algorithm 0.00. This directly attacks the only remaining Python loop, the confirmed source of the 0.25 expert-balance plateau (the greedy argmax heuristic, not the loop structure, was the quality limiter in Gens 20–22).

2. **Guarantee scatter invariants before returning from any new `replicate_experts`**: After the tensorized allocation, assert `logcnt.sum(-1) == num_phy` and `logcnt.max() <= maxlogcnt` (where `maxlogcnt = num_redundant_experts + 1` at the global level, and correspondingly smaller at node level). Gens 11/15/16/23 all crashed with all-zero scores from exactly these violations (`phy2log * maxlogcnt + phyrank` out of bounds, or 72-vs-64 shape mismatches from misaligned per-node flattening). A cheap shape/index check converts a guaranteed 0.00 into a correct fallback.

3. **If attempting joint replication–packing refinement, mutate `logcnt`/`phy2mlog` inputs *before* Step 3 packing, never post-hoc**: After Step 2, compute hypothetical GPU loads via `scatter_add` of `tokens_per_phy`, and if the hottest pack exceeds the row mean by a threshold, shift one replica count from the highest-load logical expert in the hottest node to the lowest in the coldest node using tensorized top-k — a single loop-free pass. This is the safe form of Gen 23's refinement: it changes the *inputs* to `balanced_packing` rather than rebuilding counts from per-node `mlogcnt` (which caused the 72-vs-64 crash because `mlogcnt.view(num_layers, -1)` must align with `log2mlog`'s per-node unflattened ordering before any gather).

4. **Leave `balanced_packing`, the dual `scatter_`, and all index arithmetic byte-identical**: GPU balancedness is saturated at 0.66 across 10+ correct programs and the snake-LPT + dual-scatter construction delivers the only speed_score > 0 (0.01, times_inference 0.23). Every packing/swap variant (Gens 12, 13, 15, 16, 18, 19) either crashed or bought zero balance at 2–3× inference cost. All future mutation budget should concentrate exclusively on the replication stage.

5. **Preserve evaluation-timing and structure hygiene in every variant**: Keep `weight = weight.float().cpu()` as the first operation, keep the global-fallback branch for `num_groups % num_nodes != 0`, use only `torch.sort(..., descending=True)` (Gen 5's kwargs crash), and never create tensors on other devices mid-algorithm. Gens 3/7/17 show correct programs can score all-zeros from flaky capture — re-run any variant that scores 0.00 without a crash message before treating it as an algorithmic regression. Also verify `tokens_per_phy = (tokens_per_mlog / mlogcnt).gather(-1, phy2mlog)` still yields integers-free float semantics after count changes, since downstream `balanced_packing` only needs ordering.
