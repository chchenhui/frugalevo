<DESCRIPTION>
The main bottleneck of the algorithm (times_algorithm = 0.56) is `balanced_packing`: it uses a pure-Python O(n · num_packs) scan per layer to find the least-loaded pack with remaining capacity. Replace this linear scan with a min-heap keyed by (load, pack_id): each item assignment costs O(log num_packs) instead of O(num_packs), and the heap automatically enforces the "exactly n/m objects per pack" capacity constraint (a pack is simply not pushed back once full). Additionally, the per-element tensor writes from Python are very slow; we buffer the (group, pack) assignments per layer in Python lists and perform a single vectorized indexed write into the tensors per layer. This keeps the same greedy LPT-with-cardinality-constraint packing quality (so balancedness is unchanged) while dramatically cutting the Python-side execution time, which improves the speed score and hence the combined score.
