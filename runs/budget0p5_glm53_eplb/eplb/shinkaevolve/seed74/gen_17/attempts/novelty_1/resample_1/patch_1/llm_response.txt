<DESCRIPTION>
The current algorithm replicates experts *within* each node (Step 2 runs `replicate_experts` on node-local expert subsets with only `num_physical_experts // num_nodes` slots per node). This caps the achievable balance: a hot expert living on one node cannot receive replicas proportional to its global load. Following the recommendation, I swap the order: first replicate globally over the full `num_physical_experts` pool, then (keeping the node-level group packing from Step 1 for network locality) adjust replica counts so each node holds exactly `num_physical_experts // num_nodes` replicas, and finally place replicas onto GPUs with an LPT-style greedy (min-load GPU with free slots) instead of the count-constrained `balanced_packing`. This removes the per-node replication granularity bottleneck, improves GPU balancedness, and replaces the O(n·m) Python `balanced_packing` loop for physical experts with a single greedy pass per layer/node (faster).
</DESCRIPTION>
