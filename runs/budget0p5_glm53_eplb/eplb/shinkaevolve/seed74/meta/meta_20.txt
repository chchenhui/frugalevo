# Analysis of Hierarchical Expert Parallelism Load Balancer Evaluations

## Successful Algorithmic Patterns

- **The current best program (Gen 18, "gpu_lpt_swap_refine", combined 0.15) sets a new ceiling** by breaking the 0.13–0.14 plateau of all prior correct programs. Its winning combination: global water-filling replication (marginal gain `weight/logcnt`) + vectorized cardinality-constrained LPT packing + **fully-tensorized heavy↔light GPU swap local search** evaluating all `num_gpus²` candidate swaps in one batched op per round. This is the only program to simultaneously achieve GPU balancedness 0.76 *and* the best runtime (times_algorithm 0.02, times_inference 0.24), yielding speed_score 0.01 (best among correct programs).

- **Three-tier scoring has emerged**: flat hierarchical programs (Gens 10, 15, 19) sit at 0.13 with GPU 0.66 / expert 0.24–0.25; global-replication + LPT programs (Gens 12, 14, 16) sit at 0.14 with GPU 0.76 / expert 0.29; the current best adds swap refinement to reach 0.15. **Abandoning the hierarchical groups→nodes decomposition in favor of a global flat policy is what moved GPU balancedness from 0.66 to 0.76** and expert balancedness from 0.25 to 0.29.

- **On-device computation with no host round-trips** is confirmed essential: the current best keeps all packing, replication, and swap-refinement loops on-device, matching Gen 4's earlier runtime win (0.00 algorithm time) and avoiding Gen 16's fate (pure-Python CPU bin-packing, speed_score 0.00 despite 0.76 GPU balance).

- **The `scatter_`-based permutation/inversion idiom remains the proven correctness backbone**: the current best uses `inv.scatter_(1, pos, arange)` then `gather(1, inv)` to reorder slots after packing, and `log2phy.view(L,-1).scatter_(-1, phy2log*maxlogcnt + phyrank, arange)` to build the logical map — compact, validated across every correct program.

## Implementation Insights

- **The current best's `_refine_gpu_balance` is the key novel pattern**: per round it computes `gpu_load = slot_load.view(L, G, P).sum(-1)`, identifies heaviest/lightest GPU per layer, then evaluates all `new_h = lh - wa + wb` / `new_l = ll + wa - wb` combinations in a `[L, P, P]` tensor, takes `argmin` of the elementwise max, and applies swaps via gather/scatter — all vectorized across layers with a `mask` no-op guard (`bv < cur - 1e-12`) for non-improving layers. This converts local search from O(G²) Python iterations to O(max_rounds) batched tensor ops.

- **Water-filling replication (`weight/logcnt` marginal-gain argmax, one expert per loop iteration)** is now validated across Gens 12, 14, 16, and 18 at expert balancedness 0.29 — strictly better than the hierarchical in-node replication (0.24–0.25). Note Gen 19's static top-k batched replication (`w/(j·(j+1))` gains) scored *worse* (expert 0.24), so the sequential `weight/logcnt` formulation in a `for i in range(num_log, num_phy)` loop appears superior and its Python loop cost (over `num_redundant` iterations only) is tolerable.

- **`balanced_packing` as vectorized greedy LPT with INF-masking** is the proven packing core (Gens 4, 18, 19): sort descending, iterate `t in range(num_groups)` with `torch.where(pack_items < groups_per_pack, pack_weights, INF)` then `argmin` + `scatter_add_` — O(num_groups) Python iterations regardless of layer count, preserving exact cardinality constraints. Gen 19's feedback confirms even this retains a per-item loop that caps speed, suggesting further vectorization headroom exists.

- **Scatter-key encoding for `log2phy`**: `phy2log * maxlogcnt + phyrank` as a flattened scatter key avoids nested indexing — a pattern shared by all passing programs.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Extend `_refine_gpu_balance` to evaluate all (heavy_gpu, all_gpus) pairs, not just heavy↔lightest.** The current full P×P matrix is only computed between the single heaviest and single lightest GPU per layer. Instead, evaluate swaps between the top-K heaviest GPUs and the bottom-K lightest GPUs each round (e.g., a [L, K, P] candidate tensor), taking argmin over all combinations. This is a drop-in generalization of the proven batched pattern, stays O(max_rounds) in Python iterations, and directly attacks the 0.76 GPU balancedness ceiling.

2. **Add a swap-based *replication* refinement pass.** After water-filling replication, the per-replica load `w/logcnt` is fixed and experts are locked to their replica counts. Add a post-packing pass that reassigns one replica of a highly-replicated expert (e.g., `logcnt ≥ 2` with lowest per-replica load) to an under-replicated expert, recompute slot loads, and re-run the existing GPU swap refinement. This targets expert balancedness (0.29, the binding constraint) via the same batched argmin/scatter machinery, potentially unlocking the ~+0.1 combined gains seen when replication strategy last changed.

3. **Iterate Stage 2 + Stage 3 as an outer loop (2–3 iterations).** After swap refinement perturbs the packing, re-running LPT packing on the (unchanged) slot_load may find a better assignment that the one-shot pack→swap sequence misses; conversely, alternate rounds let swaps escape local minima the single pass found. Wrap Stages 2–3 in `for _ in range(iters)` with an early-exit when max GPU load stops improving (reuse the existing `mask.any()` guard pattern). Runtime stays ~0.02s since each iteration is fully tensorized.

4. **Vectorize the `replicate_experts` water-filling loop in blocks.** The sequential `for i in range(num_log, num_phy)` loop is now the remaining per-item Python iteration. Replace it with block-top-k: select the next `B` (e.g., 16) replicas at once by taking top-B over `w/logcnt` per row with tie-broken ranks, then update `logcnt` in one scatter_add — reducing iterations by B×. This is the same top-k batching idea that failed in Gen 19 only because it *changed the gain formula*; keep the exact `weight/cnt` marginal-gain semantics, only batch the selection mechanics.

5. **Validate all new tensor ops against PyTorch signatures and mapping invariants before submission — one mutation per program.** 4 of 10 generations scored 0.00 from single defects (`argsort(stable=)`, edit delimiters, `log2phy`/`phy2pphy` shape mismatches). Any mutation touching the scatter-key construction (`phy2log * maxlogcnt + phyrank`) must assert `phyrank < maxlogcnt` and output shapes match `[layers, num_logical_experts, maxlogcnt]`; avoid unproven kwargs and stick to the validated primitive set (`scatter_`, `gather`, `torch.where`+INF masking, `sort().indices`). This makes the ~40% zero-score failure rate the cheapest win available.
