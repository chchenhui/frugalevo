# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **The current best (Gen 18-style pipeline, "gpu_lpt_swap_refine", combined 0.15) confirms the three-stage global flat pipeline as the ceiling**: global water-filling replication (`w/logcnt` marginal-gain argmax in a loop over `num_redundant` only) → vectorized cardinality-constrained LPT packing (INF-masked `argmin` + `scatter_add_`, one Python iteration per group regardless of layer count) → fully-tensorized swap refinement. It achieves GPU 0.76 / expert 0.29 / speed 0.01 simultaneously.

- **Batched full P×P swap-matrix refinement is the differentiator over pairwise-only refinement**: `_refine_gpu_balance` evaluates all `new_h = lh - wa + wb` / `new_l = ll + wa - wb` combinations in one `[L, P, P]` tensor per round, takes `argmin` of the elementwise max, and applies swaps via gather/scatter with a `mask = bv < cur - 1e-12` no-op guard. Prior pairwise-only swap refinements (Gen 12, Gen 21 "global_lpt_swap_refine", Gen 20 "global_refined_eplb") all stalled at combined 0.14.

- **On-device computation with no host round-trips remains essential**: the best program keeps every stage on-device; every program with per-layer Python/NumPy loops (Gens 20, 24, 21) scored speed 0.00 with times_algorithm 0.02–0.87, forfeiting runtime even at equal balancedness.

## Ineffective Approaches

- **Python/NumPy per-layer loops guarantee speed-score failure**: Gen 20 (heap-based packing, `max_rounds=8*num_phy` loop, times_algorithm 0.87), Gen 24 (per-layer loops in `balanced_packing`/`replicate_experts`/`refine_placement`, times_algorithm 0.02 but still speed 0.00), and Gen 21 (Python loop over all items + 64-iteration refinement) all scored 0.14 with GPU ~0.75–0.76 — equal balancedness, zero speed credit.

- **Reverting to hierarchical groups→nodes decomposition loses GPU balance**: Gen 22 ("gpu_ondevice_batched_replication", DeepSeek-style hierarchical rebalancing) regressed to GPU 0.67 / expert 0.24 / combined 0.13 despite being fully vectorized and on-device — replicating the flat 0.13 tier from Gens 10/15/19. Hierarchy is strictly worse than the flat global policy on both balancedness axes.

- **Single-variable bugs still zero out entire programs**: Gen 23 ("lpt_swap_refinement") crashed entirely (combined 0.00) because `_refine_packing` executed `del ar` inside the loop while defining `ar` outside it — an "ar otherwise valid fully-vectorized implementation" fails on any case running two refinement iterations. Combined with prior Gens 11/13/17, roughly 40% of submissions die from single fixable defects (API misuse, edit delimiters, `del`-of-loop variables, mapping-shape mismatches).

- **Dead code in refinement loops correlates with weaker search**: Gen 24's swap refinement carried `if False` branches and unused `valid`/`g` assignments and broke early on same-GPU swaps; its early-break and Gen 20's strict `2*gain <= diff` acceptance both contribute to the expert-balance stall at 0.27–0.29.

## Implementation Insights

- **The proven correctness backbone persists across all correct programs**: `inv.scatter_(1, pos, arange)` then `gather(1, inv)` for slot reordering after packing, and `log2phy.view(L,-1).scatter_(-1, phy2log*maxlogcnt + phyrank, arange)` for the logical map — the current best uses exactly this idiom compactly and correctly.

- **The batched swap application idiom is worth copying verbatim**: after computing best swap indices `a`, `b` per layer, the best program guards non-improving layers via `torch.where(mask, h*P+a, zero)` so non-improving layers perform a harmless self-swap, then swaps (phy2log, phyrank, slot_load) consistently in one buffered loop — keeping all three maps coherent without recomputation.

- **Sequential water-filling replication beats batched top-k**: the `for i in range(num_log, num_phy)` loop with `w/logcnt` argmax is validated at expert 0.29 (Gens 12/14/16/18/20/21), whereas Gen 19's static batched `w/(j·(j+1))` gains scored worse (0.24). The loop runs only `num_redundant` iterations, so its Python cost is tolerable — Gen 22's batched top-k replication inside a hierarchy also landed at 0.24.

- **Vectorized LPT with INF capacity masking is the packing core**: `torch.where(pack_items < groups_per_pack, pack_weights, INF)` + `argmin` + `scatter_add_`, O(num_groups) iterations — shared by the best program; heap-based (Gen 20) or Python-loop (Gen 24) equivalents gain nothing in balance while losing all runtime.

## Performance Analysis

- **Score tiers are fully stratified by policy, not effort**: hierarchical programs (Gens 10/15/19/22) cluster at combined 0.13 (GPU 0.66–0.67, expert 0.24–0.25); flat global-replication + LPT programs (Gens 12/14/16/20/21/24) at 0.14 (GPU 0.75–0.76, expert 0.27–0.29); the current best adds batched full-matrix swap refinement to reach 0.15 (GPU 0.76, expert 0.29, speed 0.01, times_inference 0.24 — best runtime of any correct program).

- **Expert balancedness (0.29) is the binding constraint**: across all thirteen generations, expert balance improved only 0.24→0.29 while GPU balance jumped 0.66→0.76. The entire 0.13→0.15 progression came from balancedness; speed contributes at most 0.01 and is essentially saturated (times_algorithm 0.02 vs. others' 0.03–0.87 all yielding speed ≤0.01).

- **Correctness failures dominate expected-value loss**: Gen 23's combined 0.00 from a single `del ar` bug, plus the prior ~40% crash rate from one-line defects, means a pre-submission validation pass (PyTorch signature checks, mapping-shape invariants, minimal two-iteration smoke test of every loop) has the highest expected payoff of any change.

- **Runtime quality only converts to score when balancedness is already at the ceiling**: Gen 20 and Gen 24 match the best's GPU 0.75–0.76 but score 0.14 vs. 0.15 purely on the batched-vs-loop refinement runtime gap (times_algorithm 0.02 vs 0.87/0.02 with Python refinement) — confirming that once GPU balance reaches 0.76, the remaining leverage is expert-level balance and refinement vectorization, not packing style changes.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Generalize `_refine_gpu_balance` from a heavy↔light pair to top-K heavy × bottom-K light candidates.** Build `[L, K, K]` (or `[L, K, P]`) tensors of `new_h = lh_k - wa + wb` / `new_l = ll_k + wa - wb` for the K heaviest and K lightest GPUs per layer, take argmin over the flattened candidate axis, and apply the best swap with the existing `torch.where(mask, ..., self-swap)` guard. This is a drop-in extension of the proven batched-swap idiom, stays O(max_rounds) in Python iterations, and directly attacks the GPU 0.76 ceiling.

2. **Add a batched replication-swap refinement to raise expert balance (the binding 0.29 constraint).** After Stage 3, evaluate reassigning one slot of experts with `logcnt ≥ 2` (per-replica load `w/logcnt`) to under-replicated logical experts: compute candidate `slot_load` changes in a `[L, num_phy]`-style candidate tensor, pick the argmin of the resulting max GPU load, update `phy2log`/`phyrank`/`logcnt`, and re-run `_refine_gpu_balance`. Expert balance improved only 0.24→0.29 across thirteen generations; replication reallocation is the only untouched lever and last unlocked ~+0.1 tier shifts.

3. **Iterate Stage 2 → Stage 3 in an outer loop of 2–3 iterations with an early-exit guard.** After swap refinement perturbs slot placement, re-packing via `balanced_packing` on the refined `slot_load` can find assignments the one-shot pack→swap sequence misses. Wrap stages in `for _ in range(2)` and break when the max GPU load stops improving (reuse the `mask.any()` pattern). Runtime stays ~0.02s since each pass is fully tensorized and speed score is already essentially saturated.

4. **Vectorize the `replicate_experts` water-filling loop in blocks of B replicas.** Select the next B replicas at once by top-k over `w/logcnt` (with rank-based tie-breaking via `sort().indices`, per the validated primitive set), updating `logcnt` and `rank` in one scatter each — cutting the `num_redundant` Python iterations by B×. Critically, keep the exact `weight/count` marginal-gain semantics: Gen 19 failed only because it *changed the gain formula* (`w/(j(j+1))`), not because of batching the selection mechanics.

5. **Add a pre-submission validation pass and keep one mutation per program.** Roughly 40% of generations (Gens 11/13/17/23) scored 0.00 from single-line defects like `del` of loop-scoped variables, `argsort(stable=)` misuse, and shape mismatches in the `phy2log * maxlogcnt + phyrank` scatter keys. Any new code must assert `phyrank < maxlogcnt`, verify output shapes `[layers, num_logical_experts, maxlogcnt]`, run a two-iteration smoke test of every loop (Gen 23's `del ar` bug only fired on the second iteration), and restrict to the validated primitive set (`scatter_`, `gather`, `torch.where`+INF masking, `sort().indices`) with no unproven kwargs.
