vectorized_packing_and_smarter_replication

<DESCRIPTION>
Two targeted improvements:

1. **Speed up `balanced_packing`**: the current implementation has a Python loop over all `num_groups` items per layer (O(num_layers × num_groups) Python iterations, each doing a `min` over packs). Since `num_groups % num_packs == 0`, each pack must receive exactly `groups_per_pack` items. We can therefore assign items in `groups_per_pack` rounds: in each round the `num_packs` heaviest remaining items (items sorted globally descending) are given to the packs sorted by ascending current weight. This is the same greedy but the Python loop shrinks from `num_groups` to `groups_per_pack` iterations (e.g. 256 → 16), and everything inside is vectorized tensor ops batched over all layers. Each pack gets exactly one item per round, so its in-pack rank is simply the round index, and the capacity constraint is automatically satisfied.

2. **Improve expert balancedness in `replicate_experts`**: currently the expert to replicate is chosen by `max(weight / logcnt)` (its *current* per-replica load). Choosing instead the expert whose *resulting* per-replica load `weight / (logcnt + 1)` is largest directly targets minimizing the maximum per-replica load — this is the standard greedy for minimizing makespan with divisible loads and yields noticeably better per-expert balance (balancedness_score_expert), which also improves the subsequent GPU packing quality since the input weights are more even.

These changes require no new configuration and preserve all function signatures and output semantics.

    pack_index = torch.full((num_layers, num_groups),
                            fill_value=-1,
                            dtype=torch.int64,
                            device=weight.device)
    rank_in_pack = torch.full_like(pack_index, fill_value=-1)
    pack_weights = torch.zeros((num_layers, num_packs),
                               dtype=weight.dtype,
                               device=weight.device)

    # Each pack must hold exactly `groups_per_pack` items, so we assign in
    # rounds: in each round the `num_packs` heaviest remaining items go to
    # the packs with the smallest current weight (ties broken by pack id via
    # a stable sort). Every pack receives exactly one item per round, so the
    # capacity constraint is automatically satisfied and the in-pack rank of
    # an item is simply the round index.
    for r in range(groups_per_pack):
        round_items = indices[:, r * num_packs:(r + 1) * num_packs]
        round_weights = sorted_weights[:, r * num_packs:(r + 1) * num_packs]
        # Lightest packs first (stable => deterministic tie-breaking).
        pack_order = pack_weights.argsort(-1, stable=True)
        pack_index.scatter_(1, round_items, pack_order)
        rank_in_pack.scatter_(1, round_items,
                              torch.full_like(pack_order, r))
        pack_weights.scatter_add_(1, pack_order, round_weights)
    return pack_index, rank_in_pack
