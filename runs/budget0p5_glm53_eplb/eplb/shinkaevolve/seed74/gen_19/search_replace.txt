<DESCRIPTION>
Three changes targeting both goals:

1. **Vectorize `balanced_packing`**: the current version has a pure-Python double loop (layer × groups) with a `min()` scan per item — this is why `times_algorithm` blew up to 0.55s. Replace with the fully vectorized greedy LPT from the earlier generation (loop only over item positions, all layer rows processed at once with `scatter_`/`argmin`), which scored `times_algorithm ≈ 0.01` with the same (or slightly better) balance quality (expert 0.25 vs 0.24).

2. **Batch `replicate_experts` with one top-k**: the per-iteration scatter loop runs `num_redundant` kernel launches. Key insight: giving expert `e` its `j`-th duplicate has marginal gain `w/(j*(j+1))`, which strictly decreases in `j`. Therefore the greedy "pick max marginal gain each step" sequence is exactly the sorted top-k over the static candidate set `{(e, j)}` — a candidate `(e, j)` can never be selected before `(e, j-1)` since it has strictly smaller gain. So a single `topk` over `[n, num_log × num_redundant]` candidates reproduces the greedy picks, replica ranks (`j`), and final counts in O(1) kernel launches instead of O(num_redundant).

3. **Remove the `.cpu()` round-trip** in `rebalance_experts`: `weight.float().cpu()` forces a device copy and moves all subsequent ops (and the returned maps) off the GPU. Keeping the tensor on its original device lets all the sort/gather/scatter ops run on-device with float32, cutting the dominant inference-time cost noted in the recommendations.

These are mutually consistent: all three operate device-agnostically and on the same tensor layouts.
