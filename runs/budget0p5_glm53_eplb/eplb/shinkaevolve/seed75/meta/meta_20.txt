# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **The current best program (Gen 19, "restore_local_search_and_policy_selection", combined 0.14) breaks the long-standing 0.13 plateau** by combining two elements: (1) local-search swap refinement in `balanced_packing`, and (2) policy selection in `rebalance_experts` that always computes the global policy (num_groups=1, num_nodes=1) and picks whichever of hierarchical/global better minimizes per-GPU squared-deviation imbalance. This GPU-imbalance-based policy selection lifted balancedness_score_gpu from 0.66 → 0.76, the first GPU-balance improvement observed across the entire evaluation history.
- **Greedy sorted-descending packing that fills each pack to exactly n/m items followed by heaviest↔lightest swap refinement** is the consistently successful packing core — it appears in Gen 19 and Gen 12 (both at combined 0.14, GPU 0.76, expert 0.29), confirming the score gain comes from this combination rather than a one-off.
- **Keeping the validated DeepSeek three-stage hierarchical structure intact (groups→nodes, replication, experts→GPUs) with the scatter-based inverse permutation and `log2phy` construction** remains the reliability backbone: all correct programs using it scored ≥0.13, while all structural rewrites that broke invariants (Gen 17, 18, 22) scored 0.00.
- **Aggressive vectorization that preserves correctness IS possible**: Gen 20 ("lpt_swap_refine_packing") achieved times_algorithm 0.02 (vs 0.07 for the current best) with the same GPU 0.66 / expert 0.25 profile — but only via batched-tensor LPT with capacity masking, not per-item Python loops.

## Ineffective Approaches

- **Pure-Python nested swap loops destroy the speed score**: the current best's O(num_groups) pairwise-swap refinement (double loop over pack members, per iteration) and Gen 11's `.argmax()`/`.nonzero()` per-layer refinement yield times_algorithm 0.07–1.31s and speed_score 0.00–0.01. The refinement improves balancedness but its Python-level cost caps the combined score.
- **Naive vectorization of replication is catastrophically buggy**: Gen 17's shared-`slot` counter assumed identical per-row expert counts and its broken `dev_sub` count fix-up produced out-of-bounds indices (index 1095953 vs dim size 64), crashing to 0.00. Gen 22's water-filling binary search failed on a scatter dtype error (`Expected dtype int32/int64 for index`), also 0.00. Gen 18 died on a syntax error (malformed walrus expression) before even loading — 0.00.
- **Expert-level balancedness remains stuck at 0.25–0.29 despite varied refinement**: local-search swaps (Gen 11, 14, 15, 20, 21) all plateau expert balancedness at exactly 0.25, because the bottleneck is the *replication* stage (`replicate_experts` greedy max weight/logcnt), not the packing. Only Gen 19/12's policy selection nudged it to 0.29 — pack-level refinement alone cannot fix replica-count fairness.
- **More refinement iterations ≠ better GPU balance**: Gen 14's 20-iteration greedy swap loop (times_algorithm 0.49) scored GPU 0.66, identical to Gen 15's snake-pack refinement and Gen 20's 8-round single-swap (GPU 0.66 each, times_algorithm 0.00–0.02). Refinement depth beyond a few rounds costs runtime with no balancedness gain.

## Implementation Insights

- **The current best's key differentiator is the `gpu_imbalance` comparison in `rebalance_experts`**: it computes `per_replica = (weight / logcnt).gather(-1, phy2log)`, sums loads per GPU, and picks global vs. hierarchical by squared deviation. This is a cheap (vectorized, single tensor expression) post-hoc selection that turned two 0.66-level policies into a 0.76 outcome — the highest-leverage change per line of code in the entire history.
- **Gen 20 shows the correct vectorization template**: batched LPT with `masked_fill(..., inf)` on full packs + `argmin(-1)` per iteration across all layer rows in lockstep achieves times_algorithm 0.02 — 3.5× faster than the current best's `.tolist()` Python packer (0.07) while producing identical balancedness (GPU 0.66). The current best's speed headroom is precisely this gap.
- **`replicate_experts` remains the identified-but-unfixed hot spot and accuracy bottleneck**: every program uses the same per-replica Python loop (max of `weight / logcnt`, incremental rank/logcnt updates). Gen 17's attempt to fix it via target-load rounding is the right *idea* (better expert balance) but failed on per-row count bookkeeping — count-sum and `maxlogcnt` invariants must be enforced per row, not globally.
- **The early-exit for groups_per_pack==1 (identity pack_index, zero rank)** in the current best and all top programs is a preserved cheap correctness win; the `inverse()` scatter-based permutation helper and the global fallback for non-divisible configs are structural must-keeps (present in every passing program).

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Target expert balancedness by changing the replication objective in `replicate_experts` from weight/logcnt-greedy to LPT over post-replication loads**: The insights show expert balance is stuck at 0.25–0.29 across all packing refinements because the bottleneck is the replication stage. Replace the `weight / logcnt` max-greedy with the proven masked-argmin LPT pattern: sort logical experts by weight descending and assign each redundant replica to the replica-group with the minimum current total load (using `masked_fill` + `argmin` batched across layer rows, per Gen 20's template). Critically, keep the per-row `logcnt` count bookkeeping and its invariant `logcnt.sum(-1) == num_phy - num_log + num_log` to avoid Gen 17's count-crash failure mode.

2. **Add expert-balance-based policy selection analogous to the GPU-imbalance selector that produced the 0.14 breakthrough**: The single highest-leverage change in history was computing global vs. hierarchical policies and selecting by per-GPU squared deviation. Extend this: compute a third candidate policy (e.g., hierarchical with `num_groups = num_gpus`, or the current policy plus its per-node-reversed variant) and select among candidates by a *combined* objective — a weighted sum of the existing `gpu_imbalance` and a new `expert_imbalance` (squared deviation of `logcnt * weight / mean` per logical expert). This reuses validated plumbing, adds no Python loops, and directly attacks the 0.29 expert score ceiling that pure refinement never moved.

3. **Replace the pure-Python packing loop in `balanced_packing` with Gen 20's batched-tensor LPT while keeping the swap refinement as a cheap bounded post-pass**: Gen 20 proved `masked_fill(..., inf)` on full packs + `argmin(-1)` per iteration across all layer rows in lockstep achieves times_algorithm 0.02 with identical balancedness (GPU 0.66). Port that batched packer, then run the existing heaviest↔lightest swap refinement with a hard cap of 2–3 rounds (insights show 20 iterations gained nothing over a few rounds) and restrict swap evaluation to the min(num_packs, k) extreme members per side to keep it cheap. This preserves the 0.76 GPU balance while recovering the 3.5× runtime gap.

4. **Add a vectorized replica-migration post-pass between Steps 2 and 3**: After `replicate_experts` fixes logcnt but before GPU packing, compute per-replica-group loads (`weight / logcnt` gathered per replica slot) and greedily *reassign which logical expert a redundant slot replicates*: pick the redundant slot of the most-loaded expert and re-point it to the least-loaded expert (one `logcnt` decrement/increment pair, batched with predicate masks across layers), re-running `phy2mlog`/`phyrank` construction after. This builds on the insight that replication — not packing — gates expert balance, while reusing the validated gather/scatter plumbing rather than rewriting it.

5. **Generalize the policy-selection ensemble to per-layer (not per-program) selection**: The current `rebalance_experts` picks one policy for all layers. Since `gpu_imbalance` is computed per layer via `(loads - mean)**2 .sum()` over a `[num_layers, num_gpus]` tensor, compute the per-layer imbalance vector for both hierarchical and global policies and assemble a hybrid output by selecting, for each layer independently, whichever policy's row has lower squared deviation (gather the corresponding rows of `phy2log`, `phyrank`, `logcnt` via a boolean/`torch.where` mask).
