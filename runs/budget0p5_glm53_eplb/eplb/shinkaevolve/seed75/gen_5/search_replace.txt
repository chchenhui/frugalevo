<DESCRIPTION>
The main bottleneck is `balanced_packing`, which runs a pure-Python double loop over `num_layers * num_groups` items. This makes the algorithm itself slow (speed_score = 0.00), which drags down the combined score. We can batch the greedy LPT-style assignment across all layers: sort each layer's weights once (already done via torch), then iterate only over item positions (`num_groups` iterations). In each iteration, we pick, for every layer at once, the pack with minimum accumulated weight among packs that still have capacity, and update the pack weights/counts with vectorized tensor ops. This reduces the Python loop count by a factor of `num_layers` while keeping the exact same greedy assignment (descending order, least-loaded feasible pack), so balancedness is preserved and runtime drops substantially. The `groups_per_pack == 1` fast path is kept unchanged.
</DESCRIPTION>
