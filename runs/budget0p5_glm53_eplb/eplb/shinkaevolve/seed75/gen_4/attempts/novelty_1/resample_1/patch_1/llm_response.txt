vectorize_balanced_packing

<DESCRIPTION>
The main runtime bottleneck is `balanced_packing`: it runs a pure-Python double loop over `num_layers x num_groups` items (called once for groups→nodes and once for physical experts→GPUs), each iteration doing Python-level list operations and `min()`. This dominates the algorithm time (speed_score is currently 0.00).

We can vectorize across layers: keep `pack_weights` and `pack_items` as tensors of shape [num_layers, num_packs], and only loop over the `num_groups` placement steps. In each step we place the next-heaviest remaining item of every layer simultaneously: mask out full packs with +inf, take an `argmin` over packs (which preserves the original min-index tie-breaking), and update state with advanced indexing. This reduces the Python loop count from `num_layers * num_groups` to `num_groups`, with each iteration doing a handful of vectorized tensor ops, and keeps identical greedy semantics (sort descending, place each item in the lightest non-full pack).

The greedy packing logic and outputs are unchanged, so GPU/ node balancedness is preserved, while algorithm runtime drops substantially, improving the speed score and thus the combined score.
</DESCRIPTION>
