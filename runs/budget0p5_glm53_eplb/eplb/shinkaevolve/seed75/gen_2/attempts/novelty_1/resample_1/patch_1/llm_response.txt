<DESCRIPTION>
The dominant cost of the algorithm is `balanced_packing`, which runs an O(num_layers × num_groups) Python loop where each iteration does `min(...)` over generator packs AND indexes into a torch tensor (`indices[i]` iterates over 0-d tensors — each access is a slow tensor-to-Python conversion). Converting the sorted indices and weights to plain Python lists once per call removes all tensor overhead from the hot loop. Additionally, we only need `min` over packs that aren't full — tracking the pack candidates in a small list and using `min(candidates, key=...)` on a plain list is dramatically faster than a generator over all packs with a conditional. Since `num_groups` is at most a few hundred, pure-Python lists are far faster than tensor ops per element. This cuts algorithm execution time substantially (improving `times_algorithm` and the speed score) while producing identical packing results, so balancedness is preserved. We also vectorize `replicate_experts`'s per-iteration division (weight/logcnt each iteration recomputes a full tensor division on all experts; we can update only the changed entry) — actually simpler: keep it but compute on the smaller per-node slice which it already is; the main win is balanced_packing.
