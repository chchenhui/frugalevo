<DESCRIPTION>
Replace the naive `weight/logcnt` argmax heuristic in `replicate_experts` with a proper LPT-style greedy over post-replication loads. Currently the heuristic keeps duplicating the hottest expert even when its per-replica load `w/c` has already dropped, wasting redundancy budget. Instead, at each step we evaluate the *resulting* per-replica load `w/(c+1)` for every logical expert (i.e., what its load would become if we gave it one more replica) and pick the expert with the highest resulting load — which is exactly the replica placement that minimizes the current maximum per-replica load across all replicas. This mirrors the proven LPT `balanced_packing` structure (iterative argmax/argmin over candidate loads) and directly targets the weakest metric, expert balancedness (0.25). The loop is over the (small) number of redundant experts only, and each iteration is a single batched op across all layers, so runtime impact is negligible compared to the existing implementation (same loop count, same per-iteration cost).
