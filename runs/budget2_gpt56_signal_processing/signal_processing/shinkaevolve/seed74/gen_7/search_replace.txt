hysteretic_slope_reversal
</NAME>

<DESCRIPTION>
Add a short confirmation hysteresis for slope sign changes. The current alpha-beta tracker can reverse its slope estimate from a single noisy innovation, which explains the elevated slope-change and false-reversal counts despite good tracking accuracy. The replacement requires two consecutive, noise-significant slope proposals in the new direction before accepting a reversal. While confirmation is pending, the existing slope is only gently decayed, preventing noise-driven direction flips while retaining rapid acceptance of sustained genuine turns. The normal same-direction update is unchanged in character, preserving responsiveness and low latency.
</DESCRIPTION>

        level = predicted_level + alpha * clipped_innovation
        proposed_slope = slope + beta * clipped_innovation

        # A reversal must persist for two significant innovations.  This temporal
        # hysteresis removes isolated noise reversals without adding window delay.
        reversal_threshold = 0.18 * noise_scale
        old_direction = np.sign(slope)
        new_direction = np.sign(proposed_slope)
        is_reversal = (
            old_direction != 0.0
            and new_direction != 0.0
            and new_direction != old_direction
            and abs(proposed_slope) >= reversal_threshold
        )

        if is_reversal:
            if new_direction == reversal_direction:
                reversal_count += 1
            else:
                reversal_direction = new_direction
                reversal_count = 1
